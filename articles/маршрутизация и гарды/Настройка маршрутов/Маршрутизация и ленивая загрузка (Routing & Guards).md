# Маршрутизация и ленивая загрузка (Routing & Guards)

## БЫСТРЫЙ СТАРТ

*   **Маршрутизатор Angular (`@angular/router`)** — это системный сервис и набор директив, превращающий приложение в полноценное одностраничное веб-приложение (SPA) путем синхронизации состояния адресной строки браузера и отображаемой структуры компонентов.
*   **Ленивая загрузка (Lazy Loading)** — асинхронное деление монолитного бандла приложения на изолированные физические фрагменты (chunks), загружаемые браузером строго по требованию при переходе на конкретный URL.
*   **Функциональные защитники (Functional Guards)** — легковесные функции-обработчики контроля переходов, принимающие решения о разрешении или блокировке навигации на основе проверок прав доступа (`CanMatch`, `CanActivate`, `CanDeactivate`).
*   **Используйте для:** организации структуры многостраничного приложения, динамического разделения JS-кода и разграничения прав доступа пользователей.
*   **Не используйте для:** переключения мелких презентационных вкладок внутри одного экрана (для этого достаточно локального состояния или сигналов).

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Конфигурация ленивых маршрутов с функциональными гардами
*   **Назначение:** Описание файла конфигурации маршрутизации с использованием асинхронного импорта `loadComponent` и легковесных функциональных проверок доступа через `inject()`.

#### 1. Файл описания маршрутов: `app.routes.ts`
```typescript
// Импортируем типы маршрутизатора и системный инжектор
import { Routes, Router } from '@angular/router';
import { inject } from '@angular/core';
import { AuthService } from './auth.service';

// Хорошо: Легковесный функциональный гард аутентификации вместо устаревших классов.
// Возвращает true для продолжения перехода или UrlTree для редиректа.
export const authGuard = () => {
  const authService = inject(AuthService);
  const router = inject(Router);

  // Возвращаем UrlTree для декларативного редиректа на страницу логина при отсутствии сессии
  return authService.isLoggedIn() ? true : router.createUrlTree(['/login']);
};

export const routes: Routes = [
  {
    path: '',
    // Обязательно указываем 'full' для пустого корневого пути во избежание бесконечного редиректа
    pathMatch: 'full', 
    redirectTo: 'home'
  },
  {
    path: 'home',
    // Хорошо: loadComponent разделяет код, загружая чанк HomeComponent только при переходе
    loadComponent: () => import('./home').then(m => m.Home)
  },
  {
    path: 'admin',
    loadComponent: () => import('./admin').then(m => m.Admin),
    // Привязываем функциональный гард к защищаемой ветке
    canActivate: [authGuard] 
  },
  {
    path: 'user/:id',
    // Параметризованный маршрут. Значение :id будет передано в компонент
    loadComponent: () => import('./user').then(m => m.User)
  }
];
```

### Шаблон 2: Включение сквозного связывания параметров в конфигурации приложения
*   **Назначение:** Регистрация провайдеров маршрутизатора в `app.config.ts` со специальной опцией `withComponentInputBinding()` для автоматической маппинга параметров путей в сигнальные входы компонентов.

#### 1. Файл глобальной конфигурации: `app.config.ts`
```typescript
import { ApplicationConfig } from '@angular/core';
import { provideRouter, withComponentInputBinding } from '@angular/router';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    // Конфигурируем роутер с поддержкой автоматического связывания
    provideRouter(
      routes,
      // Хорошо: withComponentInputBinding() маппит параметры пути (:id) и query-параметры (?tab=...)
      // напрямую в @Input() или сигнальные входы input() дочернего компонента
      withComponentInputBinding() 
    )
  ]
};
```

### Шаблон 3: Чтение параметров маршрута с помощью Signal Inputs
*   **Назначение:** Описание компонента личного кабинета, принимающего параметр `:id` из URL напрямую в сигнальный вход без ручной подписки на `ActivatedRoute`.

#### 1. Файл логики компонента: `user.ts`
```typescript
// Импортируем декоратор, сигнальные входы и стратегию OnPush
import { Component, input, ChangeDetectionStrategy } from '@angular/core';

@Component({
  selector: 'app-user',
  // standalone: true опущен согласно стандартам Angular 19+
  templateUrl: './user.html',
  styleUrl: './user.css',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class User {
  // Благодаря withComponentInputBinding() значение параметра :id из URL-адреса
  // автоматически запишется в этот сигнальный вход при монтировании компонента
  readonly id = input.required<string>(); 
}
```

#### 2. Файл разметки компонента: `user.html`
```html
<section class="profile-layout">

  </header>

    <p>Данные для выбранного идентификатора успешно привязаны реактивным роутером.</p>
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как устроен конвейер обработки переходов (Navigation Lifecycle)
Каждое изменение URL в адресной строке запускает сложный, строго регламентированный процесс обработки перехода внутри ядра маршрутизатора Angular:

```text
               Изменение URL в адресной строке (/admin/settings)
                                      │
                                      ▼
                       [Поиск маршрута в конфигурации]
                                      │
                                      ▼
             1. Проверка CanMatch (Разрешено ли сопоставить путь?)
                    ├── Нет ──> [Поиск альтернативного пути]
                    └── Да
                                      │
                                      ▼
               2. Проверка CanDeactivate (Разрешено уйти с текущей страницы?)
                    ├── Нет ──> [Навигация заблокирована]
                    └── Да
                                      │
                                      ▼
                3. Проверка CanActivate (Разрешено войти на новую страницу?)
                    ├── Нет ──> [Навигация заблокирована / Редирект]
                    └── Да
                                      │
                                      ▼
             4. Загрузка чанка (Если маршрут ленивый через loadComponent)
                                      │
                                      ▼
       5. Инстанцирование компонента -> Вставка в <router-outlet>
```

Прохождение фаз выполняется последовательно. Если на любом этапе гард возвращает `false` или `UrlTree`, конвейер немедленно прерывается. Подобная жесткая иерархия проверок позволяет гарантировать безопасность приложения до того, как начнется физический рендеринг новых DOM-структур.

### 2. Физика защитника `CanMatch` против `CanActivate` при ленивой загрузке
Разработчики часто путают назначение гардов `CanActivate` и `CanMatch`, что приводит к утечкам кода и уязвимостям:

*   **`CanActivate`**: Срабатывает *после* того, как маршрутизатор успешно сопоставил URL с конфигурационным путем. В случае ленивой загрузки (`loadComponent` / `loadChildren`) это означает, что браузер **сначала скачает по сети JS-бандл (chunk)** компонента, и только потом запустит гард `CanActivate`. Если гард вернет `false`, переход заблокируется, но исходный код страницы уже будет доставлен на клиент, что делает его уязвимым для анализа.
*   **`CanMatch`**: Срабатывает на самом раннем этапе — сопоставлении URL с путями. Проверка происходит *до* загрузки ленивого ресурса. Если `CanMatch` возвращает `false`, роутер игнорирует эту строчку конфигурации, **не скачивает JS-бандл по сети** и переходит к поиску других совпадений в массиве `Routes`. Это гарантирует абсолютную безопасность коммерческого кода и оптимизирует сетевой трафик.

### 3. Детальный пошаговый разбор выполнения шаблона 3
1.  **Конфигурация инициализации**: При запуске приложения `provideRouter` регистрирует провайдеры со сквозным связыванием параметров `withComponentInputBinding()`.
2.  **Переход на маршрут**: Пользователь переходит по адресу `/user/42`. Роутер находит совпадение с шаблоном пути `user/:id`.
3.  **Асинхронная загрузка**: Вызывается `loadComponent`. Браузер скачивает JS-файл с компонентом `User` и импортирует его класс в рантайм.
4.  **Разрешение параметров**: Маршрутизатор извлекает значение `42` из сегмента `:id` и записывает его во временную карту параметров.
5.  **Связывание с сигнальным входом**: На этапе инстанцирования класса `User` роутер обращается к свойству `id`, которое является сигнальным входом `input.required<string>()`, и автоматически записывает туда значение `'42'`.
6.  **Отображение в шаблоне**: Angular рендерит компонент `User`. В HTML-разметке вызов `id()` возвращает `'42'`, отображая идентификатор пользователя на экране без ручных подписок.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Бесконечный цикл редиректов при префиксном сопоставлении пути по умолчанию**
    *   *Симптомы:* Зависание браузера при старте приложения, критическая ошибка рантайма: `Error: Maximum call stack size exceeded` или бесконечный рост истории переходов.
    *   *Физика процесса:* Маршрут по умолчанию `{ path: '', redirectTo: 'home' }` настроен со стратегией сопоставления по умолчанию `pathMatch: 'prefix'`. Поскольку пустая строка `''` является префиксом для абсолютно любого URL-адреса, роутер пытается применить редирект на каждом переходе (даже когда URL уже равен `/home`), приводя к бесконечному зацикливанию.
    *   *Решение:* При перенаправлении с пустого пути всегда явно указывайте стратегию точного соответствия `pathMatch: 'full'`.

```typescript
// ПЛОХО (Вызовет бесконечный цикл редиректов при переходе на любой URL)
{ path: '', redirectTo: 'home' } 

// ХОРОШО (Редирект сработает только в том случае, если в адресной строке нет сегментов пути)
{ path: '', pathMatch: 'full', redirectTo: 'home' } // ✅ Безопасно
```

*   **Ошибка 2: Утечка и сохранение невалидного состояния при уходе со страниц форм без предупреждения**
    *   *Симптомы:* Пользователь случайно кликает по ссылке меню во время заполнения сложной длинной формы, страница мгновенно меняется, и все введенные данные необратимо теряются без предупреждения.
    *   *Физика процесса:* Отсутствие контроля перехода в обратную сторону. Роутер безбарьерно уничтожает текущий компонент формы при изменении URL.
    *   *Решение:* Реализуйте функциональный гард `CanDeactivate`, который будет запрашивать у пользователя подтверждение выхода (например, через нативный `confirm`) при наличии изменений в форме.

```typescript
// Реализуем функциональный гард CanDeactivate
export const pendingChangesGuard = (component: UserForm) => {
  // Если форма была изменена, запрашиваем подтверждение выхода у пользователя
  if (component.form.dirty) {
    return confirm('У вас есть несохраненные изменения. Вы уверены, что хотите уйти?');
  }
  return true;
};

// Привязываем гард к маршруту формы в app.routes.ts
{
  path: 'settings',
  loadComponent: () => import('./settings').then(m => m.Settings),
  canDeactivate: [pendingChangesGuard] // ✅ Защита от случайной потери данных
}
```

*   **Ошибка 3: Утечка памяти при ручной подписке на `ActivatedRoute.params` в OnPush компонентах**
    *   *Симптомы:* Постепенный рост потребления памяти вкладкой, некорректное обновление данных в UI при повторных переходах на тот же роут с другими параметрами.
    *   *Физика процесса:* Разработчик вручную подписался на поток параметров `this.route.params.subscribe(...)` в коде класса для считывания `:id`, но забыл отписаться при уничтожении. Ссылка на подписку остается активной, блокируя сборку мусора.
    *   *Решение:* Полностью откажитесь от ручных подписок на `ActivatedRoute` в пользу сквозного связывания параметров через `withComponentInputBinding()` и сигнальных входов `input()`.

```typescript
// ПЛОХО (Ручная подписка без отписки создает утечку памяти)
export class User implements OnInit {
  private route = inject(ActivatedRoute);
  userId!: string;

  ngOnInit() {
    this.route.params.subscribe(p => this.userId = p['id']); // ❌ Утечка памяти!
  }
}

// ХОРОШО (Компонент реактивно получает параметр в сигнальный вход, отписка не требуется)
export class User {
  readonly id = input.required<string>(); // ✅ Идеально, утечки исключены
}
```
