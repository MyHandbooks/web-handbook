# Автоматическое связывание параметров маршрута

## БЫСТРЫЙ СТАРТ

*   **Функция `withComponentInputBinding()`** — это встроенный конфигурационный модификатор Angular-роутера. Он заставляет фреймворк автоматически пробрасывать параметры пути (Path Params), параметры строки запроса (Query Params) и статические данные (Route Data) напрямую в соответствующие входные свойства (`input` или `@Input`) целевого компонента.
*   **Устранение бойлерплейта:** Эта функция полностью избавляет от необходимости ручного внедрения службы `ActivatedRoute`, подписок на асинхронные потоки `paramMap` / `queryParamMap` и ручного извлечения значений в классе компонента.
*   **Используйте:** Для всех компонентов-экранов, поведение которых зависит от параметров URL (например, ID просматриваемого объекта, поисковые фильтры, номера страниц пагинации).
*   **Не используйте:** Если вам требуется сложный, скоординированный анализ истории переходов или низкоуровневый доступ к состоянию роутера (для этого по-прежнему применяется служба `Router` или `ActivatedRoute`).

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Автоматическое связывание динамического параметра пути (Route Parameters)
*   **Назначение:** Компонент детального просмотра пользователя принимает параметр `:userId` из URL-адреса (`/users/usr-772`) прямо во входной сигнальный параметр без внедрения `ActivatedRoute`.

#### 1. Конфигурация маршрута: `app.routes.ts`
```typescript
import { Routes } from '@angular/router';

export const routes: Routes = [
  {
    path: 'users/:userId', // Параметр пути userId должен в точности совпадать с именем input-сигнала
    loadComponent: () => import('./user-details').then(m => m.UserDetails)
  }
];
```

#### 2. Файл логики компонента: `user-details.ts`
```typescript
import { Component, ChangeDetectionStrategy, input, computed } from '@angular/core';

@Component({
  selector: 'app-user-details',
  templateUrl: './user-details.html',
  styleUrl: './user-details.css',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class UserDetails {
  // Роутер автоматически запишет значение :userId из URL в этот input-сигнал
  public readonly userId = input.required<string>();

  // Используем computed-сигнал для декларативного вычисления связанных данных
  public readonly apiEndpoint = computed(() => {
    return `https://api.web-archive.org/v1/users/${this.userId()}`;
  });
}
```

#### 3. Файл разметки компонента: `user-details.html`
```html
<div class="details-card">
  <h3>Профиль пользователя</h3>
  <p>Идентификатор (из URL): <strong>{{ userId() }}</strong></p>
  <p>Эндпоинт загрузки данных: <code>{{ apiEndpoint() }}</code></p>
</div>
```

#### 4. Файл стилей компонента: `user-details.css`
```css
.details-card {
  padding: 20px;
  background-color: var(--bg-secondary);
  border: 1px solid var(--border);
  border-radius: 8px;
}

code {
  background-color: var(--code-bg);
  padding: 4px 8px;
  border-radius: 4px;
}
```

### Шаблон 2: Привязка параметров строки запроса и кастинг типов (Query Parameters)
*   **Назначение:** Компонент каталога принимает поисковый запрос `?query=angular` и номер страницы `?page=3` из строки запроса. Демонстрирует автоматическое приведение строковых параметров URL к числовым типам через встроенный трансформер.

#### 1. Файл логики компонента: `catalog-search.ts`
```typescript
import { Component, ChangeDetectionStrategy, input, numberAttribute } from '@angular/core';

@Component({
  selector: 'app-catalog-search',
  templateUrl: './catalog-search.html',
  styleUrl: './catalog-search.css',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class CatalogSearch {
  // Связываем необязательный query-параметр "?query="
  public readonly query = input<string>('');

  // Связываем query-параметр "?page=". 
  // Используем трансформер numberAttribute для преобразования строкового параметра URL в тип number!
  public readonly page = input<number, string>(1, { 
    transform: numberAttribute 
  });
}
```

#### 2. Файл разметки компонента: `catalog-search.html`
```html
<div class="search-panel">
  <h3>Каталог продукции</h3>
  
  <div class="search-state">
    <p>Поисковый фильтр: <strong>{{ query() || 'Все товары' }}</strong></p>
    <p>Активная страница: <strong>{{ page() }}</strong> (Тип данных: <code>{{ typeofPage }}</code>)</p>
  </div>
</div>
```

#### 3. Файл стилей компонента: `catalog-search.css`
```css
.search-panel {
  padding: 24px;
  background-color: var(--bg-secondary);
  border: 1px dashed var(--border);
  border-radius: 10px;
}

.search-state {
  margin-top: 12px;
  display: flex;
  flex-direction: column;
  gap: 8px;
}
```

### Шаблон 3: Связывание статических данных роута (Route Data)
*   **Назначение:** Экран настроек считывает статический параметр `title` и конфигурационный флаг `readOnly` напрямую из конфигурации роута.

#### 1. Конфигурация маршрута: `settings.routes.ts`
```typescript
import { Routes } from '@angular/router';

export const routes: Routes = [
  {
    path: 'settings/security',
    loadComponent: () => import('./security-settings').then(m => m.SecuritySettings),
    // Объявляем статические метаданные маршрута
    data: {
      pageTitle: 'Безопасность учетной записи',
      isSystemLocked: true
    }
  }
];
```

#### 2. Файл логики компонента: `security-settings.ts`
```typescript
import { Component, ChangeDetectionStrategy, input, booleanAttribute } from '@angular/core';

@Component({
  selector: 'app-security-settings',
  templateUrl: './security-settings.html',
  styleUrl: './security-settings.css',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class SecuritySettings {
  // Связываем статическое свойство pageTitle из data-объекта роута
  public readonly pageTitle = input.required<string>();

  // Связываем флаг, приводя его к строгому булеву типу
  public readonly isSystemLocked = input<boolean, string | boolean>(false, {
    transform: booleanAttribute
  });
}
```

#### 3. Файл разметки компонента: `security-settings.html`
```html
<div class="settings-box">
  <h2>{{ pageTitle() }}</h2>
  
  @if (isSystemLocked()) {
    <div class="alert-box">
      <p>⚠️ Доступ к редактированию заблокирован администратором системы.</p>
    </div>
  }
</div>
```

#### 4. Файл стилей компонента: `security-settings.css`
```css
.settings-box {
  padding: 24px;
}

.alert-box {
  margin-top: 16px;
  padding: 12px 16px;
  background-color: var(--warning-bg);
  border: 1px solid var(--warning-border);
  color: var(--warning-text);
  border-radius: 6px;
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как работает связывание параметров под капотом Angular
Реализация связывания в Angular роутере основана на системном сервисе — `ComponentInputBinder`. Схема работы выглядит следующим образом:

1.  **Активация маршрута:** Пользователь переходит по URL. Роутер сопоставляет сегменты и определяет целевой Standalone-компонент.
2.  **Сбор параметров:** Роутер собирает все доступные данные из текущего снимка состояния маршрута (`ActivatedRouteSnapshot`). Он создает единый плоский ассоциативный массив (словарь), последовательно сливая в него:
    *   Параметры пути (Path params)
    *   Параметры строки запроса (Query params)
    *   Данные конфигурации (Route data)
3.  **Запись во входные свойства (Inputs):**
    `ComponentInputBinder` обращается к фабрике компонента и находит все зарегистрированные входные свойства (как классические `@Input()`, так и новые `input()` сигналы). Если имя ключа в собранном словаре параметров в точности совпадает с именем входного свойства компонента, сервис принудительно вызывает обновление этого свойства, передавая значение из URL.

### 2. Почему сигнальные свойства `input()` идеальны для связывания параметров
Использование сигналов `input()` взамен классических `@Input()` дает колоссальные преимущества при автосвязывании:

*   **Декларативная реактивность:**
    Поскольку параметры из URL приходят асинхронно по мере навигации, входные свойства компонента обновляются динамически. С классическими `@Input()` разработчик был вынужден реализовывать хук `ngOnChanges()` или переписывать свойства на сеттеры (`set userId(val)`), чтобы своевременно реагировать на изменения. С `input()` сигналами реактивная цепочка выстраивается автоматически с помощью `computed()` и `effect()`.
*   **Иммунитет к гонкам зацепления:**
    Если пользователь быстро переходит от `/users/1` к `/users/2`, входной сигнал `userId()` обновится мгновенно. Все зависимые вычисления (например, сигнальный ресурс `resource` или `rxResource`, запрашивающий данные по API) автоматически прервут старый сетевой запрос и начнут новый для актуального ID, гарантируя целостность интерфейса.

### 3. Детальный пошаговый разбор процесса обновления параметров в сигнале
Проследим шаги фреймворка при переходе с `/catalog?page=1` на `/catalog?page=2` (Шаблон 2):

1.  **Изменение URL:** URL в браузере меняется. Роутер перехватывает событие.
2.  **Обновление состояния:** Роутер парсит query-параметры. Поле `page` меняет значение с `'1'` на `'2'`.
3.  **Передача в компонент:** `ComponentInputBinder` находит входное свойство `page` в инстансе компонента `CatalogSearch`.
4.  **Кастинг через трансформер:** Перед передачей значения запускается функция трансформации `numberAttribute('2')`. Строка `'2'` успешно преобразуется в число `2`.
5.  **Обновление сигнала:** Сигнал `page` обновляет свое внутреннее значение на `2`.
6.  **Триггер Change Detection:** Поскольку сигнал изменился, Angular помечает компонент `CatalogSearch` как требующий проверки. Шаблон обновляется, выводя на экран актуальный номер страницы `2`.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Конфликт имен (Перезапись параметров URL в процессе слияния)**
    *   *Симптомы:* Вместо ожидаемого ID пользователя во входной сигнал попадает поисковый запрос, либо данные отображаются некорректно.
    *   *Физика процесса:* Роутер объединяет все типы параметров в один плоский словарь. Если имя параметра пути совпадает с именем query-параметра (например, роут `path: 'users/:id'` и переход по URL `/users/77?id=search-term`), одно свойство молча затрет другое в зависимости от приоритета слияния.
    *   *Приоритет слияния роутера:* Параметры пути (Path params) -> Параметры строки запроса (Query params) -> Данные (Route data).
    *   *Решение:* Всегда используйте уникальные и семантически понятные имена для параметров пути и query-параметров во избежание пересечения пространств имен. Называйте параметры адреса уникально (например, `userId` для пути, а `searchTerm` или `query` для поиска).

*   **Ошибка 2: Проблема строковой природы URL (Типизация данных)**
    *   *Симптомы:* Ошибки компиляции TypeScript, либо неожиданное поведение математических расчетов (например, `page() + 1` выдает на экране `'11'` вместо `2`).
    *   *Физика процесса:* Все параметры, извлекаемые из строки браузера, изначально считываются как обычные строки (`string`). Если входной сигнал типизирован как `number`, прямая запись строки из URL приведет к неконсистентному состоянию runtime.
    *   *Решение:* Всегда применяйте встроенные или кастомные трансформеры (`transform: numberAttribute`, `transform: booleanAttribute`) для принудительного приведения строковых параметров к целевым типам в месте объявления сигналов.

*   **Ошибка 3: Отсутствие конфигурационного флага `withComponentInputBinding()`**
    *   *Симптомы:* Приложение запускается, роуты работают, но все входные сигналы остаются пустыми (`undefined`) или содержат только дефолтные значения.
    *   *Физика процесса:* По умолчанию автоматическая привязка выключена из соображений обратной совместимости. Роутер игнорирует сопоставление параметров с `@Input` свойствами компонентов.
    *   *Решение:* Убедитесь, что при регистрации провайдера роутинга в файле `app.config.ts` (или `main.ts`) передан модификатор конфигурации `withComponentInputBinding()`, как продемонстрировано в Шаблоне 3.
