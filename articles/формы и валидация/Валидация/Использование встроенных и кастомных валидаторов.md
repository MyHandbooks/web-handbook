# Использование встроенных и кастомных валидаторов

## БЫСТРЫЙ СТАРТ

*   **Валидаторы (Validators)** — это функции, проверяющие значение элементов управления (`FormControl`, `FormGroup`, `FormArray`) и возвращающие объект ошибок `ValidationErrors`, если значение невалидно, или `null`, если проверка пройдена успешно.
*   **Синхронные vs Асинхронные:** 
    *   *Синхронные валидаторы* выполняются мгновенно на локальных данных.
    *   *Асинхронные валидаторы* возвращают поток `Observable` или `Promise` и применяются для проверок, требующих запроса к бэкенду (например, проверка уникальности логина или email).
*   **Используйте:** Для проверки форматов ввода, контроля обязательности заполнения полей, проверки паролей на сложность и кросс-валидации нескольких полей (например, сравнение пароля и его подтверждения).
*   **Не используйте:** Для тяжелых вычислений на каждом нажатии клавиши без подавления дребезга (debouncing) или для жесткой бизнес-логики, которая должна находиться на стороне бэкенда.

### Шаблон 1: Форма со встроенными валидаторами и OnPush детекцией
*   **Назначение:** Описание структуры формы регистрации `UserRegistration` со встроенной валидацией (обязательность, формат email, минимальная длина).

#### 1. Файл логики: `user-registration.ts`
```typescript
import { Component, ChangeDetectionStrategy, inject } from '@angular/core';
import { NonNullableFormBuilder, ReactiveFormsModule, Validators } from '@angular/forms';

@Component({
  selector: 'app-user-registration',
  // standalone: true опускается по умолчанию начиная с v19
  imports: [ReactiveFormsModule], // Импортируем только необходимый модуль для реактивных форм
  templateUrl: './user-registration.html',
  styleUrl: './user-registration.css',
  changeDetection: ChangeDetectionStrategy.OnPush // OnPush гарантирует перерисовку только при изменении состояния
})
export class UserRegistration { // Класс не содержит устаревшего суффикса Component
  // Внедряем NonNullableFormBuilder через inject() для защиты от сброса в null
  private readonly fb = inject(NonNullableFormBuilder);

  // Описываем дерево формы со встроенными синхронными валидаторами
  public readonly regForm = this.fb.group({
    email: ['', [Validators.required, Validators.email]],
    password: ['', [Validators.required, Validators.minLength(8)]]
  });

  public submitForm(): void {
    if (this.regForm.invalid) {
      return; // Предотвращаем отправку невалидной формы
    }
    console.log('Данные формы готовы к отправке:', this.regForm.getRawValue());
  }
}
```

### Шаблон 2: Кастомный синхронный валидатор (Factory Pattern)
*   **Назначение:** Описание кастомной функции-валидатора для запрета определенных нежелательных слов в поле ввода (например, "admin", "root") с выводом ошибок.

#### 1. Файл логики: `create-profile.ts`
```typescript
import { Component, ChangeDetectionStrategy, inject } from '@angular/core';
import { NonNullableFormBuilder, ReactiveFormsModule, AbstractControl, ValidationErrors, ValidatorFn } from '@angular/forms';

/**
 * Функция-фабрика кастомного валидатора (Factory Pattern).
 * Принимает список запрещенных слов и возвращает стандартную функцию ValidatorFn
 */
export function bannedWordsValidator(bannedWords: string[]): ValidatorFn {
  return (control: AbstractControl): ValidationErrors | null => {
    const value = String(control.value || '').trim().toLowerCase();
    
    // Ищем, содержит ли введенная строка хотя бы одно запрещенное слово
    const foundWord = bannedWords.find(word => value.includes(word.toLowerCase()));

    // Если слово найдено — возвращаем объект ошибки с метаданными.
    // Если всё в порядке — возвращаем null, пропуская валидацию.
    return foundWord ? { bannedWordDetected: { word: foundWord } } : null;
  };
}

@Component({
  selector: 'app-create-profile',
  imports: [ReactiveFormsModule],
  templateUrl: './create-profile.html',
  styleUrl: './create-profile.css',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class CreateProfile {
  private readonly fb = inject(NonNullableFormBuilder);

  // Подключаем наш кастомный валидатор в массив валидаторов поля username
  public readonly profileForm = this.fb.group({
    username: ['', [
      bannedWordsValidator(['admin', 'root', 'moderator'])
    ]]
  });

  public saveProfile(): void {
    if (this.profileForm.invalid) {
      return;
    }
    console.log('Профиль успешно создан:', this.profileForm.getRawValue());
  }
}
```

#### 2. Файл разметки: `create-profile.html`
```html
<form [formGroup]="profileForm" (ngSubmit)="saveProfile()" class="profile-form">
  <div class="field">
    <label for="username">Имя пользователя (никнейм):</label>
    <input id="username" type="text" formControlName="username" class="theme-input">

    @if (profileForm.controls.username.touched && profileForm.controls.username.errors) {
      <div class="error-container">
        <!-- 
          Считываем ошибку по ключу 'bannedWordDetected', 
          который мы передали в объекте возврата кастомного валидатора
        -->
        @if (profileForm.controls.username.errors['bannedWordDetected']; as errorDetail) {
          <span class="error-text">
            Имя содержит зарезервированное слово: <b>{{ errorDetail.word }}</b>
          </span>
        }
      </div>
    }
  </div>

  <button type="submit" [disabled]="profileForm.invalid" class="action-btn">Сохранить профиль</button>
</form>
```

### Шаблон 3: Асинхронный кастомный валидатор (Async Validator)
*   **Назначение:** Описание асинхронного валидатора для проверки уникальности имени пользователя на сервере с оптимизацией частоты запросов (`updateOn: 'blur'`).

#### 1. Имитация API-службы: `username-api.service.ts`
```typescript
import { Injectable, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable, delay, map } from 'rxjs';

@Injectable({
  providedIn: 'root'
})
export class UsernameApiService {
  private readonly http = inject(HttpClient);

  /**
   * Имитирует сетевой запрос для проверки занятости имени
   */
  public checkAvailability(username: string): Observable<boolean> {
    // В реальном приложении: return this.http.get<boolean>(`/api/check?name=${username}`);
    // Имитируем задержку сети в 1 секунду
    return this.http.get<unknown>('https://api.github.com/users/' + encodeURIComponent(username)).pipe(
      delay(1000),
      map(() => true), // Если пользователь найден на GitHub — имя занято
      () => {
        // Fallback если пользователь не найден (имя свободно)
        return new Observable<boolean>(subscriber => {
          subscriber.next(false);
          subscriber.complete();
        });
      }
    );
  }
}
```

#### 2. Файл логики: `registration-setup.ts`
```typescript
import { Component, ChangeDetectionStrategy, inject } from '@angular/core';
import { NonNullableFormBuilder, ReactiveFormsModule, AbstractControl, ValidationErrors, AsyncValidatorFn } from '@angular/forms';
import { Observable, of } from 'rxjs';
import { catchError, map } from 'rxjs/operators';
import { UsernameApiService } from './username-api.service';

/**
 * Асинхронный валидатор (Factory Pattern).
 * Принимает сервис в аргументы и возвращает AsyncValidatorFn
 */
export function uniqueUsernameValidator(api: UsernameApiService): AsyncValidatorFn {
  return (control: AbstractControl): Observable<ValidationErrors | null> => {
    if (!control.value) {
      return of(null); // Если поле пустое, асинхронную валидацию пропускаем (за это должен отвечать required)
    }

    // Запускаем асинхронный сетевой поток
    return api.checkAvailability(control.value).pipe(
      // Маппим булево значение занятости в ValidationErrors или null
      map(isTaken => isTaken ? { usernameTaken: true } : null),
      // КРИТИЧЕСКИ ВАЖНО: обрабатываем ошибку внутри потока.
      // Если сервер упадет с ошибкой 500, поток должен выжить и вернуть null (или ошибку валидации),
      // иначе форма зависнет в статусе PENDING навсегда.
      catchError(() => of(null)) 
    );
  };
}

@Component({
  selector: 'app-registration-setup',
  imports: [ReactiveFormsModule],
  templateUrl: './registration-setup.html',
  styleUrl: './registration-setup.css',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class RegistrationSetup {
  private readonly fb = inject(NonNullableFormBuilder);
  private readonly apiService = inject(UsernameApiService);

  public readonly setupForm = this.fb.group({
    // Передаем асинхронный валидатор третьим аргументом конфигурации.
    // Настраиваем обновление по событию 'blur' (потеря фокуса), чтобы защитить API сервера от спама при каждом вводе буквы.
    username: ['', {
      asyncValidators: [uniqueUsernameValidator(this.apiService)],
      updateOn: 'blur'
    }]
  });

  public completeSetup(): void {
    if (this.setupForm.invalid) {
      return;
    }
    console.log('Настройка завершена:', this.setupForm.getRawValue());
  }
}
```

#### 3. Файл разметки: `registration-setup.html`
```html
<form [formGroup]="setupForm" (ngSubmit)="completeSetup()" class="setup-form">
  <div class="field">

    <div class="input-wrapper">
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Физика работы валидаторов в Angular
Валидация в реактивных формах Angular построена на функциональном программировании и синхронном обходе дерева элементов управления:

1.  **Запуск валидации:** Валидация триггерится автоматически каждый раз, когда меняется значение контрола (событие `valueChanges`), или когда форма переинициализируется.
2.  **Очередь выполнения:** Сначала Angular выполняет все зарегистрированные **синхронные** валидаторы. Они обходят переданный `AbstractControl` и собирают массив результатов.
3.  **Переход к асинхронной фазе:**
    *   Если хотя бы один синхронный валидатор вернул ошибку (не-null значение), асинхронные валидаторы **вообще не запускаются**. Смысла тратить сетевой трафик нет, так как поле уже гарантированно невалидно.
    *   Если все синхронные валидаторы вернули `null` (успешно), контрол переходит в системный статус **`PENDING`** (ожидание решения).
    *   Запускаются все асинхронные валидаторы. По завершении их работы статус меняется на `VALID` или `INVALID`, а форма пересчитывает свой итоговый статус.

### 2. Защита бэкенда от перегрузки: Опция `updateOn`
По умолчанию Angular реагирует на каждое нажатие клавиши пользователем (`updateOn: 'change'`). Если повесить асинхронный валидатор в стандартном режиме, то при вводе имени "Administrator" Angular сделает 13 последовательных сетевых запросов к серверу в течение секунды. Это приведет к лавинообразному расходу трафика клиентов и создаст DDOS-нагрузку на базу данных (Thundering Herd).

Для оптимизации используется свойство `updateOn` [fb]:
*   `'change'` (по умолчанию) — валидация на каждый ввод.
*   `'blur'` — валидация запускается строго тогда, когда пользователь убрал фокус из поля ввода (например, перешел к следующему полю). Это идеальный стандарт для асинхронных проверок уникальности (Шаблон 3).
*   `'submit'` — валидация запускается только в момент физической отправки всей формы.

### 3. Детальный пошаговый разбор асинхронного валидатора
Проследим шаги выполнения валидатора `uniqueUsernameValidator` при вводе имени `"mario"` и потере фокуса:

1.  **Потеря фокуса (Blur):** Пользователь выходит из текстового инпута. Начинается фаза валидации.
2.  **Проверка синхронной фазы:** Ошибок синхронной валидации нет. Статус контрола меняется на `PENDING` (`setupForm.controls.username.pending === true`). На экране рендерится лоадер "⌛ Проверка..." из шаблона HTML.
3.  **Вызов лоадера:** Запускается метод `api.checkAvailability('mario')`. Он возвращает `Observable`.
4.  **Сетевой запрос:** HTTP-клиент отправляет запрос на сервер. На это уходит 1 секунда.
5.  **Получение результата:** Сервер отвечает: имя свободно (метод API возвращает `false`).
6.  **Маппинг результата:** Оператор `map(isTaken => isTaken ? { usernameTaken: true } : null)` преобразует `false` в значение `null`.
7.  **Применение изменений:** Валидатор возвращает `null`. Статус контрола меняется с `PENDING` на `VALID`. Лоадер скрывается из разметки, а кнопка "Зарегистрироваться" становится активной.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Зависание формы в статусе PENDING при сбоях сети во внешнем API**
    *   *Симптомы:* Сервер бэкенда упал с ошибкой 500, после чего форма пользователя намертво зависает в состоянии "⌛ Проверка...", а кнопка отправки остается заблокированной навсегда.
    *   *Причина:* Если поток Observable, возвращаемый асинхронным валидатором, выбрасывает необработанную сетевую ошибку (error notification), Angular прерывает выполнение валидации, но не сбрасывает статус `PENDING` у контрола, оставляя форму заблокированной.
    *   *Решение:* Всегда перехватывайте ошибки внутри трубы `pipe()` самого HTTP-запроса с помощью оператора `catchError` и возвращайте безопасное значение `of(null)` (или объект ошибки валидации), гарантируя успешное завершение потока (как показано в Шаблоне 3).

```typescript
// ПЛОХО (Сетевая ошибка убьет поток, форма навсегда зависнет в PENDING)
// return api.checkAvailability(val).pipe(map(res => ...));

// ХОРОШО (Ошибки локализованы внутри потока)
return api.checkAvailability(val).pipe(
  map(res => res ? { usernameTaken: true } : null),
  catchError(() => of(null)) // Возвращаем null, чтобы форма разблокировалась
);
```

*   **Ошибка 2: Бесконечные рекурсивные петли при кросс-валидации нескольких полей**
    *   *Симптомы:* Страница зависает, а в консоли браузера появляется критическая ошибка `Maximum call stack size exceeded`.
    *   *Причина:* Разработчик пытается синхронизировать значения двух связанных полей (например, Пароль и Подтверждение пароля) путем ручного вызова `.updateValueAndValidity()` внутри валидаторов друг друга. Это запускает бесконечный цикл взаимных вызовов валидации.
    *   *Решение:* Навешивайте кросс-валидаторы строго на уровень всей родительской группы `FormGroup` целиком, а не на отдельные дочерние контролы `FormControl`.

```typescript
// ПЛОХО (Вызовет бесконечный цикл)
// controlPassword.valueChanges.subscribe(() => controlConfirm.updateValueAndValidity());
// controlConfirm.valueChanges.subscribe(() => controlPassword.updateValueAndValidity());

// ХОРОШО (Валидатор совпадения паролей навешивается на уровне всей FormGroup)
export const passwordMatchValidator: ValidatorFn = (control: AbstractControl): ValidationErrors | null => {
  const password = control.get('password');
  const confirmPassword = control.get('confirmPassword');
  return password && confirmPassword && password.value !== confirmPassword.value 
    ? { passwordsMismatch: true } 
    : null;
};
```

*   **Ошибка 3: Создание новых инстансов валидатора на каждом проходе проверки (Instantiation Leak)**
    *   *Проблема:* Теряется состояние валидации; ошибки ведут себя непредсказуемо; падение производительности Change Detection.
    *   *Причина:* Разработчик генерирует функции валидаторов динамически внутри циклов или computed-методов рендеринга, заставляя Angular каждый раз проверять новые ссылки на функции-валидаторы в памяти.
    *   *Решение:* Создавайте экземпляры кастомных валидаторов один раз при инициализации формы в классе компонента и переиспользуйте ссылки на них.
