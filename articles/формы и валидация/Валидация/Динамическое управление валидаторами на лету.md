# Динамическое управление валидаторами на лету

## БЫСТРЫЙ СТАРТ

*   **Динамическое управление валидацией** — это механизм изменения правил проверки элементов управления (`FormControl`, `FormGroup`) непосредственно во время выполнения программы в ответ на действия пользователя.
*   **Основные API-методы:**
    *   `setValidators(validators)` — полностью заменяет текущую очередь синхронных валидаторов новыми.
    *   `addValidators(validators)` — добавляет новые валидаторы в существующую очередь без удаления старых.
    *   `removeValidators(validators)` — точечно удаляет указанные валидаторы из очереди.
    *   `clearValidators()` — полностью очищает список валидаторов.
    *   `updateValueAndValidity()` — принудительно пересчитывает значение и статус валидности контрола и поднимает статус вверх по иерархии к родительской группе. **Вызов этого метода обязателен** после любого изменения состава валидаторов.
*   **Используйте:** Когда требования к заполнению полей зависят от выбранных опций (например, при выборе доставки курьером поле "Адрес" становится обязательным, а при самовывозе — скрывается и очищается от проверок).
*   **Не используйте:** Для статических форм, где правила проверки неизменны на протяжении всего жизненного цикла формы.

### Шаблон 1: Динамическая условная валидация (Чекбокс доставки)
*   **Назначение:** Описание класса настроек доставки `DeliverySettings`, где переключение чекбокса "Нужна доставка" динамически накладывает или снимает валидатор `Validators.required` с поля адреса.

#### 1. Файл логики: `delivery-settings.ts`
```typescript
import { Component, ChangeDetectionStrategy, inject, OnInit, DestroyRef } from '@angular/core';
import { NonNullableFormBuilder, ReactiveFormsModule, Validators } from '@angular/forms';
import { takeUntilDestroyed } from '@angular/core/rxjs-interop';

@Component({
  selector: 'app-delivery-settings',
  // standalone: true опускается по умолчанию начиная с v19
  imports: [ReactiveFormsModule], // Импортируем ReactiveFormsModule для связи шаблона и формы
  templateUrl: './delivery-settings.html',
  styleUrl: './delivery-settings.css',
  changeDetection: ChangeDetectionStrategy.OnPush // OnPush оптимизирует CD-циклы при изменениях
})
export class DeliverySettings implements OnInit { // Класс не содержит устаревшего суффикса Component
  private readonly fb = inject(NonNullableFormBuilder);
  private readonly destroyRef = inject(DestroyRef); // Ссылка для безопасной отписки

  // Инициализируем форму. Поле address изначально не имеет валидатора обязательности
  public readonly orderForm = this.fb.group({
    needsDelivery: [false],
    address: ['']
  });

  public ngOnInit(): void {
    // Отслеживаем изменения состояния чекбокса доставки через valueChanges
    this.orderForm.controls.needsDelivery.valueChanges.pipe(
      // Автоматически завершаем подписку при уничтожении компонента
      takeUntilDestroyed(this.destroyRef)
    ).subscribe((needsDelivery) => {
      this.toggleAddressValidation(needsDelivery);
    });
  }

  /**
   * Управляет валидацией поля адреса на лету
   */
  private toggleAddressValidation(needsDelivery: boolean): void {
    const addressControl = this.orderForm.controls.address;

    if (needsDelivery) {
      // 1. Если доставка нужна — добавляем валидатор обязательности
      addressControl.addValidators(Validators.required);
    } else {
      // 2. Если доставка не нужна — очищаем поле от валидаторов и сбрасываем значение
      addressControl.clearValidators();
      addressControl.setValue('', { emitEvent: false }); // Избегаем запуска лишних событий
    }

    // 3. КРИТИЧЕСКИ ВАЖНО: Принудительно запускаем пересчет статуса валидности.
    // Без этого вызова Angular продолжит считать поле валидным/невалидным по старым правилам!
    addressControl.updateValueAndValidity();
  }

  public submitOrder(): void {
    if (this.orderForm.invalid) {
      return;
    }
    console.log('Заказ успешно сформирован:', this.orderForm.getRawValue());
  }
}
```

### Шаблон 2: Полная замена валидаторов при смене типа верификации
*   **Назначение:** Описание класса настройки подтверждения `VerificationSetup`. При выборе типа "Почта" поле ввода валидируется как email, а при выборе "Телефон" — накладывается жесткий паттерн регулярного выражения для мобильных номеров.

#### 1. Файл логики: `verification-setup.ts`
```typescript
import { Component, ChangeDetectionStrategy, inject, OnInit, DestroyRef } from '@angular/core';
import { NonNullableFormBuilder, ReactiveFormsModule, Validators } from '@angular/forms';
import { takeUntilDestroyed } from '@angular/core/rxjs-interop';

@Component({
  selector: 'app-verification-setup',
  imports: [ReactiveFormsModule],
  templateUrl: './verification-setup.html',
  styleUrl: './verification-setup.css',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class VerificationSetup implements OnInit {
  private readonly fb = inject(NonNullableFormBuilder);
  private readonly destroyRef = inject(DestroyRef);

  // Инициализируем форму. По умолчанию выбран тип верификации 'email'
  public readonly authForm = this.fb.group({
    contactType: ['email' as 'email' | 'phone'],
    contactValue: ['', [Validators.required, Validators.email]] // Дефолтные валидаторы для email
  });

  public ngOnInit(): void {
    this.authForm.controls.contactType.valueChanges.pipe(
      takeUntilDestroyed(this.destroyRef)
    ).subscribe((type) => {
      this.updateContactValidation(type);
    });
  }

  /**
   * Полностью перестраивает очередь валидаторов на основе выбранного типа
   */
  private updateContactValidation(type: 'email' | 'phone'): void {
    const valueControl = this.authForm.controls.contactValue;

    // Сбрасываем текущее значение и очищаем отметки взаимодействия (touched, dirty)
    valueControl.setValue('');
    valueControl.markAsUntouched();

    if (type === 'email') {
      // Использование setValidators полностью перезаписывает предыдущие проверки
      valueControl.setValidators([Validators.required, Validators.email]);
    } else if (type === 'phone') {
      // Регулярное выражение для проверки международного формата телефона
      const phoneRegex = /^\+?[1-9]\d{1,14}$/;
      valueControl.setValidators([Validators.required, Validators.pattern(phoneRegex)]);
    }

    // Принудительно запускаем пересчет статуса валидности в рантайме
    valueControl.updateValueAndValidity();
  }

  public submitVerification(): void {
    if (this.authForm.invalid) {
      return;
    }
    console.log('Запрос отправлен:', this.authForm.getRawValue());
  }
}
```

### Шаблон 3: Групповая блокировка валидации (Включение/Отключение блоков)
*   **Назначение:** Описание класса профиля организации `OrganizationProfile`. При включении тумблера "Юридическое лицо" активируется вся соответствующая вложенная группа полей (ИНН, название компании). При отключении — группа полностью деактивируется, автоматически исключая вложенные валидаторы из общей проверки формы.

#### 1. Файл логики: `organization-profile.ts`
```typescript
import { Component, ChangeDetectionStrategy, inject, OnInit, DestroyRef } from '@angular/core';
import { NonNullableFormBuilder, ReactiveFormsModule, Validators } from '@angular/forms';
import { takeUntilDestroyed } from '@angular/core/rxjs-interop';

@Component({
  selector: 'app-organization-profile',
  imports: [ReactiveFormsModule],
  templateUrl: './organization-profile.html',
  styleUrl: './organization-profile.css',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class OrganizationProfile implements OnInit {
  private readonly fb = inject(NonNullableFormBuilder);
  private readonly destroyRef = inject(DestroyRef);

  public readonly profileForm = this.fb.group({
    isOrganization: [false],
    // Вложенная группа полей компании. Изначально мы полностью отключаем ее в модели.
    // Отключенные контролы (disabled) игнорируются валидацией Angular по умолчанию!
    orgDetails: this.fb.group({
      companyName: [{ value: '', disabled: true }, [Validators.required, Validators.minLength(3)]],
      innNumber: [{ value: '', disabled: true }, [Validators.required, Validators.pattern(/^\d{10}$/)]]
    })
  });

  public ngOnInit(): void {
    this.profileForm.controls.isOrganization.valueChanges.pipe(
      takeUntilDestroyed(this.destroyRef)
    ).subscribe((isOrg) => {
      this.toggleOrganizationDetails(isOrg);
    });
  }

  /**
   * Активирует или деактивирует целую группу полей.
   * Это наиболее чистый паттерн управления условной валидацией групп в Angular.
   */
  private toggleOrganizationDetails(isOrg: boolean): void {
    const detailsGroup = this.profileForm.controls.orgDetails;

    if (isOrg) {
      // Включаем группу. Все вложенные валидаторы (required, pattern) автоматически активируются
      detailsGroup.enable();
    } else {
      // Отключаем группу. Поля серые, их значения исключаются из итоговой формы,
      // а все вложенные валидаторы полностью игнорируются системой
      detailsGroup.disable();
      detailsGroup.reset(); // Сбрасываем введенные данные
    }
  }

  public saveProfile(): void {
    if (this.profileForm.invalid) {
      return;
    }
    // getRawValue() вернет значения даже отключенных полей (если это необходимо)
    console.log('Профиль сохранен:', this.profileForm.getRawValue());
  }
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Физика переключения валидаторов и важность `updateValueAndValidity`
Когда вы вызываете методы изменения состава валидаторов на уровне контрола (такие как `addValidators` или `clearValidators`), Angular производит операцию изменения во внутренней коллекции замыканий валидаторов этого элемента.

Однако, **это чисто конфигурационная мутация**. Механизм изменения валидаторов не инициирует автоматический пересчет состояния поля. 
*   Если поле было невалидным, и вы вызвали `clearValidators()`, его статус в памяти Angular продолжит оставаться `INVALID`.
*   Пользователь не сможет отправить форму, пока статус не обновится.

Для принудительного перезапуска процесса проверки разработан метод **`updateValueAndValidity()`**:
1.  Он берет текущее значение контрола и прогоняет его по обновленной очереди валидаторов.
2.  Вычисляет новый статус валидности элемента (`VALID`, `INVALID` или `PENDING`).
3.  Оповещает родительскую группу (`FormGroup`), заставляя её также пересчитать свой статус на основе обновленного состояния дочернего контрола.

### 2. Сравнение стратегий: Очистка валидаторов против Отключения контролов (Disable)
При реализации динамических полей у вас есть две архитектурные стратегии скрыть валидацию поля:

| Сценарий сравнения | Стратегия 1: `clearValidators()` | Стратегия 2: `disable()` |
| :--- | :--- | :--- |
| **Что происходит с валидацией** | Список валидаторов полностью очищается, поле становится валидным. | Контрол полностью отключается, его валидаторы игнорируются [fb]. |
| **Что происходит со значением в `form.value`** | Значение поля сохраняется и будет отправлено на сервер, если не очистить вручную. | Значение полностью исключается из объекта `form.value` [fb]. |
| **Визуальное отображение в HTML** | Поле остается обычным инпутом (если не скрыть через `@if`). | Поле автоматически получает атрибут `disabled` и серый цвет [fb]. |
| **Область применения** | Поле остается видимым на экране, но временно становится необязательным. | Целый блок полей скрывается и его данные не должны отправляться на бэкенд [fb]. |

Использование `.disable()` (Шаблон 3) является предпочтительным паттерном при скрытии сложных вложенных групп форм [fb]. Это избавляет вас от необходимости рекурсивно обходить все вложенные контролы, очищать их валидаторы и вручную сбрасывать их значения — Angular делает всю работу одной нативной системной командой [fb].

### 3. Детальный пошаговый разбор динамической валидации
Рассмотрим пошагово выполнение метода `toggleAddressValidation(true)` в `DeliverySettings` (Шаблон 1):

1.  **Событие:** Пользователь выбирает чекбокс "Мне нужна доставка". Поток `valueChanges` испускает значение `true` [valueChanges].
2.  **Перехват:** Подписка в `ngOnInit` ловит событие и вызывает `toggleAddressValidation(true)`.
3.  **Применение валидатора:** Выполняется `addressControl.addValidators(Validators.required)`. Angular добавляет ссылку на функцию `required` во внутренний массив синхронных валидаторов контрола `address`.
4.  **Срабатывание перерасчета:** Вызывается `addressControl.updateValueAndValidity()`. 
    *   Angular считывает значение адреса (изначально пустая строка `""`).
    *   Пропускает её через `Validators.required`. Валидатор возвращает ошибку `{ required: true }`.
    *   Статус контрола `address` меняется на `INVALID`.
5.  **Каскадное уведомление:** Статус `INVALID` поднимается к родительской форме `orderForm`. Кнопка отправки формы блокируется на основе привязки `[disabled]="orderForm.invalid"`.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Забытый вызов `updateValueAndValidity()`**
    *   *Симптомы:* Состав валидаторов успешно изменен в коде класса (например, вырезаны валидаторы обязательности), но кнопка отправки формы на экране продолжает оставаться заблокированной, а поле подсвечивается красным.
    *   *Причина:* Angular не знает, что вы изменили правила проверки, пока вы явно не попросите его перепроверить текущее значение контрола.
    *   *Решение:* Всегда пишите `control.updateValueAndValidity()` на последней строчке кода изменения валидации.

```typescript
// ПЛОХО (Форма останется невалидной, пока пользователь не введет новые данные)
removeValidation(): void {
  this.form.controls.address.clearValidators();
}

// ХОРОШО (Статус валидности пересчитан мгновенно в рантайме)
removeValidationCorrectly(): void {
  this.form.controls.address.clearValidators();
  this.form.controls.address.updateValueAndValidity(); // Принудительный пересчет
}
```

*   **Ошибка 2: Бесконечный цикл событий при обновлении значений внутри `valueChanges`**
    *   *Симптомы:* Вкладка браузера зависает, в консоли отображается ошибка `Maximum call stack size exceeded`.
    *   *Причина:* При изменении значения или статуса поля внутри подписки `valueChanges` Angular генерирует новое событие `valueChanges` [valueChanges]. Это запускает бесконечную рекурсивную цепочку вызовов.
    *   *Решение:* Используйте опцию `{ emitEvent: false }` при программной установке значений или сбросе контролов внутри реактивных подписок [valueChanges].

```typescript
// ПЛОХО (Вызовет бесконечный цикл событий в рантайме)
// this.form.controls.needsDelivery.valueChanges.subscribe(() => {
//   this.form.controls.address.setValue(''); // Запустит новое событие
// });

// ХОРОШО (Блокировка генерации цикличных событий)
this.form.controls.needsDelivery.valueChanges.pipe(
  takeUntilDestroyed(this.destroyRef)
).subscribe(() => {
  this.form.controls.address.setValue('', { emitEvent: false }); // Безопасное тихое обновление
});
```

*   **Ошибка 3: Ошибка валидации на скрытых неактивных полях (Hidden Field Trap)**
    *   *Симптомы:* Пользователь заполнил все видимые поля на форме, но кнопка отправки остается заблокированной без видимых причин. Ошибок в разметке нет.
    *   *Причина:* Поля были скрыты в HTML-шаблоне с помощью директивы `@if` или CSS-стиля `display: none`, однако их контролы в TypeScript-коде формы остались активными и содержат включенные валидаторы обязательности (`Validators.required`). Невидимые для пользователя поля блокируют валидацию всей формы.
    *   *Решение:* При скрытии элементов в шаблоне всегда синхронно отключайте их валидацию с помощью `clearValidators()` или вызова метода `disable()` на уровне модели формы [fb].
