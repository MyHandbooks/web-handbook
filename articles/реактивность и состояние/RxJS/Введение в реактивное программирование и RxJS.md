# Введение в реактивное программирование и RxJS

## БЫСТРЫЙ СТАРТ

*   **Реактивное программирование** — это декларативная парадигма разработки, ориентированная на работу с асинхронными потоками данных и распространением изменений в реальном времени.
*   **Библиотека RxJS (Reactive Extensions for JavaScript)** — основной реактивный инструмент Angular, предоставляющий единый стандарт для работы с асинхронными процессами (события DOM, таймеры, HTTP-запросы, веб-сокеты).
*   **Используйте для:** декларативного управления сложными асинхронными цепочками данных, организации реактивных шин событий, фильтрации и преобразования сетевых запросов.
*   **Не используйте для:** хранения простого, синхронного локального состояния компонентов (для этого гораздо лучше подходят нативные реактивные Сигналы).

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Декларативное управление потоками и контейнер состояния
*   **Назначение:** Описание сервиса управления темой оформления приложения на базе `BehaviorSubject` и OnPush-компонента, читающего поток с помощью производительного и безопасного пайпа `async`.

#### 1. Файл логики сервиса: `theme-manager.service.ts`
```typescript
// Импортируем декоратор Injectable для регистрации сервиса
import { Injectable } from '@angular/core';
// Импортируем классы BehaviorSubject и Observable из ядра RxJS
import { BehaviorSubject, Observable } from 'rxjs';

@Injectable({
  providedIn: 'root' // Регистрируем как глобальный синглтон с поддержкой Tree-Shaking
})
export class ThemeManagerService {
  // BehaviorSubject требует начального значения и хранит последнее испущенное состояние в памяти
  private readonly themeState$ = new BehaviorSubject<string>('light');

  // Хорошо: Инкапсулируем состояние, отдавая наружу только Observable только для чтения.
  // Это исключает неконтролируемое изменение состояния через .next() из внешнего кода.
  readonly currentTheme$: Observable<string> = this.themeState$.asObservable();

  toggleTheme(): void {
    // Получаем текущее зафиксированное состояние из буфера BehaviorSubject
    const nextTheme = this.themeState$.getValue() === 'light' ? 'dark' : 'light';
    // Проталкиваем новое вычисленное значение всем активным подписчикам
    this.themeState$.next(nextTheme);
  }
}
```

#### 2. Файл логики компонента: `modern-counter.ts`
```typescript
// Импортируем ChangeDetectionStrategy для включения режима OnPush
import { Component, inject, ChangeDetectionStrategy } from '@angular/core';
import { CommonModule } from '@angular/common';
import { Observable, interval } from 'rxjs';
// Импортируем pipeable-оператор map для трансформации данных
import { map } from 'rxjs/operators';
import { ThemeManagerService } from './theme-manager.service';

@Component({
  selector: 'app-modern-counter',
  // standalone: true опущен по умолчанию для стандартов Angular 19+
  imports: [CommonModule], // Подключаем CommonModule для поддержки AsyncPipe
  templateUrl: './modern-counter.html',
  styleUrl: './modern-counter.css',
  // OnPush-стратегия превосходно работает в паре с AsyncPipe
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class ModernCounter {
  // Внедряем сервис управления темой через функциональный inject()
  private readonly themeService = inject(ThemeManagerService);

  // Считываем реактивный поток текущей темы оформления
  readonly currentTheme$: Observable<string> = this.themeService.currentTheme$;

  // Создаем асинхронный поток чисел на базе interval, удваивая значение через pipe-операторы.
  // Поток абсолютно ленивый и запустится только тогда, когда на него подпишутся в шаблоне.
  readonly doubledCounter$: Observable<number> = interval(1000).pipe(
    map((val: number) => val * 2)
  );

  changeTheme(): void {
    // Вызываем публичный метод изменения темы в сервисе
    this.themeService.toggleTheme();
  }
}
```

#### 3. Файл разметки: `modern-counter.html`
```html
<section class="counter-card">
  <header class="card-header">

    <h3>Значение счетчика: {{ doubledCounter$ | async }}</h3>

    <!-- Метод клика меняет тему в сервисе, запуская отправку нового значения в BehaviorSubject -->
    <button class="action-btn" (click)="changeTheme()">Сменить тему оформления</button>
  </div>
</section>
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Архитектурная физика реактивных потоков (Observable)
Потоки в RxJS делятся на две фундаментальные категории — холодные (Cold) и горячие (Hot):

```text
Холодный Observable (Unicast: Каждому подписчику — свой изолированный запуск)
  Observable (interval) ───► [Подписчик A: 0 ... 1 ... 2]
  Observable (interval) ───► [Подписчик B: (подписался позже) 0 ... 1]

Горячий Subject (Multicast: Один общий источник, трансляция на всех)
                            ┌───► [Подписчик A: получает 2 ... 3]
  Данные ───► Subject (2) ──┼───► [Подписчик B: (подписался позже) получает 2 ... 3]
                            └───► [Подписчик C: получает 2 ... 3]
```

*   **Холодные потоки (Unicast)**: Ленивы по своей природе и не начинают производить данные до появления подписчика (`subscribe`). При каждой новой подписке запускается изолированный независимый источник данных (Producer). Классический пример — `HttpClient.get()` в Angular: если три компонента подпишутся на один поток запроса, браузер выполнит три независимых сетевых запроса к серверу.
*   **Горячие потоки (Multicast)**: Производят данные независимо от наличия активных подписчиков. Все подписчики делят один и тот же источник данных в реальном времени. Пример — события движения мыши, Websocket-соединение или экземпляры классов `Subject`. Подписчики, подключившиеся позже, упустят ранее сгенерированные события и будут получать только новые фреймы данных.

### 2. Спецификация семейства `Subject`
`Subject` — это уникальный гибридный примитив RxJS, который одновременно является и наблюдаемым объектом `Observable` (на него можно подписаться), и наблюдателем `Observer` (у него можно вызвать методы `.next()`, `.error()`, `.complete()`).

*   **Классический `Subject`**: Проталкивает события без сохранения истории. Подписчики получают строго те значения, которые испущены после момента их подписки. Подходит для трансляции мгновенных триггеров (клики, экшены).
*   **`BehaviorSubject`**: Контейнер реактивного состояния. Всегда хранит в памяти последнее актуальное значение (буфер размером 1). При подписке новый потребитель мгновенно получает это последнее сохраненное значение, даже если оно было сгенерировано давно. Требует передачи начального значения в конструктор.
*   **`ReplaySubject`**: Запоминает заданное число `N` последних значений. При подписке прокручивает всю эту сохраненную историю новому подписчику по цепочке, после чего транслирует новые события в реальном времени.

### 3. Детальный пошаговый разбор выполнения шаблона 1
1.  **Создание стейта**: Сервис `ThemeManagerService` инициализируется при старте приложения. В памяти выделяется место под `BehaviorSubject` со стартовым стейтом `'light'`.
2.  **Инициализация компонента**: Инстанцируется компонент `ModernCounter`. Его свойства `currentTheme$` и `doubledCounter$` получают ссылки на потоки. Реальных вычислений в этот момент не происходит.
3.  **Авто-подписка**: Шаблон компонента компилируется, рантайм натыкается на инструкцию `doubledCounter$ | async`. `AsyncPipe` неявно вызывает метод `.subscribe()` на потоке.
4.  **Запуск интервала**: Подписка активирует ленивый поток `interval`. Браузер запускает фоновый таймер. Каждую секунду значение увеличивается на 1, проходит через оператор `map` (где удваивается) и передается подписчику.
5.  **Локальное обновление (Change Detection)**: При получении нового числа из потока `AsyncPipe` считывает ссылку на локальный `ChangeDetectorRef` компонента и вызывает метод `markForCheck()`. Angular помечает OnPush-компонент грязным и точечно перерисовывает только измененный узел в DOM.
6.  **Смена темы**: При клике на кнопку вызывается метод `toggleTheme()`. Серверный стейт вычисляет `'dark'` и проталкивает его через `themeState$.next()`. Все подписанные через `async`-пайп узлы шаблона мгновенно получают новое значение и обновляют стили.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Утечка памяти из-за ручных подписок без последующей отписки**
    *   *Симптомы:* Постепенное замедление работы браузера, рост потребления памяти (Memory Leak) при частых переходах пользователя между страницами приложения.
    *   *Физика процесса:* Разработчик вручную вызвал метод `.subscribe()` на бесконечном асинхронном потоке внутри кода класса (например, в методе `ngOnInit`). При уничтожении компонента Angular не закрывает эту подписку автоматически. Ссылка на обработчик остается в памяти, блокируя сборку мусора для всего графа зависимостей уничтоженного компонента.
    *   *Решение:* Никогда не вызывайте ручной `.subscribe()` в классах без явного управления отпиской. По возможности используйте `AsyncPipe` в шаблоне (он сам отпишется на хуке деструктора) либо применяйте современный оператор `takeUntilDestroyed()`.

```typescript
// ПЛОХО (Стрим продолжит работать в фоновом режиме вечно, удерживая компонент в памяти)
export class BadCounter implements OnInit {
  ngOnInit() {
    interval(1000).subscribe(val => console.log(val)); // ❌ Утечка памяти!
  }
}

// ХОРОШО (Использование takeUntilDestroyed автоматически вызовет отписку при уничтожении компонента)
import { takeUntilDestroyed } from '@angular/core/rxjs-interop';

export class GoodCounter implements OnInit {
  ngOnInit() {
    interval(1000).pipe(
      takeUntilDestroyed() // ✅ Безопасно, подписка уничтожится автоматически
    ).subscribe(val => console.log(val));
  }
}
```

*   **Ошибка 2: Смерть внешнего потока при некорректном перехвате ошибок (Stream Termination)**
    *   *Симптомы:* После первой сетевой ошибки поток полностью прекращает реагировать на любые действия (например, строка ввода поиска больше не генерирует новые запросы).
    *   *Физика процесса:* Оператор `catchError` был размещен во внешнем конвейере `pipe` основного стрима. По спецификации Reactive Streams, когда поток переходит в статус `error`, он необратимо завершает свою работу. Любые последующие действия пользователя игнорируются.
    *   *Решение:* Переносите перехват ошибок (`catchError`) внутрь конвейера вложенных потоков (например, внутрь оператора `switchMap`), возвращая резервный пустой поток `of([])` для изоляции сбоя.

```typescript
// ПЛОХО (Первая ошибка сети полностью убьет поток ввода, поиск перестанет работать навсегда)
readonly search$ = this.control.valueChanges.pipe(
  switchMap(q => this.http.get(`/api/search?q=${q}`)),
  catchError(() => of([])) // ❌ Убивает внешний стрим
);

// ХОРОШО (Сбой изолирован во внутреннем потоке, внешний стрим ввода продолжает функционировать)
readonly searchSafe$ = this.control.valueChanges.pipe(
  switchMap(q => this.http.get(`/api/search?q=${q}`).pipe(
    catchError(() => of([])) // ✅ Внутренний catchError защищает внешний стрим
  ))
);
```

*   **Ошибка 3: Нарушение инкапсуляции и утечка методов записи `Subject` во внешний код**
    *   *Симптомы:* Непредсказуемое поведение состояния сервиса, труднонаходимые баги при отладке, изменение стейта в обход бизнес-правил сервиса.
    *   *Физика процесса:* Сервис отдает во внешний мир прямую ссылку на приватный `BehaviorSubject`. Внешние компоненты начинают императивно вызывать на нем метод `.next()`, меняя реактивное состояние приложения в обход методов сервиса.
    *   *Решение:* Всегда делайте `Subject` строго приватным (`private`), а наружу отдавайте только безопасную обертку через метод `.asObservable()`.

```typescript
// ПЛОХО (Любой компонент может вызвать .next() и перезаписать состояние темы в обход логики сервиса)
export class BadThemeService {
  readonly themeState$ = new BehaviorSubject<string>('light'); // ❌ Нарушение инкапсуляции
}

// ХОРОШО (Компоненты могут только подписываться на поток текущей темы через currentTheme$)
export class GoodThemeService {
  private readonly themeState$ = new BehaviorSubject<string>('light');
  
  //asObservable() скрывает методы записи .next(), оставляя только методы чтения
  readonly currentTheme$ = this.themeState$.asObservable(); // ✅ Строгая инкапсуляция
}
```
