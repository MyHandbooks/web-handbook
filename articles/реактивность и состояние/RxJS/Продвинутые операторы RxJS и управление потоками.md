# Продвинутые операторы RxJS и управление потоками

## БЫСТРЫЙ СТАРТ

*   **Классификация операторов RxJS** — операторы делятся на порождающие новые потоки (Creation Operators, включая объединяющие Join Creation) и трансформирующие потоки (Pipeable Operators), выполняемые внутри метода `.pipe()`.
*   **Операторы преобразования высшего порядка (Higher-Order Mapping)** — управляют подписками на внутренние асинхронные потоки, решая проблемы отмены устаревших запросов (`switchMap`), параллельной загрузки (`mergeMap`), строгого соблюдения очереди (`concatMap`) и блокировки повторных вызовов (`exhaustMap`).
*   **Мультивещание (Multicasting)** — преобразование холодных ленивых потоков в горячие с кэшированием результатов (`shareReplay`), исключающее дублирование тяжелых сетевых запросов бэкенда.
*   **Используйте для:** построения сложных систем фильтрации, поиска на лету (Typeahead), надежной обработки ошибок транзакций, предотвращения двойных кликов по кнопкам и оптимизации общей сетевой нагрузки приложения.
*   **Не используйте для:** простых синхронных вычислений и тривиального считывания полей данных — реактивные Сигналы сделают эту работу проще и производительнее.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Декларативный поисковый поток с защитой от race conditions и дебаунсом
*   **Назначение:** Реализация безопасного и отзывчивого UI-поиска, который ожидает паузу в вводе пользователя, игнорирует повторяющиеся символы, отменяет предыдущие незавершенные сетевые запросы при новом вводе и безопасно обрабатывает ошибки локально.

#### 1. Файл логики: `good-search.ts`
```typescript
// Импортируем ChangeDetectionStrategy для оптимизации рендеринга OnPush
import { Component, inject, ChangeDetectionStrategy } from '@angular/core';
import { ReactiveFormsModule, FormControl } from '@angular/forms';
import { CommonModule } from '@angular/common';
import { HttpClient } from '@angular/common/http';
import { takeUntilDestroyed } from '@angular/core/rxjs-interop';
import { Observable, of } from 'rxjs';
// Импортируем продвинутые операторы управления потоками
import { debounceTime, distinctUntilChanged, filter, switchMap, catchError } from 'rxjs/operators';

export interface SearchResult {
  id: string;
  title: string;
}

@Component({
  selector: 'app-good-search',
  // standalone: true опущен по умолчанию для стандартов Angular 19+
  imports: [ReactiveFormsModule, CommonModule], // Импортируем только нужные реактивные директивы
  templateUrl: './good-search.html',
  styleUrl: './good-search.css',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class GoodSearch {
  // Внедряем HttpClient через функциональный DI
  private readonly http = inject(HttpClient);
  
  // Инициализируем реактивный контроллер строки ввода
  readonly searchControl = new FormControl('', { nonNullable: true });

  // Декларативный поток результатов поиска.
  // takeUntilDestroyed автоматически отпишет стрим при уничтожении контекста компонента.
  readonly results$: Observable<SearchResult[]> = this.searchControl.valueChanges.pipe(
    // 1. Ожидаем паузу в вводе пользователя 300мс (оптимизация нагрузки на сеть)
    debounceTime(300),
    // 2. Игнорируем повторные отправки, если текст не изменился (например, при навигации стрелками)
    distinctUntilChanged(),
    // 3. Отсекаем слишком короткие запросы для экономии ресурсов
    filter((query: string) => query.trim().length >= 3),
    // 4. Отменяем текущий сетевой запрос и переключаемся на новый при изменении текста
    switchMap((query: string) => this.fetchResults(query)),
    // Автоматическая отписка на основе DestroyRef Angular 19+
    takeUntilDestroyed() 
  );

  private fetchResults(query: string): Observable<SearchResult[]> {
    const params = { q: query };
    return this.http.get<SearchResult[]>('/api/search', { params }).pipe(
      // Важно: перехватываем ошибку локально внутри switchMap, чтобы внешний поток results$ не умер!
      catchError((error) => {
        console.error('Сетевой сбой при поиске:', error);
        // Возвращаем резервный пустой массив, сохраняя работоспособность стрима
        return of([]); 
      })
    );
  }
}
```

#### 2. Файл разметки: `good-search.html`
```html
<section class="search-panel">
  <div class="input-wrapper">
    <!-- Связываем поле ввода с реактивным FormControl -->
    <input [formControl]="searchControl" class="search-input" placeholder="Введите текст для поиска..." />
  </div>

  <!-- Декларативно подписываемся на поток через AsyncPipe -->
  @if (results$ | async; as results) {
    <ul class="results-list">
      @for (item of results; track item.id) {
        <li class="result-item">
          {{ item.title }}
        </li>
      } @empty {
        <li class="empty-item">Ничего не найдено по вашему запросу.</li>
      }
    </ul>
  }
</section>
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как работают операторы высшего порядка (Higher-Order Mapping)
Операторы высшего порядка принимают на вход обычные значения внешнего потока (например, клики или ввод) и преобразуют их в новые внутренние потоки (Observable), управляя подписками на них.

Визуализация обработки непрерывных пользовательских кликов при отправке асинхронных сетевых запросов:

```text
Входящие события (клики): -------(click 1)----------------(click 2)-------------------->
Внутренний запрос по сети:       \--[req A]--|             \--[req B]--| (длительность)

1. switchMap (Переключение):
Результат:                       ---[  req A  ]-------------[  req B  ]--------------->
* Если click 2 происходит до завершения req A, подписка на req A немедленно отменяется.

2. mergeMap (Параллельно):
Результат:                       ---[  req A  ]---------------------------------------->
                                              \--[  req B  ]---| (выполняются одновременно)

3. concatMap (Очередь):
Результат:                       ---[  req A  ]-------------[  req B  ]--------------->
* Выполнение req B начнется строго ПОСЛЕ того, как req A полностью завершится.

4. exhaustMap (Блокировка):
Результат:                       ---[  req A  ]---------------------------------------->
* click 2 полностью игнорируется, так как req A в этот момент еще не завершен.
```

*   **`switchMap`**: При получении нового внешнего события мгновенно отменяет текущую внутреннюю подписку (вызывает `unsubscribe()`) и переключается на новый внутренний поток. Незаменим при поиске и фильтрации, когда старые сетевые запросы теряют актуальность при изменении параметров.
*   **`mergeMap` (flatMap)**: Запускает внутренние потоки параллельно по мере поступления, не дожидаясь завершения предыдущих. Порядок ответов не гарантирован (какой запрос быстрее вернется из сети, тот первым и испустит значение).
*   **`concatMap`**: Ставит внутренние потоки в очередь и выполняет их строго последовательно. Подписка на второй поток начнется только тогда, когда первый поток перейдет в статус `complete`.
*   **`exhaustMap`**: Игнорирует абсолютно все входящие внешние события до тех пор, пока выполняется текущий внутренний поток. Идеален для защиты транзакций от двойных кликов пользователей.

### 2. Физика кэширования и мультивещания через `shareReplay`
Холодные потоки ленивы и вызывают создание нового независимого процесса генерации данных на каждого подписчика. Для предотвращения дублирования сетевых вызовов используется оператор `shareReplay`:

1.  **Преобразование в горячий**: При первом вызове `.subscribe()` на потоке, содержащем `shareReplay`, оператор создает единую общую подписку на оригинальный холодный источник (например, GET-запрос `HttpClient`).
2.  **Буферизация**: Полученное значение сохраняется во внутреннем буфере оператора.
3.  **Раздача**: Все последующие подписчики подключаются к этому же горячему источнику и мгновенно получают сохраненное значение из буфера без повторного запуска оригинального холодного потока.
4.  **Управление жизненным циклом**: Параметр `refCount: true` указывает оператору, что он должен автоматически отписаться от оригинального источника, когда число активных подписчиков падает до нуля, предотвращая утечки памяти.

### 3. Детальный пошаговый разбор выполнения шаблона 1
1.  **Ввод символа**: Пользователь вводит третью букву в поле. Значение `valueChanges` испускает строку `'abc'`.
2.  **Фильтрация времени**: Оператор `debounceTime(300)` перехватывает строку и запускает таймер. Если в течение 300мс пользователь не нажмет новые клавиши, строка пропускается дальше по конвейеру.
3.  **Уникальность**: Оператор `distinctUntilChanged()` сверяет `'abc'` с предыдущим обработанным значением. Так как они различаются, строка идет дальше.
4.  **Проверка длины**: Оператор `filter` проверяет условие `3 >= 3`. Оно истинно. Строка пропускается.
5.  **Переключение потоков**: Оператор `switchMap` принимает `'abc'` и запускает вспомогательный метод `fetchResults('abc')`. Тот формирует холодный Observable сетевого запроса. `switchMap` автоматически подписывается на него, отправляя запрос в сеть.
6.  **Отмена при быстром вводе**: Если во время ожидания ответа пользователь нажмет клавишу `'d'`, `debounceTime` отсчитает 300мс и пропустит строку `'abcd'`. Оператор `switchMap` мгновенно отпишется от запроса по слову `'abc'` (браузер прервет выполнение текущего сетевого запроса) и подпишется на новый запрос для `'abcd'`.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Нарушение порядка вызова `takeUntil` в конвейере операторов**
    *   *Симптомы:* Скрытая утечка памяти — внутренние потоки продолжают выполняться в памяти даже после уничтожения компонента.
    *   *Физика процесса:* Если оператор `takeUntil` (или `takeUntilDestroyed`) расположен перед операторами преобразования высшего порядка (например, перед `switchMap`), он отпишется только от внешнего потока. Внутренний поток, порожденный `switchMap` после срабатывания деструктора, продолжит жить в памяти.
    *   *Решение:* Всегда располагайте операторы ограничения жизненного цикла (`takeUntil`, `take`, `takeUntilDestroyed`) **последними** в цепочке `.pipe()`.

```typescript
// ПЛОХО (Внутренний поток switchMap может утечь, если уничтожение произойдет во время сетевого запроса)
readonly dataBad$ = this.trigger$.pipe(
  takeUntilDestroyed(), // ❌ Неверная позиция!
  switchMap(() => this.http.get('/api/data'))
);

// ХОРОШО (takeUntilDestroyed на последнем месте гарантированно отпишет всю цепочку целиком)
readonly dataGood$ = this.trigger$.pipe(
  switchMap(() => this.http.get('/api/data')),
  takeUntilDestroyed() // ✅ Верная позиция
);
```

*   **Ошибка 2: Утечка памяти при использовании `shareReplay` без параметра `refCount`**
    *   *Симптомы:* Постепенное накопление неиспользуемых данных в оперативной памяти, которые никогда не очищаются сборщиком мусора.
    *   *Физика процесса:* По умолчанию `shareReplay` вызывается с конфигурацией `refCount: false`. Это означает, что даже когда все компоненты отписались от потока, оператор продолжает вечно удерживать активную подписку на оригинальный источник, не позволяя высвободить память.
    *   *Решение:* При кэшировании данных на уровне компонентов всегда явно передавайте конфигурацию `{ bufferSize: 1, refCount: true }`.

```typescript
// ПЛОХО (Подписка на источник никогда не закроется, вызывая утечку памяти)
readonly cachedDataBad$ = this.http.get('/api/config').pipe(
  shareReplay(1) // ❌ refCount по умолчанию равен false!
);

// ХОРОШО (Оператор автоматически отпишется от источника, когда число подписчиков обнулится)
readonly cachedDataGood$ = this.http.get('/api/config').pipe(
  shareReplay({ bufferSize: 1, refCount: true }) // ✅ Идеально для кэша
);
```

*   **Ошибка 3: Использование `mergeMap` для операций изменения данных (сайд-эффектов)**
    *   *Симптомы:* Нарушение целостности данных на сервере, race conditions при последовательном сохранении форм.
    *   *Физика процесса:* Разработчик использовал `mergeMap` для отправки POST-запросов сохранения данных. Поскольку запросы выполняются параллельно, медленный первый запрос может перезаписать в базе данных быстрый второй, нарушив хронологию изменений.
    *   *Решение:* Для деструктивных транзакций и сохранения данных всегда используйте оператор `concatMap` (строго сохраняет очередь выполнения запросов) или `exhaustMap` (игнорирует новые запросы до завершения текущей отправки).

```typescript
// ПЛОХО (Параллельная отправка может привести к перезаписи актуальных данных старыми)
saveDataUnsafe(data$: Observable<any>) {
  data$.pipe(
    mergeMap(payload => this.http.post('/api/save', payload)) // ❌ Параллельное сохранение опасно
  ).subscribe();
}

// ХОРОШО (concatMap гарантирует, что запросы сохранятся строго один за другим по очереди)
saveDataSafe(data$: Observable<any>) {
  data$.pipe(
    concatMap(payload => this.http.post('/api/save', payload)) // ✅ Очередь строго соблюдена
  ).subscribe();
}
```
