# Анатомия конвейера pipe и базовые операторы обработки (map, filter, tap)

## БЫСТРЫЙ СТАРТ

*   **Метод `.pipe()`** — это центральный механизм композиции в RxJS. Он принимает список функций-операторов и последовательно передает результат работы одного оператора на вход следующему, выстраивая однонаправленный конвейер обработки данных.
*   **Главные базовые операторы:**
    *   `map(fn)` — трансформирует проходящее значение (чистая функция). Длина потока не меняется, меняется только структура или тип данных.
    *   `filter(predicate)` — пропускает значение дальше по цепочке только в том случае, если предикат возвращает `true`. Может сокращать длину потока.
    *   `tap(fn)` — предназначен исключительно для выполнения побочных эффектов (Side Effects), таких как логирование, отладка или изменение внешнего состояния. Не изменяет проходящее значение и не влияет на поток.
*   **Используйте конвейер `.pipe()` для:** декларативной подготовки данных перед выводом в шаблон, фильтрации мусорных событий и безопасного логирования этапов прохождения асинхронного сигнала.
*   **Не выполняйте побочные эффекты внутри `map` или `filter`:** это нарушает принцип чистых функций, делает поток непредсказуемым и крайне усложняет написание юнит-тестов. Любое внешнее действие должно находиться строго внутри `tap` или в методе `.subscribe()`.

### Шаблон 1: Классический конвейер трансформации, фильтрации и логирования
*   **Назначение:** Обработка сырого потока событий ввода: очистка от пустых значений, приведение к верхнему регистру и логирование каждого шага.

#### 1. Файл логики: `text-processor.ts`
```typescript
import { Component, inject, OnInit, signal, DestroyRef, ChangeDetectionStrategy } from '@angular/core';
import { FormControl, ReactiveFormsModule } from '@angular/forms';
import { takeUntilDestroyed } from '@angular/core/rxjs-interop';
import { map, filter, tap } from 'rxjs/operators';

@Component({
  selector: 'app-text-processor',
  // standalone: true опускается по умолчанию начиная с v19
  imports: [
    ReactiveFormsModule // Подключаем модуль форм для работы с FormControl
  ],
  templateUrl: './text-processor.html',
  styleUrl: './text-processor.css',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class TextProcessor implements OnInit { // Имя класса очищено от суффикса Component
  private readonly destroyRef = inject(DestroyRef);

  // Управляющий контрол реактивной формы
  public readonly textControl = new FormControl<string>('', { nonNullable: true });
  
  // Сигнал для вывода обработанного значения в шаблоне
  public readonly processedValue = signal<string>('');

  public ngOnInit(): void {
    // Подписываемся на поток изменений значения инпута
    this.textControl.valueChanges.pipe(
      // 1. Оператор tap: логируем сырое значение для отладки. 
      // Он не изменяет данные, поток течет дальше без изменений
      tap((rawText) => console.log('[RxJS Pipe] Получено сырое значение:', rawText)),

      // 2. Оператор map: трансформируем данные, обрезая пробелы по краям
      map((text) => text.trim()),

      // 3. Оператор filter: пропускаем значение дальше, только если длина строки больше 3 символов
      filter((trimmedText) => trimmedText.length > 3),

      // 4. Оператор map: переводим очищенную строку в верхний регистр
      map((validText) => validText.toUpperCase()),

      // 5. Оператор tap: фиксируем успешное прохождение валидации в логах
      tap((finalText) => console.warn('[RxJS Pipe] Значение успешно прошло все фильтры:', finalText)),

      // Гарантированно отписываемся при уничтожении компонента
      takeUntilDestroyed(this.destroyRef)
    ).subscribe({
      // Записываем финальное обработанное значение в сигнал чтения
      next: (value) => this.processedValue.set(value)
    });
  }
}
```

#### 2. Файл разметки: `text-processor.html`
```html
<div class="processor-card">
  <input type="text" [formControl]="textControl" placeholder="Введите текст..." class="theme-input" />
  <p>Обработанный результат: <b>{{ processedValue() }}</b></p>
</div>
```

#### 3. Файл стилей: `text-processor.css`
```css

  border: 1px solid var(--border);
  border-radius: 8px;
}
```

### Шаблон 2: Ограничение эмиссий потока и безопасная работа с DOM
*   **Назначение:** Ограничение времени жизни потока событий (например, реагирование только на первые 3 клика пользователя) с выполнением побочных эффектов.

#### 1. Файл логики: `limited-clicker.ts`
```typescript
import { Component, inject, ElementRef, viewChild, OnInit, DestroyRef, ChangeDetectionStrategy, signal } from '@angular/core';
import { fromEvent } from 'rxjs';
import { map, filter, tap, take } from 'rxjs/operators';
import { takeUntilDestroyed } from '@angular/core/rxjs-interop';

@Component({
  selector: 'app-limited-clicker',
  imports: [],
  templateUrl: './limited-clicker.html',
  styleUrl: './limited-clicker.css',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class LimitedClicker implements OnInit {
  private readonly destroyRef = inject(DestroyRef);

  // Запрашиваем нативную кнопку из шаблона через viewChild
  private readonly buttonRef = viewChild<ElementRef<HTMLButtonElement>>('targetBtn');

  public readonly remainingClicks = signal<number>(3);

  public ngOnInit(): void {
    const buttonNative = this.buttonRef()?.nativeElement;
    if (!buttonNative) return;

    // Создаем RxJS-поток на основе нативного браузерного события клика
    fromEvent<MouseEvent>(buttonNative, 'click').pipe(
      // 1. Оператор map: извлекаем из объекта события только координаты клика X и Y
      map((event: MouseEvent) => ({ x: event.clientX, y: event.clientY })),

      // 2. Оператор tap: уменьшаем значение реактивного счетчика (побочный эффект)
      tap(() => this.remainingClicks.update((count) => Math.max(0, count - 1))),

      // 3. Оператор take: принудительно завершает (complete) весь поток после 3-й эмиссии.
      // Это автоматически отпишет нас от события клика нативной кнопки
      take(3),

      // На случай форс-мажорного уничтожения компонента до совершения всех 3 кликов
      takeUntilDestroyed(this.destroyRef)
    ).subscribe({
      next: (coords) => console.log('[Click] Зафиксированы координаты клика:', coords),
      complete: () => {
        console.log('[Click] Лимит исчерпан. Поток кликов успешно закрыт.');
        // Безопасно отключаем кнопку в DOM (побочный эффект при завершении)
        buttonNative.disabled = true;
      }
    });
  }
}
```

#### 2. Файл разметки: `limited-clicker.html`
```html
<div class="clicker-box">
  <button #targetBtn class="action-btn">Кликни меня (Лимит: 3 раза)</button>
  <p>Осталось кликов: <b>{{ remainingClicks() }}</b></p>
</div>
```

#### 3. Файл стилей: `limited-clicker.css`
```css

  background-color: var(--bg-secondary);
  border-radius: 8px;
}

}

}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как метод `.pipe()` устроен под капотом RxJS (Композиция функций)
До версии RxJS 5.5 операторы импортировались как методы, расширяющие прототип класса `Observable` (паттерн Prototype Patching). Этот подход имел две критические проблемы:
1.  **Отсутствие Tree-Shaking:** Сборщики проекта не могли определить, используется ли импортированный метод `.map()` реально в коде. В результате абсолютно все импортированные операторы жестко упаковывались в финальный бандл приложения, раздувая его размер.
2.  **Загрязнение глобальных прототипов:** Импорт оператора в одном файле делал его доступным во всем приложении, что приводило к скрытым багам при неявных зависимостях.

Переход на pipeable-операторы решил эти проблемы. Теперь каждый оператор — это чистая изолированная функция, которая возвращает другую функцию, принимающую поток и возвращающую новый поток.

Сам метод `.pipe()` — это классическая реализация **функциональной композиции** (Function Composition). На уровне исходного кода RxJS метод представляет собой свертку массива функций:
```javascript
// Упрощенная низкоуровневая реализация метода pipe в ядре RxJS
function pipe(...fns) {
  return function(source) {
    // Последовательно передаем результат выполнения предыдущей функции на вход следующей
    return fns.reduce((prevResult, fn) => fn(prevResult), source);
  };
}
```
Благодаря этому сборщики проекта видят неиспользуемые функции-операторы как "мертвый код" и беспрепятственно удаляют их из сборки.

### 2. Физика чистых функций против побочных эффектов (`map` vs `tap`)
Одной из фундаментальных концепций реактивного программирования является предсказуемость движения данных. 

*   **Операторы `map` и `filter` должны быть математически чистыми (Pure Functions):** Они не должны обращаться к глобальным переменным, менять свойства класса или выполнять сетевые вызовы. Они принимают значение, трансформируют его или проверяют условие, и возвращают результат. Это гарантирует, что при одних и тех же входных данных конвейер всегда вернет один и тот же результат.
*   **Оператор `tap` — это легальный шлюз для побочных эффектов (Side Effects):** Он специально спроектирован так, чтобы перехватить проходящее значение, передать его во внешнюю систему (например, записать в `localStorage`, вызвать метод аналитики или обновить сигнал состояния UI) и передать это же значение дальше по цепочке в абсолютно неизменном виде. На системном уровне `tap` возвращает тот же самый Observable-источник, полностью игнорируя то, что вернула функция внутри него.

### 3. Детальный пошаговый разбор выполнения шаблона 1
Проследим движение строки `"  hello  "` в `TextProcessor` при вводе пользователем:

1.  **Эмиссия события:** Пользователь вводит текст. Поток `valueChanges` испускает значение `"  hello  "`.
2.  **Шаг 1 (`tap`):** Первая функция логирует строчку `"  hello  "`. Значение течет дальше без изменений.
3.  **Шаг 2 (`map`):** Функция `map(text => text.trim())` обрезает пробелы. На выход передается очищенная строка `"hello"`.
4.  **Шаг 3 (`filter`):** Вычисляется предикат `filter(text => text.length > 3)`. Длина строки `"hello"` равна 5. Условие истинно (`5 > 3`). Значение `"hello"` пропускается дальше.
    *   *Примечание:* Если бы длина строки была $\le 3$, `filter` прервал бы выполнение цепочки. Нижележащие операторы и конечный метод `subscribe` даже не были бы вызваны для этой итерации.
5.  **Шаг 4 (`map`):** Выполняется `map(text => text.toUpperCase())`. Строка переводится в верхний регистр: `"HELLO"`.
6.  **Шаг 5 (`tap`):** Вторая функция `tap` логирует успешный результат `"HELLO"`.
7.  **Получение результата:** Метод `.subscribe({ next })` перехватывает финальное значение `"HELLO"` и записывает его в сигнал `processedValue.set("HELLO")`, обновляя интерфейс в HTML.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Выполнение побочных эффектов внутри трансформаций (The Impure Pipeline Bug)**
    *   *Симптомы:* Непредсказуемое поведение UI, хаотичное изменение переменных класса, невозможность написать стабильные unit-тесты на цепочку обработки.
    *   *Физика процесса:* Разработчик мутирует состояние класса прямо внутри оператора `map`:
        ```typescript
        // ОШИБКА: Мутация внешнего состояния внутри чистого оператора map
        map(user => {
          this.isUserLoaded = true; // ! Побочный эффект разрушает чистоту цепочки
          return user.name;
        })
        ```
    *   *Решение:* Перенесите все внешние изменения состояния строго в оператор `tap`.

```typescript
// ИСПРАВЛЕНИЕ: Четкое разделение ответственности операторов
tap(() => this.isUserLoaded = true), // Побочный эффект изолирован в tap
map(user => user.name)              // map остается чистой функцией трансформации
```

*   **Ошибка 2: Пропуск оператора `return` в многострочных стрелочных функциях**
    *   *Симптомы:* Последующие операторы в цепочке или метод `.subscribe` начинают получать на вход `undefined` вместо ожидаемых данных.
    *   *Физика процесса:* Если стрелочная функция обернута в фигурные скобки `{}`, неявный возврат значения отключается. Разработчик забыл написать ключевое слово `return`, из-за чего функция по умолчанию вернула `undefined`.
    *   *Решение:* Всегда пишите `return` внутри многострочных стрелочных функций в операторах `map`/`filter`, либо избавляйтесь от фигурных скобок для авто-возврата.

```typescript
// ОШИБКА: Функция ничего не возвращает, в поток уходит undefined
// map(val => { const doubled = val * 2; }) 

// ИСПРАВЛЕНИЕ: Явный возврат значения
map(val => {
  const doubled = val * 2;
  return doubled; // Успешно
})
```

*   **Ошибка 3: Написание вложенных вызовов pipe (Nested Piping Anti-pattern)**
    *   *Симптомы:* Сложный, трудночитаемый код, напоминающий Callback Hell, но на уровне RxJS-цепочек.
    *   *Физика процесса:* Разработчик вызывает `.pipe()` внутри другого `.pipe()` без архитектурной необходимости.
    *   *Решение:* Держите конвейер плоским. Все операторы должны перечисляться через запятую в рамках одного единого вызова `.pipe()`. Вложенные вызовы `.pipe()` допускаются только внутри операторов высшего порядка (таких как `switchMap`, `concatMap`) для изоляции ошибок или ограничения времени жизни конкретно внутреннего потока.

```typescript
// ОШИБКА: Избыточная и нечитаемая вложенность конвейеров
// stream$.pipe(
//   map(val => val * 2),
//   tap(val => {
//     of(val).pipe(filter(x => x > 10)).subscribe(); // ! Ужасный антипаттерн вложенности и подписок
//   })
// )

// ИСПРАВЛЕНИЕ: Единый плоский конвейер обработки
stream$.pipe(
  map(val => val * 2),
  filter(val => val > 10),
  tap(val => console.log(val))
)
```
