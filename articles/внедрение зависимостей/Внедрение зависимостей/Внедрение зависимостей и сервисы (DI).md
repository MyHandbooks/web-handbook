# Внедрение зависимостей и сервисы (DI)

## БЫСТРЫЙ СТАРТ

*   **Внедрение зависимостей (Dependency Injection / DI)** — это встроенный механизм и системный паттерн Angular, который берет на себя создание, управление жизненным циклом и доставку зависимых объектов (сервисов, конфигураций, токенов) в потребители (компоненты, директивы, другие сервисы).
*   **Функциональный DI (функция `inject()`)** — современный стандарт Angular (версий 16–19+), полностью заменяющий старое внедрение зависимостей через параметры конструктора класса. Он избавляет классы от бойлерплейта и кардинально упрощает наследование.
*   **Контекст внедрения (Injection Context):** Вызывать `inject()` разрешено строго в фазе инициализации класса: при объявлении свойств класса, в теле конструктора или внутри фабрик провайдеров (`useFactory`). Попытка вызвать `inject()` асинхронно или внутри обычных методов жизненного цикла (`ngOnInit`) приведет к системной ошибке.
*   **Используйте для:** разделения бизнес-логики и UI-представления, организации слабосвязанной архитектуры, легкого модульного тестирования и управления глобальным или изолированным состоянием.
*   **Не используйте для:** хранения временных, чисто презентационных данных одного экрана, которые должны уничтожаться мгновенно без внешнего доступа — для этого достаточно локального состояния компонента или Сигналов.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Функциональный DI в Standalone-компоненте через `inject()`
*   **Назначение:** Описание современной структуры компонента со сбором зависимостей на уровне свойств класса без написания конструкторов.

#### 1. Файл логики: `dashboard-stats.ts`
```typescript
import { Component, OnInit, inject, ChangeDetectionStrategy, signal } from '@angular/core';
import { AnalyticsService } from './analytics.service';
import { NetworkLogger } from './network-logger';

@Component({
  selector: 'app-dashboard-stats',
  // standalone: true опущен по умолчанию в Angular 19+
  imports: [],
  templateUrl: './dashboard-stats.html',
  styleUrl: './dashboard-stats.css',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class DashboardStats implements OnInit { // Класс переименован по современным стандартам без суффикса Component
  // Внедряем сервис аналитики напрямую на уровне объявления свойств класса.
  // Конструктор компонента остается полностью чистым и может быть опущен.
  private readonly analytics = inject(AnalyticsService);
  
  // Внедряем службу логирования
  private readonly logger = inject(NetworkLogger);

  // Реактивный сигнал для вывода данных на экран
  public readonly activeConnections = signal<number>(12);

  public ngOnInit(): void {
    // Безопасно вызываем методы внедренных служб
    this.logger.log('Компонент статистики успешно инициализирован.');
    this.analytics.sendEvent('dashboard_view', { timestamp: Date.now() });
  }
}
```

#### 2. Файл разметки: `dashboard-stats.html`
```html
<div class="stats-card">
  <h4>Статистика подключений</h4>
  <p>Активных соединений: <b>{{ activeConnections() }}</b></p>
</div>
```

#### 3. Файл стилей: `dashboard-stats.css`
```css
.stats-card {
  padding: 16px;
  background-color: var(--bg-secondary);
  border: 1px solid var(--border);
  border-radius: 8px;
}
```

### Шаблон 2: Асинхронное получение зависимостей через `runInInjectionContext`
*   **Назначение:** Безопасный вызов `inject()` вне стандартной фазы инициализации класса (например, внутри асинхронного колбэка или метода жизненного цикла `ngOnInit`) за счет явного восстановления контекста.

#### 1. Файл логики: `lazy-logger.ts`
```typescript
import { Component, OnInit, inject, Injector, runInInjectionContext, ChangeDetectionStrategy } from '@angular/core';
import { NetworkLogger } from './network-logger';

@Component({
  selector: 'app-lazy-logger',
  imports: [],
  templateUrl: './lazy-logger.html',
  styleUrl: './lazy-logger.css',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class LazyLogger implements OnInit {
  // 1. Внедряем и сохраняем ссылку на системный инжектор во время фазы конструирования класса
  private readonly injector = inject(Injector);

  public ngOnInit(): void {
    // Имитируем асинхронную задержку (например, ожидание ответа от сервера)
    setTimeout(() => {
      // ПЛОХО: const logger = inject(NetworkLogger); 
      // Вызов упадет с ошибкой NG0203, так как фаза конструктора завершена и контекст DI закрыт.

      // ХОРОШО: Вручную восстанавливаем контекст внедрения Angular с помощью сохраненного инжектора.
      // Внутри этого колбэка вызовы функции inject() снова становятся абсолютно легальными!
      runInInjectionContext(this.injector, () => {
        const logger = inject(NetworkLogger);
        logger.log('Асинхронный отложенный лог успешно записан.');
      });
    }, 2000);
  }
}
```

#### 2. Файл разметки: `lazy-logger.html`
```html
<div class="logger-box">
  <p>Инициализирован отложенный фоновый процесс...</p>
</div>
```

#### 3. Файл стилей: `lazy-logger.css`
```css
.logger-box {
  padding: 12px;
  border-left: 4px solid var(--accent);
  background-color: var(--bg-secondary);
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Двухуровневая иерархическая структура инжекторов в Angular
Система внедрения зависимостей в Angular построена по древовидному иерархическому принципу. Поиск любой запрашиваемой зависимости всегда происходит строго снизу вверх по двум ключевым уровням:

```text
               NullInjector (Вершина графа. Кидает ошибку "No provider for...")
                        ▲
                        │
               PlatformInjector (Системные зависимости ядра Angular)
                        ▲
                        │
               EnvironmentInjector (Корневые синглтоны / providedIn: 'root' / app.config.ts)
                        ▲
                        │
            [Родительский ElementInjector] (providers: [MyService])
                        ▲
                        │ (Поиск поднимается снизу вверх по DOM-дереву)
            [Дочерний ElementInjector] (inject(MyService))
```

#### Уровень 1: ElementInjector (Инжекторы элементов)
Создается индивидуально для каждого HTML-элемента DOM-дерева, на котором объявлен компонент или директива.
*   Каждый `ElementInjector` хранит зависимости, зарегистрированные в массиве `providers` или `viewProviders` декоратора `@Component`.
*   Время жизни этих зависимостей жестко привязано к жизненному циклу DOM-узла: при удалении компонента из дерева все локальные экземпляры сервисов уничтожаются сборщиком мусора, освобождая память.

#### Уровень 2: EnvironmentInjector (Инжекторы окружения)
Совпадает с жизненным циклом всего запущенного веб-приложения:
*   **EnvironmentInjector** (ранее `ModuleInjector`): Регистрирует провайдеры уровня приложения (сконфигурированные в `appConfig` в файле `main.ts` или в лениво загруженных роутах), а также все классы с декоратором `@Injectable({ providedIn: 'root' })`.
*   **PlatformInjector**: Содержит провайдеры системного уровня, общие для нескольких приложений Angular на одной странице.
*   **NullInjector**: Вершина графа. Не содержит провайдеров. Если поиск доходит до него, Angular мгновенно генерирует критическую ошибку `"StaticInjectorError"`.

### 2. Физика работы Контекста Внедрения (Injection Context)
Функция `inject()` не принимает ссылку на инжектор в качестве прямого аргумента. Она определяет нужный инжектор неявно, опираясь на текущую глобальную переменную контекста среды выполнения.

Когда Angular инициализирует класс компонента:
1.  Ядро Angular временно записывает ссылку на активный инжектор текущего элемента в скрытую глобальную переменную среды.
2.  Запускается фаза инстанцирования класса (вызываются конструкторы, инициализируются свойства и поля класса).
3.  Любой вызов `inject()` внутри этой фазы считывает ссылку из глобальной переменной, обращается к инжектору и возвращает нужную зависимость.
4.  После завершения инициализации класса глобальная переменная контекста принудительно очищается (сбрасывается в `null`).

Если вы попытаетесь вызвать `inject()` позже (например, при асинхронном клике пользователя или внутри `ngOnInit`), Angular не обнаружит активного контекста и выбросит ошибку `NG0203`. Утилита `runInInjectionContext` временно восстанавливает эту связь в рантайме, подменяя глобальный указатель инжектора на сохраненный `Injector` на время работы переданного колбэка.

### 3. Преимущества функционального DI перед конструкторами
*   **Решение проблемы наследования классов:**
    В классическом Angular при наследовании классов с зависимостями возникал лавинообразный рост бойлерплейта. Если базовому классу требовалось добавить новую зависимость (например, сервис логирования), разработчику приходилось вручную менять сигнатуры конструкторов абсолютно всех дочерних классов по всей кодовой базе и прокидывать аргумент в `super()`. С использованием `inject()` дочерний класс наследует все свойства "бесплатно", не зная о них на уровне своего конструктора.
*   **Возможность функциональной композиции:**
    Вы можете создавать чистые переиспользуемые функции-утилиты вне классов, которые самостоятельно запрашивают зависимости из контекста (например, функции для автоматической отписки `takeUntilDestroyed()`, динамического изменения метаданных или синхронизации с API).

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Вызов `inject()` вне контекста внедрения зависимостей (NG0203)**
    *   *Симптомы:* Критическая рантайм-ошибка: `NG0203: inject() must be called from an active injection context...` при старте приложения.
    *   *Физика процесса:* Разработчик попытался вызвать `inject()` внутри метода жизненного цикла `ngOnInit` или в асинхронном колбэке, когда фаза конструирования класса уже завершена и глобальный указатель инжектора сброшен в `null`.
    *   *Решение:* Перенесите вызовы `inject()` на уровень объявления свойств класса, либо сохраните ссылку на `Injector` в конструкторе и используйте `runInInjectionContext` (как показано в Шаблоне 2).

```typescript
// ПЛОХО (Вызов inject внутри ngOnInit вызовет критическую ошибку в рантайме)
export class BadComponent implements OnInit {
  ngOnInit(): void {
    const logger = inject(NetworkLogger); // ❌ Ошибка NG0203! Контекст DI уже закрыт.
  }
}

// ХОРОШО (Инициализация на уровне полей класса)
export class GoodComponent {
  private readonly logger = inject(NetworkLogger); // ✅ Отлично, контекст DI активен
}
```

*   **Ошибка 2: Проблема циклической зависимости (Circular Dependency)**
    *   *Симптомы:* Ошибка компиляции или рантайм-ошибка: `Circular dependency detected` или `Cannot access '...' before initialization`.
    *   *Физика процесса:* Сервис `ServiceA` внедряет в себя `ServiceB`, а `ServiceB` одновременно пытается внедрить в себя `ServiceA`. При попытке создать один из сервисов Angular попадает в бесконечный рекурсивный цикл разрешения зависимостей и падает.
    *   *Решение:* Избавьтесь от циклической зависимости путем вынесения общей логики в третий независимый сервис, либо лениво разрешайте зависимость в момент вызова метода с помощью ручного обращения к `Injector`.

```typescript
// ПЛОХО (Бесконечный цикл взаимного создания)
@Injectable({ providedIn: 'root' })
export class ServiceA {
  private serviceB = inject(ServiceB);
}
@Injectable({ providedIn: 'root' })
export class ServiceB {
  private serviceA = inject(ServiceA); // ❌ Циклическая зависимость!
}

// ХОРОШО (Ленивое разрешение зависимости через Injector)
@Injectable({ providedIn: 'root' })
export class ServiceB {
  private readonly injector = inject(Injector);

  doSomethingWithA(): void {
    // Разрешаем зависимость только тогда, когда метод физически вызван
    runInInjectionContext(this.injector, () => {
      const serviceA = inject(ServiceA);
      // ...
    });
  }
}
```

*   **Ошибка 3: Случайное дублирование экземпляров синглтона при неверной регистрации**
    *   *Симптомы:* Состояние сервиса расхронизировано между компонентами: один компонент пишет данные в сервис-синглтон, а второй компонент видит пустой дефолтный стейт.
    *   *Физика процесса:* Разработчик указал декоратор `@Injectable({ providedIn: 'root' })` для сервиса-синглтона, но при этом случайно продублировал имя этого класса в массиве `providers` локального компонента. В итоге Angular создал для этого компонента локальный изолированный экземпляр сервиса на уровне `ElementInjector`, проигнорировав глобальный синглтон из `EnvironmentInjector`.
    *   *Решение:* Никогда не указывайте глобальные синглтоны в массиве `providers` отдельных компонентов, если вам не нужен изолированный экземпляр.
