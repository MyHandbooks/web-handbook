# Механизм Change Detection и Zone.js

## БЫСТРЫЙ СТАРТ

*   **Change Detection (Обнаружение изменений)** — это внутренний движок Angular, отвечающий за синхронизацию текущего состояния приложения (моделей данных) с его визуальным представлением (структурой DOM).
*   **Библиотека Zone.js** — системная библиотека, которая подменяет (monkey-patches) стандартные асинхронные API браузера, чтобы автоматически запускать тотальную проверку изменений в приложении при завершении любой асинхронной задачи (таймеры, сетевые запросы, события кликов).
*   **Стратегия `OnPush`** — отключает компонент и его потомков от автоматического сканирования при каждом асинхронном тике Zone.js, повышая производительность за счет точечного обновления.
*   **Используйте для:** минимизации вычислительной нагрузки на процессор клиента, исключения холостых циклов рендеринга и оптимизации сложных динамических интерфейсов.
*   **Не используйте для:** статических страниц с редким обновлением данных, где накладные расходы по умолчанию незначительны и не требуют тонкой оптимизации.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: OnPush-компонент реального времени с ручным управлением ChangeDetectorRef
*   **Назначение:** Описание оптимизированного компонента мониторинга, изолированного от глобальных тиков приложения и запускающего перерисовку вручную только при получении новых данных из асинхронного потока.

#### 1. Файл логики: `realtime-feed.ts`
```typescript
// Импортируем системные декораторы, стратегии и сервис управления проверками
import { Component, ChangeDetectionStrategy, ChangeDetectorRef, OnInit, OnDestroy, inject } from '@angular/core';
import { CommonModule } from '@angular/common';
import { interval, Subscription } from 'rxjs';

@Component({
  selector: 'app-realtime-feed',
  // standalone: true опущен по умолчанию для стандартов Angular 19+
  imports: [CommonModule], // Декларативно импортируем базовые директивы
  templateUrl: './realtime-feed.html',
  styleUrl: './realtime-feed.css',
  // OnPush полностью изолирует компонент от холостых глобальных сканирований приложения
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class RealtimeFeed implements OnInit, OnDestroy {
  // Внедряем ChangeDetectorRef через функциональный инжектор inject()
  private readonly cdr = inject(ChangeDetectorRef);
  
  currentRate: number = 1.0;
  private feedSubscription?: Subscription;

  ngOnInit(): void {
    // Имитируем получение сетевого потока котировок каждую секунду в фоновом режиме
    this.feedSubscription = interval(1000).subscribe((val: number) => {
      this.currentRate = 1.0 + val * 0.05;
      
      // Так как включена стратегия OnPush, асинхронная запись в локальное свойство
      // не спровоцирует автоматическое обновление шаблона в браузере.
      // Помечаем эту ветку компонентов грязной (dirty) для следующего тика рендеринга.
      this.cdr.markForCheck();
    });
  }

  onLocalClick(): void {
    // Любое событие внутри шаблона OnPush компонента (например, клик)
    // автоматически ставит флаг dirty и инициирует проверку изменений без вызова markForCheck()
    console.log('Локальное клик-событие обработано. Angular обновит шаблон.');
  }

  ngOnDestroy(): void {
    // Предотвращаем утечку памяти путем гарантированной отписки
    if (this.feedSubscription) {
      this.feedSubscription.unsubscribe();
    }
  }
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как Zone.js перехватывает асинхронные события (Физика ранкипатчинга)
В основе автоматической реактивности Angular лежит библиотека Zone.js. На этапе старта приложения она производит операцию, называемую манкипатчингом (monkey-patching).

```text
Нативный браузерный API:
  window.setTimeout = f (вызов напрямую в ОС через Web API)

API, переписанный Zone.js:
  window.setTimeout = function(callback, delay) {
    const activeZone = this.currentZone;
    // Регистрируем макрозадачу в Zone.js
    activeZone.scheduleTask();
    
    nativeSetTimeout(() => {
      callback(); // Выполняем оригинальный код
      activeZone.onMicrotaskEmpty(); // Сигнализируем Angular о завершении задачи
    }, delay);
  }
```

Zone.js подменяет глобальные объекты браузера (такие как `setTimeout`, `setInterval`, `fetch`, `Promise.prototype.then`, `addEventListener`) своими собственными обертками. 
*   Когда в приложении завершается асинхронный процесс (например, возвращается сетевой ответ), Zone.js перехватывает окончание этой задачи.
*   Библиотека генерирует событие `onMicrotaskEmpty`, сообщая фреймворку, что стек вызовов пуст.
*   Angular слушает это событие и автоматически вызывает метод `ApplicationRef.tick()`, который запускает полный обход дерева компонентов сверху вниз для сверки актуальности данных в шаблонах.

### 2. Специфика обхода дерева при Default и OnPush стратегиях
Иерархическая структура компонентов определяет, сколько узлов Angular проверит при очередном вызове `tick()`:

```text
       DEFAULT СТРАТЕГИЯ                           ONPUSH СТРАТЕГИЯ
    (Проверяются все узлы)                (Пропускаются чистые OnPush-узлы)
            
           [Корневой]                                  [Корневой]
            /      \                                    /      \
           ▼        ▼                                  ▼        ▼
       [Узел A]  [Узел B]                          [Узел A]  [Узел B] (OnPush)
       /      \                                    /      \   (Пропущен)
      ▼        ▼                                  ▼        ▼
  [Узел C]  [Узел D]                          [Узел C]  [Узел D]
```

1.  **Default (По умолчанию)**: Рантайм-движок сканирует абсолютно каждый узел дерева компонентов при любом асинхронном событии (клике в шапке, фоновом интервале, сетевом запросе), даже если данные в проверяемом узле физически не менялись. Это создает колоссальную нагрузку при масштабировании.
2.  **OnPush**: Компонент помечается чистым и исключается из глобального сканирования. Angular зайдет в его проверку только в следующих случаях:
    *   Ссылка на входящие данные (`input()` или `@Input`) изменилась (поверхностное равенство `===`).
    *   Событие произошло внутри самого OnPush компонента (клик по кнопке в шаблоне).
    *   AsyncPipe, привязанный к шаблону OnPush компонента, испустил новое значение.
    *   Реактивный Сигнал (Signal), считываемый шаблоном, обновил свое значение.
    *   Разработчик вручную вызвал метод `markForCheck()` или `detectChanges()`.

### 3. Детальный пошаговый разбор выполнения шаблона 1
1.  **Монтирование**: Компонент `RealtimeFeed` инициализируется, регистрируется в OnPush режиме. `ChangeDetectorRef` внедряется в свойство `cdr`.
2.  **Исключение из CD**: При очередном событии в стороннем компоненте (например, скролл в шапке) Zone.js вызывает `tick()`. Angular обходит дерево, видит стратегию OnPush у `RealtimeFeed` и полностью пропускает его проверку, экономя такты процессора.
3.  **Срабатывание интервала**: Истекает секунда таймера `interval(1000)`. Zone.js перехватывает событие. Запускается колбэк подписки.
4.  **Изменение свойства**: Свойство `currentRate` получает новое число. Но шаблон по-прежнему не обновляется.
5.  **Ручной вызов markForCheck**: Выполняется инструкция `this.cdr.markForCheck()`. Она поднимается по дереву от текущего компонента до корневого и помечает всю эту ветку как грязную (dirty).
6.  **Обновление в следующем тике**: Zone.js завершает выполнение макрозадачи таймера, Call Stack пустеет, генерируется `onMicrotaskEmpty`. Angular запускает `tick()`, видит флаг dirty у ветки `RealtimeFeed`, заходит в его шаблон и точечно обновляет выводимое значение курса в DOM.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Использование неиммутабельных объектов (мутация по ссылке) в OnPush компонентах**
    *   *Симптомы:* Новые данные не отображаются на экране в OnPush компоненте, хотя родительский элемент передает обновленный объект в `@Input()`.
    *   *Физика процесса:* Родительский элемент изменил свойство объекта (например, `user.name = 'Новый'`), но ссылка на сам объект в памяти осталась прежней. OnPush-компонент производит проверку изменений по ссылочному принципу (`===`). Так как адрес ссылки не изменился, Angular считает, что входные данные не менялись, и пропускает всю ветку при проверке изменений.
    *   *Решение:* Всегда передавайте в OnPush компоненты новые, иммутабельные копии объектов с помощью деструктуризации или spread-операторов.

```typescript
// ПЛОХО (Свойства изменены, но ссылка в памяти та же. OnPush компонент не обновит UI)
updateProfileUnsafe() {
  this.profile.name = 'Иван'; // ❌ Мутация объекта по ссылке
}

// ХОРОШО (Новый объект в памяти гарантирует успешное прохождение OnPush верификации)
updateProfileSafe() {
  this.profile = { ...this.profile, name: 'Иван' }; // ✅ Ссылка обновилась, UI перерисуется
}
```

*   **Ошибка 2: Вызов тяжелых математических расчетов в геттерах или функциях шаблона**
    *   *Симптомы:* Резкое снижение FPS, лаги при прокрутке и анимациях, вентилятор процессора начинает работать на максимальных оборотах.
    *   *Физика процесса:* Шаблон содержит вызов метода `{{ calculateValue() }}`. Angular не может знать, изменился ли результат метода, и принудительно вызывает его на абсолютно каждом глобальном проходе Change Detection (даже если узел не грязный, в режиме Default).
    *   *Решение:* Замените методы на чистые пайпы (`pure pipe`), кэширующие расчеты по ссылочной мемоизации, либо на реактивные вычисляемые сигналы `computed`.

```html
<!-- ПЛОХО (Метод calculateTax() будет грузить процессор на каждом тике проверки изменений) -->
<p>Налог: {{ calculateTax(salary) }}</p>

<!-- ХОРОШО (computed сигнал выполнит расчет только при реальном изменении сигнала salary) -->
<p>Налог: {{ tax() }}</p> <!-- tax = computed(() => this.salary() * 0.13) -->
```

*   **Ошибка 3: Утечка памяти при ручном отключении Change Detection через `detach()`**
    *   *Симптомы:* Постепенный рост потребления памяти, отсутствие обновления данных даже после явных кликов, зависшие подписки в фоновых потоках.
    *   *Физика процесса:* Разработчик временно отключил компонент от проверок вызовом `cdr.detach()` для выполнения тяжелых расчетов, но забыл подключить его обратно (`cdr.reattach()`) или не отписался от фоновых бесконечных потоков.
    *   *Решение:* Всегда контролируйте очистку ресурсов и своевременное возвращение компонента в контур проверок. Оптимальным решением является переход на Zoneless-архитектуру Angular 18/19+, где Zone.js полностью отключается, а проверки происходят точечно на базе Сигналов.

```typescript
// Включение Zoneless-архитектуры в app.config.ts (Полностью избавляет от накладных расходов Zone.js)
import { provideExperimentalZonelessChangeDetection } from '@angular/core';

export const appConfig = {
  providers: [
    // Активируем производительный режим без Zone.js. Проверки изменений теперь 
    // будут триггериться точечно строго при обновлении реактивных Сигналов.
    provideExperimentalZonelessChangeDetection() // ✅ Трендовый стандарт Angular 19+
  ]
};
```
