# Zoneless-архитектура без Zone.js (provideExperimentalZonelessChangeDetection)

## БЫСТРЫЙ СТАРТ

*   **Эпоха Zone.js:** На протяжении более чем десяти лет Angular полагался на библиотеку `zone.js`, которая переопределяла (*monkey-patching*) все асинхронные браузерные API (таймеры, клики, сетевые запросы), чтобы автоматически запускать глобальную проверку изменений (Change Detection) во всем приложении при любом асинхронном событии.
*   **Революция Zoneless (Angular 18+):** Современный стандарт разработки позволяет полностью отказаться от `zone.js` и перевести приложение в режим **Zoneless** с помощью регистрации провайдера `provideExperimentalZonelessChangeDetection()`.
*   **Принцип точечной реактивности:** В Zoneless-архитектуре проверка изменений перестает быть глобальной и автоматической. Она триггерится строго в тех компонентах, где реактивные примитивы (Сигналы) отправили сигнал об изменении (*dirty-уведомление*) по своему ориентированному графу зависимостей.
*   **Используйте для:** радикального уменьшения веса бандла (минус ~30-50 КБ чистого JS), устранения тысяч паразитных циклов проверки изменений от фоновых микрозадач и достижения максимальной частоты кадров (FPS) в тяжелых UI-интерфейсах.
*   **Не используйте для:** устаревших легаси-проектов, где сотни компонентов написаны на обычных мутабельных свойствах класса без использования Сигналов или явного вызова `ChangeDetectorRef.markForCheck()`.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Активация Zoneless-режима в `app.config.ts`
*   **Назначение:** Глобальное отключение `zone.js` на уровне конфигурации современного автономного (Standalone) приложения.

```typescript
import { ApplicationConfig, provideZoneChangeDetection, provideExperimentalZonelessChangeDetection } from '@angular/core';
import { provideRouter } from '@angular/router';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    // УДАЛЯЕМ старый провайдер provideZoneChangeDetection()
    // provideZoneChangeDetection({ eventCoalescing: true }),

    // АКТИВИРУЕМ современный Zoneless-режим.
    // Это сообщает ядру Angular больше не ожидать сигналов от библиотеки zone.js
    provideExperimentalZonelessChangeDetection(),
    
    provideRouter(routes)
  ]
};
```

### Шаблон 2: Строго реактивный Zoneless-компонент на Сигналах
*   **Назначение:** Описание компонента, который работает со 100% производительностью в Zoneless-режиме за счет использования Сигналов для вывода данных на экран.

```typescript
import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-reactive-zoneless-card',
  standalone: true,
  template: `
    <div class="card">
      <!-- Сигналы гарантируют мгновенное точечное обновление шаблона в Zoneless-режиме -->
      <p>Локальный счетчик: <b>{{ clickCount() }}</b></p>
      <button (click)="increment()">Инкремент</button>
    </div>
  `
})
export class ReactiveZonelessCardComponent {
  public readonly clickCount = signal<number>(0);

  public increment(): void {
    // Вызов .update() инкрементирует значение, сигнал помечает этот компонент dirty.
    // Планировщик Angular мгновенно перерисует этот узел DOM на следующем микрошаге
    this.clickCount.update((c) => current + 1);
  }
}
```

### Шаблон 3: Безопасная интеграция нереактивных легаси-сервисов в Zoneless
*   **Назначение:** Явное ручное информирование планировщика Angular о необходимости запустить проверку изменений при получении асинхронных данных из старых сторонних библиотек, которые не используют Сигналы.

```typescript
import { Component, inject, ChangeDetectorRef, OnInit, signal } from '@angular/core';

@Component({
  selector: 'app-legacy-integration',
  standalone: true,
  template: `
    <div class="box">
      <!-- Обычное свойство класса, не обернутое в сигнал -->
      <p>Статус из легаси сокета: <b>{{ legacyStatus }}</b></p>
    </div>
  `
})
export class LegacyIntegrationComponent implements OnInit {
  // Внедряем службу управления проверкой изменений текущего компонента
  private readonly cdr = inject(ChangeDetectorRef);

  public legacyStatus: string = 'connecting';

  public ngOnInit(): void {
    // Имитируем старый асинхронный сокет-сервер
    setInterval(() => {
      this.legacyStatus = 'received_data_at_' + Date.now();

      // В Zoneless-режиме изменение обычной переменной класса "legacyStatus" 
      // никак не зафиксируется фреймворком. Экран останется старым!
      // Вызов markForCheck() принудительно помечает этот компонент dirty для планировщика
      this.cdr.markForCheck();
    }, 5000);
  }
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Накладные расходы Zone.js: Почему старый подход замедлял рендеринг
До появления Zoneless-архитектуры Angular использовал "магический" подход. Библиотека `zone.js` при старте приложения вторгалась в глобальный контекст браузера `window` и перезаписывала прототипы абсолютно всех асинхронных функций: `setTimeout`, `addEventListener`, `fetch`, `Promise.prototype.then` и других.

Когда вы вешали обработчик клика в коде:
1.  Пользователь кликал на кнопку.
2.  `zone.js` перехватывал завершение этого события.
3.  Библиотека сигнализировала ядру Angular: «Произошла асинхронная операция! Срочно запусти проверку изменений».
4.  Angular запускал глобальный цикл Change Detection **с самого верха корневого компонента `AppComponent` до самого низа DOM-дерева**, обходя сотни компонентов по пути.

Если у вас в фоне работал сокет, отправляющий системный пинг раз в секунду, или выполнялась анимация через `requestAnimationFrame`, `zone.js` заставлял Angular непрерывно перепроверять всю страницу целиком, даже если ни одно свойство на экране не изменилось. Это приводило к просадкам производительности и фризам интерфейса на мобильных устройствах.

### 2. Физика Zoneless Change Detection и планировщик микрозадач
В Zoneless-режиме библиотека `zone.js` полностью исключается из бандла (она больше не импортируется в `angular.json` и не полифилит глобальные API). Процесс проверки изменений переходит на декларативную Pull-модель реактивного графа Сигналов:

1.  **dirty-уведомление:** Когда вы вызываете метод изменения сигнала (`clickCount.set()`), сигнал по цепочке своего графа зависимостей отправляет короткое синхронное уведомление наверх: *«Компонент, в шаблоне которого я считан, стал грязным (dirty)»*.
2.  **Регистрация задачи в планировщике:** Компонент помечается системным статусом `dirty`. Его инжектор отправляет команду глобальному планировщику Angular — **`ChangeDetectionScheduler`**.
3.  **Планирование микрозадачи:** Планировщик не запускает проверку изменений синхронно (это вызвало бы тормоза при множественных последовательных записях в сигналы). Он регистрирует выполнение рендеринга как одну микрозадачу в очереди событий браузера: `Promise.resolve().then(() => runChangeDetection())`.
4.  **Точечный рендеринг (Pull):** Как только текущий синхронный стек JavaScript полностью завершается, планировщик просыпается, обходит строго те компоненты, которые имеют статус `dirty`, синхронно считывает новые значения сигналов и перерисовывает измененные пиксели на экране.

Благодаря этому количество пустых, паразитных циклов проверки изменений сокращается на 99%, а FPS приложения становится стабильным.

### 3. Пошаговый разбор выполнения шаблона 2 в Zoneless-режиме
1.  **Инициализация:** Приложение запускается без `zone.js`. Шаблон `ReactiveZonelessCardComponent` рендерится один раз, регистрируя зависимость от сигнала `clickCount()`.
2.  **Клик пользователя:** Пользователь нажимает на кнопку "Инкремент". Нативное браузерное событие `click` перехватывается стандартным образом (без участия `zone.js`).
3.  **Изменение значения:** Выполняется метод `this.clickCount.update(...)`. Значение сигнала меняется.
4.  ** dirty-сигнал:** Сигнал `clickCount` отправляет dirty-уведомление вверх к инжектору компонента `ReactiveZonelessCardComponent`. Компонент помечается как `dirty`.
5.  **Планирование:** Планировщик Angular ставит микрозадачу CD в очередь событий браузера.
6.  **Рендеринг:** Синхронный стек выполнения клика завершается. Браузер переходит к очереди микрозадач. Выполняется CD планировщика: он видит, что `ReactiveZonelessCardComponent` помечен как `dirty`, заходит в его шаблон, считывает новое значение сигнала `clickCount()` и точечно перерисовывает число на экране.

### 5. Типичные ошибки и их решение

*   **Ошибка 1: Обычные (не-сигнальные) свойства класса не обновляются на экране в Zoneless**
    *   *Симптомы:* Метод класса успешно изменяет переменную (например, `this.userName = 'Alex'`), но текст на экране упрямо остается старым.
    *   *Причина:* Обычные мутабельные свойства класса не умеют отправлять dirty-уведомления по реактивному графу Angular. Так как `zone.js` отключен, Angular просто не догадывается, что данные изменились, и проверка изменений для этого компонента никогда не запустится.
    *   *Решение:* Оборачивайте любые свойства класса, участвующие в рендеринге шаблона, в реактивные Сигналы (`signal`), либо вручную вызывайте `ChangeDetectorRef.markForCheck()` при изменении обычных переменных (как показано в Шаблоне 3).

```typescript
// ПЛОХО (В Zoneless-режиме изменение свойстваuserName никогда не отобразится в HTML)
// userName = 'Ivan';
// change() { this.userName = 'Alex'; }

// ХОРОШО (Использование Сигналов гарантирует автоматическую работу в Zoneless)
public readonly userName = signal<string>('Ivan');
public change(): void {
  this.userName.set('Alex'); // Успешно перерисует экран
}
```

*   **Ошибка 2: Ломается работа сторонних не-Angular JS библиотек (например, Chart.js или Leaflet)**
    *   *Симптомы:* Графики или карты сторонних библиотек перестают интерактивно реагировать на действия пользователя (перетаскивание, зум), либо не обновляют свои данные.
    *   *Причина:* Многие сторонние библиотеки были спроектированы в расчете на то, что Angular неявно перерисовывает всё приложение при возникновении любых асинхронных событий в браузере (благодаря `zone.js`). В Zoneless-режиме их внутренние асинхронные обработчики выполняются "молча" для Angular.
    *   *Решение:* Оборачивайте колбэки сторонних библиотек в вызовы изменения сигналов, либо явно внедряйте `ChangeDetectorRef` и вызывайте метод `markForCheck()` внутри колбэков обновления данных библиотеки.

*   **Ошибка 3: Ошибка принудительной мутации DOM-элементов вне реактивного графа**
    *   *Симптомы:* Нарушение консистентности интерфейса, хаотичные наложения стилей или мерцание текста.
    *   *Причина:* Разработчик пытается изменять геометрические размеры или стили элементов напрямую через нативный DOM API (`element.nativeElement.style.width = ...`) внутри асинхронных таймеров в Zoneless-режиме, минуя проверки изменений Angular.
    *   *Решение:* Изменяйте стили и атрибуты строго через привязки шаблона на базе Сигналов или используйте директивы со службой `Renderer2`.
