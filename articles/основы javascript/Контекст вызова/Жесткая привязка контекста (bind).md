# Жесткая привязка контекста (bind)

## БЫСТРЫЙ СТАРТ

*   **Жесткая привязка контекста (`.bind()`)** — метод прототипа функций, который возвращает новую функцию-обертку с фиксированным значением `this` и необязательными предопределенными первыми аргументами.
*   **Ленивый характер:** В отличие от `.call()` и `.apply()`, метод `.bind()` **не вызывает функцию немедленно**, а лишь подготавливает ее для запуска в будущем.
*   **Используйте его для:** гарантированного сохранения связи метода с его классом перед передачей ссылки во внешние асинхронные системы, таймеры или планировщики, а также для частичного применения аргументов (каррирования).
*   **Не используйте его:** на стрелочных функциях (они игнорируют привязку) и внутри циклов или функций отрисовки, так как постоянное создание новых оберток в памяти снижает производительность приложения.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Базовая фиксация контекста метода класса
*   **Назначение:** Принудительное связывание метода с экземпляром класса для предотвращения его поломки при вызове из стороннего кода.

```typescript
export interface TargetPayload {
  identifier: string;
  statePayload: string;
}

export class ConfigurationController {
  private activePrefix: string = "CONF_SECURE";

  public processConfiguration(data: TargetPayload): void {
    // Метод обращается к приватному свойству класса через this
    console.log(`[${this.activePrefix}] Обработка: ${data.identifier}`);
  }

  public exportCallback(): (data: TargetPayload) => void {
    // Возвращаем копию метода с жестко зафиксированным контекстом текущего экземпляра
    return this.processConfiguration.bind(this); 
  }
}
```

### Шаблон 2: Частичное применение аргументов (Partial Application) через `.bind()`
*   **Назначение:** Предустановка первых аргументов функции в замыкании для создания специализированных конфигурационных версий этой функции.

```typescript
export interface ConfigOptions {
  protocol: string;
  hostDomain: string;
  targetPath: string;
}

// Обобщенная функция для конструирования URL-адресов
export function buildEndpoint(this: void, protocol: string, hostDomain: string, targetPath: string): string {
  return `${protocol}://${hostDomain}/${targetPath}`;
}

export function executePartialApplication(): void {
  // Фиксируем контекст как null (он не используется внутри функции)
  // И жестко задаем первый аргумент (протокол) и второй аргумент (домен)
  const createSecureEltexLink = buildEndpoint.bind(null, "https", "eltex-co.ru");

  // Теперь возвращенная функция ожидает на вход только ОДИН последний аргумент
  const articlesEndpoint = createSecureEltexLink("academy/blog");
  const configEndpoint = createSecureEltexLink("api/v1/config");

  console.log(articlesEndpoint); // Вывод: "https://eltex-co.ru/academy/blog"
  console.log(configEndpoint);   // Вывод: "https://eltex-co.ru/api/v1/config"
}
```

### Шаблон 3: Использование `.bind()` во вложенных асинхронных колбэках
*   **Назначение:** Передача контекста класса во внутренние служебные функции, написанные через стандартный синтаксис `function`.

```typescript
export interface TemporaryResult {
  records: string[];
}

export class DataManager {
  private baseOffset: number = 100;

  public processRecords(data: TemporaryResult): void {
    // Передаем обычную функцию-колбэк в метод foreach
    data.records.forEach(function(this: DataManager, item: string) {
      // Благодаря принудительной привязке .bind(this) вложенная функция видит baseOffset
      console.log(`Смещение: ${this.baseOffset}, Элемент: ${item}`);
    }.bind(this)); // Связываем контекст вложенной функции с контекстом метода processRecords
  }
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как метод `.bind()` устроен под капотом движка V8
Когда вы вызываете метод `func.bind(thisArg, ...args)`, в оперативной памяти не происходит копирования исходного текста функции. Вместо этого спецификация ECMAScript предписывает движку создать специальный внутренний системный объект — **Bound Function Exotic Object (Экзотический объект привязанной функции)**.

Этот экзотический объект хранит в своих скрытых системных слотах (Internal Slots) три критически важные ссылки:
*   `[[BoundTargetFunction]]` — прямая ссылка на исходную функцию, которую мы привязываем.
*   `[[BoundThis]]` — объект, который мы принудительно передали в качестве первого аргумента `thisArg`.
*   `[[BoundArguments]]` — список предопределенных аргументов, переданных при вызове `.bind()`.

Когда рантайм V8 встречает запуск этой привязанной функции, он не создает обычный кадр стека. Он считывает данные из скрытых слотов, конкатенирует (склеивает) аргументы из `[[BoundArguments]]` с новыми аргументами, переданными в момент вызова, подменяет регистр `this` на значение из `[[BoundThis]]` и только после этого передает управление оригинальной функции `[[BoundTargetFunction]]`.

### 2. Частичное применение (Partial Application) и каррирование
Частичное применение аргументов через `.bind()` — мощный инструмент функционального программирования. 

Когда вы передаете аргументы в метод `.bind()` после контекста:
1.  Они записываются в массив внутри скрытого слота `[[BoundArguments]]`.
2.  При вызове возвращенной обертки любые переданные новые аргументы помещаются в стек **строго после** тех аргументов, которые были зафиксированы при вызове `.bind()`.
3.  Это позволяет «замораживать» конфигурационные параметры функций на ранних этапах инициализации приложения и отдавать в дочерние модули чистые, легковесные функции, требующие минимум параметров при вызове.

### 3. Детальный пошаговый разбор выполнения шаблона 2
1.  **Создание обертки:** Вызывается `buildEndpoint.bind(null, "https", "eltex-co.ru")`. 
2.  **Запись в слоты:** V8 создает в куче экзотический объект. В его скрытый слот `[[BoundTargetFunction]]` записывается ссылка на тело функции `buildEndpoint`, в `[[BoundThis]]` пишется `null`, а в `[[BoundArguments]]` — массив `["https", "eltex-co.ru"]`. Ссылка на обертку возвращается и сохраняется в `createSecureEltexLink`.
3.  **Вызов обертки:** Выполняется вызов `createSecureEltexLink("academy/blog")`.
4.  **Разрешение аргументов:** Движок V8 видит, что вызываемый объект является экзотическим. Он берет массив из `[[BoundArguments]]` (`["https", "eltex-co.ru"]`), добавляет в конец переданный аргумент `"academy/blog"` и получает итоговый набор параметров `["https", "eltex-co.ru", "academy/blog"]`.
5.  **Запуск:** Движок запускает оригинальную функцию `buildEndpoint` с итоговым набором параметров, возвращая готовую строковую ссылку.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Попытка повторной привязки (Re-binding) уже привязанной функции**
    *   *Проблема:* Разработчик пытается изменить контекст у функции, которая ранее уже была привязана через `.bind()`, вызвав метод `.bind()` или `.call()` повторно (например, `boundFunc.bind(newContext)`). Вызов проходит без ошибок, но контекст не меняется — функция по-прежнему выполняется в контексте первой привязки.
    *   *Причина:* Экзотический объект привязанной функции при вызове всегда берет значение `this` из своего скрытого слота `[[BoundThis]]` первой привязки, игнорируя любые последующие слои оберток.
    *   *Решение:* Не пытайтесь повторно привязывать функции. Если контекст должен меняться динамически, используйте обычные методы вызова через точку или `.call()`/`.apply()`.

```typescript
// ПЛОХО (Повторная привязка игнорируется рантаймом)
const initialContext = { value: "first_state" };
const secondaryContext = { value: "second_state" };

function logState(this: typeof initialContext) { console.log(this.value); }

const firstBound = logState.bind(initialContext);
const secondBound = firstBound.bind(secondaryContext);

secondBound(); // Выведет: "first_state" (Вторая привязка полностью проигнорирована!)
```

*   **Ошибка 2: Создание привязанных методов внутри циклов или шаблонов**
    *   *Проблема:* Разработчик привязывает метод прямо внутри цикла или в Angular-шаблоне (например, `(click)="save.bind(this, item)"` в старых подходах). При каждом цикле проверки изменений (Change Detection) или на каждой итерации цикла в памяти создается абсолютно новый экзотический объект, забивая кучу и нагружая сборщик мусора.
    *   *Решение:* Выполняйте привязку методов заранее в конструкторе класса, или используйте замыкания/стрелочные функции, объявленные один раз на этапе инициализации.

```typescript
// ПЛОХО (Создает новый объект в памяти на каждый проход цикла)
export function processLoopUnsafe(dataList: string[], handler: (item: string) => void): void {
  for (let i = 0; i < dataList.length; i++) {
    const boundHandler = handler.bind(null, dataList[i]); // ! Создание сотен тяжелых объектов в куче
    boundHandler();
  }
}

// ХОРОШО (Передаем аргументы напрямую при вызове без дублирования функций в памяти)
export function processLoopSafe(dataList: string[], handler: (item: string) => void): void {
  for (let i = 0; i < dataList.length; i++) {
    handler(dataList[i]); // Чистый прямой вызов без накладных расходов на создание объектов DI
  }
}
```

*   **Ошибка 3: Попытка вызвать привязанную функцию как конструктор**
    *   *Проблема:* Вызов привязанной функции со словом `new` (например, `new BoundClass()`). Разработчик ожидает, что `this` внутри конструктора сошлется на объект из `[[BoundThis]]`, однако это не так.
    *   *Причина:* По спецификации, если привязанная функция вызывается как конструктор через `new`, системный слот `[[BoundThis]]` полностью игнорируется. Движок создает новый пустой объект и использует его в качестве `this`, как при обычном вызове конструктора.
    *   *Решение:* Не используйте привязанные функции в качестве конструкторов. Для инстанцирования классов всегда используйте оригинальные непривязанные классы или фабричные функции.
