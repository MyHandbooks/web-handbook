# Динамическое управление контекстом (bind, call, apply)

## БЫСТРЫЙ СТАРТ

*   **Динамическое управление контекстом** — это набор встроенных инструментов языка (`bind`, `call`, `apply`), позволяющих принудительно переопределить значение ключевого слова `this` для конкретной функции во время её выполнения.
*   **Методы `.call()` и `.apply()`** — осуществляют **немедленный запуск** функции в контексте переданного объекта. Единственное различие между ними заключается в формате передачи аргументов: `.call()` принимает аргументы списком (через запятую), а `.apply()` — в виде единого массива.
*   **Метод `.bind()`** — работает «лениво». Он **не вызывает функцию немедленно**, а возвращает новую функцию-обертку с жестко зафиксированным контекстом и возможностью частичного применения аргументов (каррирования) для отложенного запуска в будущем.
*   **Используйте для:** одалживания методов у сторонних объектов (Method Borrowing), построения гибких утилит обработки данных, реализации частичного применения аргументов и гарантированной фиксации контекста в асинхронных архитектурах.
*   **Не используйте для:** стрелочных функций (они аппаратно игнорируют любые попытки подмены динамического контекста) и внутри высоконагруженных циклов анимации рендеринга (вызовы через методы принудительного связывания работают медленнее обычных прямых вызовов методов).

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Динамическая подмена контекста со списком аргументов через `.call()`
*   **Назначение:** Немедленное выполнение внешней обобщенной функции форматирования в контексте конкретного изолированного объекта.

#### 1. Файл логики: `call-executor.ts`
```typescript
export interface TargetPayload {
  identifier: string;
  statePayload: string;
}

// Обобщенная утилитарная функция, ожидающая контекст типа TargetPayload.
// Декларативное указание "this: TargetPayload" в аргументах нужно исключительно 
// для статической проверки типов компилятором TypeScript и стирается при сборке в JS.
export function formatDataState(this: TargetPayload, prefix: string, suffix: string): string {
  // Считываем свойства напрямую из динамического контекста this
  return `${prefix}_${this.identifier}_${this.statePayload}_${suffix}`;
}

export function executeCall(): void {
  // Изолированный объект с данными (не содержит собственных методов)
  const activeRecord: TargetPayload = {
    identifier: "record_801",
    statePayload: "active_connection"
  };

  // Вызываем функцию formatDataState немедленно.
  // Первым параметром передаем объект контекста, последующими — аргументы функции по отдельности.
  const resultString = formatDataState.call(activeRecord, "SYS", "INFO");
  
  console.log(`[CALL RESULT] Сгенерированная строка: ${resultString}`);
}
```

### Шаблон 2: Динамический запуск с массивом аргументов через `.apply()`
*   **Назначение:** Выполнение математических или служебных расчетов в контексте объекта, когда аргументы вычисляются динамически и поступают в виде массива.

#### 1. Файл логики: `apply-executor.ts`
```typescript
export interface DataState {
  multiplier: number;
}

export function calculateAggregatedValue(this: DataState, baseOffset: number, correctionFactor: number): number {
  // Вычисляем значение, опираясь на динамический контекст и переданные параметры
  return (baseOffset + correctionFactor) * this.multiplier;
}

export function executeApply(): void {
  // Объект контекста, хранящий коэффициент умножения
  const currentMetric: DataState = {
    multiplier: 1.2
  };

  // Аргументы подготовлены динамически в виде массива (например, получены из внешнего API)
  const calculatedArgs: [number, number] = [200, 50];

  // Вызываем функцию с передачей контекста и массива аргументов.
  // Движок V8 автоматически распакует массив и передаст элементы как отдельные параметры.
  const totalScore = calculateAggregatedValue.apply(currentMetric, calculatedArgs);

  console.log(`[APPLY RESULT] Вычисленный показатель: ${totalScore}`);
}
```

### Шаблон 3: Ленивая жесткая привязка и частичное применение аргументов через `.bind()`
*   **Назначение:** Создание специализированной функции-обертки для отложенного построения URL-адресов с фиксированными базовыми параметрами (каррирование).

#### 1. Файл логики: `bind-executor.ts`
```typescript
// Обобщенная функция для конструирования URL-адресов
export function buildEndpoint(protocol: string, hostDomain: string, targetPath: string): string {
  return `${protocol}://${hostDomain}/${targetPath}`;
}

export function executePartialApplication(): void {
  // Контекст передаем как null, так как функция buildEndpoint не использует this внутри себя.
  // Жестко фиксируем первый аргумент (протокол) и второй аргумент (домен).
  // Метод .bind() не запускает функцию, а возвращает новую настроенную обертку.
  const createSecureEltexLink = buildEndpoint.bind(null, "https", "eltex-co.ru");

  // Теперь возвращенная функция-обертка ожидает на вход только ОДИН последний аргумент.
  // Первые два аргумента будут автоматически извлечены из сохраненных дескрипторов обертки.
  const academyUrl = createSecureEltexLink("academy/blog");
  const configUrl = createSecureEltexLink("api/v1/config");

  console.log(`[BIND RESULT 1] ${academyUrl}`); // https://eltex-co.ru/academy/blog
  console.log(`[BIND RESULT 2] ${configUrl}`);  // https://eltex-co.ru/api/v1/config
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Системные механизмы call, apply и bind на уровне движка V8
В архитектуре JavaScript-движков все функции являются полноценными объектами, унаследованными от системного класса `Function.prototype`. Методы `.call()`, `.apply()` и `.bind()` физически объявлены внутри этого прототипа.

Движок V8 разделяет логику их выполнения на две категории:

#### А. Немедленный вызов (`call` и `apply`)
При вызове `func.call(context, ...args)` движок не создает новых функций в куче (`Heap`). Он приостанавливает выполнение текущего контекста, создает новый кадр стека (`Execution Context Stack`) для функции `func`, принудительно записывает переданный объект `context` в системный регистр `this` текущего кадра и немедленно передает управление интерпретатору. После завершения работы функции этот временный кадр уничтожается.

#### Б. Ленивое связывание (`bind`)
Метод `func.bind(context, ...args)` устроен сложнее. На уровне спецификации ECMAScript он возвращает так называемый **Bound Function Exotic Object (Экзотический объект привязанной функции)**. 

Этот объект создается в куче и содержит три скрытых системных слота (Internal Slots):
*   `[ [BoundTargetFunction] ]` — прямая ссылка на оригинальную функцию `func`.
*   `[ [BoundThis] ]` — ссылка на объект `context`, который мы привязали.
*   `[ [BoundArguments] ]` — массив аргументов, которые были зафиксированы при вызове `.bind()`.

Когда в будущем происходит вызов этой привязанной функции, движок V8 распознает её экзотическую природу, извлекает данные из скрытых слотов, конкатенирует (склеивает) аргументы из `[ [BoundArguments] ]` с новыми аргументами, переданными в момент вызова, подменяет регистр `this` значением из `[ [BoundThis] ]` и только после этого запускает оригинальный метод `[ [BoundTargetFunction] ]`.

### 2. Оптимизация передачи аргументов: apply против call и Spread-оператора
*   **Исторический аспект:** В старых версиях движков метод `.call()` работал нативно быстрее, чем `.apply()`. Это связано с тем, что при вызове `.apply()` движок был обязан выполнить дополнительную операцию: проитерироваться по массиву, выделить память в стеке под каждый элемент и скопировать значения.
*   **Современный JIT-компилятор (Turbofan):** В современном JavaScript вызов `func.call(context, ...args)` с использованием spread-оператора практически полностью вытеснил метод `.apply()`. Компилятор оптимизирует spread-синтаксис на лету, превращая его в эффективный низкоуровневый массив инструкций процессора. По производительности этот подход равен или превосходит `.apply()`, являясь при этом более безопасным и читаемым.

### 3. Детальный пошаговый разбор выполнения шаблона 3
Проследим шаги работы частичного применения аргументов в `executePartialApplication()`:

1.  **Создание экзотического объекта:** Вызывается `buildEndpoint.bind(null, "https", "eltex-co.ru")`. 
2.  **Заполнение слотов:** V8 создает объект в куче. В слот `[ [BoundTargetFunction] ]` записывается ссылка на тело функции `buildEndpoint`, в `[ [BoundThis] ]` пишется `null`, а в `[ [BoundArguments] ]` — массив `["https", "eltex-co.ru"]`. Ссылка на обертку сохраняется в `createSecureEltexLink`.
3.  **Вызов обертки:** Выполняется вызов `createSecureEltexLink("academy/blog")`.
4.  **Слияние аргументов:** Движок V8 видит, что вызываемый объект является экзотическим. Он берет массив из `[ [BoundArguments] ]` (`["https", "eltex-co.ru"]`), добавляет в конец переданный аргумент `"academy/blog"` и формирует итоговый набор параметров: `["https", "eltex-co.ru", "academy/blog"]`.
5.  **Запуск:** Движок запускает оригинальную функцию `buildEndpoint` с итоговым набором параметров, возвращая готовую строковую ссылку.

### 4. Типичные ошибки и их решение

#### Ошибка 1: Попытка повторной привязки (Re-binding) уже привязанной функции
*   **Симптомы:** Разработчик пытается изменить контекст у функции, которая ранее уже была привязана через `.bind()`, вызвав метод `.bind()` или `.call()` повторно. Изменение контекста игнорируется, и функция продолжает выполняться в контексте первой привязки.
*   **Физика процесса:** Экзотический объект привязанной функции при вызове всегда берет значение `this` строго из своего скрытого слота `[ [BoundThis] ]` первой привязки, игнорируя любые последующие слои оберток.
*   **Решение:** Не пытайтесь повторно привязывать функции. Если контекст должен меняться динамически, используйте обычные методы вызова через точку или `.call()`/`.apply()`.

```typescript
// ПЛОХО (Повторная привязка игнорируется рантаймом)
const initialContext = { value: "first_state" };
const secondaryContext = { value: "second_state" };

function logState(this: typeof initialContext) { console.log(this.value); }

const firstBound = logState.bind(initialContext);
const secondBound = firstBound.bind(secondaryContext);

secondBound(); // Выведет: "first_state" (Вторая привязка полностью проигнорирована!)
```

#### Ошибка 2: Одалживание методов (Method Borrowing) без учета внутренней структуры зависимостей
*   **Симптомы:** Разработчик одалживает метод у одного класса для объекта другого класса, но программа падает с критической ошибкой `TypeError: this.helper is not a function`.
*   **Физика процесса:** Вызов `.call()` успешно подменил контекст `this`. Однако внутри одалживаемого метода происходит обращение к другому методу класса (например, `this.helper()`), которого физически нет на целевом объекте-приемнике.
*   **Решение:** Перед одалживанием методов убедитесь, что целевой объект-приемник полностью реализует все интерфейсы, свойства и методы, к которым обращается одалживаемая функция.

```typescript
// ПЛОХО (Одалживание метода ломает программу, так как helper() отсутствует на badObject)
export class Processor {
  public helper() { return 10; }
  public compute(this: Processor, x: number) { return x + this.helper(); }
}
const badObject = { value: 5 };
// const res = Processor.prototype.compute.call(badObject, 2); // ! TypeError: this.helper is not a function
```

#### Ошибка 3: Неявная замена контекста на глобальный объект в нестрогом режиме (Sloppy Mode)
*   **Симптомы:** Передача `null` или `undefined` в качестве контекста в `.call()` приводит к тому, что функция начинает неконтролируемо перезаписывать глобальные свойства объекта `window` или `globalThis`.
*   **Физика процесса:** В обычном нестрогом режиме (sloppy mode) движок JS принудительно заменяет переданные `null` или `undefined` в качестве контекста на глобальный объект `window`. Это приводит к случайному загрязнению глобальной памяти.
*   **Решение:** Всегда пишите код в строгом режиме `"use strict"` (в TypeScript он включен по умолчанию). В строгом режиме передача `null`/`undefined` запишет в `this` именно `null`/`undefined`, защищая глобальную память.

```javascript
// ПЛОХО (В нестрогом режиме перезапишет window.dataState)
function modifyGlobal(val) {
  this.dataState = val; // В sloppy mode создаст глобальную переменную window.dataState!
}
// modifyGlobal.call(null, "broken"); 
```
