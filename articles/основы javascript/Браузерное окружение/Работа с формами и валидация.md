# Работа с формами и валидация

## БЫСТРЫЙ СТАРТ

*   **Формы (HTMLFormElement)** — специализированный интерфейс для сбора данных, предоставляющий быстрый доступ к элементам через коллекцию `form.elements` по атрибуту `name`.
*   **Событие `submit`** — генерируется на уровне формы в момент отправки. Обработчик обязан вызывать `event.preventDefault()` для отмены стандартной перезагрузки страницы браузером и запуска асинхронной AJAX/Fetch отправки.
*   **Constraint Validation API** — встроенный стандарт браузера для проверки данных на основе HTML5-атрибутов (`required`, `pattern`, `type`), предоставляющий детальные маркеры ошибок через объект `ValidityState`.
*   **События ввода:** Событие `input` срабатывает мгновенно при любом изменении текста в поле (используется для "живой" валидации); событие `change` срабатывает только при фиксации изменений (при потере фокуса для текстовых полей).
*   **Когда использовать:** Для сбора, валидации, маскирования и отправки пользовательских данных на бэкенд.
*   **Когда НЕ использовать:** Избегайте прямого вызова метода `form.submit()` из JS, если на форме висят обработчики события `submit` — этот программный вызов отправляет данные на сервер напрямую, обходя событие отправки.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: "Живая" валидация полей ввода через `ValidityState`
*   **Назначение:** Отслеживание ввода пользователя в реальном времени, установка кастомных сообщений об ошибках и динамический вывод предупреждений.

```typescript
export interface ValidationResult {
  isValid: boolean;
  errorMessage: string;
}

export function initializeLiveValidation(formName: string, inputName: string): void {
  // Получаем доступ к форме из глобальной коллекции document.forms по имени
  const form = document.forms.namedItem(formName) as HTMLFormElement | null;
  if (!form) return;

  // Извлекаем конкретное поле ввода по его атрибуту name из коллекции elements
  const emailInput = form.elements.namedItem(inputName) as HTMLInputElement | null;
  const errorFeedback = form.querySelector(".email-error-feedback") as HTMLElement | null;

  if (!emailInput || !errorFeedback) return;

  // Слушаем мгновенное событие 'input' на каждый введенный символ
  emailInput.addEventListener("input", (): void => {
    // 1. Анализируем встроенный объект validity (Constraint Validation API)
    if (emailInput.validity.valueMissing) {
      // Устанавливаем кастомное сообщение об ошибке. Поле автоматически помечается как невалидное.
      emailInput.setCustomValidity("Пожалуйста, заполните это поле. Почта обязательна.");
    } else if (emailInput.validity.typeMismatch) {
      emailInput.setCustomValidity("Введенный адрес не соответствует формату электронной почты.");
    } else {
      // КРИТИЧЕСКИ ВАЖНО: Сбрасываем ошибку пустой строкой, чтобы вернуть полю статус валидного
      emailInput.setCustomValidity("");
    }

    // 2. Отображаем результат проверки пользователю
    if (!emailInput.validity.valid) {
      errorFeedback.textContent = emailInput.validationMessage;
      errorFeedback.classList.remove("hidden");
      emailInput.classList.add("invalid-border");
    } else {
      errorFeedback.textContent = "";
      errorFeedback.classList.add("hidden");
      emailInput.classList.remove("invalid-border");
    }
  });
}
```

### Шаблон 2: Делегирование фокуса на форме через события `focusin` / `focusout`
*   **Назначение:** Стилизация и подсветка активных полей формы на основе одного общего обработчика фокуса, работающего благодаря механизму всплытия.

```typescript
export function setupFormFocusDelegation(formSelector: string): void {
  const form: HTMLFormElement | null = document.querySelector(formSelector);
  if (!form) return;

  // Поскольку стандартные события focus/blur не всплывают, 
  // мы используем их всплывающие аналоги focusin/focusout.
  form.addEventListener("focusin", (event: FocusEvent): void => {
    const target = event.target as HTMLElement;
    
    // Подсвечиваем только текстовые поля ввода при получении фокуса
    if (target.matches("input[type='text'], input[type='email'], textarea")) {
      target.classList.add("active-focus-highlight");
    }
  });

  form.addEventListener("focusout", (event: FocusEvent): void => {
    const target = event.target as HTMLElement;
    
    if (target.matches("input[type='text'], input[type='email'], textarea")) {
      target.classList.remove("active-focus-highlight");
    }
  });
}
```

### Шаблон 3: Сбор данных через `FormData` и асинхронный AJAX-Submit
*   **Назначение:** Перехват отправки формы, валидация всех полей, сбор данных в один пакет и асинхронная отправка по сети.

```typescript
export interface ResponsePayload {
  success: boolean;
  message: string;
}

export function setupAsyncSubmit(formSelector: string, endpointUrl: string): void {
  const form: HTMLFormElement | null = document.querySelector(formSelector);
  if (!form) return;

  form.addEventListener("submit", async (event: SubmitEvent): Promise<void> => {
    // 1. Отменяем стандартную отправку и перезагрузку страницы браузером
    event.preventDefault();

    // 2. Проверяем валидность всей формы перед отправкой
    if (!form.checkValidity()) {
      console.warn("[VALIDATION FAILED] Форма содержит ошибки.");
      return;
    }

    const submitButton = form.querySelector("button[type='submit']") as HTMLButtonElement | null;
    if (submitButton) submitButton.disabled = true; // Блокируем кнопку на время запроса

    try {
      // 3. Автоматически собираем все поля формы (включая файлы) с помощью FormData
      const payloadData = new FormData(form);

      // Выполняем асинхронный Fetch-запрос
      const response = await fetch(endpointUrl, {
        method: "POST",
        body: payloadData
      });

      if (!response.ok) {
        throw new Error(`Сетевой сбой. Статус: ${response.status}`);
      }

      const result = (await response.json()) as ResponsePayload;
      console.log("[SUBMIT SUCCESS] Ответ сервера:", result);
      form.reset(); // Сбрасываем форму при успешной отправке

    } catch (error) {
      console.error("[SUBMIT ERROR] Ошибка при отправке формы:", error);
    } finally {
      if (submitButton) submitButton.disabled = false;
    }
  });
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Constraint Validation API и устройство объекта `ValidityState`
Встроенный в браузер механизм Constraint Validation API выполняет проверку полей на низком уровне силами самого браузера, не нагружая поток JavaScript ручными регулярными выражениями.

Каждое интерактивное поле ввода содержит свойство `validity`, ссылающееся на объект класса `ValidityState`. Этот объект состоит из набора только для чтения булевых флагов-маркеров:

*   `valueMissing` — `true`, если поле помечено атрибутом `required`, но осталось пустым.
*   `typeMismatch` — `true`, если введенный текст не соответствует типу поля (например, неверный формат в `type="email"` или `type="url"`).
*   `patternMismatch` — `true`, если текст не совпадает с регулярным выражением, указанным в атрибуте `pattern`.
*   `tooShort` / `tooLong` — `true`, если длина текста выходит за границы, заданные атрибутами `minlength` / `maxlength`.
*   `rangeUnderflow` / `rangeOverflow` — `true`, если числовое значение выходит за рамки `min` / `max`.
*   `customError` — `true`, если для поля была установлена кастомная ошибка через метод `setCustomValidity()`.
*   `valid` — результирующий флаг. Он равен `true` только в том случае, если все остальные флаги-ошибки равны `false`.

### 2. Специфика всплытия: `focus`/`blur` против `focusin`/`focusout`
При организации работы с формами критически важно понимать поведение событий фокусировки:
*   События **`focus`** и **`blur`** по спецификации W3C **не всплывают** (они проходят только фазы погружения и цели). Если вы установите обработчик `form.addEventListener("focus", handler)`, он никогда не сработает при фокусе на внутренних инпутах, так как событие не поднимется до формы.
*   События **`focusin`** и **`focusout`** являются современными аналогами, которые полностью идентичны по смыслу, но при этом **успешно всплывают**. Это позволяет использовать паттерн делегирования и вешать один компактный обработчик фокуса на уровне всей формы.

### 3. Жизненный цикл обработки и отправки формы

```text
  Пользователь нажимает кнопку Submit
                   │
                   ▼
       Генерируется событие 'submit' на форме
                   │
                   ▼
       Запуск event.preventDefault() (Отмена перезагрузки)
                   │
                   ▼
  Вызов checkValidity() (Браузерная проверка полей по ValidityState)
        ├── Не валидна ──► Отображение ошибок ──► Остановка
        └── Валидна
                   │
                   ▼
  Сбор данных через new FormData(form)
                   │
                   ▼
  Асинхронная отправка по сети через fetch() -> Сервер
```

### 4. Детальный пошаговый разбор выполнения шаблона 3
1.  **Клик на Submit:** Пользователь заполняет форму и кликает на кнопку отправки. На объекте `HTMLFormElement` генерируется событие `submit`.
2.  **Перехват события:** Срабатывает асинхронный обработчик. Первой строчкой выполняется `event.preventDefault()`. Это останавливает дефолтный браузерный процесс отправки POST-запроса на адрес `action` и защищает страницу от перезагрузки.
3.  **Валидация полей:** Выполняется `form.checkValidity()`. Метод обходит все элементы коллекции `elements`. Если натыкается на невалидный инпут, генерирует на нем событие `invalid`, прерывает метод и возвращает `false`.
4.  **Сбор данных:** Создается экземпляр `new FormData(form)`. Конструктор сканирует форму и собирает все пары `name: value` для заполненных элементов. Если на форме были элементы `<input type="file">`, они кодируются и добавляются в тело запроса как бинарные данные.
5.  **Запрос:** Выполняется метод `fetch()`. Браузер отправляет асинхронный HTTP-запрос с типом контента `multipart/form-data`.

### 5. Типичные ошибки и их решение

*   **Ошибка 1: Пропуск `event.preventDefault()` в обработчике `submit`**
    *   *Симптомы:* При клике на кнопку отправки страница на долю секунды мигает, полностью перезагружается, а все локальное состояние JavaScript-приложения стирается и сбрасывается к начальному.
    *   *Причина:* Без вызова `preventDefault()` браузер выполняет свое дефолтное действие — собирает данные и отправляет их синхронным GET/POST запросом на текущий URL (или на адрес из атрибута `action`), перезагружая вкладку.
    *   *Решение:* Всегда вызывайте `event.preventDefault()` на первой строчке обработчика отправки формы.

```typescript
// ПЛОХО (страница перезагрузится, JS-код прервется)
form.addEventListener("submit", () => {
  this.sendData();
});

// ХОРОШО (стандартное поведение полностью отменено)
form.addEventListener("submit", (event: SubmitEvent) => {
  event.preventDefault();
  this.sendData();
});
```

*   **Ошибка 2: Бесконечный цикл при программном вызове `form.submit()` из обработчика**
    *   *Симптомы:* Браузер зависает, вкладка уходит в бесконечный цикл вызовов или падает с ошибкой переполнения стека (Stack Overflow).
    *   *Причина:* Разработчик перехватывает событие `submit`, делает валидацию и в случае успеха пытается отправить форму программно, вызывая `form.submit()`. Если для этого используется ручная отправка события, это заново триггерит обработчик `submit`, уходя в бесконечную рекурсию.
    *   *Решение:* Программный метод `form.submit()` отправляет форму напрямую, минуя обработчик `submit`. Если вам нужно отправить данные асинхронно, используйте Fetch API, не вызывая метод `submit()` вручную. Если же вам действительно нужно отправить форму классическим синхронным методом после проверок, вызывайте нативный метод `form.submit()` на самом HTML-элементе, предварительно сняв слушатель событий.

```typescript
// ПЛОХО (бесконечный цикл, если вызывать отправку события внутри)
form.addEventListener("submit", (e) => {
  e.preventDefault();
  if (isValid) form.dispatchEvent(new Event("submit")); // Рекурсия!
});

// ХОРОШО (асинхронная отправка данных без перезагрузки и рекурсий)
form.addEventListener("submit", async (e) => {
  e.preventDefault();
  if (isValid) {
    await fetch("/api", { method: "POST", body: new FormData(form) });
  }
});
```

*   **Ошибка 3: Блокировка валидации из-за "зависшего" сообщения `setCustomValidity`**
    *   *Симптомы:* Поле ввода было заполнено корректно, но форма по-прежнему считает его невалидным и отказывается отправляться, выводя старую ошибку.
    *   *Причина:* Метод `setCustomValidity("ошибка")` устанавливает для поля внутренний флаг `customError: true`. Это состояние сохраняется до тех пор, пока не будет вызван метод очистки. Если при успешном исправлении ошибки разработчик не вызвал очистку, поле останется в невалидном статусе навсегда.
    *   *Решение:* При прохождении проверки обязательно сбрасывайте кастомную ошибку, вызывая метод с пустой строкой `setCustomValidity("")`.

```typescript
// ПЛОХО (поле навсегда останется невалидным после первой же ошибки)
if (input.value.length < 3) {
  input.setCustomValidity("Слишком короткое значение.");
}

// ХОРОШО (ошибка сбрасывается, возвращая полю статус валидного)
if (input.value.length < 3) {
  input.setCustomValidity("Слишком короткое значение.");
} else {
  input.setCustomValidity(""); // Сброс
}
```
