# События и их обработка в DOM

## БЫСТРЫЙ СТАРТ

*   **Событие** — это отправляемый браузером асинхронный сигнал о том, что на веб-странице произошло определенное действие (клик, прокрутка, ввод текста, полная загрузка страницы).
*   **Метод `addEventListener()`** — современный стандарт регистрации слушателей, поддерживающий назначение множества независимых обработчиков на одно событие, управление фазами распространения и безопасное удаление через `removeEventListener()`.
*   **Жизненный цикл события** проходит три последовательные фазы: погружение (Capturing), фаза цели (Target) и всплытие (Bubbling). Большинство обработчиков по умолчанию работают на фазе всплытия.
*   **Делегирование событий** — ключевой паттерн оптимизации производительности, при котором один обработчик вешается на родительский узел для централизованной обработки событий на всех его дочерних элементах.
*   **Когда использовать:** Для любого интерактивного взаимодействия пользователя с интерфейсом страницы.
*   **Когда НЕ использовать:** Избегайте назначения индивидуальных обработчиков на сотни однотипных элементов списков (всегда применяйте делегирование на общем контейнере).

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Паттерн делегирования событий с методом `closest()`
*   **Назначение:** Оптимизация памяти за счет установки одного слушателя на родительский контейнер для обработки кликов по динамически создаваемым дочерним элементам.

```typescript
export interface ActionPayload {
  nodeId: string;
  actionType: string;
}

export function initializeDelegatedMenu(containerSelector: string): void {
  const container: HTMLElement | null = document.querySelector(containerSelector);

  if (!container) {
    console.error(`[EVENTS ERROR] Родительский контейнер "${containerSelector}" не найден.`);
    return;
  }

  // Вешаем один обработчик на весь родительский контейнер
  container.addEventListener("click", (event: MouseEvent): void => {
    const target = event.target as HTMLElement;

    // Ищем ближайшую кнопку с нужным классом вверх по дереву от места клика.
    // Это гарантирует корректную работу, даже если кликнули по иконке внутри кнопки.
    const actionButton = target.closest(".menu-action-btn") as HTMLElement | null;

    // Если кликнули мимо кнопок действия или вне контейнера, игнорируем событие
    if (!actionButton || !container.contains(actionButton)) {
      return;
    }

    // Считываем data-атрибуты для определения параметров действия
    const payload: ActionPayload = {
      nodeId: actionButton.dataset.id || "unknown",
      actionType: actionButton.dataset.action || "default"
    };

    console.log(`[DELEGATION SUCCESS] Выполнено действие "${payload.actionType}" на узле "${payload.nodeId}"`);
  });
}
```

### Шаблон 2: Безопасное подавление поведения по умолчанию и всплытия
*   **Назначение:** Предотвращение стандартного поведения браузера (например, перезагрузки при отправке формы) и изоляция события внутри компонента.

```typescript
export function setupSecureFormHandler(formSelector: string): void {
  const form: HTMLFormElement | null = document.querySelector(formSelector);

  if (!form) return;

  form.addEventListener("submit", (event: SubmitEvent): void => {
    // 1. Отменяем стандартную отправку формы и перезагрузку страницы браузером
    event.preventDefault();

    // 2. Останавливаем дальнейшее всплытие события к родительским контейнерам.
    // Это защищает внешние глобальные клик-трекеры от ложного срабатывания.
    event.stopPropagation();

    console.log("[EVENTS SUCCESS] Форма обработана локально через AJAX-транзакцию.");
  });
}
```

### Шаблон 3: Генерация и обработка пользовательских событий (`CustomEvent`)
*   **Назначение:** Создание независимых UI-компонентов, которые общаются между собой посредством отправки кастомных сигналов с полезной нагрузкой.

```typescript
export interface ChatNotification {
  messageText: string;
  senderName: string;
}

export function emitNewMessageNotification(widgetElement: HTMLElement, payload: ChatNotification): void {
  // Создаем пользовательское событие. 
  // Полезная нагрузка обязательно передается внутри свойства detail.
  const customEvent = new CustomEvent<ChatNotification>("chat:new-message", {
    detail: payload,
    bubbles: true,     // Разрешаем всплытие события вверх по DOM-дереву
    cancelable: true   // Разрешаем отмену события через preventDefault
  });

  // Инициируем вызов события на конкретном DOM-элементе
  widgetElement.dispatchEvent(customEvent);
}

export function listenGlobalNotifications(): void {
  // Благодаря bubbles: true мы можем поймать событие на уровне всего документа
  document.addEventListener("chat:new-message", (event: Event): void => {
    // Приводим событие к типу CustomEvent со строгим указанием типа полезной нагрузки
    const customEvent = event as CustomEvent<ChatNotification>;
    
    const { senderName, messageText } = customEvent.detail;
    console.log(`[CUSTOM EVENT] Сообщение от ${senderName}: "${messageText}"`);
  });
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Жизненный цикл события: Capturing, Target и Bubbling
Каждое событие в DOM проходит три последовательные фазы в строгом порядке, определенном спецификацией W3C:

```text
               Фаза Погружения (1. Capturing Phase)
             [ window ]  ─────────────────────────┐
                 │                                │
                 ▼                                │
            [ document ]                          │
                 │                                │
                 ▼                                │
             [ body ]                             ▼
                 │                         Фаза Всплытия (3. Bubbling Phase)
                 ▼                                │
              [ div ]                             │
                 │                                │
                 +───────► [ button ] ────────────┘
                    Фаза Цели (2. Target Phase)
```

1.  **Фаза погружения (Capturing Phase):** Событие спускается от корня (`window`, `document`) вниз по иерархическому дереву к элементу, который инициировал действие. По умолчанию обработчики, добавленные через `addEventListener`, игнорируют эту фазу. Чтобы поймать событие на погружении, нужно передать флаг в третий параметр метода: `addEventListener("click", handler, true)` или `{ capture: true }`.
2.  **Фаза цели (Target Phase):** Событие достигает самого глубокого целевого элемента, на котором произошло действие. На этой фазе срабатывают все обработчики, установленные на самом элементе.
3.  **Фаза всплытия (Bubbling Phase):** Событие начинает подниматься обратно по цепочке родителей от целевого элемента к корню. Большинство стандартных событий браузера (клик, ввод, нажатие клавиш) всплывают. Это фаза по умолчанию для всех слушателей.

### 2. Свойства `target` и `currentTarget` на уровне движка V8
Внутри обработчика событий объект `Event` предоставляет два важнейших свойства, которые часто путают:
*   **`event.target`** — это ссылка на *целевой элемент*, который изначально инициировал событие (самый глубокий тег в DOM-дереве, на который пришелся физический клик). Это свойство остается стабильным и не меняется по мере всплытия события.
*   **`event.currentTarget`** — это ссылка на элемент, на котором в данный момент *выполняется текущий обработчик* (тот элемент, на который был непосредственно повешен метод `addEventListener`). По мере всплытия события значение `currentTarget` динамически обновляется движком.

### 3. Детальный пошаговый разбор выполнения шаблона 1
Разберем клик по иконке `<i>`, находящейся внутри кнопки `.menu-action-btn`:
1.  **Клик пользователя:** Пользователь кликает по иконке. Движок V8 определяет целевой элемент. `event.target` ссылается на `HTMLStyleElement` (`<i>`).
2.  **Проход фаз:** Событие погружается к иконке, затем начинает всплывать. Оно достигает родительского контейнера меню, на котором установлен общий обработчик.
3.  **Вызов обработчика:** Запускается функция-колбэк. `event.currentTarget` ссылается на сам контейнер.
4.  **Поиск кнопки:** Вызывается `target.closest(".menu-action-btn")`. Метод `closest` проверяет текущий элемент `<i>`. Тот не имеет нужного класса. Метод поднимается к родителю — кнопке `<button class="menu-action-btn">`. Класс совпадает. Переменная `actionButton` получает ссылку на кнопку.
5.  **Валидация:** Проверяется условие `container.contains(actionButton)`. Кнопка находится внутри меню. Проверка пройдена.
6.  **Выполнение логики:** Извлекаются `data`-атрибуты, выводится лог. Работа обработчика успешно завершена.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Потеря контекста `this` при передаче метода класса в качестве обработчика**
    *   *Симптомы:* При срабатывании события внутри метода класса `this` равен `undefined` (в строгом режиме) или ссылается на DOM-элемент вместо экземпляра вашего класса, вызывая ошибку при попытке прочитать свойства.
    *   *Причина:* Когда вы передаете метод класса по ссылке (`btn.addEventListener("click", this.handleClick)`), связь метода с объектом разрушается. Метод вызывается как простая изолированная функция в контексте DOM-элемента.
    *   *Решение:* Оборачивайте вызов метода в анонимную стрелочную функцию или привязывайте контекст жестко через `.bind(this)`.

```typescript
export class ClickManager {
  private counter = 0;

  public setup(btn: HTMLButtonElement): void {
    // ПЛОХО (this.counter внутри handleClick вызовет ошибку)
    btn.addEventListener("click", this.handleClick);

    // ХОРОШО (стрелочная функция сохраняет лексический контекст класса)
    btn.addEventListener("click", () => this.handleClick());
  }

  private handleClick(): void {
    this.counter++;
    console.log(`Кликов: ${this.counter}`);
  }
}
```

*   **Ошибка 2: Накопление утечек памяти из-за анонимных функций**
    *   *Симптомы:* Потребление оперативной памяти вкладки непрерывно растет, приложение начинает зависать после частого создания и удаления UI-компонентов.
    *   *Причина:* Разработчик вешает слушатели с анонимными функциями, но при удалении компонента из DOM забывает снять их. Поскольку анонимные функции не имеют имени, на них невозможно сослаться в методе `removeEventListener()`. Ссылка на функцию и переменные из ее замыкания остаются жить в памяти навечно.
    *   *Решение:* Сохраняйте ссылку на функцию в свойство класса или переменную и обязательно вызывайте `removeEventListener()` при уничтожении компонента.

```typescript
// ПЛОХО (слушатель невозможно удалить из памяти)
element.addEventListener("scroll", () => { this.handleScroll(); });

// ХОРОШО (контролируемое удаление по ссылке)
private scrollListener = (): void => this.handleScroll();

public init(): void {
  element.addEventListener("scroll", this.scrollListener);
}

public destroy(): void {
  element.removeEventListener("scroll", this.scrollListener);
}
```

*   **Ошибка 3: Бездумное использование `stopPropagation()`**
    *   *Симптомы:* Ломается работа внешних сторонних библиотек (например, выпадающие меню не закрываются при клике вовне, или перестают работать системы веб-аналитики Yandex.Metrika / Google Analytics).
    *   *Причина:* Метод `stopPropagation()` намертво блокирует всплытие события. Из-за этого глобальные обработчики на уровне `document` или `body`, которые слушают клики для аналитики или закрытия модальных окон, никогда не увидят совершенный пользователем клик.
    *   *Решение:* Вместо полной блокировки всплытия проверяйте `event.target` на уровне родителя, либо используйте флаги-маркеры внутри объекта события.

```typescript
// ПЛОХО (сломает глобальную аналитику на странице)
btn.addEventListener("click", (e) => {
  e.stopPropagation(); 
  this.doAction();
});

// ХОРОШО (анализируем целевой элемент без блокировки всплытия)
document.addEventListener("click", (e) => {
  const target = e.target as HTMLElement;
  if (target.closest(".my-modal")) return; // Игнорируем клики внутри модалки
  this.closeModal(); // Закрываем при клике вовне
});
```
