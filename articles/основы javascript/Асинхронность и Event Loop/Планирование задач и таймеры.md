# Планирование задач и таймеры

## БЫСТРЫЙ СТАРТ

*   **Планирование выполнения (scheduling)** — это механизм отложенного запуска функций на определенное время или регулярного циклического выполнения задач силами браузерного окружения.
*   **Метод `setTimeout`** — запускает переданную функцию-коллбэк один раз после того, как пройдет указанная задержка в миллисекундах. Возвращает числовой идентификатор таймера.
*   **Метод `setInterval`** — регулярно и бесконечно перезапускает функцию-коллбэк через строго заданные равные интервалы времени.
*   **Используйте для:**
    *   Реализации плавных анимаций, фоновых опросов серверов (polling) и некритичных отложенных обновлений интерфейса.
    *   Реализации таймаутов для сетевых запросов и механизмов экспоненциального отката (exponential backoff).
*   **Не используйте для:**
    *   Сценариев, требующих точной синхронизации времени выполнения (таймеры в JS не гарантируют запуск миллисекунда в миллисекунду из-за однопоточности событийного цикла).
    *   Сложной анимации интерфейсов (для обеспечения высокой плавности и синхронизации с частотой обновления экрана 60fps/120fps используйте `requestAnimationFrame`).

### Шаблон 1: Рекурсивный `setTimeout` с динамической задержкой (Экспоненциальный откат)
*   **Назначение:** Опрос сервера с увеличивающимся интервалом ожидания при ошибках связи для защиты бэкенда от перегрузки.

```typescript
export interface PollResult {
  status: "pending" | "completed";
  data?: any;
}

export class ExponentialPoller {
  private timerId: number | null = null;
  private attempt = 0;

  constructor(private readonly maxAttempts = 5) {}

  public startPolling(): void {
    this.attempt = 0;
    this.executePollStep();
  }

  private executePollStep(): void {
    console.log(`[ОПРОС] Попытка №${this.attempt + 1}...`);

    // Имитируем сетевую асинхронную операцию
    this.fakeFetch().then((result: PollResult) => {
      if (result.status === "completed") {
        console.log("Данные успешно получены, опрос завершен.");
        this.stop();
        return;
      }

      this.attempt++;
      if (this.attempt >= this.maxAttempts) {
        console.warn("Превышено максимальное число попыток опроса.");
        this.stop();
        return;
      }

      // Вычисляем динамическую задержку: 1000мс, 2000мс, 4000мс, 8000мс...
      const nextDelay = Math.pow(2, this.attempt) * 1000;
      console.log(`Ожидание следующего шага: ${nextDelay} мс.`);

      // Рекурсивно планируем следующий шаг ПОСЛЕ полного завершения текущего
      this.timerId = window.setTimeout(() => this.executePollStep(), nextDelay);
    });
  }

  public stop(): void {
    if (this.timerId !== null) {
      window.clearTimeout(this.timerId);
      this.timerId = null;
    }
  }

  private fakeFetch(): Promise<PollResult> {
    return Promise.resolve({ status: "pending" });
  }
}
```

### Шаблон 2: Очистка таймеров для предотвращения утечек памяти
*   **Назначение:** Реализация надежного механизма очистки циклических интервалов при уничтожении содержащего их UI-компонента или виджета.

```typescript
export class LiveClockWidget {
  private intervalId: number | null = null;
  private secondsElapsed = 0;

  public init(container: HTMLElement): void {
    this.secondsElapsed = 0;

    // Запускаем циклический интервал
    this.intervalId = window.setInterval(() => {
      this.secondsElapsed++;
      container.textContent = `Время сессии: ${this.secondsElapsed} сек.`;

      // Пример внутренней самоочистки при достижении лимита
      if (this.secondsElapsed >= 3600) {
        this.destroy();
      }
    }, 1000); // Срабатывание каждую секунду
  }

  public destroy(): void {
    // Критически важно: удаляем интервал из памяти Web APIs при деструкции виджета
    // Если этого не сделать, замыкание функции и ссылка на container останутся жить в памяти вечно
    if (this.intervalId !== null) {
      window.clearInterval(this.intervalId);
      this.intervalId = null;
      console.log("[WIDGET] Фоновые таймеры успешно очищены.");
    }
  }
}
```

### Шаблон 3: Использование нулевого таймаута для отложенного рендеринга
*   **Назначение:** Перенос тяжелой операции в конец очереди макрозадач для предотвращения зависания текущего потока и разблокировки визуальной отрисовки UI.

```typescript
export function renderLargeListDeferred(items: string[], container: HTMLElement): void {
  console.log("1. Инициация рендеринга...");

  // Обычный синхронный рендеринг миллионов элементов заблокировал бы поток на секунды
  // Используем setTimeout(f, 0) для переноса задачи в макроочередь
  window.setTimeout(() => {
    // Этот код выполнится строго ПОСЛЕ того, как браузер завершит текущие отрисовки
    console.log("3. Начало сборки элементов в фоне...");
    
    const fragment = document.createDocumentFragment();
    items.forEach(item => {
      const li = document.createElement("li");
      li.textContent = item;
      fragment.appendChild(li);
    });
    container.appendChild(fragment);
    
    console.log("4. Рендеринг в DOM завершен.");
  }, 0);

  // Код ниже выполнится незамедлительно, не дожидаясь рендеринга списка
  console.log("2. Основной поток разблокирован. Браузер может отрисовать лоадер.");
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как движок JavaScript и Web APIs координируют таймеры
Движок JavaScript (например, V8) сам по себе не умеет отсчитывать время и не содержит механизмов планирования — он абсолютно синхронен и имеет лишь один Call Stack. Таймеры являются частью окружения браузера (**Web APIs**).

Процесс координации шагов при вызове `setTimeout(f, 1000)`:
1.  **Регистрация:** Движок V8 встречает инструкцию `setTimeout`. Поскольку это метод глобального объекта `window`, V8 делегирует выполнение браузеру (Web APIs), передавая ему ссылку на колбэк `f` и задержку `1000`. Сама строка `setTimeout` мгновенно завершается и выталкивается из Call Stack.
2.  **Отсчет времени:** Сетевой или системный таймер Web APIs в фоновом режиме (параллельно основному потоку) начинает отсчет 1000 миллисекунд.
3.  **Перенос в очередь:** По истечении 1000 мс Web APIs перемещает ссылку на колбэк `f` в **Очередь макрозадач (Macrotask Queue)**. В этот момент функция еще не выполняется.
4.  **Событийный цикл:** Диспетчер **Event Loop** непрерывно проверяет состояние Call Stack. Как только Call Stack полностью освобождается (весь синхронный код выполнен) и очередь микрозадач становится пустой, Event Loop извлекает первую макрозадачу `f` из очереди и помещает ее в Call Stack для компиляции и выполнения.

### 2. Спецификация задержек, зажимы (clamping) и фоновые вкладки
Реальное время задержки таймеров регулируется строгими стандартами HTML5 и оптимизациями браузеров:

*   **Зажим вложенных вызовов (Timer Clamping):**
    По спецификации HTML5, если в коде происходит цепочка из более чем 5 последовательных вложенных (рекурсивных) вызовов `setTimeout` (или интервал `setInterval` работает дольше 5 тактов), браузер принудительно увеличивает минимально возможную задержку до **`4 мс`**. Даже если вы явно укажете `0` или `1` миллисекунду, V8 выполнит ограничение и установит задержку в `4 мс` для экономии энергии процессора.
*   **Замораживание фоновых вкладок (Throttling):**
    Для сохранения ресурса батареи ноутбуков и мобильных устройств современные браузеры принудительно зажимают частоту выполнения таймеров на неактивных (свернутых) вкладках. Минимальная задержка на фоновой вкладке автоматически увеличивается до **`1000 мс` (1 секунда)**, а в некоторых агрессивных режимах энергосбережения таймеры могут полностью останавливаться до возвращения пользователя на вкладку.

### 3. Детальный пошаговый разбор выполнения шаблона 1
Рассмотрим пошаговую физику выполнения рекурсивного таймаута:
1.  **Шаг 1:** Метод `executePollStep()` запускается. Он вызывает асинхронный метод `fakeFetch()`, возвращающий промис.
2.  **Шаг 2:** Промис разрешается. В очереди микрозадач регистрируется колбэк обработки ответа `.then()`.
3.  **Шаг 3:** Call Stack освобождается, микрозадача запускается. Условие `result.status === "completed"` ложно. Переменная `attempt` увеличивается до 1.
4.  **Шаг 4:** Вычисляется `nextDelay = 2000` мс.
5.  **Шаг 5:** Вызывается `window.setTimeout(() => this.executePollStep(), 2000)`. Браузер регистрирует таймер на 2 секунды. Шаг `executePollStep` завершается, Call Stack пуст.
6.  **Шаг 6 (Спустя 2 секунды):** Таймер Web APIs завершает работу, анонимная функция `() => this.executePollStep()` уходит в очередь макрозадач.
7.  **Шаг 7:** Event Loop видит свободный стек, перемещает анонимную функцию в Call Stack. Она запускается и инициирует новый вызов метода `executePollStep()`, возобновляя весь цикл на новой итерации.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Эффект «наползания» и зависание интерфейса в `setInterval`**
    *   *Проблема:* Разработчик использует `setInterval(heavyTask, 100)` для регулярного запуска асинхронной задачи. Через некоторое время вкладка браузера зависает или потребляет 100% мощности процессора.
    *   *Причина:* `setInterval` запускает отсчет времени строго от начала предыдущего запуска, не дожидаясь его завершения. Если выполнение `heavyTask` заняло 150 мс, то к моменту окончания работы функции очередь макрозадач уже будет содержать новое готовое событие запуска. Вызовы начинают выполняться без пауз один за другим, полностью забивая Call Stack.
    *   *Решение:* Замените `setInterval` на рекурсивный вызов `setTimeout`. Следующий шаг запланируется только тогда, когда текущий полностью завершит свою работу.

```typescript
// ПЛОХО (Вызовы наползают друг на друга, если функция выполняется дольше 100мс)
export function runUnsafeInterval() {
  setInterval(() => {
    // Имитируем тяжелую операцию, блокирующую поток на 150мс
    const end = Date.now() + 150;
    while (Date.now() < end) {}
    console.log("Интервал сработал");
  }, 100);
}

// ХОРОШО (Рекурсивный таймаут гарантирует паузу ровно в 100мс между запусками)
export function runSafeInterval() {
  function step() {
    const end = Date.now() + 150;
    while (Date.now() < end) {}
    console.log("Шаг выполнен безопасным таймаутом");
    
    // Планируем следующий шаг только после того, как текущий завершен
    setTimeout(step, 100);
  }
  
  setTimeout(step, 100);
}
```

*   **Ошибка 2: Утечки памяти из-за неочищенных интервалов и замыканий**
    *   *Проблема:* Компонент удаляется со страницы, но в памяти продолжают висеть тяжелые объекты, связанные с этим компонентом.
    *   *Причина:* Запущенный `setInterval` удерживает ссылку на функцию-коллбэк в Web APIs. Функция-коллбэк через замыкание удерживает ссылки на локальные переменные, методы и DOM-элементы компонента. Сборщик мусора не может их удалить, так как они остаются досягаемыми из Web APIs.
    *   *Решение:* Всегда сохраняйте `timerId` и явно вызывайте `clearTimeout` / `clearInterval` при уничтожении компонентов.

```typescript
// ПЛОХО (Утечка памяти: после удаления кнопки интервал продолжит жить в памяти)
export function leakMemoryInWidget(button: HTMLButtonElement) {
  let counter = 0;
  setInterval(() => {
    counter++;
    button.textContent = `Кликнуто раз: ${counter}`; // Ссылка на button вечно жива
  }, 1000);
}

// ХОРОШО (Использование механизма очистки)
export function runSafeWidget(button: HTMLButtonElement): () => void {
  let counter = 0;
  const intervalId = setInterval(() => {
    counter++;
    button.textContent = `Кликнуто раз: ${counter}`;
  }, 1000);

  // Возвращаем функцию очистки (Tear-down)
  return () => {
    clearInterval(intervalId);
  };
}
```

*   **Ошибка 3: Передача строк вместо функций в параметры планировщика**
    *   *Проблема:* Использование синтаксиса `setTimeout("console.log('Сбой')", 1000)`. Программа работает медленно или не проходит проверки безопасности.
    *   *Причина:* Передача строки принуждает движок JS запустить внутренний транслятор и выполнить динамическую компиляцию (аналогично вызову `eval`), что блокирует оптимизации V8 и повышает уязвимость приложения перед XSS-инъекциями.
    *   *Решение:* Передавайте исключительно анонимные функции или ссылки на существующие методы.

```typescript
// ПЛОХО (Динамический eval-парсинг строки компилятором)
// @ts-ignore
setTimeout("console.log('Небезопасная компиляция')", 1000);

// ХОРОШО (Передача ссылки на анонимную функцию)
setTimeout(() => {
  console.log("Безопасное и быстрое выполнение.");
}, 1000);
```
