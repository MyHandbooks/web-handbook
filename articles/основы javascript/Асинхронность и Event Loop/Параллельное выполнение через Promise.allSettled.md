# Параллельное выполнение через Promise.allSettled

## БЫСТРЫЙ СТАРТ

*   **`Promise.allSettled([p1, p2, ...])`** — статический метод-комбинатор, который запускает все переданные промисы параллельно и ожидает их полного завершения, независимо от того, выполнены они успешно или с ошибкой.
*   **Гарантия выполнения:** Метод **никогда не переходит в состояние `rejected`** сам по себе. Он всегда завершается успешно (`fulfilled`), возвращая массив объектов с описанием исхода для каждого промиса.
*   **Используйте его для:** независимых параллельных задач (например, загрузка нескольких виджетов на дашборде, отправка пакета аналитики), где падение одного запроса не должно ломать выполнение остальных.
*   **Не используйте его:** когда задачи критически зависят друг от друга (например, транзакция списания денег и запись в БД). Для цепочек, требующих принципа «всё или ничего» (fail-fast), используйте `Promise.all()`.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Параллельный запуск независимых запросов
*   **Назначение:** Одновременная загрузка данных из нескольких источников с безопасным разбором результатов каждого процесса на успешные и провалившиеся.

```typescript
export interface DataPayload {
  identifier: string;
  statePayload: string;
}

// Описываем стандартную структуру ответа allSettled на уровне типов TypeScript
export type SettledResult<T> = 
  | { status: "fulfilled"; value: T } 
  | { status: "rejected"; reason: Error };

export async function loadIndependentSources(sourceIds: string[]): Promise<SettledResult<DataPayload>[]> {
  // 1. Формируем массив невыполненных промисов (запросы запускаются параллельно в фоне)
  const taskPromises = sourceIds.map(async (id): Promise<DataPayload> => {
    if (id === "bad_id") {
      throw new Error(`Не удалось загрузить ресурс с ID: ${id}`);
    }
    return { identifier: id, statePayload: "source_data_content" };
  });

  // 2. Ждем завершения всех задач без исключения
  // V8 соберет результаты в упорядоченный массив, соответствующий исходному порядку
  const results = await Promise.allSettled(taskPromises);

  // 3. Приводим сырые результаты JS к строго типизированному виду для безопасной работы
  return results.map((res): SettledResult<DataPayload> => {
    if (res.status === "fulfilled") {
      return { status: "fulfilled", value: res.value };
    } else {
      // res.reason в JS может быть любым типом, принудительно кастим к Error
      const errorInstance = res.reason instanceof Error ? res.reason : new Error(String(res.reason));
      return { status: "rejected", reason: errorInstance };
    }
  });
}
```

### Шаблон 2: Сбор только успешно выполненных результатов
*   **Назначение:** Параллельный запуск задач с фильтрацией и извлечением исключительно успешно полученных данных для последующего рендеринга.

```typescript
export interface ConfigOptions {
  activeUrl: string;
}

async function fetchConfig(endpoint: string): Promise<ConfigOptions> {
  if (endpoint.includes("error")) throw new Error("Сбой сети");
  return { activeUrl: `https://${endpoint}.eltex.co` };
}

export async function gatherValidConfigs(endpoints: string[]): Promise<ConfigOptions[]> {
  // Запускаем все запросы на получение конфигураций параллельно
  const promises = endpoints.map(url => fetchConfig(url));

  const settledResults = await Promise.allSettled(promises);

  // Фильтруем массив результатов, оставляя только успешные, и извлекаем их значения
  return settledResults
    .filter((res): res is PromiseFulfilledResult<ConfigOptions> => res.status === "fulfilled")
    .map(res => res.value); // Безопасно забираем очищенные данные типа ConfigOptions
}
```

### Шаблон 3: Логирование сбоев отдельных задач в пакете
*   **Назначение:** Параллельное выполнение пачки операций с точечной обработкой и логированием ошибок без прерывания работы основного приложения.

```typescript
export async function executeBatchOperations(tasks: Promise<void>[]): Promise<void> {
  // Ожидаем завершения всей группы транзакций
  const outcomes = await Promise.allSettled(tasks);

  // Итерируемся по исходам для выявления и логирования сбойных операций
  outcomes.forEach((outcome, index) => {
    if (outcome.status === "rejected") {
      const errorMsg = outcome.reason instanceof Error ? outcome.reason.message : String(outcome.reason);
      console.warn(`[СБОЙ] Операция под индексом №${index} завершилась неудачей: ${errorMsg}`);
    } else {
      console.log(`[УСПЕХ] Операция под индексом №${index} завершена.`);
    }
  });
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Сравнительный анализ комбинаторов: all, allSettled, any и race
Движок V8 предоставляет четыре различных стратегии для параллельного управления промисами, различающиеся поведением при возникновении первого успеха или первой ошибки:

1.  **`Promise.all` (Всё или ничего):** Ждет выполнения всех промисов. Если хотя бы один из них завершается ошибкой (`rejected`), метод немедленно прерывает работу (fail-fast) и выбрасывает эту ошибку. Результаты остальных (даже успешных) промисов полностью отбрасываются.
2.  **`Promise.allSettled` (Полная независимость):** Ждет полного завершения всех промисов (settled). Никогда не выбрасывает исключение при отклонении одного из них. Результатом всегда является массив объектов, описывающих индивидуальное состояние каждого промиса.
3.  **`Promise.any` (Первый успешный):** Ждет первый успешно выполненный промис (`fulfilled`) и возвращает его значение. Ошибки игнорируются. Если все промисы завершились неудачей, выбрасывается общая групповая ошибка `AggregateError`.
4.  **`Promise.race` (Гонка скоростей):** Возвращает результат первого завершившегося промиса, независимо от того, успешен он или завершился ошибкой.

### 2. Спецификация структуры объектов ответа в allSettled
Возвращаемый методом `Promise.allSettled` массив состоит из объектов, структура которых строго зафиксирована в спецификации ECMAScript:

*   Для успешных промисов:
    ```javascript
    { status: "fulfilled", value: T }
    ```
    Где `value` — это данные, переданные в вызов `resolve()` внутри промиса.
*   Для отклоненных промисов:
    ```javascript
    { status: "rejected", reason: any }
    ```
    Где `reason` — объект ошибки (обычно `Error`), переданный в вызов `reject()` или выброшенный через `throw`.

Эта жесткая структура гарантирует, что вы можете использовать безопасный статический анализ типов TypeScript для ветвления логики на основе свойства `status`.

### 3. Детальный пошаговый разбор выполнения шаблона 2
1.  **Параллельный запуск:** Выражение `endpoints.map(...)` создает массив промисов. Движок V8 регистрирует все сетевые запросы в Web APIs. Запросы уходят в сеть одновременно (параллельно).
2.  **Инициализация allSettled:** Вызывается `Promise.allSettled(promises)`. Движок создает новый промис-координатор и заводит внутренний счетчик активных задач, равный длине массива.
3.  **Регистрация микрозадач:** На каждый переданный промис движок навешивает внутренние обработчики успешного и неуспешного завершения. Каждое срабатывание уменьшает внутренний счетчик на 1 и записывает результат в соответствующий индекс результирующего массива.
4.  **Сбои в сети:** Один из запросов падает. Внутренний обработчик перехватывает ошибку, записывает в ячейку массива `{ status: "rejected", reason: Error }` и уменьшает счетчик задач. Программа не прерывается.
5.  **Завершение координатора:** Последний промис завершает работу. Счетчик равен нулю. Промис-координатор переходит в состояние `fulfilled` и отправляет итоговый массив в очередь микрозадач. Вызов `await` разблокирует выполнение функции.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Бесконечное зависание всей группы из-за "зависшего" промиса**
    *   *Проблема:* Метод `allSettled` ждет завершения **абсолютно всех** промисов. Если один из запросов зависнет на сервере из-за отсутствия тайм-аута (будет находиться вечно в состоянии `pending`), `allSettled` никогда не разрешится. Интерфейс приложения заблокируется (бесконечный лоадер).
    *   *Решение:* Ограничивайте максимальное время ожидания для каждого сетевого запроса с помощью гонки `Promise.race` с тайм-аут промисом.

```typescript
// ПЛОХО (Если один запрос зависнет, вся цепочка allSettled заблокируется навсегда)
export async function loadUnsafeBatch(promises: Promise<any>[]): Promise<any> {
  return await Promise.allSettled(promises);
}

// ХОРОШО (Ограничение времени жизни каждой задачи через гонку)
function withTimeout<T>(promise: Promise<T>, timeoutMs: number): Promise<T> {
  const timeoutPromise = new Promise<never>((_, reject) => 
    setTimeout(() => reject(new Error("Превышен лимит ожидания запроса (Timeout)")), timeoutMs)
  );
  return Promise.race([promise, timeoutPromise]);
}

export async function loadSafeBatch(promises: Promise<any>[]): Promise<any> {
  const securedPromises = promises.map(p => withTimeout(p, 5000)); // лимит 5 секунд на задачу
  return await Promise.allSettled(securedPromises);
}
```

*   **Ошибка 2: Неверный разбор ошибок (Обращение к `value` у отклоненных промисов)**
    *   *Проблема:* Разработчик обходит массив результатов `allSettled` и пытается прочитать свойство `value` у всех элементов без проверки статуса. Это приводит к получению `undefined` или падению программы.
    *   *Решение:* Всегда делайте явное логическое ветвление по свойству `.status` перед чтением полей `value` или `reason`.

```typescript
// ПЛОХО (Попытка прочитать value без проверки статуса)
export function processOutcomesUnsafe(results: any[]): void {
  results.forEach(res => {
    // Если res.status === "rejected", свойства value у него нет (оно равно undefined)
    console.log(res.value.toLowerCase()); // ! TypeError: Cannot read properties of undefined
  });
}
```

*   **Ошибка 3: Передача гигантских динамических массивов в `Promise.allSettled`**
    *   *Проблема:* Передача массива на десятки тысяч задач в `allSettled`. Это приводит к мгновенному исчерпанию лимитов оперативной памяти вкладки браузера, так как V8 вынужден держать в памяти тысячи активных контекстов одновременно.
    *   *Решение:* Разбивайте гигантские массивы задач на небольшие пакеты (батчи) и обрабатывайте их последовательно-параллельно.
