# Подключение скриптов

## БЫСТРЫЙ СТАРТ

*   **Управление приоритетом** — подключение скриптов в HTML определяет, как именно браузер будет скачивать и выполнять JavaScript-код относительно парсинга (разбора) HTML-страницы и построения DOM (Document Object Model).
*   **Синхронный `<script>`** — полностью блокирует построение DOM-дерева на время скачивания и выполнения файла. Рекомендуется подключать в самом конце тега `</body>`, если не используются современные атрибуты.
*   **Атрибут `async`** — скачивает файл асинхронно в фоновом режиме, но **немедленно прерывает парсинг HTML для выполнения**, как только скачивание завершено. Порядок выполнения нескольких асинхронных скриптов не гарантирован.
*   **Атрибут `defer`** — скачивает файл в фоновом режиме и **выполняет его строго после полного завершения парсинга HTML**, сохраняя исходный порядок объявления скриптов на странице.
*   **Используйте для:**
    *   `defer` (или модульные скрипты) — для подключения основного кода веб-приложения, которому требуется гарантированный доступ к готовым DOM-элементам и строгая очередность выполнения модулей.
    *   `async` — для абсолютно независимых сторонних скриптов (системы аналитики, счетчики посещений, реклама, чат-виджеты), которые не зависят от структуры вашего DOM и других скриптов.
*   **Не используйте для:**
    *   Синхронные скрипты в теге `<head>` — это задерживает первичную отрисовку страницы и приводит к эффекту «белого экрана» для пользователя.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Подключение основного скрипта приложения с гарантией порядка
*   **Назначение:** Загрузка ключевой логики интерфейса в фоновом режиме с выполнением строго после готовности DOM-структуры.

#### 1. Файл разметки: `index.html`
```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>Приложение с отложенной загрузкой</title>
  
  <!-- Хорошо: defer запускает фоновую загрузку скрипта без блокировки парсинга HTML -->
  <!-- Скрипт гарантированно выполнится до события DOMContentLoaded -->
  <script defer src="app.js"></script>
</head>
<body>
  <header>
    <h1>Интерактивная панель</h1>
  </header>
  <main>
    <!-- Кнопка будет создана в DOM до того, как выполнится app.js -->
    <button id="action-btn">Выполнить расчет</button>
  </main>
</body>
</html>
```

#### 2. Файл логики: `app.js`
```javascript
"use strict";

// Функция инициализации приложения
function initializeApp() {
  // Благодаря атрибуту defer элемент гарантированно существует в DOM
  const actionButton = document.getElementById("action-btn");

  if (actionButton) {
    actionButton.addEventListener("click", () => {
      console.log("Клик успешно обработан основным приложением!");
    });
  } else {
    console.error("Критическая ошибка: Кнопка действия не найдена в DOM.");
  }
}

// Запускаем инициализацию. Нам не нужно вешать слушатели на DOMContentLoaded,
// так как defer уже гарантирует полную сборку DOM-дерева на момент выполнения.
initializeApp();
```

### Шаблон 2: Подключение изолированного скрипта аналитики
*   **Назначение:** Асинхронная загрузка стороннего счетчика метрики, не влияющая на скорость отображения основного контента страницы.

#### 1. Файл разметки: `index.html`
```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>Страница с аналитикой</title>
  
  <!-- Хорошо: async скачает скрипт в фоне и выполнит сразу, как только получит пакет -->
  <!-- Основное приложение не зависит от аналитики, поэтому порядок не важен -->
  <script async src="tracker.js"></script>
</head>
<body>
  <div class="content">
    <p>Основной контент страницы...</p>
  </div>
</body>
</html>
```

#### 2. Файл логики: `tracker.js`
```javascript
"use strict";

// Автономная самовызывающаяся функция (IIFE) для изоляции контекста
(function() {
  console.log("Инициализация фонового трекера аналитики...");

  const trackEvent = (eventName) => {
    // В строгом режиме this === undefined, работаем с глобальными объектами явно
    const userAgent = navigator.userAgent;
    console.log(`[МЕТРИКА] Событие: ${eventName}. Браузер: ${userAgent}`);
  };

  // Имитируем отправку стартового события
  trackEvent("page_view");
})();
```

### Шаблон 3: Модульное подключение скриптов (ES Modules)
*   **Назначение:** Использование преимуществ инкапсуляции и поддержки современной системы импортов/экспортов в браузере.

#### 1. Файл разметки: `index.html`
```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>Модульное приложение</title>
  
  <!-- Хорошо: type="module" по умолчанию ведет себя аналогично defer -->
  <!-- Скрипт загружается асинхронно, выполняется строго после сборки DOM -->
  <script type="module" src="main.js"></script>
</head>
<body>
  <div class="wrapper">
    <span id="output">Ожидание модуля...</span>
  </div>
</body>
</html>
```

#### 2. Файл логики: `main.js`
```javascript
// Внутри модулей (type="module") строгий режим "use strict" активен по умолчанию
import { formatMessage } from "./utils.js";

const outputSpan = document.getElementById("output");

if (outputSpan) {
  // Вызываем импортированную функцию форматирования
  outputSpan.textContent = formatMessage("Модульная система успешно запущена!");
}
```

#### 3. Файл утилит: `utils.js`
```javascript
// Изолированная функция утилит, экспортируемая наружу
export function formatMessage(text) {
  const timestamp = new Date().toLocaleTimeString();
  return `[${timestamp}] ${text}`;
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как браузер обрабатывает HTML и строит DOM (парсер и блокировка)
Процесс разбора HTML-документа выполняется специальным парсером браузера, который последовательно считывает байты разметки, преобразует их в токены и строит древовидную структуру DOM.

Физика блокировки парсера обычным скриптом:
1.  **Обнаружение тега:** Когда парсер натыкается на тег `<script src="...">`, он останавливает свою работу.
2.  **Запрос по сети:** Браузер открывает новое сетевое соединение (HTTP/HTTPS) и начинает скачивать файл. В этот момент разбор страницы полностью приостановлен, новые элементы в DOM-дерево не добавляются, а визуальный рендеринг замирает.
3.  **Выполнение скрипта:** Как только файл скачан, браузер передает его JS-движку (например, V8) на компиляцию и выполнение.
4.  **Разблокировка:** Только после полного выполнения JavaScript-кода парсер HTML возобновляет свою работу с прерванного места.

**Почему браузер так жестко блокирует поток?**
Это заложено в архитектуре языка. JavaScript имеет доступ к динамическому изменению DOM-структуры во время выполнения (например, через старый метод `document.write()`). Если бы браузер продолжал строить дерево во время загрузки скрипта, скрипт мог бы полностью переписать HTML-структуру, сделав проделанную работу парсера невалидной. Поэтому браузер выбирает гарантированно безопасный, но медленный путь блокировки.

### 2. Спецификация выполнения: async против defer и модульные скрипты
Атрибуты `async` и `defer` сообщают браузеру, что скачивание JS-файла можно перенести в фоновые сетевые потоки (Web APIs), не мешая парсингу HTML. Однако фазы выполнения у них принципиально различаются:

*   **`async` (Асинхронность):**
    Скачивание происходит в фоне. Как только скачивание завершается, браузер **незамедлительно приостанавливает парсинг HTML**, выполняет скрипт в основном потоке и только затем возвращается к разбору HTML. Если на странице объявлено несколько `async` скриптов, их очередность выполнения непредсказуема и зависит исключительно от скорости работы сети (кто быстрее скачался, тот первым и выполнится).
*   **`defer` (Отложенность):**
    Скачивание также происходит в фоне. Но выполнение скрипта строго блокируется до тех пор, пока парсер HTML полностью не закончит свою работу и не построит DOM-дерево. Очередность выполнения `defer` скриптов строго соответствует порядку их объявления в HTML-коде.

#### Связь с событием `DOMContentLoaded`
Событие `DOMContentLoaded` сигнализирует о том, что DOM-дерево полностью готово.
*   **`defer` скрипты** гарантированно выполняются **до** срабатывания события `DOMContentLoaded`. Браузер дождется окончания выполнения всех отложенных скриптов и только тогда сгенерирует это событие.
*   **`async` скрипты** не связаны с этим событием. Они могут выполниться как до, так и после `DOMContentLoaded` (в зависимости от того, как быстро они загрузились по сети).

### 3. Детальный пошаговый разбор выполнения шаблона 1
1.  **Чтение HTML:** Браузер начинает парсить `index.html`.
2.  **Обнаружение отложенного скрипта:** Парсер доходит до тега `<script defer src="app.js">`.
3.  **Фоновый запрос:** Парсер регистрирует задачу загрузки файла в сетевом потоке и **без остановки** продолжает парсить HTML ниже по коду (строит теги `header`, `main`, `button`).
4.  **Завершение скачивания:** Файл `app.js` полностью скачивается по сети. Браузер сохраняет его в кэше, но не выполняет, так как парсинг HTML еще продолжается.
5.  **Готовность DOM:** Парсер доходит до закрывающего тега `</html>`. DOM-дерево полностью сформировано.
6.  **Выполнение скрипта:** Браузер извлекает `app.js` из кэша и выполняет его в основном потоке. Скрипт успешно находит кнопку `action-btn` в готовом DOM.
7.  **Генерация события:** После завершения работы скрипта браузер инициирует событие `DOMContentLoaded`.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Ошибка обращения к несуществующему DOM-элементу (`TypeError`)**
    *   *Проблема:* Разработчик подключает скрипт в `<head>` без атрибутов. При попытке повесить слушатель событий на кнопку (например, `document.getElementById('btn').addEventListener(...)`), приложение падает с ошибкой `Cannot read properties of null`.
    *   *Причина:* Скрипт выполняется синхронно до того, как парсер дошел до тела `<body>` и создал кнопку в DOM-дереве.
    *   *Решение:* Добавьте атрибут `defer` к тегу скрипта, чтобы отложить его выполнение до готовности DOM.

```typescript
// ПЛОХО (Скрипт в head без атрибутов упадет при старте)
// index.html: <script src="app.js"></script>
// app.js:
const btn = document.getElementById("action-btn");
// @ts-ignore
btn.addEventListener("click", () => {}); // ! Сбой: TypeError (btn равен null)

// ХОРОШО (С использованием defer)
// index.html: <script defer src="app.js"></script>
// app.js:
const btnOk = document.getElementById("action-btn");
if (btnOk) {
  btnOk.addEventListener("click", () => {
    console.log("Клик успешно обработан.");
  });
}
```

*   **Ошибка 2: Нарушение очередности выполнения зависимых скриптов (Race Condition)**
    *   *Проблема:* На странице подключены два скрипта: библиотека (например, `jquery.js`) и плагин к ней (`plugin.js`), использующий глобальные методы библиотеки. У обоих установлен атрибут `async`. Периодически плагин падает с ошибкой о том, что библиотека не найдена.
    *   *Причина:* Атрибут `async` не гарантирует порядок. Если тяжелый файл `jquery.js` скачивается дольше легкого `plugin.js`, плагин попытается выполниться первым, когда библиотеки еще нет в памяти.
    *   *Решение:* Используйте атрибут `defer` для обоих скриптов. Браузер гарантированно выполнит их строго в порядке объявления.

```html
<!-- ПЛОХО (Порядок выполнения не гарантирован, возможен сбой при медленной сети) -->
<script async src="heavy-library.js"></script>
<script async src="light-plugin-dependent.js"></script>

<!-- ХОРОШО (Очередность строго гарантирована спецификацией) -->
<script defer src="heavy-library.js"></script>
<script defer src="light-plugin-dependent.js"></script>
```

*   **Ошибка 3: Использование устаревшего `document.write()` в отложенных сценариях**
    *   *Проблема:* Разработчик пытается динамически внедрить разметку на страницу с помощью `document.write()` внутри `defer` или `async` скрипта. В результате страница полностью очищается (белый экран), либо браузер блокирует операцию.
    *   *Причина:* Метод `document.write()` может безопасно записывать данные только во время активного парсинга HTML. В `defer`/`async` скриптах выполнение происходит тогда, когда поток документа уже закрыт. Вызов `document.write()` в этот момент принудительно открывает новый поток, полностью стирая всю существующую страницу.
    *   *Решение:* Используйте современные методы манипуляции DOM-деревом (`document.createElement`, `appendChild`, `insertAdjacentHTML`).

```javascript
// ПЛОХО (Полностью перезапишет/сотрет всю страницу в defer-скрипте)
function renderBadWidget() {
  "use strict";
  // @ts-ignore
  document.write("<div class='widget'>Новый контент</div>"); 
}

// ХОРОШО (Безопасное добавление элемента в DOM)
function renderGoodWidget() {
  "use strict";
  const widget = document.createElement("div");
  widget.className = "widget";
  widget.textContent = "Новый контент";
  
  document.body.appendChild(widget); // Безопасно монтируем в DOM
}
```
