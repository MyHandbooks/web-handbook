# Гонка асинхронных операций (Promise.race, Promise.any)

## БЫСТРЫЙ СТАРТ

*   **`Promise.race([p1, p2, ...])`** — возвращает первый завершившийся промис (успешно или с ошибкой). Используйте для реализации таймаутов сетевых запросов и ограничителей времени.
*   **`Promise.any([p1, p2, ...])`** — возвращает первый **успешно** завершившийся промис. Если все переданные промисы упали с ошибкой, метод отклоняется с системной ошибкой класса `AggregateError`. Используйте для загрузки данных из резервных зеркал (серверов) или поиска первого доступного API-эндпоинта.
*   **Эмиссия не останавливает процессы:** Помните, что победа в гонке не отменяет выполнение проигравших асинхронных операций. Они продолжат тихо выполняться на уровне сетевой карты ОС или таймеров, забивая оперативную память, если их не отменить принудительно (например, через `AbortController`).
*   **Не используйте их:** когда задачи критически зависят друг от друга (используйте последовательный запуск) или когда критически важен успех каждой отдельной операции (используйте `Promise.all` [5] или `Promise.allSettled`).

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Реализация сетевого таймаута (`Promise.race`)
*   **Назначение:** Ограничение максимального времени ожидания ответа сервера для предотвращения бесконечного зависания UI-лоадера.

```typescript
export interface TargetPayload {
  identifier: string;
  statePayload: string;
}

// Имитируем асинхронный сетевой запрос к серверу
async function fetchRemoteData(id: string): Promise<TargetPayload> {
  return new Promise((resolve) => {
    setTimeout(() => resolve({ identifier: id, statePayload: "resolved_data" }), 5000); // 5 секунд
  });
}

export async function requestWithTimeout(targetId: string, limitMs: number): Promise<TargetPayload> {
  // 1. Создаем промис-таймаут, который гарантированно завершится ошибкой по истечении limitMs
  const timeoutPromise = new Promise<never>((_, reject) => {
    setTimeout(() => {
      reject(new Error(`[Timeout] Превышено время ожидания ответа сервера (${limitMs}мс)`));
    }, limitMs);
  });

  // 2. Запускаем гонку между реальным запросом и таймером. 
  // Тот, кто выполнится быстрее, определит исход всей гонки
  return Promise.race<TargetPayload>([
    fetchRemoteData(targetId),
    timeoutPromise
  ]);
}
```

### Шаблон 2: Загрузка данных из резервных зеркал (`Promise.any`)
*   **Назначение:** Отправка запросов на несколько серверов-дублеров одновременно с получением данных от самого быстрого и работоспособного узла.

```typescript
export interface ConfigOptions {
  activeUrl: string;
}

async function fetchFromMirror(url: string): Promise<ConfigOptions> {
  if (url.includes("broken")) {
    throw new Error(`[Server Error] Зеркало ${url} недоступно.`);
  }
  return { activeUrl: url };
}

export async function loadConfigFromBestNode(mirrors: string[]): Promise<ConfigOptions> {
  // Создаем массив промисов-запросов к зеркалам
  const taskPromises = mirrors.map(url => fetchFromMirror(url));

  try {
    // Ждем первый УСПЕШНЫЙ ответ.
    // Если одно из зеркал упадет с ошибкой, Any это проигнорирует и продолжит ждать остальные
    return await Promise.any(taskPromises);
  } catch (error: unknown) {
    // Сюда мы попадем, только если абсолютно все зеркала вернули ошибку
    if (error instanceof AggregateError) {
      console.error("[AggregateError] Все зеркала недоступны. Логи ошибок:", error.errors);
    }
    throw new Error("Критический сбой инфраструктуры: ни одно зеркало не ответило.");
  }
}
```

### Шаблон 3: Автоматический сброс ресурсов проигравшей операции (`AbortController`)
*   **Назначение:** Корректная отмена сетевого запроса, проигравшего гонку по таймауту, для предотвращения утечек трафика и процессора.

```typescript
export async function requestWithStrictAbort(targetId: string, limitMs: number): Promise<Response> {
  // Инициализируем стандартный браузерный контроллер отмены
  const controller = new AbortController();
  const signal = controller.signal;

  const timeoutPromise = new Promise<never>((_, reject) => {
    setTimeout(() => {
      // Принудительно отменяем сетевой запрос в браузере (прерываем TCP сокет)
      controller.abort();
      reject(new Error("[Abort] Превышен лимит времени. Сетевой запрос отменен."));
    }, limitMs);
  });

  const fetchPromise = fetch(`https://api.enterprise-service.com/v1/data/${targetId}`, {
    signal // Привязываем токен отмены к нативному fetch-запросу
  });

  return Promise.race([fetchPromise, timeoutPromise]);
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как движок V8 координирует `Promise.race` и `Promise.any`
Методы-комбинаторы — это не просто синтаксический сахар, а сложные конечные автоматы, управляемые C++ ядром движка V8.

#### Механика `Promise.race`:
1.  Движок V8 принимает массив промисов, проверяет его структуру и создает новый результирующий промис-координатор `racePromise`.
2.  Запускается немедленный синхронный цикл обхода переданного массива.
3.  На каждый промис в массиве вешаются внутренние скрытые обработчики разрешения и отклонения:
    ```typescript
    promise.then(
      value => resolveRace(value), // Победитель разрешен успешно
      error => rejectRace(error)   // Победитель завершился ошибкой
    );
    ```
4.  Как только один из промисов срабатывает, он вызывает `resolveRace` или `rejectRace`. Метод мгновенно переводит `racePromise` в конечное состояние (*settled*).
5.  Все последующие вызовы обработчиков от проигравших промисов полностью игнорируются, так как состояние промиса иммутабельно и не может быть изменено повторно.

#### Механика `Promise.any`:
1.  Создается результирующий промис `anyPromise` и внутренний счетчик ошибок, равный длине переданного массива, а также пустой массив под причины ошибок.
2.  На каждый промис вешаются обработчики:
    ```typescript
    promise.then(
      value => resolveAny(value), // Первый успех мгновенно завершает anyPromise
      error => handleRejection(error) // Ошибки накапливаются
    );
    ```
3.  Каждое срабатывание ошибки уменьшает внутренний счетчик на 1.
4.  Когда счетчик доходит до `0` (все промисы завершились ошибкой), движок V8 конструирует объект `AggregateError` и отклоняет `anyPromise`.

### 2. Спецификация системного класса `AggregateError`
Класс `AggregateError` (введен в ES2021) наследует свойства стандартного `Error`, но расширяет его структуру свойством `errors`.

```typescript
interface AggregateError extends Error {
  errors: any[]; // Массив причин отклонения (rejection reasons) каждого из промисов
}
```

Порядок ошибок в массиве `errors` **строго соответствует исходному порядку** переданных в метод промисов, а не хронологическому порядку их падения. Это позволяет сопоставлять ошибки с конкретными серверами или операциями по их индексам.

### 3. Физика "призрачных" фоновых процессов
Многие разработчики полагают, что `Promise.race` физически уничтожает проигравшие промисы. В JavaScript это невозможно.

Когда вы вызываете сетевой запрос через `fetch` или тяжелое вычисление и запускаете гонку по таймауту:
*   Если таймаут сработал быстрее, `Promise.race` мгновенно возвращает ошибку.
*   Но сетевой сокет браузера продолжает оставаться открытым. Сетевая карта продолжает скачивать байты ответа с сервера, а браузер тратит оперативную память на их парсинг в куче.
*   Это создает скрытые "призрачные" процессы (Ghost Processes), которые крадут трафик пользователей и перегружают CPU.

Единственный способ остановить проигравшую операцию — использовать нативный `AbortController` (как показано в Шаблоне 3), который физически закрывает системный TCP-сокет на уровне операционной системы.

### 4. Детальный пошаговый разбор выполнения шаблона 1
1.  **Создание гонщиков:** Вызывается функция `requestWithTimeout("id_1", 1000)`.
2.  **Запуск таймера:** Инструкция `setTimeout` регистрирует макрозадачу таймаута на 1000мс. Промис `timeoutPromise` создается в состоянии `pending`.
3.  **Запуск запроса:** Функция `fetchRemoteData` регистрирует асинхронный процесс на 5000мс. Промис-запрос создается в состоянии `pending`.
4.  **Срабатывание таймаута:** Спустя 1000мс таймер срабатывает. Макрозадача запускается, вызывая колбэк `reject(Error)`. Промис `timeoutPromise` переходит в состояние `rejected`.
5.  **Победа в гонке:** `Promise.race` фиксирует, что один из участников цепочки отклонен. Координатор `racePromise` мгновенно переходит в состояние `rejected`, пробрасывая ошибку в основной стек.
6.  **Фоновый процесс:** Сетевой запрос к серверу на 5000мс продолжает пассивно выполняться в фоне браузера. Спустя еще 4 секунды он успешно завершится, но его результат будет молча отброшен сборщиком мусора, так как на него больше нет активных подписчиков.

### 5. Типичные ошибки и их решение

*   **Ошибка 1: Передача пустого массива в `Promise.race` (Вечное зависание)**
    *   *Проблема:* Приложение намертво зависает, лоадер бесконечно крутится на экране, память не очищается.
    *   *Причина:* Вы передали пустой массив `Promise.race([])` (например, динамически сформированный список серверов оказался пустым). По спецификации, если передан пустой массив, `Promise.race` **навсегда зависает в состоянии `pending`**, так как в массиве нет ни одного элемента, который мог бы прийти первым и разрешить координатор.
    *   *Решение:* Перед запуском гонки всегда делайте проверку длины массива.

```typescript
// ПЛОХО (Промис зависнет навсегда)
const winner = await Promise.race([]); 

// ХОРОШО (Защитная проверка на пустую коллекцию)
if (tasks.length === 0) {
  throw new Error("Список задач на гонку пуст");
}
const winner = await Promise.race(tasks);
```

*   **Ошибка 2: Падение всей гонки `Promise.race` при первой же ошибке второстепенного промиса**
    *   *Проблема:* Вы запустили гонку между быстрым сервером и медленным сервером. Быстрый сервер упал с ошибкой `500` через 10мс, а медленный успешно вернул бы данные через 200мс. Но гонка полностью прерывается ошибкой через 10мс.
    *   *Причина:* `Promise.race` реагирует на **любое** первое завершение (включая `reject`). Сбой быстрого сервера мгновенно перевел всю гонку в состояние ошибки, отбросив потенциальный успех медленного сервера.
    *   *Решение:* Если вам нужен именно успешный ответ, используйте `Promise.any` (который проигнорирует ошибку быстрого сервера и дождется успеха медленного). Если нужен именно `Promise.race`, но с игнорированием ошибок определенных участников, оборачивайте их вызовы в локальный `catch` с возвратом бесконечного промиса-заглушки.

```typescript
// ПЛОХО (Если быстрый сервер упадет, гонка сломается)
const winner = await Promise.race([fastButUnstable(), slowButStable()]);

// ХОРОШО (any проигнорирует ошибку быстрого и дождется медленного)
const winner = await Promise.any([fastButUnstable(), slowButStable()]);
```

*   **Ошибка 3: Передача пустого массива в `Promise.any` (Мгновенный сбой)**
    *   *Проблема:* Код падает с ошибкой `AggregateError` мгновенно, не пытаясь выполнить операции.
    *   *Причина:* По спецификации, если в `Promise.any([])` передан пустой массив, он не зависает (в отличие от `race`), а **мгновенно отклоняется** с ошибкой `AggregateError`, так как в массиве нет ни одного успешного промиса.
    *   *Решение:* Перед запуском `Promise.any` проверяйте длину массива или возвращайте дефолтное значение без запуска асинхронного комбинатора.
