# Событийный цикл Event Loop

## БЫСТРЫЙ СТАРТ

*   **Однопоточность** — JavaScript является однопоточным языком программирования: он имеет единственный стек вызовов (Call Stack) и может выполнять строго одну операцию в каждый момент времени.
*   **Событийный цикл (Event Loop)** — это встроенный механизм рантайма (браузера или Node.js), координирующий выполнение синхронного кода, обработку асинхронных колбэков, очереди микро/макрозадач и фазы отрисовки интерфейса.
*   **Используйте для:**
    *   Асинхронного разделения (чанкования) тяжелых синхронных вычислений для сохранения отзывчивости интерфейса (60fps/120fps).
    *   Планирования операций, которые должны выполниться строго после завершения текущего синхронного потока, но до того, как браузер перерисует экран (через `queueMicrotask`).
*   **Не используйте для:**
    *   Попыток реализовать высокоточный тайминг в реальном времени (любая макрозадача в очереди будет заблокирована и отложена, если стек вызовов занят тяжелой синхронной работой).

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Асинхронное чанкование (разделение) тяжелых вычислений
*   **Назначение:** Разделение долгого синхронного цикла на небольшие неблокирующие пакеты (чанки) для предотвращения зависания страницы и плавной отрисовки прогресс-бара.

```typescript
export function processHeavyDataDeferred(totalItems: number, container: HTMLElement): void {
  let processedCount = 0;
  const chunkSize = 15000; // Оптимальный размер пакета для обработки за один "вдох" браузера (до 10-16мс)

  function executeChunk(): void {
    const endLimit = Math.min(processedCount + chunkSize, totalItems);

    // 1. Выполняем небольшую часть тяжелой работы синхронно
    for (; processedCount < endLimit; processedCount++) {
      // Имитируем сложные математические расчеты
      const _result = Math.sqrt(processedCount) * Math.cos(processedCount);
    }

    // 2. Обновляем статус прогресса в DOM
    // Благодаря чанкованию браузер получит окно для рендеринга этого изменения
    const progressPercent = Math.round((processedCount / totalItems) * 100);
    container.textContent = `Вычислено: ${progressPercent}%`;

    if (processedCount < totalItems) {
      // 3. Планируем следующий чанк как новую макрозадачу в конце очереди
      // Браузер успеет перерисовать экран (отрендерить прогресс) до того, как этот колбэк запустится
      window.setTimeout(executeChunk, 0);
    } else {
      console.log("[ВЫЧИСЛЕНИЯ] Весь массив успешно обработан без блокировки UI.");
    }
  }

  // Запускаем первую итерацию
  executeChunk();
}
```

### Шаблон 2: Использование микрозадач через `queueMicrotask`
*   **Назначение:** Планирование безопасного асинхронного выполнения логики, которая должна гарантированно сработать сразу после очистки стека вызовов, но строго перед отрисовкой экрана или запуском макрозадач.

```typescript
export class ReactiveState {
  private isBatchingScheduled = false;
  private internalState = 0;

  constructor(private readonly updateCallback: (val: number) => void) {}

  public updateState(newValue: number): void {
    this.internalState = newValue;

    // Пакетное обновление (Batching): предотвращаем множественные вызовы отрисовки при частых изменениях
    if (!this.isBatchingScheduled) {
      this.isBatchingScheduled = true;

      // Планируем микрозадачу. Она выполнится сразу после текущего синхронного потока
      // Но до того, как Event Loop перейдет к Render Queue или макрозадачам
      queueMicrotask(() => {
        this.updateCallback(this.internalState);
        this.isBatchingScheduled = false; // Сбрасываем флаг блокировки
        console.log(`[STATE] Состояние обновлено пакетно: ${this.internalState}`);
      });
    }
  }
}
```

### Шаблон 3: Синхронизация рендеринга через `requestAnimationFrame`
*   **Назначение:** Точное выполнение манипуляций с DOM и CSS-стилями синхронно с частотой обновления экрана монитора (для исключения Layout Thrashing).

```typescript
export function animateProgressBar(progressBar: HTMLElement, targetWidth: number): void {
  let currentWidth = 0;

  function step(): void {
    currentWidth += 2;
    progressBar.style.width = `${currentWidth}px`;

    if (currentWidth < targetWidth) {
      // Запрашиваем анимационный кадр. 
      // Браузер выполнит функцию шаг за шагом в фазе Render Queue, строго перед перерисовкой экрана
      window.requestAnimationFrame(step);
    }
  }

  window.requestAnimationFrame(step);
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Архитектура событийного цикла браузера (Call Stack, Web APIs, Queues)
Событийный цикл — это бесконечный процесс координации асинхронного кода, обеспечиваемый хост-средой браузера. Он состоит из четырех ключевых областей:

1.  **Call Stack (Стек вызовов):** Однопоточная структура данных, куда движок V8 помещает выполняемые кадры функций (по принципу LIFO). Если в стеке находится тяжелая функция, поток блокируется.
2.  **Web APIs (Фоновые API браузера):** Системные потоки браузера, выполняющие отложенную работу (таймеры `setTimeout`, запросы `fetch`, парсинг событий мыши). Они работают параллельно с V8.
3.  **Очереди задач (Task Queues):** Хранилища колбэков, готовых к перемещению в стек. Разделены на Макрозадачи и Микрозадачи.
4.  **Event Loop (Событийный цикл):** Диспетчер, который непрерывно проверяет, пуст ли Call Stack. Если стек пуст, он переносит задачи из очередей в стек вызовов.

### 2. Приоритеты выполнения: Микрозадачи против Макрозадач и Очередь Отрисовки (Render Queue)
При обработке асинхронного кода Event Loop строго следует спецификации приоритетов:

*   **Микрозадачи (Microtasks):**
    Берутся из внутренней очереди движка V8 (слот `[ [PromiseJobs] ]`). Сюда относятся: `.then()`/`.catch()`/`.finally()` промисов, вызовы `queueMicrotask` и `MutationObserver`.
    *   *Правило приоритета:* Очередь микрозадач должна быть очищена **абсолютно полностью до последнего элемента** при переходе к следующему этапу. Если микрозадача добавляет в очередь новую микрозадачу, она также выполнится в текущем цикле.
*   **Макрозадачи (Macrotasks):**
    Поступают из Web APIs. Сюда относятся: `setTimeout`, `setInterval`, события DOM, сетевые ответы, `postMessage`.
    *   *Правило приоритета:* За один цикл Event Loop извлекает из очереди и выполняет **строго одну** макрозадачу. После этого выполнение макрозадач прерывается, и движок немедленно переключается на очистку очереди микрозадач.
*   **Render Queue (Очередь отрисовки):**
    Запускается периодически (обычно каждые `16.6 мс` для 60Hz), если браузер считает, что наступило время обновить экран. Фаза отрисовки выполняется только тогда, когда стек вызовов пуст, и строго после завершения всех накопившихся микрозадач, но до выполнения следующей макрозадачи из очереди.

### 3. Детальный пошаговый разбор выполнения шаблона 1
1.  **Синхронный старт:** Вызывается `processHeavyDataDeferred(100000, container)`. В Call Stack создается кадр функции.
2.  **Выполнение чанка:** Запускается функция `executeChunk`. Выполняется цикл от 0 до 15000. Это синхронная операция, занимающая около 5-10 мс.
3.  **Запрос обновления DOM:** Записывается новое значение `container.textContent = "Вычислено: 15%"`. Браузер регистрирует изменение стилей, но физически экран еще не обновляется, так как Call Stack занят.
4.  **Планирование макрозадачи:** Выполняется `window.setTimeout(executeChunk, 0)`. Браузер регистрирует таймер в Web APIs. По истечении 0 мс (реально 1-4 мс) колбэк следующего чанка отправляется в конец очереди макрозадач.
5.  **Освобождение Call Stack:** Функция `executeChunk` завершает работу и покидает стек вызовов. Синхронная часть полностью завершена.
6.  **Микрозадачи:** Event Loop проверяет очередь микрозадач. Она пуста.
7.  **Отрисовка (Render):** Браузер понимает, что стек пуст, и запускает фазу рендеринга. Элемент `container` на экране физически перерисовывается, пользователь видит текст "Вычислено: 15%".
8.  **Следующий цикл:** Event Loop переходит к очереди макрозадач, находит там колбэк второго чанка `executeChunk` и помещает его в Call Stack. Весь процесс повторяется для следующего пакета данных.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Бесконечная рекурсия микрозадач и блокировка рендеринга**
    *   *Проблема:* Разработчик запускает рекурсивный вызов функции через `queueMicrotask` или бесконечный цикл промисов. Страница намертво зависает, браузер перестает реагировать на клики, прокрутку, а вкладка аварийно закрывается по превышению памяти.
    *   *Причина:* Очередь микрозадач обладает абсолютным приоритетом и должна быть вычищена полностью. Если микрозадача порождает новую микрозадачу, Event Loop никогда не сможет выйти из этой фазы, блокируя переход к фазе отрисовки (Render) и очереди макрозадач.
    *   *Решение:* Тяжелые рекурсивные фоновые циклы планируйте через макрозадачи (`setTimeout` / `setInterval`), чтобы давать браузеру окно для рендеринга.

```typescript
// ПЛОХО (Намертво заблокирует отрисовку экрана и вкладку браузера)
export function blockUiInsecure() {
  function step() {
    queueMicrotask(step); // Рекурсивно забиваем очередь микрозадач
  }
  step();
}

// ХОРОШО (Макрозадача выполняется по одной за цикл, давая браузеру время на отрисовку)
export function runNonBlockingCycle() {
  function step() {
    setTimeout(step, 0); // Переносим выполнение в очередь макрозадач
  }
  step();
}
```

*   **Ошибка 2: Нарушение таймингов при блокировке стека вызовов**
    *   *Проблема:* Разработчик настраивает таймер на 1 секунду: `setTimeout(f, 1000)`, но функция `f` запускается только через 5 секунд.
    *   *Причина:* После того как Web APIs отсчитал 1000 мс, колбэк уходит в очередь макрозадач. Если в этот момент основной поток выполнения (Call Stack) занят тяжелым синхронным вычислением (например, обработкой тяжелого JSON или расчетом графики), Event Loop не сможет забрать задачу из очереди. Она будет ожидать, пока стек полностью не освободится.
    *   *Решение:* Не выполняйте тяжелые синхронные вычисления в основном потоке. Переносите их в фоновые потоки через Web Workers или делите на неблокирующие асинхронные пакеты (чанкование).

```typescript
// ПЛОХО (Таймер сработает с огромной задержкой из-за блокировки потока)
export function testTimingUnsafe() {
  const start = Date.now();
  setTimeout(() => {
    console.log(`Таймер сработал через: ${Date.now() - start} мс`); // Покажет ~5000мс вместо 1000мс
  }, 1000);

  // Тяжелый синхронный цикл на 4 секунды полностью блокирует Call Stack
  const blockEnd = Date.now() + 4000;
  while (Date.now() < blockEnd) {}
}
```

*   **Ошибка 3: Избыточные задержки при рекурсивных таймерах (Clamping)**
    *   *Проблема:* Разработчик планирует частую анимацию или опрос через `setTimeout(f, 0)`, ожидая мгновенных срабатываний, но видит просадку скорости выполнения и задержки.
    *   *Причина:* По спецификации HTML5, после 5 последовательных вложенных вызовов `setTimeout` браузер принудительно увеличивает минимальную задержку (Clamping) до **`4 мс`**, а на фоновых вкладках — до **`1000 мс`**.
    *   *Решение:* Для плавной анимации используйте `requestAnimationFrame`. Для быстрых фоновых вычислений вне Event Loop используйте `Web Workers`.

```typescript
// ПЛОХО (Скорость анимации упадет из-за принудительного зажима 4мс)
export function animateUnsafe(el: HTMLElement) {
  let pos = 0;
  function draw() {
    pos++;
    el.style.left = `${pos}px`;
    if (pos < 500) {
      setTimeout(draw, 0); // Попадет под clamping 4мс после 5 вызовов
    }
  }
  setTimeout(draw, 0);
}

// ХОРОШО (Анимация синхронизирована с частотой обновления экрана без задержек)
export function animateSafe(el: HTMLElement) {
  let pos = 0;
  function draw() {
    pos++;
    el.style.left = `${pos}px`;
    if (pos < 500) {
      requestAnimationFrame(draw); // Идеальный плавный рендеринг
    }
  }
  requestAnimationFrame(draw);
}
```
