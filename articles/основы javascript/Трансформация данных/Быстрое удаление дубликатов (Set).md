# Быстрое удаление дубликатов (Set)

## БЫСТРЫЙ СТАРТ

*   **`Set`** — это встроенная системная коллекция уникальных значений (множество). Одно и то же значение не может быть добавлено в `Set` дважды.
*   **Быстрая чистка примитивов:** С помощью конструкции `[...new Set(array)]` можно мгновенно очистить массив от дублирующихся строк, чисел или логических значений.
*   **Поиск за O(1):** Проверка наличия элемента в множестве через метод `Set.prototype.has()` выполняется за константное время $O(1)$, в то время как поиск в массиве через `.includes()` требует обхода всех элементов за линейное время $O(N)$.
*   **Используйте для:** быстрой дедупликации плоских списков и оптимизации частых проверок вхождения элементов в больших наборах данных.
*   **Не используйте для:** дедупликации объектов «из коробки» — движок сравнивает объекты по ссылке в куче, а не по их содержимому, поэтому внешне идентичные объекты будут расценены как уникальные.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Дедупликация массива примитивов (строки / числа)
*   **Назначение:** Очистка плоского списка данных от повторяющихся значений в однострочном функциональном стиле.

```typescript
export function removePrimitiveDuplicates(rawList: string[]): string[] {
  // 1. Конструктор Set принимает массив и отсекает дубликаты на этапе создания
  const uniqueSet = new Set<string>(rawList);

  // 2. С помощью spread-оператора разворачиваем уникальное множество обратно в массив
  return [...uniqueSet];
}
```

---

### Шаблон 2: Очистка массива объектов по уникальному свойству (например, по ID)
*   **Назначение:** Удаление дублирующихся объектов из списка на основе уникального ключевого поля с использованием вспомогательного множества для отслеживания уникальности.

```typescript
export interface TargetPayload {
  uid: string;
  statePayload: string;
}

export function filterDuplicateObjects(payloads: TargetPayload[]): TargetPayload[] {
  // Множество для быстрого отслеживания уже обработанных идентификаторов
  const seenIds = new Set<string>();

  // Фильтруем исходный массив
  return payloads.filter((item): boolean => {
    if (seenIds.has(item.uid)) {
      // Если ID уже есть в множестве, отбрасываем текущий объект
      return false; 
    }
    // Если ID встретился впервые, добавляем его в множество и пропускаем объект вперед
    seenIds.add(item.uid);
    return true;
  });
}
```

---

### Шаблон 3: Быстрая проверка членства элементов в больших наборах данных
*   **Назначение:** Оптимизация ресурсоемких проверок вхождения элементов (например, проверка прав или ролей) при обработке тяжелых массивов.

```typescript
export function checkElementsInSet(largeData: string[], allowedValues: string[]): string[] {
  // Конвертируем разрешенные значения во внутренний Set для хэш-поиска
  const allowedSet = new Set<string>(allowedValues);

  // Фильтруем массив. Метод .has() отработает мгновенно за O(1) на каждом шаге
  return largeData.filter((item): boolean => {
    return allowedSet.has(item); // Быстрая хэш-проверка вхождения
  });
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как структура `Set` устроена под капотом движка V8
В оперативной памяти компьютера структура `Set` реализована движком V8 в виде динамической **хэш-таблицы (Hash Set)**. 

Особенности внутренней спецификации:
1.  **Алгоритм хэш-функции:** При добавлении элемента в `Set` движок вычисляет его уникальный числовой хэш-код и по нему определяет ячейку (bucket) в памяти, куда записывается значение. При проверке `.has(value)` движок вычисляет хэш для `value` и сразу обращается к нужной ячейке в памяти. Это избавляет его от необходимости сканировать всю коллекцию, обеспечивая скорость доступа за константное время $O(1)$.
2.  **Сравнение значений (SameValueZero):** Для определения уникальности элементов `Set` использует внутренний алгоритм сравнения `SameValueZero`. Он работает почти как строгое сравнение `===`, но с одним важным отличием: значение `NaN` считается равным самому себе. Поэтому, если добавить несколько `NaN` в `Set`, в коллекции останется ровно один `NaN` (в отличие от обычного JS, где `NaN !== NaN`).
3.  **Порядок вставки:** Спецификация гарантирует, что `Set` сохраняет исходный порядок вставки элементов при итерации (например, при вызове `forEach` или конвертации в массив).

### 2. Сравнение производительности: `Set.prototype.has()` против `Array.prototype.includes()`
Для небольших массивов (до 30–50 элементов) разница в скорости поиска между массивом и множеством незначительна. Однако при росте объема данных различия становятся критическими:

*   **Поиск в массиве (`includes` / `indexOf`):** Работает за линейное время $O(N)$. Чтобы подтвердить отсутствие элемента в массиве из 10 000 ячеек, движок V8 вынужден синхронно выполнить 10 000 операций сравнения в цикле.
*   **Поиск в множестве (`has`):** Работает за константное время $O(1)$. Независимо от того, содержит ли `Set` 10 элементов или 1 000 000 элементов, проверка `.has()` всегда выполняется практически за одинаковое микроскопическое количество инструкций процессора.

Если вам необходимо регулярно проверять вхождение элементов в коллекцию внутри других циклов, предварительная конвертация массива в `Set` дает колоссальный прирост производительности.

### 3. Детальный пошаговый разбор выполнения шаблона 2
1.  **Создание хэш-таблицы:** Вызывается функция `filterDuplicateObjects(payloads)`. В памяти инициализируется пустой хэш-сет `seenIds`.
2.  **Инициация фильтрации:** Запускается метод `.filter()`. Движок считывает первый объект `payloads[0]` (у него `uid: "id_1"`).
3.  **Хэш-проверка:** Вызывается `seenIds.has("id_1")`. Движок V8 вычисляет хэш для `"id_1"`, проверяет хэш-таблицу. Она пуста. Метод возвращает `false`.
4.  **Регистрация ключа:** Выполняется ветка `seenIds.add("id_1")`. Хэш-код строки записывается в таблицу. Коллбэк возвращает `true`. Первый объект копируется в результирующий массив.
5.  **Итерация 2:** Считывается объект `payloads[1]` (у него тоже `uid: "id_1"`). Вызывается `seenIds.has("id_1")`. Движок находит хэш-код в таблице и мгновенно возвращает `true`. Коллбэк возвращает `false`. Вторая копия объекта отбрасывается.
6.  **Завершение:** Отфильтрованный массив уникальных объектов возвращается из функции.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Попытка автоматического удаления дубликатов-объектов**
    *   *Проблема:* Разработчик передает массив объектов в `Set` (например, `[...new Set([{id: 1}, {id: 1}])]`), ожидая получить массив с одним уникальным объектом. На выходе дубликаты остаются на месте.
    *   *Причина:* Объекты сравниваются по ссылкам в памяти. Хотя эти объекты внешне идентичны по структуре, они занимают разные адреса в куче, поэтому `Set` считает их уникальными.
    *   *Решение:* Выполняйте дедупликацию объектов вручную через фильтрацию с использованием вспомогательного `Set` для отслеживания уникальности конкретного поля (как показано в Шаблоне 2).

```typescript
// ПЛОХО (Объекты имеют разные ссылки в памяти, дубликаты не удалятся)
export function deduplicateObjectsUnsafe(items: { id: number }[]): any[] {
  return [...new Set(items)]; // На выходе по-прежнему два объекта
}
```

*   **Ошибка 2: Утечки памяти в долгоживущих классах из-за удержания сильных ссылок в `Set`**
    *   *Проблема:* Вы используете глобальный `Set` для кэширования или отслеживания активных объектов. Как только объекты удаляются из основной программы, они навсегда «зависают» в памяти, так как `Set` продолжает удерживать на них жесткие ссылки.
    *   *Решение:* Если вам нужно связывать метаданные с объектами или отслеживать их активность, используйте `WeakSet`. В `WeakSet` ссылки на объекты являются слабыми, что позволяет Garbage Collector беспрепятственно удалять их из кучи, как только исчезнут внешние ссылки.

```typescript
// ПЛОХО (Объект никогда не сотрется из памяти, пока существует set)
const strongSet = new Set<object>();
let user: object | null = { name: "Alex" };
strongSet.add(user);
user = null; // Объект остался в куче, так как strongSet держит сильную ссылку

// ХОРОШО (Сборщик мусора автоматически очистит объект в куче)
const weakSet = new WeakSet<object>();
let activeSession: object | null = { token: "secret" };
weakSet.add(activeSession);
activeSession = null; // Объект успешно удалится из памяти в следующем цикле GC
```

*   **Ошибка 3: Попытка прямого обращения по индексу к элементам `Set`**
    *   *Проблема:* Попытка получить элемент множества по его индексу: `const value = mySet[0]`. Код возвращает `undefined`.
    *   *Причина:* Множество `Set` не является индексированной коллекцией. У него отсутствуют числовые ключи.
    *   *Решение:* Если вам нужен доступ к конкретному элементу по индексу, конвертируйте множество обратно в массив через spread-оператор или метод `Array.from(mySet)[index]`.
