# Стандартные структуры данных

## БЫСТРЫЙ СТАРТ

*   **Массив (Array)** — динамическая упорядоченная последовательность элементов, оптимизированная для быстрого доступа по индексу ($O(1)$) и работы с упорядоченными данными.
*   **Множество (Set)** — коллекция уникальных значений, исключающая дубликаты и обеспечивающая быструю проверку наличия элемента за $O(1)$.
*   **Карта (Map)** — ассоциативная структура данных "ключ-значение", позволяющая использовать в качестве ключей любые типы данных (включая объекты) и сохраняющая порядок вставки.
*   **Вспомогательные объекты (`Math`, `Date`, `JSON`)** — встроенные системные инструменты для выполнения математических расчетов, работы с временными метками и сериализации данных.
*   **Правило выбора:** Используйте `Array` для упорядоченных списков; `Set` — для уникальных наборов и быстрых проверок; `Map` — для динамических словарей с ключами произвольных типов; `Object` — для статических структур с известными строковыми ключами.

### Шаблон 1: Безопасное немутирующее изменение массивов (ES2023+)
*   **Назначение:** Модификация, сортировка и разворот массивов без изменения исходных ссылок в памяти (иммутабельное управление состоянием).

```typescript
export interface DataPayload {
  identifier: string;
  ratingValue: number;
}

export function processStateSafely(sourceList: DataPayload[]): DataPayload[] {
  // Исходный массив остается абсолютно неизменным в памяти
  
  // 1. Безопасная сортировка по возрастанию (toSorted возвращает копию)
  const sorted: DataPayload[] = sourceList.toSorted((a, b) => a.ratingValue - b.ratingValue);

  // 2. Безопасный разворот последовательности (toReversed возвращает копию)
  const reversed: DataPayload[] = sorted.toReversed();

  // 3. Безопасная точечная замена элемента по конкретному индексу (with)
  // Заменяем элемент на индексе 0 новым объектом с сохранением иммутабельности
  const updatedWith: DataPayload[] = reversed.with(0, {
    identifier: "forced-lead",
    ratingValue: 999
  });

  // 4. Безопасное вырезание и вставка элементов (toSpliced)
  // Удаляем 1 элемент на позиции 1 и вставляем новый объект
  const fullyProcessed: DataPayload[] = updatedWith.toSpliced(1, 1, {
    identifier: "inserted-node",
    ratingValue: 500
  });

  return fullyProcessed;
}
```

### Шаблон 2: Связывание сложных объектов-ключей с метаданными через `Map`
*   **Назначение:** Организация ассоциативной карты, где ключами выступают уникальные ссылки на объекты (без риска неявного приведения к строке `[object Object]`).

```typescript
export interface UserSession {
  token: string;
  assignedRole: string;
}

export interface ActivityMetadata {
  lastActiveTimestamp: number;
  requestCount: number;
}

export class SessionCoordinator {
  // Инициализируем карту, где ключом является целый объект сессии
  private readonly activityRegistry = new Map<UserSession, ActivityMetadata>();

  public registerSession(session: UserSession): void {
    // Записываем данные в карту. Ссылка на объект служит уникальным ключом
    this.activityRegistry.set(session, {
      lastActiveTimestamp: Date.now(),
      requestCount: 1
    });
  }

  public incrementActivity(session: UserSession): void {
    // Быстро проверяем наличие ключа в памяти за O(1)
    if (!this.activityRegistry.has(session)) {
      return;
    }

    const currentMeta = this.activityRegistry.get(session)!;
    
    // Обновляем данные, перезаписывая значение по ссылке-ключу
    this.activityRegistry.set(session, {
      lastActiveTimestamp: Date.now(),
      requestCount: currentMeta.requestCount + 1
    });
  }

  public getSessionMeta(session: UserSession): ActivityMetadata | undefined {
    return this.activityRegistry.get(session);
  }
}
```

### Шаблон 3: Очистка дубликатов и вычисление пересечения коллекций через `Set`
*   **Назначение:** Удаление повторяющихся значений и нахождение общих элементов между несколькими наборами данных за линейное время $O(N)$.

```typescript
export function removeDuplicates<T>(items: T[]): T[] {
  // Set автоматически отсекает повторяющиеся элементы на этапе добавления
  const uniqueSet = new Set<T>(items);
  // Преобразуем множество обратно в массив с помощью spread-оператора
  return [...uniqueSet];
}

export function findIntersection<T>(listA: T[], listB: T[]): T[] {
  // Создаем множество из первого списка для быстрого поиска за O(1)
  const setA = new Set<T>(listA);
  
  // Оставляем только те элементы из списка B, которые гарантированно присутствуют в множестве A
  return listB.filter((item: T) => setA.has(item));
}
```

  };

export class SerializationManager {

      // Парсим входящую строку с явным приведением к безопасному типу unknown

  }
}

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как массивы устроены под капотом движка V8: SMI, Double и Elements Kinds
В низкоуровневой архитектуре V8 массивы не являются простыми непрерывными цепочками байтов в памяти, как в компилируемых языках. Движок V8 динамически переключает способы хранения элементов массива в зависимости от их содержимого (концепция **Elements Kinds**):

1.  **SMI (Small Integers):** Если массив содержит исключительно целые числа, V8 хранит его как плоский массив целых чисел. Это самый производительный режим с минимальным расходом памяти.
2.  **Double Elements:** Если в массив записывается хотя бы одно число с плавающей точкой (дробное), весь массив неявно приводится (деоптимизируется) к режиму Double Elements. Каждое число теперь занимает 64 бита памяти.
3.  **Dictionary/Holey Elements (Разреженные массивы):** Если в массиве появляются пустые слоты (например, при вызове `arr[100] = 5` при длине массива 2) или в него записываются разнородные типы данных (строки, объекты, числа), V8 переводит его в структуру хэш-таблицы (Dictionary). Доступ к элементам по индексу в таком массиве замедляется, так как движку приходится вычислять хэши ключей вместо простого смещения по адресу в памяти.

### 2. Физика сравнения: Map против Object и Set против Array в V8
*   **Поиск в массиве против Set:** Метод `Array.prototype.includes()` выполняет линейный поиск по всей длине коллекции за время $O(N)$ (сканирует элементы по очереди). Метод `Set.prototype.has()` под капотом использует высокопроизводительную хэш-таблицу. V8 вычисляет хэш-значение ключа и мгновенно проверяет его наличие в таблице за константное время $O(1)$, что критически важно при работе со списками на десятки тысяч элементов.
*   **Map против Object:** Обычный объект `Object` в JS оптимизирован под быструю работу со статичным набором строковых ключей (скрытые классы и формы объектов). Если в объект постоянно динамически добавляются и удаляются произвольные ключи, V8 вынужден непрерывно разрушать и перестраивать его внутренние скрытые классы, переходя в Dictionary-режим. `Map` изначально спроектирована как стабильная динамическая хэш-таблица. Она оптимизирована для частых мутаций ключей, сохраняет порядок их вставки и исключает коллизии с унаследованными свойствами прототипов (такими как `constructor` или `toString`), которые присутствуют в обычном `Object`.

### 3. Детальный пошаговый разбор выполнения шаблона 1
Разобьем выполнение цепочки: `processStateSafely(sourceList)`
1.  **Сортировка (`toSorted`):** Движок V8 выделяет в памяти новый массив аналогичной длины, копирует туда ссылки на элементы `sourceList`, выполняет быструю сортировку (алгоритм Timsort под капотом) на основе переданной функции сравнения и возвращает отсортированный клон. Исходный массив `sourceList` не мутирует.
2.  **Разворот (`toReversed`):** На основе отсортированного массива создается еще один массив. Движок проходит по индексам в обратном порядке и записывает ссылки на элементы. Ссылки на объекты внутри ячеек остаются прежними, но сам массив-контейнер создается заново.
3.  **Замена (`with`):** Метод `with(0, { identifier: "forced-lead", ratingValue: 999 })` создает очередной массив. На индекс `0` записывается ссылка на новый переданный объект, а остальные элементы копируются из предыдущего шага.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Мутация исходного массива методами `sort`, `reverse`, `splice` внутри чистых функций**
    *   *Симптомы:* Изменение порядка элементов в одном месте приложения неожиданно ломает отображение данных в других компонентах.
    *   *Причина:* Классические методы `sort()`, `reverse()`, `splice()` мутируют исходный массив на месте (in-place). Поскольку массивы передаются по ссылке, все переменные, ссылавшиеся на этот массив, начинают видеть мутированную структуру.
    *   *Решение:* Переходите на современные немутирующие аналоги `toSorted()`, `toReversed()`, `toSpliced()`, либо выполняйте поверхностное копирование перед сортировкой `[...sourceList].sort()`.

```typescript
// ПЛОХО (мутирует оригинал)
export function badSort(arr: number[]) {
  return arr.sort((a, b) => a - b); 
}

// ХОРОШО (ES2023+ немутирующий метод)
export function goodSort(arr: number[]) {
  return arr.toSorted((a, b) => a - b);
}
```

*   **Ошибка 2: Использование обычных объектов в качестве ключей в структуре `Object`**
    *   *Симптомы:* При записи данных по ключу-объекту значения начинают перезаписывать друг друга, данные теряются.
    *   *Причина:* Ключами в объектах `Object` могут быть только строки или символы. При попытке передать объект в качестве ключа (например, `obj[user] = "meta"`), движок принудительно вызывает метод `user.toString()`. Любой стандартный объект превращается в строковый ключ `"[object Object]"`. В итоге все объекты-ключи пишут данные в одно и то же свойство.
    *   *Решение:* Используйте `Map` для связывания объектов с метаданными.

```typescript
// ПЛОХО (произойдет коллизия ключей "[object Object]")
const registry: any = {};
registry[userA] = "admin";
registry[userB] = "editor"; // Перезапишет userA!

// ХОРОШО (индивидуальное сопоставление по ссылкам в памяти)
const registry = new Map<object, string>();
registry.set(userA, "admin");
registry.set(userB, "editor");
```

*   **Ошибка 3: Утечки памяти при удержании тяжелых объектов-ключей в `Map`**
    *   *Симптомы:* Объем оперативной памяти приложения постоянно растет (утечка памяти), хотя сами DOM-элементы или пользователи были удалены из интерфейса.
    *   *Причина:* Обычная `Map` удерживает сильные ссылки (Strong References) на свои ключи и значения. Если объект-ключ был удален из основной программы, сборщик мусора (Garbage Collector) не сможет удалить его из памяти, так как на него продолжает ссылаться `Map`.
    *   *Решение:* Если время жизни метаданных должно быть жестко привязано к времени жизни самого объекта-ключа, используйте `WeakMap`. В `WeakMap` ссылки на ключи являются слабыми (Weak References): если на объект-ключ больше никто не ссылается во внешней программе, он автоматически удаляется из памяти вместе со своими метаданными в `WeakMap`.

```typescript
// ПЛОХО (удерживает удаленные объекты в памяти, вызывая утечку)
const cache = new Map<HTMLElement, string>();

// ХОРОШО (объекты будут автоматически удалены сборщиком мусора)
const cache = new WeakMap<HTMLElement, string>();
```
