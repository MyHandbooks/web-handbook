# Развертывание многомерных структур (flat, flatMap)

## БЫСТРЫЙ СТАРТ

*   **Избегайте антипаттерна** использования связки `.map().flat()` без параметров. Это заставляет движок V8 выделять память под временный промежуточный массив в куче, удваивая нагрузку на Garbage Collector при обработке больших данных.
*   **Метод `.flat(depth)`** — возвращает новый плоский массив, рекурсивно разворачивая вложенные массивы до указанной глубины `depth` (по умолчанию `1`). Для полного развертывания любой степени вложенности передавайте значение `Infinity`.
*   **Метод `.flatMap(callback)`** — объединяет шаги маппинга и развертывания глубиной `1` в одну неделимую высокопроизводительную операцию. Он работает быстрее, так как не создает промежуточный массив между шагами.
*   **Используйте их для:** обработки иерархических структур данных (деревья категорий, комментарии с ветками ответов), извлечения плоских массивов тегов из списков статей или фильтрации с одновременным изменением типа элементов.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Рекурсивное плоское развертывание древовидного меню (`flat`)
*   **Назначение:** Преобразование многомерного массива вложенных подразделов в плоский линейный список для построения карты сайта или индексации поиска.

```typescript
export type NavigationNode = string | NavigationNode[];

export function buildFlatMenu(tree: NavigationNode[]): string[] {
  // Метод .flat() с параметром Infinity рекурсивно развернет массив любой глубины.
  // Все пустые ячейки (дыры) при этом будут автоматически удалены из результата.
  const flatResult = tree.flat(Infinity);

  // Кастим тип, так как после flat(Infinity) компилятор TS возвращает тип FlatArray
  return flatResult as string[];
}
```

---

### Шаблон 2: Извлечение связанных списков без промежуточных массивов (`flatMap`)
*   **Назначение:** Быстрый сбор всех уникальных тегов из списка статей в один плоский массив для облака тегов.

```typescript
export interface BlogPost {
  title: string;
  tagsList: string[]; // Каждая статья содержит свой массив тегов
}

export function extractAllUniqueTags(posts: BlogPost[]): string[] {
  // map().flat() создал бы промежуточный массив массивов.
  // flatMap() сразу нативно возвращает плоский массив строк за один проход.
  const allTags = posts.flatMap((post) => post.tagsList);

  // Удаляем дубликаты с помощью коллекции Set и возвращаем массив
  return [...new Set(allTags)];
}
```

### Шаблон 3: Одновременная фильтрация и маппинг (Фильтр-Мап паттерн через `flatMap`)
*   **Назначение:** Трансформация массива, где некоторые элементы должны быть пропущены (отфильтрованы). Более лаконичная альтернатива связкам `filter().map()` или тяжелым `reduce()`.

```typescript
export interface UserTransaction {
  id: string;
  amount: number;
  status: "success" | "failed";
}

export interface SuccessReceipt {
  transactionId: string;
  taxAmount: number;
}

export function generateReceipts(transactions: UserTransaction[]): SuccessReceipt[] {
  // Если транзакция успешна — возвращаем массив с одним объектом-чеком.
  // Если транзакция провалена — возвращаем пустой массив [].
  // flatMap() автоматически развернет эти массивы: пустые сотрутся, а заполненные встанут в общий ряд.
  return transactions.flatMap((tx): SuccessReceipt[] => {
    if (tx.status !== "success") {
      return []; // Элемент отфильтрован (стерт при развертывании)
    }

    return [{
      transactionId: tx.id,
      taxAmount: tx.amount * 0.2 // Вычисляем налог
    }];
  });
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Почему `.flatMap()` производительнее связки `.map().flat()`
Рассмотрим разницу на уровне управления памятью в куче движка V8:

#### Цепочка `.map().flat()`:
1.  Движок V8 берет исходный массив и запускает `.map()`.
2.  Выделяется память под новый промежуточный массив `TempArray` той же длины. Внутри него лежат ссылки на вложенные массивы.
3.  Движок берет `TempArray` и запускает `.flat()`.
4.  Выделяется память под второй, уже результирующий массив. Элементы копируются туда.
5.  Промежуточный массив `TempArray` становится ненужным и зависает в памяти до тех пор, пока его не очистит сборщик мусора во время очередного цикла.

#### Нативный `.flatMap()`:
*   Движок V8 сразу выделяет память под один результирующий плоский массив.
*   При проходе по исходному массиву движок вызывает коллбэк, берет возвращаемый им массив и копирует его элементы напрямую в результирующий буфер памяти.
*   Никаких промежуточных массивов-посредников не создается. Это снижает фрагментацию кучи и предотвращает внезапные фризы интерфейса, вызванные вынужденной экстренной сборкой мусора (Major GC).

### 2. Физика рекурсии в `.flat(depth)` и параметр `Infinity`
Метод `.flat()` принимает числовой параметр `depth`, указывающий глубину раскрытия вложенных структур:
*   Если передать `flat(1)`, массив вида `[1, [2, [3]]]` превратится в `[1, 2, [3]]`.
*   Если глубина вложенности динамическая или неизвестна заранее, передается системное значение `Infinity`.

При вызове `.flat(depth)` движок V8 запускает рекурсивный алгоритм на уровне C++ ядра. С каждым уровнем вложенности потребление стека вызовов возрастает. Передача гигантских массивов с глубиной вложенности в десятки тысяч уровней может вызвать переполнение системного стека вызовов, хотя на реальных бизнес-структурах данных (глубина которых редко превышает 5–10 уровней) нативная C++ рекурсия работает быстрее любых ручных JS-циклов.

### 3. Поведение на разреженных массивах
Оба метода — и `flat()`, и `flatMap()` — строго следуют спецификации по очистке разреженных структур:
*   Если в процессе развертывания движок натыкается на пустую ячейку ("дыру"), она просто **игнорируется**.
*   В результирующий плоский массив пустые ячейки не переносятся, а длина массива сокращается. Это делает методы идеальным инструментом для быстрого схлопывания разреженных массивов в плотные списки.

### 4. Детальный пошаговый разбор выполнения шаблона 3
1.  **Запуск операции:** Вызывается функция `generateReceipts(transactions)`.
2.  **Итерация 1:** Считывается успешная транзакция `tx_1` со значением `amount: 100`. Коллбэк возвращает массив из одного элемента: `[{ transactionId: "tx_1", taxAmount: 20 }]`.
3.  **Копирование:** Движок V8 копирует этот единственный объект в результирующий плоский массив на позицию 0.
4.  **Итерация 2:** Считывается неуспешная транзакция `tx_2`. Коллбэк возвращает пустой массив `[]`.
5.  **Развертывание пустоты:** Движок видит пустой массив. Операция развертывания для него ничего не делает. В результирующий массив новые элементы не добавляются, индекс записи не сдвигается.
6.  **Итерация 3:** Считывается успешная транзакция `tx_3` со значением `amount: 200`. Коллбэк возвращает чек.
7.  **Запись:** Объект чека копируется в результирующий массив на позицию 1.
8.  **Завершение:** Возвращается очищенный массив чеков длиной в 2 элемента.

### 5. Типичные ошибки и их решение

*   **Ошибка 1: Попытка глубокого развертывания через `flatMap`**
    *   *Проблема:* Массив имеет трехмерную структуру `[1, [2, [3]]]`. Разработчик вызывает `.flatMap()`, ожидая получить полностью плоский массив `[1, 2, 3]`, но на выходе остается вложенный массив `[1, 2, [3]]`.
    *   *Причина:* По спецификации метод `.flatMap()` выполняет развертывание **строго на глубину 1** (эквивалент `flat(1)`).
    *   *Решение:* Если вам нужно глубокое развертывание с одновременным маппингом, делайте сначала обычный `map()`, а затем вызывайте `.flat(Infinity)`.

```typescript
// ПЛОХО (flatMap развернет только первый уровень, тройка останется в массиве)
const data = [1, [2, [3]]];
// const result = data.flatMap(x => x); // На выходе: [1, 2, [3]]

// ХОРОШО (Комбинация с явным указанием Infinity для глубоких структур)
const resultSafe = data.map(x => x).flat(Infinity); // На выходе: [1, 2, 3]
```

*   **Ошибка 2: Использование `flatMap` для тяжелых асинхронных операций**
    *   *Проблема:* Попытка выполнить сетевые запросы внутри `flatMap` (например, возвращая массив промисов). Код компилируется, но возвращает массив неразрешенных промисов, а не данные.
    *   *Причина:* `flatMap` работает строго синхронно. Он не умеет дожидаться разрешения промисов.
    *   *Решение:* Для асинхронного развертывания потоков на сетевом уровне используйте операторы RxJS (такие как `mergeMap` или `switchMap` [6]).

*   **Ошибка 3: Потери производительности при возврате огромных массивов из колбэка `flatMap`**
    *   *Проблема:* Резкое зависание интерфейса при обработке массива.
    *   *Причина:* Если колбэк внутри `flatMap` на каждую итерацию возвращает массив из тысяч элементов, V8 вынужден совершать огромное количество операций по динамическому расширению результирующего буфера памяти.
    *   *Решение:* Ограничивайте размер возвращаемых из колбэка массивов. Метод спроектирован для точечной фильтрации (возврат 0 или 1 элемента) или легкого развертывания небольших вложенных коллекций (до 5–10 элементов). Для объединения гигантских списков используйте генераторы.
