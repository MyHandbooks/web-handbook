# Иммутабельное изменение и сортировка массивов (toSorted, toReversed, toSpliced)

## БЫСТРЫЙ СТАРТ

*   **Классические мутирующие методы** (`sort()`, `reverse()`, `splice()`) изменяют массив непосредственно в памяти (*in-place*). Это ломает предсказуемость состояния в реактивных фреймворках (Angular, React), которые сравнивают массивы по ссылке.
*   **Методы ES2023** (`toSorted()`, `toReversed()`, `toSpliced()`) выполняют ту же логику, но возвращают **новый, поверхностно скопированный массив**, сохраняя исходный массив в неизменном виде.
*   **Используйте их для:** безопасных манипуляций со списками в селекторах состояния, обработчиках событий UI-компонентов, конвейерах RxJS и при вычислении сигналов, где критически важна чистота функций.
*   **Не используйте их:** в старых браузерных средах без полифилов (требуется `core-js`), а также во внутренних низкоуровневых циклах высокой производительности, где выделение памяти под новые массивы на каждом шаге может перегрузить сборщик мусора.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Безопасная сортировка без изменения исходного состояния (`toSorted`)
*   **Назначение:** Сортировка списка элементов для вывода в интерфейсе с гарантией того, что исходный массив данных останется нетронутым.

```typescript
export interface CatalogItem {
  id: string;
  price: number;
}

export function getSortedCatalog(items: CatalogItem[], sortByDesc: boolean): CatalogItem[] {
  // Метод .toSorted() принимает стандартную функцию сравнения, как и обычный .sort()
  // Он возвращает новый отсортированный массив, оставляя оригинальный список неизменным в куче
  return items.toSorted((a, b) => {
    return sortByDesc ? b.price - a.price : a.price - b.price;
  });
}
```

---

### Шаблон 2: Безопасный разворот списка без побочных эффектов (`toReversed`)
*   **Назначение:** Отображение лога событий или истории изменений в обратном (хронологическом) порядке без мутации исходного лога.

```typescript
export interface HistoryEvent {
  timestamp: number;
  message: string;
}

export function getReverseChronologicalLog(events: HistoryEvent[]): HistoryEvent[] {
  // Метод .toReversed() возвращает зеркальную копию массива
  // Никаких побочных эффектов для переданного массива не возникает
  return events.toReversed();
}
```

---

### Шаблон 3: Иммутабельное удаление и вставка элементов по индексу (`toSpliced`)
*   **Назначение:** Точечное удаление, замена или вставка новых элементов в массив по определенному индексу без изменения исходной ссылки стейта.

```typescript
export interface DocumentNode {
  nodeId: string;
  content: string;
}

export function insertAndReplaceNode(
  nodes: DocumentNode[],
  insertIndex: number,
  newNode: DocumentNode
): DocumentNode[] {
  // toSpliced(start, deleteCount, ...items) принимает те же аргументы, что и splice()
  // Но вместо мутации и возврата вырезанных элементов, он возвращает измененную КОПИЮ массива
  // В данном примере: вырезаем 1 элемент на позиции insertIndex и вставляем на его место newNode
  return nodes.toSpliced(insertIndex, 1, newNode);
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как методы ES2023 устроены под капотом движка V8
На уровне системного рантайма и спецификации ECMAScript новые методы "Change Array by Copy" работают иначе, чем их старые мутирующие аналоги. 

*   **Классический `sort()`:** Движок V8 на низком уровне оптимизирует `sort()` на базе быстрой сортировки (Timsort/Quicksort) непосредственно в выделенном сегменте памяти массива. Это экономит оперативную память, но перезаписывает указатели элементов на месте.
*   **Копирующие аналоги:** При вызове `.toSorted()` движок V8 выполняет следующие низкоуровневые шаги:
    1.  Выделяет в куче (`Heap`) непрерывный сегмент памяти под новый массив, размер которого точно равен длине исходного.
    2.  Копирует указатели (ссылки) на элементы из исходного массива в новый (`shallow copy`).
    3.  Запускает нативный высокопроизводительный алгоритм сортировки внутри выделенного нового массива.
    4.  Возвращает ссылку на вновь созданный массив.

Это означает, что мы платим незначительным расходом памяти за полную архитектурную безопасность и иммутабельность данных.

### 2. Поведение на разреженных массивах (Sparse Arrays)
Разреженные массивы (содержащие пустые ячейки или "дыры") ведут себя неконсистентно в старых мутирующих методах JavaScript. Например, при вызове `sort()` пустые ячейки всегда перемещаются в самый конец массива, независимо от логики функции сравнения.

Спецификация ES2023 внесла строгость в обработку "дыр":
*   Методы `toSorted()`, `toReversed()` и `toSpliced()` перед началом работы неявно преобразуют разреженный массив в плотный (*dense array*).
*   Все пустые ячейки ("дыры") во время внутреннего копирования принудительно заменяются значением `undefined`.
*   Благодаря этому результирующий массив больше не содержит дыр и ведет себя абсолютно предсказуемо при последующих итерациях через `.map()` или `.forEach()`.

### 3. Детальный пошаговый разбор выполнения шаблона 3
1.  **Вызов метода:** Запускается функция `insertAndReplaceNode(nodes, 2, newNode)`.
2.  **Аллокация памяти:** Метод `toSpliced` определяет целевую длину результирующего массива. Так как мы удаляем 1 элемент и вставляем 1 элемент, длина останется прежней. V8 выделяет под нее новый сегмент памяти.
3.  **Копирование до индекса:** Движок копирует ссылки на объекты из `nodes[0]` и `nodes[1]` в первые две ячейки нового массива.
4.  **Замена элемента:** Вместо копирования оригинального `nodes[2]` движок записывает ссылку на переданный объект `newNode` в третью ячейку.
5.  **Копирование остатка:** Движок последовательно копирует ссылки на оставшиеся элементы `nodes[3]`, `nodes[4]` и т.д. в соответствующие индексы нового массива.
6.  **Возврат:** Ссылка на новый, измененный массив возвращается вызывающему коду. Исходный массив `nodes` остается неизменным в оперативной памяти.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Иллюзия глубокого копирования сложных объектов (Shallow Copy Leak)**
    *   *Проблема:* Разработчик сортирует или изменяет массив объектов через методы ES2023, а затем мутирует свойство одного из объектов внутри нового массива (например, `cloned[0].content = 'new'`). Это непреднамеренно изменяет свойства объекта в исходном массиве.
    *   *Причина:* Методы `toSorted`, `toReversed` и `toSpliced` выполняют поверхностное копирование (*shallow copy*). Копируются только адреса ссылок на объекты в куче. Сам объект в памяти остается общим для исходного и нового массивов.
    *   *Решение:* Если после иммутабельного изменения массива вам необходимо изменить свойства объектов внутри него, предварительно выполните глубокое копирование (`structuredClone`) или возвращайте измененные копии объектов через `map()`.

```typescript
// ПЛОХО (Свойство исходного объекта изменится по ссылке)
const sorted = items.toSorted((a, b) => a.price - b.price);
sorted[0].price = 999; // ! Мутирует оригинальный объект в памяти!

// ХОРОШО (Полная иммутабельность на уровне массива и объектов)
const sortedAndCloned = items
  .toSorted((a, b) => a.price - b.price)
  .map(item => ({ ...item })); // Пересоздаем ссылки на объекты первого уровня
sortedAndCloned[0].price = 999; // Абсолютно безопасно
```

*   **Ошибка 2: Падение приложения в неподдерживаемых средах (TypeError)**
    *   *Проблема:* Приложение падает с ошибкой `TypeError: items.toSorted is not a function` при запуске у некоторых пользователей или в старых версиях Node.js на бэкенде.
    *   *Причина:* Данные методы вошли в стандарт ECMAScript относительно недавно (ES2023) и отсутствуют в старых версиях браузеров (например, Safari до версии 16.4) и Node.js (до версии 20).
    *   *Решение:* Убедитесь, что ваш проект компилируется с таргетом ES2023+ или в нем подключены полифилы из пакета `core-js/actual/array`.

```json
// package.json (необходимый полифил для старых окружений)
"dependencies": {
  "core-js": "^3.35.0"
}
```

*   **Ошибка 3: Попытка прочитать удаленные элементы из `toSpliced`**
    *   *Проблема:* Разработчик пытается получить вырезанные элементы, как это было при использовании классического `splice()`, но метод возвращает измененный массив целиком.
    *   *Причина:* Классический `arr.splice()` возвращает массив *удаленных* элементов, а сам массив `arr` мутирует на месте. Метод `toSpliced()` возвращает *новый измененный массив* с учетом вырезания/вставки. Удаленные элементы в нем безвозвратно теряются.
    *   *Решение:* Если вам необходимы именно удаленные элементы без изменения оригинального массива, сначала сделайте копирование через `.slice()`, а затем вызовите классический `.splice()` на копии.

```typescript
// ПЛОХО (Пытаемся получить удаленные элементы, но получаем весь массив)
// const deletedItems = items.toSpliced(0, 2); // deletedItems будет содержать измененный массив!

// ХОРОШО (Использование классического splice на копии для получения удаленных элементов)
const copy = [...items];
const deletedItems = copy.splice(0, 2); // В deletedItems попадут строго вырезанные элементы
```
