# Современная группировка данных (Object.groupBy, Map.groupBy)

## БЫСТРЫЙ СТАРТ

*   **Нативная группировка данных** (стандарт ES2024) реализуется с помощью статических методов `Object.groupBy()` и `Map.groupBy()`. Они полностью заменяют старые императивные циклы на базе `.reduce()`.
*   **`Object.groupBy(iterable, callback)`** — возвращает специальный **объект с пустым прототипом** (`null-prototype object`). Ключами в нем могут быть только строки или символы, а значениями — массивы сгруппированных элементов.
*   **`Map.groupBy(iterable, callback)`** — возвращает стандартный экземпляр коллекции `Map`. Этот метод незаменим, когда в качестве ключей группировки нужно использовать сложные объекты, булевы флаги, числа или другие ссылочные типы данных без их принудительного приведения к строкам.
*   **Используйте их для:** разделения списков пользователей по ролям, группировки логов по уровням критичности или сортировки транзакций по датам.
*   **Не используйте их:** в старых окружениях без полифила (требуется `core-js`, так как методы нативно поддерживаются только начиная с Node.js v20+ и современных браузеров 2024 года).

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Простая группировка объектов по строковому свойству (`Object.groupBy`)
*   **Назначение:** Быстрое разделение плоского списка задач по категориям без ручного создания пустых массивов-аккумуляторов.

```typescript
export interface TaskPayload {
  id: string;
  title: string;
  category: "work" | "personal" | "shopping";
}

export function groupTasksByCategory(tasks: TaskPayload[]) {
  // Нативно группируем массив. Метод возвращает объект с ключами-категориями
  // Под капотом создается высокопроизводительный объект без прототипа
  return Object.groupBy(tasks, (task) => task.category);
}
```

---

### Шаблон 2: Группировка списка по логическому состоянию (`Object.groupBy`)
*   **Назначение:** Разделение массива на две группы (например, активные и неактивные пользователи) с автоматическим неявным приведением булева флага к строке.

```typescript
export interface UserRecord {
  username: string;
  isActive: boolean;
}

export function splitUsersByActiveStatus(users: UserRecord[]) {
  // Коллбэк возвращает булево значение. 
  // Object.groupBy автоматически приведет true и false к строкам "true" и "false"
  const grouped = Object.groupBy(users, (user) => user.isActive);

  return {
    activeUsers: grouped["true"] ?? [], // Извлекаем по строковому ключу
    inactiveUsers: grouped["false"] ?? []
  };
}
```

---

### Шаблон 3: Сложная группировка на базе объектов-ссылок (`Map.groupBy`)
*   **Назначение:** Группировка данных с использованием сложных объектов-ключей, что позволяет избежать коллизий и сохранить строгие типы данных без строковой сериализации.

```typescript
export interface ProjectManager {
  managerId: string;
  name: string;
}

export interface ProjectTask {
  title: string;
  manager: ProjectManager; // Объект-ссылка, по которому будем группировать
}

export function groupTasksByManager(tasks: ProjectTask[]): Map<ProjectManager, ProjectTask[]> {
  // Используем Map.groupBy. Ключами в результирующей карте станут 
  // оригинальные ссылки на объекты ProjectManager из кучи (без кастинга к строкам)
  return Map.groupBy(tasks, (task) => task.manager);
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Архитектурная уязвимость Prototype Pollution и дизайн Null-Prototype
Главная особенность метода `Object.groupBy()` заключается в том, что возвращаемый им объект создается **с абсолютно чистым прототипом `null`** (эквивалент вызова `Object.create(null)`). Он не наследует цепочку методов от глобального `Object.prototype`.

Этот дизайн был принят комитетом TC39 умышленно для решения двух критических проблем:
1.  **Защита от Prototype Pollution (Внедрения в прототип):**
    Если бы метод возвращал обычный объект, а данные от пользователя (бэкенда) содержали ключ группировки `"__proto__"`, то выполнение группировки могло бы перезаписать внутреннее свойство `__proto__` объекта-результата. Это позволило бы злоумышленнику внедрить вредоносный код в глобальный прототип приложения.
2.  **Исключение коллизии ключей:**
    В обычном объекте ключи `"toString"`, `"hasOwnProperty"` или `"constructor"` зарезервированы системными методами прототипа. Если бы вы сгруппировали данные по ключу `"toString"`, вызов `grouped.toString` вернул бы массив элементов, перезаписав нативную функцию, что сломало бы логику работы программы. 

У объекта, возвращаемого `Object.groupBy()`, полностью отсутствуют нативные методы прототипа (он чист), благодаря чему любые пользовательские строковые ключи абсолютно безопасны для записи и чтения.

### 2. Сравнение производительности: Нативный C++ V8 против `.reduce()`
В старом коде для группировки использовался паттерн с методом `.reduce()`:
```javascript
const grouped = arr.reduce((acc, item) => {
  (acc[item.category] ??= []).push(item);
  return acc;
}, {});
```
Этот подход имеет скрытые накладные расходы на уровне движка V8:
*   На каждой итерации `.reduce()` проверяет наличие ключа в объект и динамически мутирует его форму.
*   V8 вынужден постоянно перестраивать Скрытые классы (Shapes) для объекта-аккумулятора, что в конечном счете переводит его в медленный режим словаря (Dictionary Mode).

Нативный метод `Object.groupBy()` выполняется внутри С++ ядра V8. Движок заранее знает, что результирующий объект будет использоваться как динамический хэш-словарь, и сразу инициализирует его структуру в наиболее оптимальном формате Dictionary Mode на уровне системных указателей памяти, что обеспечивает значительный прирост производительности на больших массивах данных.

### 3. Разница между `Object.groupBy` и `Map.groupBy` на уровне ссылок
*   **`Object.groupBy`** выполняет **принудительное приведение ключей к строкам**. Если коллбэк вернет объект `{ id: 1 }`, метод преобразует его в строку `"[object Object]"`, что приведет к коллизии, если объектов-ключей будет несколько.
*   **`Map.groupBy`** использует стандартный алгоритм сравнения **SameValueZero** на уровне коллекции `Map`. Ключи сравниваются по их физическим адресам ссылок в куче (для объектов) или по строгому значению (для примитивов) без какого-либо приведения типов. Это позволяет группировать данные по реальным сущностям-ссылкам.

### 4. Детальный пошаговый разбор выполнения шаблона 3
1.  **Инициализация карты:** Вызывается `Map.groupBy(tasks, task => task.manager)`. Движок V8 создает в куче новый пустой экземпляр класса `Map`.
2.  **Итерация 1:** Считывается первая задача. Коллбэк возвращает объект-ссылку `manager_A`.
3.  **Поиск в Map:** Движок проверяет карту: `map.has(manager_A)`. Так как карта пуста, возвращается `false`.
4.  **Создание группы:** В карту записывается новый ключ-ссылка `manager_A` с пустым массивом в качестве значения: `map.set(manager_A, [])`.
5.  **Запись элемента:** Ссылка на первую задачу пушится в созданный массив.
6.  **Итерация 2:** Считывается вторая задача, закрепленная за тем же менеджером. Коллбэк возвращает ту же самую ссылку `manager_A`.
7.  **Добавление в группу:** Движок находит ключ по ссылке `manager_A` за $O(1)$ и пушит вторую задачу в существующий массив.
8.  **Завершение:** Наполненный объект `Map` возвращается из функции.

### 5. Типичные ошибки и их решение

*   **Ошибка 1: Попытка вызвать методы прототипа на результате `Object.groupBy`**
    *   *Проблема:* Разработчик пытается проверить наличие ключа в сгруппированном объекте через `grouped.hasOwnProperty('work')` или преобразовать его в строку через `grouped.toString()`. Приложение падает с критической ошибкой `TypeError: grouped.hasOwnProperty is not a function`.
    *   *Причина:* Объект не имеет прототипа `Object.prototype`, следовательно, у него физически отсутствуют эти методы.
    *   *Решение:* Вызывайте методы из прототипа базового класса явно через `.call()`, либо используйте стандартный оператор `in` для проверки существования ключа.

```typescript
// ПЛОХО (Вызов метода напрямую вызовет runtime-падение)
const grouped = Object.groupBy(tasks, t => t.category);
// if (grouped.hasOwnProperty('work')) { ... } // ! TypeError

// ХОРОШО (Использование безопасного оператора in)
if ('work' in grouped) {
  const workTasks = grouped['work']; // Безопасно
}

// ХОРОШО (Вызов метода прототипа через call)
const hasWork = Object.prototype.hasOwnProperty.call(grouped, 'work');
```

*   **Ошибка 2: Неявное приведение сложных объектов к строкам в `Object.groupBy`**
    *   *Проблема:* Разработчик группирует по объекту-менеджеру через `Object.groupBy` и обнаруживает, что все задачи слились в одну общую группу под именем `"[object Object]"`.
    *   *Причина:* `Object.groupBy` принудительно кастит возвращаемые ключи к строкам.
    *   *Решение:* Если ключом группировки является сложный объект, всегда строго используйте метод `Map.groupBy` вместо `Object.groupBy`.

*   **Ошибка 3: Утечки памяти при использовании `Map.groupBy` (Memory Leak)**
    *   *Проблема:* Растет потребление памяти приложением после многократной группировки временных задач по временным объектам-менеджерам.
    *   *Причина:* `Map.groupBy` возвращает стандартный `Map`, который удерживает сильные ссылки (*Strong References*) на объекты-ключи. До тех пор, пока жив результирующий `Map`, ни один из объектов-менеджеров (и связанных с ними задач) не сможет быть удален сборщиком мусора, даже если они были удалены из основной программы.
    *   *Решение:* Если время жизни сгруппированных данных должно быть коротким, своевременно очищайте полученный `Map` через метод `.clear()` или обнуляйте ссылку на него, чтобы дать возможность Garbage Collector'у освободить память.
