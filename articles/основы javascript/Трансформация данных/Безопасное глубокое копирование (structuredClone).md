# Безопасное глубокое копирование (structuredClone)

## БЫСТРЫЙ СТАРТ

*   **`structuredClone(value)`** — встроенная нативная глобальная функция (стандарт ES2022), которая выполняет **глубокое копирование (Deep Copy)** сложных объектов, рекурсивно дублируя все уровни вложенности в памяти.
*   **Решение старых проблем:** Нативно поддерживает клонирование сложных встроенных типов (`Date`, `RegExp`, `Map`, `Set`, `ArrayBuffer`, `Blob`) и умеет обрабатывать циклические ссылки (когда объект ссылается сам на себя).
*   **Используйте для:** создания абсолютно независимых копий конфигураций, состояний и структур данных перед передачей их во внешние мутирующие модули.
*   **Не используйте для:** объектов, содержащих методы (функции), DOM-элементы или геттеры/сеттеры — при попытке клонирования таких данных рантайм выбросит критическую ошибку `DataCloneError`.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Глубокое копирование вложенной конфигурации
*   **Назначение:** Создание полной автономной копии сложного конфигурационного объекта со вложенными массивами и объектами для последующей безопасной локальной модификации.

```typescript
export interface ConfigOptions {
  identifier: string;
  parameters: {
    port: number;
    endpoints: string[];
  };
}

export function cloneAndModifyConfig(original: ConfigOptions, newPort: number): ConfigOptions {
  // Нативно создаем полную глубокую копию объекта в оперативной памяти
  const configClone = structuredClone(original);

  // Локальные изменения свойств и массивов на любом уровне вложенности 
  // гарантированно не затронут оригинальный объект config
  configClone.parameters.port = newPort;
  configClone.parameters.endpoints.push("api/v2/secure");

  return configClone; // Возвращаем измененную изолированную копию
}
```

### Шаблон 2: Глубокое копирование списка объектов со сложными типами
*   **Назначение:** Клонирование массивов данных, содержащих объекты со встроенными типами (`Set`, `Date`, `Map`), без риска потери структуры типов.

```typescript
export interface DataState {
  id: string;
  created: Date;                // Встроенный объект даты
  tags: Set<string>;            // Встроенная коллекция уникальных тегов
}

export function duplicateDataStateList(rawStates: DataState[]): DataState[] {
  // Глубоко клонируем весь массив. structuredClone корректно пересоздаст 
  // новые экземпляры Date и Set для каждого элемента массива
  const clonedList = structuredClone(rawStates);

  // Убеждаемся на уровне типов и рантайма, что вложенные структуры склонированы
  clonedList.forEach((state) => {
    state.tags.add("cloned_tag"); // Изменяем Set внутри копии, оригинал не затронут
  });

  return clonedList;
}
```

### Шаблон 3: Клонирование объектов с циклическими ссылками (Circular References)
*   **Назначение:** Создание дубликатов сложных графовых структур данных (например, когда дочерний объект ссылается обратно на родительский).

```typescript
export interface TemporaryResult {
  uid: string;

  childNodes: TemporaryResult[];
}

export function cloneCircularGraph(graph: TemporaryResult): TemporaryResult {
  // structuredClone отслеживает циклические ссылки во время рекурсивного обхода.
  // Вместо бесконечной рекурсии и переполнения стека метод корректно восстановит связи в новом объекте.
  return structuredClone(graph);

```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как функция `structuredClone()` устроена под капотом движка V8
Функция `structuredClone` базируется на низкоуровневом **Алгоритме структурированного клонирования (Structured Clone Algorithm)**, реализованном на уровне C++ в движках V8, SpiderMonkey и др.

Механика работы алгоритма:
1.  **Сериализация в поток байтов:** Вместо обхода свойств на языке JavaScript, V8 сериализует исходный объект во внутренний бинарный формат прямо в системной памяти.
2.  **Картирование ссылок:** Во время сериализации алгоритм ведет скрытую таблицу соответствия объектов (Identity Map). Если в процессе обхода он встречает объект, который уже был сериализован ранее (циклическая ссылка), он записывает в поток ссылку на существующую запись, предотвращая зацикливание.
3.  **Десериализация (Восстановление):** V8 читает бинарный поток байтов и строит в куче новые независимые объекты, восстанавливая все типы данных (`Date`, `RegExp`, `Set`, `Map`), прототипы которых зарегистрированы в глобальном контексте.

### 2. Сравнительный анализ: `structuredClone` против JSON и Lodash `.cloneDeep()`

| Критерий | `structuredClone()` | `JSON.parse(JSON.stringify())` | `_.cloneDeep()` (Lodash) |
| :--- | :--- | :--- | :--- |
| **Реализация** | Нативный C++ в V8 | Синтаксический разбор JS-строк | Кастомная рекурсия на JS |
| **Производительность** | **Очень высокая** (для средних/крупных объектов) | Средняя (из-за двойной сериализации в строку) | Низкая (из-за накладных расходов выполнения JS) |
| **Циклические ссылки** | **Поддерживает** | Выбрасывает `TypeError` | Поддерживает |
| **Копирование встроенных типов** | Полная поддержка (`Set`, `Map`, `Date` и др.) | Теряет типы (превращает `Date` в строку, `Set`/`Map` зануляет) | Поддерживает |
| **Функции и методы** | Выбрасывает `DataCloneError` | Молча удаляет из объекта | Неявно копирует по ссылке |

Нативная функция `structuredClone` превосходит старый хак с `JSON` по всем параметрам безопасности и возможностям типизации, а также работает значительно быстрее тяжелых сторонних библиотек на больших объемах данных.

### 3. Детальный пошаговый разбор выполнения шаблона 3
1.  **Инициализация алгоритма:** Вызывается функция `cloneCircularGraph(graph)`. Объект `graph` имеет циклическую связь: `graph.childNodes[0].parentRef === graph`.
2.  **Запись в реестр:** Алгоритм V8 начинает сериализацию объекта `graph`. В реестр объектов записывается: `[Ссылка #1] -> Исходный объект graph`.
3.  **Рекурсивный обход:** Алгоритм спускается во вложенный массив `childNodes` и начинает обрабатывать первый дочерний узел.
4.  **Обнаружение циклической ссылки:** Алгоритм доходит до свойства `parentRef` дочернего узла. Он видит, что значением является ссылка на исходный `graph` (`Ссылка #1`). Алгоритм не идет дальше, а просто делает пометку в бинарном потоке: "Свяжи `parentRef` со `Ссылкой #1`".
5.  **Восстановление структуры:** При чтении потока V8 создает новые объекты в памяти и восстанавливает циклическую связь: `clonedGraph.childNodes[0].parentRef` начинает указывать на вновь созданный корневой `clonedGraph`.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Попытка клонирования объектов, содержащих функции или методы (DataCloneError)**
    *   *Проблема:* Запуск `structuredClone` на экземпляре класса, у которого есть методы, или на объекте, хранящем стрелочные функции. Программа падает с критической ошибкой `DOMException: Failed to execute 'structuredClone'...`.
    *   *Причина:* Функции невозможно сериализовать во внутренний бинарный формат V8, так как они неразрывно связаны со своими лексическими окружениями и замыканиями в куче.
    *   *Решение:* Если вам нужно клонировать объект с методами, используйте spread-оператор (для поверхностной копии) или пишите кастомную фабрику клонирования, которая пересоздает объект через класс.

```typescript
// ПЛОХО (Метод execute вызовет падение всего алгоритма клонирования)
export class DynamicExecutor {
  constructor(public data: string) {}
  public execute() { console.log(this.data); }
}
const exec = new DynamicExecutor("test");
// const failedCopy = structuredClone(exec); // ! DOMException: structuredClone() could not clone

// ХОРОШО (Иммутабельное пересоздание экземпляра класса вручную)
const cleanCopy = new DynamicExecutor(exec.data); // Методы класса наследуются через прототип
```

*   **Ошибка 2: Потеря прототипной цепочки у пользовательских классов**
    *   *Проблема:* При клонировании экземпляра кастомного класса (даже без методов) через `structuredClone`, результирующий объект теряет связь со своим классом и превращается в обычный плоский объект типа `Object`.
    *   *Причина:* По спецификации алгоритм воссоздает объекты общего типа, не сохраняя кастомную цепочку прототипов пользователя.
    *   *Решение:* После клонирования вручную восстанавливайте прототип объекта с помощью метода `Object.setPrototypeOf()`.

```typescript
// ПЛОХО (Экземпляр теряет свой класс после клонирования)
class CustomState { constructor(public value: number) {} }
const state = new CustomState(42);
const clonedState = structuredClone(state);
console.log(clonedState instanceof CustomState); // Вывод: false (Это теперь обычный Object)

// ХОРОШО (Ручное восстановление прототипной цепочки в рантайме)
const securedClonedState = structuredClone(state);
Object.setPrototypeOf(securedClonedState, CustomState.prototype); // Восстанавливаем прототип
console.log(securedClonedState instanceof CustomState); // Вывод: true
```

*   **Ошибка 3: Попытка клонирования DOM-элементов**
    *   *Проблема:* Запуск `structuredClone` на объектах, содержащих ссылки на нативные DOM-узлы (например, `HTMLDivElement`).
    *   *Причина:* DOM-узлы представляют собой тяжелые системные структуры браузера, не подлежащие бинарной сериализации.
    *   *Решение:* Не храните ссылки на элементы DOM внутри сложных объектов состояния. Разделяйте данные (state) и представление (view).
