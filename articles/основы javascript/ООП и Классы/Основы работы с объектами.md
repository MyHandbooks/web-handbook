# Основы работы с объектами

## БЫСТРЫЙ СТАРТ

*   **Объект (Object)** — это сложная динамическая структура данных, представляющая собой неупорядоченную коллекцию свойств формата «ключ: значение», где ключом выступает строка (или символ), а значением — любой тип данных.
*   **Хранение по ссылке** — в отличие от примитивов, объекты хранятся в куче (heap), а переменные хранят лишь ссылку (адрес ячейки памяти) на сам объект. При копировании переменной копируется только адрес ссылки.
*   **Используйте для:**
    *   Группировки связанных разнородных данных и методов для их обработки в единую логическую сущность.
    *   Создания конфигурационных моделей, DTO (Data Transfer Objects) и хранения состояния компонентов.
*   **Не используйте для:**
    *   Хранения упорядоченных списков однотипных элементов (для этого применяются массивы `Array`).
    *   Сценариев, требующих частого динамического добавления/удаления ключей произвольных типов (для этого оптимизирован `Map`).
    *   Хранения уникальных наборов значений без ключей (для этого используется `Set`).

### Шаблон 1: Безопасное глубокое копирование объектов
*   **Назначение:** Полное дублирование сложной вложенной структуры данных без сохранения ссылочной связи с оригиналом.

```typescript
export interface UserSession {
  id: string;
  profile: {
    displayName: string;
    roles: string[];
  };
  createdAt: Date;
}

export function cloneSessionData(source: UserSession): UserSession {
  // Проверяем, поддерживает ли среда выполнения современный стандарт structuredClone
  if (typeof structuredClone === "function") {
    // Выполняем полное глубокое копирование на уровне системного API браузера
    // Свойства Date, RegExp, Map, Set копируются корректно с сохранением типов
    return structuredClone(source);
  }

  // Резервный fallback для старых сред (содержит ограничения: Date превратится в строку, undefined сотрется)
  return JSON.parse(JSON.stringify(source));
}

export function executeCloningDemo(): void {
  const original: UserSession = {
    id: "session_09f",
    profile: {
      displayName: "Архитектор",
      roles: ["admin", "editor"]
    },
    createdAt: new Date()
  };

  // Копируем объект. Теперь оригинал и копия никак не связаны по ссылке в памяти
  const clone = cloneSessionData(original);

  // Изменение глубоко вложенного свойства в копии не ломает оригинал
  clone.profile.roles.push("super_user");

  console.log(`Оригинал (без изменений): ${original.profile.roles.join(", ")}`);
  console.log(`Копия (изменена): ${clone.profile.roles.join(", ")}`);
}
```

### Шаблон 2: Настройка неизменяемых свойств через дескрипторы
*   **Назначение:** Описание защищенного конфигурационного объекта с запретом на случайное изменение, удаление или скрытием служебных ключей от циклов перебора.

```typescript
export interface ProtectedConfig {
  readonly environment: string;
  readonly internalToken: string;
}

export function createProtectedConfig(): ProtectedConfig {
  const config: any = {};

  // Явно настраиваем метаданные свойств объекта
  Object.defineProperty(config, "environment", {
    value: "production",
    writable: false,      // Запрещаем изменять значение свойства
    enumerable: true,     // Разрешаем отображение в циклах for...in и Object.keys()
    configurable: false   // Запрещаем удаление свойства и изменение его дескрипторов
  });

  Object.defineProperty(config, "internalToken", {
    value: "secret_sha256_hash",
    writable: false,
    enumerable: false,    // Скрываем свойство от циклов перебора и сериализации
    configurable: false
  });

  // Замораживаем сам объект первого уровня (предотвращает добавление новых свойств)
  Object.preventExtensions(config);

  return config as ProtectedConfig;
}

export function demonstrateDescriptorProtection(): void {
  "use strict"; // Строгий режим заставит движок выбросить ошибки при нарушениях

  const secureConfig = createProtectedConfig();

  try {
    // Попытка перезаписать readonly свойство
    (secureConfig as any).environment = "staging"; // ! Ошибка: TypeError
  } catch (error: unknown) {
    if (error instanceof TypeError) {
      console.warn(`[БЛОКИРОВКА ЗАПИСИ]: ${error.message}`);
    }
  }

  // Свойство internalToken скрыто от перебора, но доступно при прямом обращении
  console.log(`Список публичных ключей: ${Object.keys(secureConfig).join(", ")}`);
  console.log(`Прямой доступ к токену: ${(secureConfig as any).internalToken}`);
}
```

### Шаблон 3: Безопасное чтение вложенных свойств и деструктуризация
*   **Назначение:** Чтение данных из глубоких API-ответов без падения приложения из-за отсутствия промежуточных узлов, с одновременным переименованием переменных.

```typescript
export interface ApiResponsePayload {
  data?: {
    resource?: {
      meta?: {
        versionCode?: number;
        checksum?: string;
      }
    }
  }
}

export function extractMetadata(response: ApiResponsePayload): { version: number; hash: string } {
  // 1. Безопасное чтение через optional chaining (?.) и nullish coalescing (??)
  // Если на любом этапе вернется null или undefined, вычисление прекратится и вернется дефолт
  const version = response?.data?.resource?.meta?.versionCode ?? 1;

  // 2. Деструктуризация с переименованием и дефолтными значениями
  // Извлекаем meta, если он есть, иначе берем пустой объект
  const { meta = {} } = response?.data?.resource ?? {};
  
  // Переименовываем checksum в hash и задаем дефолт
  const { checksum: hash = "no_hash_calculated" } = meta;

  return {
    version,
    hash
  };
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как движок V8 хранит свойства в памяти (Классы форм против Словарей)
В языках с компиляцией в машинный код (например, C++) смещения свойств в памяти известны заранее. В JavaScript объекты динамичны: свойства можно добавлять и удалять на лету. Чтобы это работало быстро, движок V8 использует три стратегии хранения свойств:

1.  **Встроенные свойства (In-object properties):**
    Самый быстрый тип доступа. V8 выделяет фиксированное количество слотов под свойства прямо в теле самого объекта в памяти. Смещение каждого свойства жестко зафиксировано.
2.  **Быстрые свойства (Fast/Hidden Class properties):**
    Если встроенных слотов не хватает, V8 создает специальный массив свойств вне объекта, а в объекте хранит ссылку на этот массив. Для быстрого поиска V8 использует **Скрытые классы (Hidden Classes / Shapes)**. 
    Когда объект создается, он получает ссылку на скрытый класс, содержащий карту смещений свойств в массиве. При добавлении свойства V8 инициирует переход (transition) к новому скрытому классу. Это позволяет выполнять доступ к свойствам за константное время O(1).
3.  **Медленные свойства (Slow/Dictionary properties):**
    Если в коде происходит частое динамическое удаление свойств через оператор `delete` или добавление хаотичного набора ключей, V8 понимает, что переходы между скрытыми классами становятся слишком дорогими. Объект переходит в **режим словаря (Dictionary Mode)**. Все свойства хранятся в виде обычной хэш-таблицы. Доступ к ним замедляется, так как V8 больше не может оптимизировать чтение через механизм Inline Caches (IC).

### 2. Работа цепочки прототипов и внутренний слот `[ [Prototype] ]`
Каждый объект в JavaScript имеет скрытую системную ссылку `[ [Prototype] ]` на другой объект-родитель. 

Физика поиска свойства (алгоритм `[ [Get] ]` спецификации ECMAScript):
1.  **Поиск в себе:** Движок V8 проверяет наличие свойства среди собственных ключей объекта.
2.  **Переход по цепочке:** Если свойство не найдено, движок считывает адрес из слота `[ [Prototype] ]` и переходит к объекту-прототипу.
3.  **Рекурсивный поиск:** Поиск повторяется по всей цепочке прототипов (Prototype Chain) вверх.
4.  **Вершина цепочки:** Поиск завершается, когда движок достигает `Object.prototype` (где определены базовые методы вроде `hasOwnProperty`), а затем ссылки `null`. Если свойство так и не найдено, возвращается `undefined`.

Мутация ссылки `[ [Prototype] ]` во время выполнения (через устаревший сеттер `__proto__` или `Object.setPrototypeOf`) является критическим антипаттерном производительности. Это полностью разрушает оптимизированные скрытые классы для всех задействованных объектов и сбрасывает доступ к свойствам в медленный режим поиска.

### 3. Детальный пошаговый разбор выполнения шаблона 2
1.  **Конструирование объекта:** Создается пустой объект `config`. В V8 ему присваивается базовый скрытый класс (Shape 0).
2.  **Определение свойства `environment`:** Вызывается `Object.defineProperty` с флагом `writable: false` и `configurable: false`.
3.  **Создание дескрипторов в V8:** Движок генерирует новый скрытый класс (Shape 1), в котором помечает, что свойство `environment` по смещению 0 защищено от перезаписи и удаления.
4.  **Попытка записи:** Выполняется инструкция `secureConfig.environment = "staging"`.
5.  **Проверка режима:** Движок V8 определяет, что активен строгий режим (`"use strict"`).
6.  **Анализ дескриптора:** V8 считывает метаданные свойства из скрытого класса Shape 1, видит флаг `writable: false`.
7.  **Генерация ошибки:** Поскольку запись в защищенное свойство в строгом режиме запрещена, V8 прерывает линейный поток выполнения кода, конструирует экземпляр класса `TypeError` и выбрасывает исключение вверх по стеку вызовов.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Утечка вложенных ссылок при поверхностном копировании (Shallow Copy Leak)**
    *   *Проблема:* Разработчик клонирует конфигурационный объект через spread-оператор `const clone = { ...original }`, меняет вложенное свойство в копии, но изменения неожиданно ломают оригинальный объект.
    *   *Причина:* Spread-оператор и метод `Object.assign` создают поверхностную копию. Они копируют свойства первого уровня по значению, а вложенные объекты и массивы копируются по ссылке.
    *   *Решение:* При наличии вложенных структур всегда используйте глубокое копирование с помощью `structuredClone()`.

```typescript
// ПЛОХО (Поверхностное копирование мутирует оригинал)
export function updateThemeUnsafe(original: any) {
  const copy = { ...original };
  copy.uiSettings.theme = "light"; // ! Сбой: original.uiSettings.theme также изменился
  return copy;
}

// ХОРОШО (Полная изоляция данных в памяти)
export function updateThemeSafe(original: any) {
  const copy = structuredClone(original);
  copy.uiSettings.theme = "light"; // Безопасно, копия полностью изолирована
  return copy;
}
```

*   **Ошибка 2: Ловушка неявного приведения ключей к строкам (String Coercion Trap)**
    *   *Проблема:* Разработчик пытается использовать объекты в качестве уникальных ключей в обычном объекте-словаре, но данные перезаписывают друг друга.
    *   *Причина:* Обычные JavaScript-объекты могут использовать в качестве ключей только строки и символы (`Symbol`). Любой переданный объект-ключ автоматически приводится к строке вызовом метода `toString()`, превращаясь в общую строку `"[object Object]"`.
    *   *Решение:* Если ключами должны выступать сложные объекты, используйте специализированную структуру `Map`.

```typescript
// ПЛОХО (Ключи перезапишут друг друга по строке "[object Object]")
export function saveMetadataUnsafe() {
  const dictionary: any = {};
  const userA = { id: 101 };
  const userB = { id: 102 };

  dictionary[userA] = "Metadata A";
  dictionary[userB] = "Metadata B"; // ! Перезапишет значение userA

  console.log(dictionary[userA]); // Вывод: "Metadata B" (данные утеряны!)
}

// ХОРОШО (Map корректно сравнивает объекты по ссылке в памяти)
export function saveMetadataSafe() {
  const dictionary = new Map<object, string>();
  const userA = { id: 101 };
  const userB = { id: 102 };

  dictionary.set(userA, "Metadata A");
  dictionary.set(userB, "Metadata B");

  console.log(dictionary.get(userA)); // Вывод: "Metadata A" (корректно)
}
```

*   **Ошибка 3: Просадка производительности из-за динамического изменения прототипов**
    *   *Проблема:* Разработчик пытается динамически подменить прототип объекта во время выполнения приложения с помощью метода `Object.setPrototypeOf(obj, newProto)`.
    *   *Причина:* Динамическое изменение прототипа приводит к мгновенной деоптимизации объекта в V8. Движок вынужден полностью уничтожить текущий скрытый класс (Shape) объекта и всех его наследников, перевести его в режим медленного словаря и сбросить кэш Inline Caches для всех связанных методов.
    *   *Решение:* Всегда создавайте объект с нужным прототипом сразу в момент инициализации с помощью метода `Object.create(proto)`.

```typescript
// ПЛОХО (Критическое падение производительности в V8)
export function createAnimalUnsafe() {
  const dog = { barks: true };
  const animalProto = { eats: true };
  
  // Меняем прототип на лету. Скрытый класс объекта dog полностью разрушен
  Object.setPrototypeOf(dog, animalProto); 
  return dog;
}

// ХОРОШО (Объект сразу инициализируется в памяти с нужной формой и прототипом)
export function createAnimalSafe() {
  const animalProto = { eats: true };
  
  // Объект создается с готовой цепочкой прототипов, V8 оптимизирует его форму
  const dog = Object.create(animalProto);
  dog.barks = true;
  return dog;
}
```
