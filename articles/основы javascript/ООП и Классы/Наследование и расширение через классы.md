# Наследование и расширение через классы

## БЫСТРЫЙ СТАРТ

*   **Классы в ES6** — это синтаксический сахар над классическим прототипным наследованием JavaScript. Конструкция `class` создает функцию-конструктор, а её методы записываются в объект-прототип этой функции.
*   **`extends`** — связывает прототипы двух классов: как прототипы их экземпляров (`Child.prototype.__proto__ === Parent.prototype`), так и прототипы самих функций-конструкторов (`Child.__proto__ === Parent`), позволяя наследовать статические методы.
*   **`super`** — выполняет два действия: в конструкторе дочернего класса вызывает конструктор родителя (`super()`), а в обычных методах дает прямой доступ к методам родителя (`super.method()`).
*   **Используйте наследование для:** создания логических иерархий с общим поведением и расширения базовых классов-сервисов.
*   **Не используйте:** глубокую вложенность наследования (более 2-3 уровней). Предпочитайте композицию наследованию (Composition over Inheritance).

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Базовое наследование и расширение (extends & super)
*   **Назначение:** Создание дочерней сущности, которая наследует базовые свойства и методы родителя, расширяет свой конструктор новыми полями и переопределяет методы.

```typescript
// Абстрактный интерфейс базового состояния
export interface TargetPayload {
  identifier: string;
  statePayload: string;
}

// Базовый класс, реализующий общую логику
export class BaseProcessor {
  constructor(public config: TargetPayload) {}

  public executeTask(): void {
    console.log(`[БАЗОВЫЙ] Обработка задачи для: ${this.config.identifier}`);
  }
}

// Дочерний класс, расширяющий базовый
export class CustomExtendedProcessor extends BaseProcessor {
  // Добавляем новое локальное свойство
  public customTimestamp: number;

  constructor(config: TargetPayload, timestamp: number) {
    // КРИТИЧЕСКИ ВАЖНО: Сначала вызываем конструктор родителя
    super(config); 
    
    // Только после super() мы можем безопасно использовать this и объявлять новые свойства
    this.customTimestamp = timestamp; 
  }

  // Полное переопределение (полиморфизм) метода родителя
  public override executeTask(): void {
    // Мы можем вызвать оригинальную логику родительского метода через super.
    super.executeTask(); 
    
    // И расширить её локальными действиями дочернего класса
    console.log(`[ДОЧЕРНИЙ] Дополнительное действие. Время: ${this.customTimestamp}`);
  }
}
```

### Шаблон 2: Наследование статических методов и свойств
*   **Назначение:** Передача вспомогательных фабричных методов от родительского класса к дочернему без создания экземпляров.

```typescript
export class BaseFactory {
  // Статическое свойство, привязанное к самому классу-конструктору
  public static defaultPrefix: string = "GENERIC_FACTORY";

  // Статический метод создания инстанса
  public static createInstance<T extends BaseFactory>(this: new () => T): T {
    // В статических методах this указывает на сам класс-конструктор, вызвавший метод
    console.log(`Инициализация фабрики: ${this.name}`);
    return new this(); 
  }
}

export class CustomFactory extends BaseFactory {
  // Дочерний класс автоматически наследует статические свойства и методы родителя
  public static override defaultPrefix: string = "CUSTOM_FACTORY";
}

export function executeStaticInheritance(): void {
  // Вызываем унаследованный статический метод на дочернем классе
  const instance = CustomFactory.createInstance();
  
  console.log(CustomFactory.defaultPrefix); // Вывод: "CUSTOM_FACTORY"
}
```

### Шаблон 3: Расширение встроенных системных классов
*   **Назначение:** Создание специализированных коллекций или ошибок на базе встроенных классов JavaScript (например, `Array`, `Error`, `Map`).

```typescript
// Создаем кастомный класс ошибок, наследуя встроенный Error
export class NetworkStateError extends Error {
  public timestamp: number;

  constructor(message: string, public statusCode: number) {
    // Инициализируем базовые свойства Error (message, stack)
    super(message); 
    
    // Записываем системное имя ошибки для корректного отображения в логах
    this.name = "NetworkStateError"; 
    this.timestamp = Date.now();

    // Восстанавливаем прототипную цепочку (критично при компиляции в старые стандарты ES5)
    Object.setPrototypeOf(this, new.target.prototype);
  }
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как наследование классов устроено под капотом движка V8
В отличие от традиционных языков, в JavaScript класс — это не физический чертеж объекта, а специальный тип функции-конструктора. Наследование через `extends` выстраивает **две параллельные цепочки прототипов**:

1.  **Цепочка прототипов экземпляров (Instance Chain):**
    Указывает, как объекты-экземпляры будут искать обычные методы. Движок связывает объект-прототип дочернего класса с объектом-прототипом родителя:
    `CustomExtendedProcessor.prototype.__proto__ === BaseProcessor.prototype`
2.  **Цепочка прототипов конструкторов (Constructor Chain/Static Chain):**
    Указывает, как дочерний класс-конструктор наследует свойства самого родительского класса (статические методы). Движок связывает сами функции-конструкторы:
    `CustomExtendedProcessor.__proto__ === BaseProcessor`

При вызове метода `super.executeTask()` во время выполнения движок V8 не ищет метод динамически по цепочке прототипов от `this`. Каждая функция метода в ES6-классе имеет внутренний скрытый слот `[[HomeObject]]`, который хранит ссылку на объект-прототип класса, где этот метод был объявлен. При вызове `super` движок берет `[[HomeObject]]`, находит его прототип через `__proto__` и запускает нужный метод строго из него, предотвращая ошибки при динамической потере контекста.

### 2. Почему в дочернем конструкторе вызов `super()` строго обязателен
В традиционном процедурном коде JS (ES5) при наследовании через функции-конструкторы память под `this` выделялась сразу в дочерней функции-конструкторе (через `new`), а родительский конструктор вызывался как вспомогательный метод `Parent.call(this)`.

В ES6-классах этот алгоритм изменен на противоположный:
*   Дочерний класс-конструктор помечается внутренним флагом **`derived`** (производный).
*   При вызове `new DerivedClass()` движок V8 **категорически запрещает выделять память для объекта `this`** на уровне дочернего класса.
*   Память для `this` обязан выделить и инициализировать **самый базовый (родительский) класс** в иерархии наследования.
*   Вызов `super()` запускает конструктор родителя, который создает объект `this`, наполняет его базовыми свойствами и передает его обратно "вверх" по цепочке дочернему конструктору. 
*   Любая попытка прочитать или записать свойства в `this` до успешного завершения вызова `super()` выбросит критическую ошибку `ReferenceError` (так как объект `this` физически еще не существует в текущем кадре стека памяти).

### 3. Детальный пошаговый разбор выполнения шаблона 1
1.  **Инициация вызова:** Выполняется `new CustomExtendedProcessor(config, 171717)`. Движок V8 видит, что класс имеет статус `derived`. Память под `this` не выделяется.
2.  **Переход в родительский конструктор:** Поток выполнения заходит в дочерний конструктор и немедленно натыкается на вызов `super(config)`. Движок переходит к конструктору `BaseProcessor`.
3.  **Создание `this`:** Конструктор `BaseProcessor` (базовый в цепочке) создает новый пустой объект в куче, записывает его адрес в стек в качестве локального `this`, выполняет инициализацию `this.config = config` и возвращает этот объект обратно в дочерний конструктор.
4.  **Расширение `this`:** Дочерний конструктор получает созданный объект `this` от родителя. Теперь обращение к `this` легально. Выполняется строчка `this.customTimestamp = timestamp`.
5.  **Возврат экземпляра:** Итоговый полностью собранный объект-экземпляр возвращается наружу.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Попытка использовать `this` до вызова `super()` в конструкторе**
    *   *Проблема:* Разработчик пытается логировать или настраивать локальные свойства до вызова родительского конструктора. Программа падает с ошибкой `ReferenceError`.
    *   *Решение:* Перенесите вызов `super()` на самую первую строчку тела конструктора дочерческого класса.

```typescript
// ПЛОХО (Вызов this до super приведет к падению)
export class BadDerived extends BaseProcessor {
  constructor(config: TargetPayload) {
    // this.customTimestamp = Date.now(); // ! ReferenceError: Must call super constructor before accessing 'this'
    super(config);
  }
}
```

*   **Ошибка 2: Потеря связи со статическими свойствами при неявном обращении**
    *   *Проблема:* Разработчик переопределяет статическое свойство в дочернем классе, но внутри родительского метода обращается к нему жестко через имя родителя (например, `BaseFactory.defaultPrefix`). В результате дочерний класс выведет родительское значение вместо своего.
    *   *Решение:* Обращайтесь к статическим свойствам динамически через контекст `this` или `new.target` внутри статических методов.

```typescript
// ПЛОХО (Метод выведет жестко "GENERIC", игнорируя переопределение потомка)
export class BadBase {
  public static prefix = "GENERIC";
  public static print() { console.log(BadBase.prefix); }
}
export class BadChild extends BadBase {
  public static override prefix = "CHILD";
}
// BadChild.print(); // Выведет "GENERIC" вместо "CHILD"!

// ХОРОШО (Использование динамического контекста this)
export class GoodBase {
  public static prefix = "GENERIC";
  public static print(this: typeof GoodBase) { console.log(this.prefix); } // this сошлется на класс-вызыватель
}
export class GoodChild extends GoodBase {
  public static override prefix = "CHILD";
}
// GoodChild.print(); // Успешно выведет "CHILD"
```

*   **Ошибка 3: Проблема прототипной цепочки при транспиляции встроенных классов (ES5-таргет)**
    *   *Проблема:* Вы наследуете встроенный класс (например, `Error` или `Array`), компилируете код в старый стандарт ES5 для совместимости, но в рантайме оператор `instanceof` перестает распознавать ваш дочерний класс, возвращая `false`.
    *   *Причина:* Спецификация ES5-функций не умеет правильно прокидывать и динамически связывать прототипы встроенных системных классов.
    *   *Решение:* Всегда вручную восстанавливайте цепочку прототипов вызовом `Object.setPrototypeOf(this, new.target.prototype)` на последней строчке конструктора.
