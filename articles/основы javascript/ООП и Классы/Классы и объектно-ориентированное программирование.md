# Классы и объектно-ориентированное программирование

## БЫСТРЫЙ СТАРТ

*   **Классы в JavaScript (ES6)** — это современный синтаксический сахар над классическим прототипным наследованием. Класс представляет собой особую функцию-конструктор, методы которой записываются в объект-прототип (`prototype`) этой функции.
*   **Инкапсуляция** — реализуется на уровне движка с помощью приватных полей с префиксом `#` (полное сокрытие в runtime) или защищенных полей с префиксом `_` (по соглашению разработчиков).
*   **Наследование** — выполняется через ключевое слово `extends` для связывания прототипов и `super` для обращения к родительскому конструктору и методам.
*   **Используйте для:**
    *   Проектирования сложных систем с собственным инкапсулированным состоянием и набором методов для его изменения.
    *   Создания переиспользуемых сервисов, контроллеров и UI-компонентов в объектно-ориентированном стиле.
*   **Не используйте для:**
    *   Простых функций-трансформеров данных (для этого лучше применять чистые немутирующие функции).
    *   Сценариев без сохранения состояния (Stateless), где создание экземпляров классов создает лишь избыточный расход оперативной памяти.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Создание базового класса с инкапсуляцией
*   **Назначение:** Описание сущности с приватными свойствами, геттерами и сеттерами для безопасного изменения данных с предварительной валидацией.

```typescript
export class UserAccount {
  // 1. Объявляем приватное свойство на уровне движка JS (начинается с #)
  // Доступ к нему извне класса физически невозможен
  #balance = 0;

  // 2. Объявляем защищенное свойство по соглашению сообщества (начинается с _)
  // Технически оно публично, но предупреждает коллег о нежелательности прямого изменения
  _accountType = "Standard";

  constructor(public readonly ownerName: string, initialDeposit: number) {
    if (initialDeposit > 0) {
      this.#balance = initialDeposit;
    }
  }

  // Геттер для безопасного контролируемого чтения приватного свойства
  public get balance(): string {
    return `${this.#balance} USD`;
  }

  // Сеттер для валидации данных перед записью в приватное свойство
  public set balance(amount: string) {
    const parsedAmount = parseFloat(amount);
    
    if (isNaN(parsedAmount) || parsedAmount < 0) {
      console.error("[ОШИБКА ВАЛИДАЦИИ] Сумма не может быть отрицательной или NaN.");
      return;
    }
    
    this.#balance = parsedAmount;
  }

  // Публичный метод, записываемый в UserAccount.prototype
  public printAccountDetails(): void {
    console.log(`Владелец: ${this.ownerName}, Тип: ${this._accountType}`);
  }
}
```

### Шаблон 2: Наследование и расширение родительского класса
*   **Назначение:** Создание дочернего класса, наследующего методы родителя, с переопределением методов и добавлением уникальных свойств.

```typescript
import { UserAccount } from "./UserAccount";

export class PremiumAccount extends UserAccount {
  private bonusMiles = 0;

  constructor(ownerName: string, initialDeposit: number, bonusMiles: number) {
    // Вызываем конструктор родительского класса. 
    // Это обязательное действие, создающее объект 'this' в памяти
    super(ownerName, initialDeposit);
    
    // Переопределяем защищенное свойство родителя
    this._accountType = "Premium";
    this.bonusMiles = bonusMiles;
  }

  // Переопределяем родительский метод с сохранением исходной логики
  public override printAccountDetails(): void {
    // Вызываем оригинальный метод родителя через super
    super.printAccountDetails();
    
    // Добавляем специфичную для дочернего класса логику
    console.log(`Премиум-бонусы: ${this.bonusMiles} миль`);
  }
}
```

### Шаблон 3: Статические свойства и методы
*   **Назначение:** Создание вспомогательных методов-фабрик или констант, привязанных к самому классу, а не к его экземплярам.

```typescript
export class CurrencyConverter {
  // Статическое свойство, привязанное непосредственно к классу CurrencyConverter
  public static readonly DEFAULT_CURRENCY = "USD";

  private static exchangeRates: Record<string, number> = {
    EUR: 0.92,
    GBP: 0.79
  };

  // Статический метод-фабрика для альтернативного создания экземпляров
  public static convert(amount: number, targetCurrency: string): number {
    const rate = this.exchangeRates[targetCurrency];
    
    if (!rate) {
      console.warn(`[КОНВЕРТЕР] Курс для ${targetCurrency} не найден. Возвращаем исходную сумму.`);
      return amount;
    }
    
    // Внутри статического метода this ссылается на сам класс, а не на экземпляр
    return amount * rate;
  }
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Синтаксический сахар над прототипами
Вопреки поведению классов в компилируемых языках (C++, Java), класс в JavaScript не является самостоятельной низкоуровневой сущностью. Это специальный тип функции.

Когда движок V8 компилирует объявление класса:
1.  Он создает функцию-конструктор с именем класса. Тело метода `constructor` компилируется в тело этой функции.
2.  Все методы, объявленные в классе (кроме конструктора и статических методов), компилируются и записываются во внутренний объект-прототип функции: `UserAccount.prototype.printAccountDetails = function() { ... }`.
3.  Статические методы записываются непосредственно на сам объект функции-конструктора: `CurrencyConverter.convert = function() { ... }`.

**Внутренний флаг `[ [IsClassConstructor] ]`**
Хотя `typeof UserAccount === "function"`, вызвать класс как обычную функцию без ключевого слова `new` (например, `UserAccount()`) запрещено на уровне спецификации. Движок V8 помечает созданную функцию скрытым слотом `[ [IsClassConstructor] ]: true`. При вызове функции движок проверяет этот флаг, и если он равен `true`, а вызов произошел без оператора `new` (через внутренний метод `[ [Call] ]` вместо `[ [Construct] ]`), генерируется критическая ошибка `TypeError`.

### 2. Наследование, вызов super() и фаза создания экземпляра
В классических языках при наследовании сначала создается дочерний объект, а затем на него накатываются родительские свойства. В JavaScript архитектура создания объектов-наследников перевернута:

1.  **Создание базы родителем:** Объект `this` физически создается базовым (родительским) классом.
2.  **Делегация дочернему классу:** Дочерний класс получает этот созданный родительский объект `this` и расширяет его своими локальными свойствами.

Именно поэтому вызов метода `super()` является строго обязательным в конструкторе дочернего класса и должен происходить **до первого обращения к `this`**. Если попытаться прочитать или записать свойство в `this` до вызова `super()`, движок прервет выполнение и выбросит ошибку `ReferenceError`. В этот момент объект `this` в памяти еще физически не инициализирован.

### 3. Детальный пошаговый разбор выполнения шаблона 2
Рассмотрим процесс выполнения инструкции `const premium = new PremiumAccount("Алексей", 1000, 250)`:
1.  **Инициация `[ [Construct] ]`:** Движок V8 вызывает внутренний конструктор `PremiumAccount` с аргументами.
2.  **Запуск `super()`:** Первой строчкой вызывается `super("Алексей", 1000)`. Движок перенаправляет вызов в конструктор родительского класса `UserAccount`.
3.  **Выделение памяти родителем:** `UserAccount` создает пустой объект в куче, связывает его внутреннее свойство `[ [Prototype] ]` со свойствами `PremiumAccount.prototype` (чтобы наследовались методы дочернего класса) и привязывает его к локальному `this`.
4.  **Заполнение свойств родителя:** Конструктор родителя записывает свойства `ownerName = "Алексей"` и приватный `#balance = 1000`.
5.  **Возврат `this` дочернему классу:** Управление возвращается в конструктор `PremiumAccount`. Инициализированный объект `this` становится доступным для дальнейшего расширения.
6.  **Заполнение свойств наследника:** Записываются свойства `_accountType = "Premium"` и `bonusMiles = 250`.
7.  **Возврат экземпляра:** Готовый объект возвращается и записывается в переменную `premium`.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Потеря контекста `this` при передаче методов класса в качестве колбэков**
    *   *Проблема:* Разработчик передает метод класса напрямую в таймер или слушатель событий (например, `setTimeout(myAccount.printAccountDetails, 100)`). Метод выполняется с потерей данных или падает с ошибкой `TypeError`.
    *   *Причина:* Метод передается как голая ссылка на функцию. В момент асинхронного вызова перед методом нет точки и объекта, поэтому `this` вычисляется как `undefined` (в строгом режиме).
    *   *Решение:* Оборачивайте вызов в стрелочную функцию или используйте синтаксис свойств класса со стрелочной функцией (Class Fields Arrow Functions).

```typescript
// ПЛОХО (Потеря контекста при вызове таймером)
export class BadController {
  private status = "running";

  public initTimer(): void {
    // Передается только ссылка, this будет равен undefined в рантайме
    setTimeout(this.showStatus, 100); // ! Сбой: TypeError
  }

  private showStatus(): void {
    console.log(this.status);
  }
}

// ХОРОШО (Использование свойств класса со стрелочной функцией)
export class GoodController {
  private status = "running";

  public initTimer(): void {
    // Метод уже жестко связан с контекстом экземпляра при создании
    setTimeout(this.showStatus, 100); 
  }

  // Стрелочная функция в поле класса автоматически биндится к экземпляру при new
  private showStatus = (): void => {
    console.log(this.status);
  }
}
```

*   **Ошибка 2: Ошибка `ReferenceError` при пропуске `super()` в конструкторе**
    *   *Проблема:* Разработчик забывает вызвать `super()` в конструкторе наследуемого класса или пытается обратиться к `this` до его вызова.
    *   *Причина:* Спецификация запрещает обращение к `this` в дочерних конструкторах до выполнения родительской инициализации.
    *   *Решение:* Всегда вызывайте `super()` первой строчкой в конструкторе дочернего класса, если он расширяет родительский класс.

```typescript
// ПЛОХО (Синтаксический сбой ReferenceError при инициализации)
export class BadChild extends UserAccount {
  constructor(ownerName: string, initialDeposit: number) {
    // @ts-ignore
    this._accountType = "Child"; // ! Сбой: обращение к this до super()
    super(ownerName, initialDeposit);
  }
}

// ХОРОШО (Сначала создаем контекст через super, затем изменяем свойства)
export class GoodChild extends UserAccount {
  constructor(ownerName: string, initialDeposit: number) {
    super(ownerName, initialDeposit); // Инициализация родителя
    this._accountType = "Child";      // Безопасное изменение свойств
  }
}
```

*   **Ошибка 3: Ошибка `TypeError` при попытке динамического обращения к приватным `#` свойствам**
    *   *Проблема:* Разработчик пытается динамически прочитать приватное свойство через квадратные скобки: `const balance = user['#balance']`.
    *   *Причина:* Приватные свойства не являются обычными динамическими ключами хэш-таблицы объекта. Они компилируются во внутренние закрытые лексические области видимости (WeakMaps на уровне V8). Обращение к ним жестко фиксируется на этапе парсинга кода. Динамический доступ по строковому ключу к приватным полям запрещен и всегда вернет `undefined`.
    *   *Решение:* Предоставляйте публичные геттеры и сеттеры для контролируемого доступа к приватным данным.

```typescript
// ПЛОХО (Вернет undefined, динамический доступ невозможен)
export function readPrivateUnsafe(account: UserAccount): any {
  // @ts-ignore
  return account["#balance"]; // ! Всегда вернет undefined
}

// ХОРОШО (Использование публичного геттера, возвращающего значение)
export function readPrivateSafe(account: UserAccount): string {
  return account.balance; // Обращение к публичному геттеру класса
}
```
