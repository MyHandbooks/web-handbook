# Строгий режим use strict

## БЫСТРЫЙ СТАРТ

*   **Строгий режим (`strict mode`)** — это специальный режим выполнения JavaScript, отключающий устаревшие, небезопасные или неоднозначные особенности синтаксиса и принудительно заставляющий движок реагировать на скрытые ошибки (silent errors) генерацией явных исключений.
*   **Директива `"use strict";`** — записывается в виде простой строки на первой строчке файла (для глобальной активации) или на первой строчке внутри тела функции (для локальной активации).
*   **Автоматическое включение** — строгий режим всегда включен по умолчанию внутри любых современных ES-модулей (файлы, импортируемые через `import`/`export` или подключенные как `type="module"`) и внутри тела классов (`class`).
*   **Правила безопасности** — запрещает неявное создание глобальных переменных, изолирует область видимости функций типа `eval`, делает глобальный контекст `this` равным `undefined` (вместо `window`) для простых вызовов и предотвращает попытки перезаписи защищенных свойств.

### Шаблон 1: Активация строгого режима на уровне файла и функции
*   **Назначение:** Изоляция кода и предотвращение неявного загрязнения глобальной области видимости необъявленными переменными.

```typescript
// Активация на уровне всего файла (должна быть строго на первой строчке)
"use strict";

export interface LogPayload {
  level: string;
  payload: string;
}

export function initializeSystem(): void {
  // Код выполняется в строгом режиме
  const systemState = "active_state";
  
  try {
    // ПЛОХО: Запись в переменную без объявления ключевыми словами let/const
    // В обычном режиме JS тихо создал бы свойство window.configValue = "debug"
    // В строгом режиме это вызовет мгновенный сбой ReferenceError
    (window as any).configValue = "debug"; 
    
    // Прямое присвоение необъявленной переменной
    // @ts-ignore (подавляем предупреждение компилятора TS для демонстрации поведения JS)
    undeclaredVar = "temporary_data"; 

  } catch (error: unknown) {
    if (error instanceof ReferenceError) {
      console.error(`[СИСТЕМНЫЙ СБОЙ] Ошибка области видимости: ${error.message}`);
    }
  }
}

// Локальная активация для старых или сторонних интеграций, не поддерживающих глобальный strict mode
export function legacyIntegration(): void {
  // Этот код выполняется в обычном режиме (Sloppy Mode)
  let legacyFlag = true;

  (function() {
    // Включаем строгий режим локально только внутри этой IIFE-функции
    "use strict";
    
    // Любые небезопасные операции здесь будут заблокированы движком
    console.log("Локальный строгий режим активен.");
  })();
}
```

### Шаблон 2: Безопасный контекст выполнения
*   **Назначение:** Предотвращение утечек контекста `this` в глобальный объект `window` при случайных вызовах методов вне контекста объектов.

```typescript
export class ConfigurationManager {
  private activeTheme = "dark_theme";

  public getTheme(): string {
    return this.activeTheme;
  }
}

export function executeContextInspection(): void {
  "use strict";

  const manager = new ConfigurationManager();
  
  // Извлекаем ссылку на метод (теряем контекст объекта manager)
  const unboundGetTheme = manager.getTheme;

  try {
    // Вызов простой функции без объекта перед точкой
    // В обычном режиме: this внутри unboundGetTheme сослался бы на window
    // В строгом режиме: this равен строго undefined, предотвращая утечку
    unboundGetTheme(); 
  } catch (error: unknown) {
    if (error instanceof TypeError) {
      console.warn(`[КОНТЕКСТ ЗАБЛОКИРОВАН] Ошибка вызова: ${error.message}`);
      // can't read properties of undefined (reading 'activeTheme')
    }
  }
}
```

### Шаблон 3: Защита дескрипторов объектов от некорректной записи
*   **Назначение:** Явный перехват ошибок при попытках изменить неизменяемые свойства, настроенные через дескрипторы метаданных.

```typescript
export interface ImmutableConfig {
  readonly environment: string;
  readonly apiVersion: string;
}

export function configureImmutableObject(): ImmutableConfig {
  "use strict";

  const config: any = {};

  // Тонкая настройка свойств через дескрипторы
  Object.defineProperty(config, "environment", {
    value: "production",
    writable: false,      // Запрещаем перезапись значения
    enumerable: true,     // Разрешаем перечисление в циклах
    configurable: false   // Запрещаем удаление свойства
  });

  Object.defineProperty(config, "apiVersion", {
    value: "v2",
    writable: false,
    enumerable: true,
    configurable: false
  });

  try {
    // Попытка перезаписать неизменяемое свойство
    // В обычном режиме: операция тихо проигнорируется, значение останется "production"
    // В строгом режиме: движок выбросит TypeError, не маскируя ошибку
    config.environment = "staging"; 

  } catch (error: unknown) {
    if (error instanceof TypeError) {
      console.error(`[ЗАЩИТА ЗАПИСИ] Ошибка: ${error.message}`);
    }
  }

  try {
    // Попытка удалить неконфигурируемое свойство
    // В обычном режиме: операция тихо вернет false, свойство не удалится
    // В строгом режиме: выбросит TypeError
    delete config.apiVersion;

  } catch (error: unknown) {
    if (error instanceof TypeError) {
      console.error(`[ЗАЩИТА СТРУКТУРЫ] Не удалось удалить свойство: ${error.message}`);
    }
  }

  return config as ImmutableConfig;
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как строгий режим оптимизирует выполнение в движке V8
Строгий режим — это не просто набор синтаксических запретов. Он напрямую помогает компиляторам движка (таким как Ignition и TurboFan в V8) генерировать более оптимизированный и быстрый машинный код.

В обычном (слоппи) режиме движок вынужден учитывать динамическую природу JavaScript:
1.  **Оптимизация Scope Chain:** В обычном режиме при вызове `eval` или при использовании конструкции `with`, новые переменные могут динамически добавляться в текущую область видимости во время выполнения. Это заставляет V8 отключать оптимизацию кэширования контекстов (Inline Caches) для поиска переменных, так как структура области видимости может измениться в любой момент. В строгом режиме конструкция `with` полностью запрещена на этапе парсинга, а `eval` создает свою собственную изолированную область видимости. Это позволяет V8 статически анализировать цепочку областей видимости и оптимизировать доступ к локальным переменным.
2.  **Оптимизация вызовов функций:** Поскольку в строгом режиме `this` для простых вызовов функций равен `undefined`, а не глобальному объекту `window`, движку не нужно выполнять тяжелую операцию неявной конвертации/упаковки (boxing) контекста в глобальный объект при каждом запуске функции.

### 2. Изменение семантики языка и внутренние слоты движка
Строгий режим изменяет поведение некоторых базовых механизмов спецификации ECMAScript:

*   **Изоляция объекта `arguments`:** 
    В обычном режиме параметры функции и элементы объекта `arguments` связаны по ссылке (sharing). Если изменить значение локального параметра, значение в `arguments` изменится автоматически:
    ```javascript
    function sloppy(x) {
      x = 42;
      console.log(arguments[0]); // 42 (связь активна)
    }
    ```
    В строгом режиме эта связь разорвана на уровне спецификации. Объект `arguments` копирует исходные переданные значения в свой внутренний массив и больше не реагирует на мутации локальных переменных:
    ```javascript
    function strict(x) {
      "use strict";
      x = 42;
      console.log(arguments[0]); // исходное значение (связь разорвана)
    }
    ```
*   **Запрет неверных имен в `LHS` (Left-Hand Side) присваиваниях:**
    При парсинге строгий режим проверяет корректность выражений присваивания. Например, попытка присвоить значение результату вызова функции или записать данные в неизменяемую ссылку (`const`) приведет к ошибкам на самом раннем этапе статического анализа.

### 3. Детальный пошаговый разбор выполнения шаблона 3
1.  **Конфигурация свойства:** Вызывается `Object.defineProperty` для настройки свойства `environment` объекта `config` с флагом `writable: false`. Движок V8 записывает эти флаги во внутреннюю структуру метаданных объекта (Hidden Class / Map объекта).
2.  **Попытка записи:** Выполняется инструкция `config.environment = "staging"`.
3.  **Поиск в цепочке:** Движок V8 производит поиск свойства `environment` в объекте `config` (операция `Set` в спецификации ECMAScript).
4.  **Анализ дескрипторов:** Движок находит свойство и считывает его дескрипторы. Он видит, что флаг `writable` равен `false` (свойство только для чтения).
5.  **Ветвление логики:** 
    *   *В обычном режиме:* Движок прекращает операцию записи, тихо возвращает управление на следующую строчку кода. Значение свойства остается неизменным.
    *   *В строгом режиме:* Движок видит активный флаг `strict` в текущем контексте выполнения (Execution Context). Он прерывает выполнение операции, конструирует объект класса `TypeError` с сообщением о невозможности записи в readonly-свойство и выбрасывает исключение вверх по Call Stack.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Неявная глобальная переменная (`ReferenceError`)**
    *   *Проблема:* Разработчик допускает опечатку в имени переменной или забывает указать `const`/`let`. В обычном режиме это привело бы к утечке памяти и созданию глобального свойства `window.userName = "Alex"`. В строгом режиме выбрасывается `ReferenceError`.
    *   *Причина:* Попытка выполнить `LHS`-поиск (поиск для записи) для переменной, которая отсутствует в текущей цепочке лексических окружений.
    *   *Решение:* Всегда явно объявляйте переменные с помощью `let` или `const`, контролируйте область видимости.

```typescript
// ПЛОХО (Вызовет ошибку ReferenceError в строгом режиме)
export function saveProfileSloppy() {
  "use strict";
  userProfileName = "Alex"; // ! Сбой: переменная не объявлена
}

// ХОРОШО (Переменная строго локализована)
export function saveProfileStrict() {
  "use strict";
  const userProfileName = "Alex"; 
  console.log(`Профиль сохранен: ${userProfileName}`);
}
```

*   **Ошибка 2: Сбои при удалении свойств (`TypeError` / `SyntaxError`)**
    *   *Проблема:* Разработчик пытается использовать оператор `delete` для удаления обычной переменной, функции или свойства, настроенного как неконфигурируемое (`configurable: false`).
    *   *Причина:* Оператор `delete` предназначен для удаления динамических свойств объектов. Удаление локальных переменных из лексического окружения или неконфигурируемых системных свойств запрещено.
    *   *Решение:* Не пытайтесь удалять переменные через `delete`. Для удаления свойств объектов убедитесь, что они являются конфигурируемыми, либо используйте иммутабельное конструирование новых объектов (через `Omit` или деструктуризацию).

```typescript
// ПЛОХО (Синтаксическая ошибка в строгом режиме)
export function destroyScopeSloppy() {
  "use strict";
  let tempValue = 100;
  // @ts-ignore
  delete tempValue; // ! Ошибка: delete не может удалять локальные переменные
}

// ХОРОШО (Иммутабельное исключение свойств)
export function excludePropertySafe(data: Record<string, any>, keyToExclude: string) {
  "use strict";
  const { [keyToExclude]: _, ...rest } = data; // Создаем копию без указанного ключа
  return rest;
}
```

*   **Ошибка 3: Изменение параметров через `arguments`**
    *   *Проблема:* Разработчик ожидает, что изменение параметров функции внутри её тела синхронно обновит значения в объекте `arguments` (или наоборот). В строгом режиме эти данные рассинхронизированы, что приводит к неверным расчетам.
    *   *Причина:* В строгом режиме объект `arguments` является статическим снимком переданных параметров на момент входа в функцию.
    *   *Решение:* Никогда не мутируйте входящие параметры функций (это также нарушает принцип чистых функций). Если вам нужно изменить значение, скопируйте его в новую локальную переменную.

```typescript
// ПЛОХО (Непредсказуемое поведение из-за рассинхронизации)
export function calculateTaxSloppy(salary: number): number {
  "use strict";
  salary = salary * 0.87; // Мутируем входящий параметр
  // arguments[0] по-прежнему хранит исходный оклад, а не измененный!
  return arguments[0] * 0.13; 
}

// ХОРОШО (Использование изолированной переменной)
export function calculateTaxStrict(salary: number): number {
  "use strict";
  const netSalary = salary * 0.87; // Исходный параметр salary не тронут
  const originalSalary = salary;   // Явное сохранение исходного значения
  return originalSalary * 0.13;
}
```
