# Переменные и области видимости

## БЫСТРЫЙ СТАРТ

*   **Переменная** — это именованная ссылка на ячейку в оперативной памяти компьютера (в контексте движка V8), которая хранит примитивное значение в стеке или ссылку на сложную структуру данных в куче (Heap).
*   **Область видимости (Scope)** — системные границы в коде, определяющие доступность переменных для чтения и записи. Бывает глобальной, функциональной и блочной.
*   **Конструкции `let` и `const`** — обладают блочной областью видимости (ограничены ближайшими фигурными скобками `{}`), исключают повторные объявления и не загрязняют глобальный контекст `window` / `globalThis`.
*   **Временная мертвая зона (TDZ)** — состояние переменной `let` или `const` от момента входа в ее область видимости до физической строки объявления в коде. Любая попытка прочитать или записать переменную в TDZ вызывает критическое исключение `ReferenceError`.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Безопасная блочная изоляция данных и предотвращение утечек
*   **Назначение:** Ограничение видимости конфиденциальных или временных данных рамками логического блока с гарантированной защитой от изменения внешними процессами.

```javascript
// Конфигурационный объект верхнего уровня (глобальная или модульная область)
const globalConfig = { Environment: "production" };

function processSystemTransaction(targetId) {
  // Переменная изолирована на уровне функциональной области видимости
  const baseTransactionAmount = 5000;

  if (targetId === "special_id") {
    // let и const видны строго внутри этого блока if {}
    // Вне этих фигурных скобок переменная dataPayload физически не существует в памяти
    const dataPayload = { id: targetId, status: "pending" };
    
    // Перезаписываемая переменная для локальных расчетов в блоке
    let localMultiplier = 1.25; 
    
    const finalAmount = baseTransactionAmount * localMultiplier;
    console.log(`[ТРАНЗАКЦИЯ] Сумма со скидкой: ${finalAmount}`);
  }

  try {
    // Ошибка: Попытка обратиться к dataPayload за пределами ее блока if
    // Движок V8 выбросит ReferenceError, так как область видимости уничтожена
    console.log(dataPayload); 
  } catch (error) {
    if (error instanceof ReferenceError) {
      console.warn("[ЗАЩИТА] Доступ заблокирован: переменная dataPayload уничтожена.");
    }
  }
}
```

### Шаблон 2: Решение проблемы асинхронного цикла без var через лексическое замыкание let
*   **Назначение:** Корректная изоляция итерационных переменных в асинхронных процессах (таймеры, сетевые запросы, обработчики событий).

```javascript
// ПЛОХО (Использование устаревшего var приводит к утечке контекста)
function runUnsafeLoop() {
  for (var i = 0; i < 3; i++) {
    // i имеет функциональную область видимости (одну на всю функцию)
    // К моменту запуска таймаута i во всей функции уже равно 3
    setTimeout(() => {
      console.log(`[VAR] Итерация: ${i}`); // Выведет "3" три раза
    }, 100);
  }
}

// ХОРОШО (Использование блочного let)
function runSecureLoop() {
  for (let i = 0; i < 3; i++) {
    // При каждой итерации V8 создает отдельное лексическое окружение (Lexical Environment)
    // Каждая анонимная функция таймаута замыкается на свою собственную копию i в памяти
    setTimeout(() => {
      console.log(`[LET] Итерация: ${i}`); // Выведет корректно: 0, 1, 2
    }, 100);
  }
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Внутреннее устройство Лексического окружения (Lexical Environment) в V8
Каждая выполняемая конструкция `{}` (функция, блок `if`, цикл `for` или глобальный скрипт) ассоциирована со скрытым системным объектом движка V8 — **Лексическим окружением (Lexical Environment)**.

Лексическое окружение состоит из двух обязательных физических компонентов:
1.  **Environment Record (Запись окружения):** Локальная таблица хэш-карты в куче, в которой хранятся все локальные переменные, объявленные в текущем блоке, и параметры функций.
2.  **Outer Reference (Ссылка на внешнее окружение):** Физический указатель (адрес в памяти) на родительское лексическое окружение, в рамках которого был объявлен текущий блок кода.

```text
Схема поиска переменных (Scope Chain / Цепочка областей видимости):

  Глобальное Лексическое Окружение (Global LE)
  [ Environment Record: globalConfig: {...} ] <-------------------+
                                                                  |
  Лексическое Окружение Функции (Function LE)                     | (Outer Reference)
  [ Environment Record: baseAmount: 5000, targetId: "special" ] --+
                                                                  |
  Лексическое Окружение Блока If (Block LE)                       | (Outer Reference)
  [ Environment Record: dataPayload: {...}, localMultiplier: 1.25 ] -+
```

Когда код пытается прочитать значение переменной, движок V8 совершает каскадный поиск:
*   Сначала проверяется `Environment Record` текущего (самого глубокого) лексического окружения.
*   Если переменная не найдена, движок переходит по ссылке `Outer Reference` к родительскому окружению.
*   Поиск продолжается рекурсивно до тех пор, пока переменная не будет найдена, либо пока указатель `Outer Reference` не примет значение `null` (что означает достижение Глобального окружения). В случае неудачи генерируется `ReferenceError`.

### 2. Физика процессов Hoisting (Поднятия) и Temporal Dead Zone (TDZ)
Процесс выполнения любого JavaScript-файла движком V8 строго разделен на две фазы: **Компиляция (Compilation)** и **Выполнение (Execution)**.

1.  **Фаза компиляции (Парсинг):**
    Движок сканирует весь файл, строит абстрактное синтаксическое дерево (AST) и регистрирует все объявления переменных в `Environment Record` текущего лексического окружения.
    *   При нахождении `var`, движок резервирует место под переменную и сразу же инициализирует её значением `undefined`. Свойство поднятия (hoisting) позволяет обращаться к `var` до строчки объявления, возвращая `undefined`.
    *   При нахождении `let` или `const`, движок резервирует под них место в `Environment Record`, но оставляет их в статусе **«неинициализировано» (uninitialized)**.
2.  **Фаза выполнения:**
    Интерпретатор начинает выполнять инструкции построчно. С момента входа в блок кода до момента выполнения строки `let x = value;` переменная `x` находится во **Временной мертвой зоне (TDZ)**. Люкое обращение к ней в этот период (даже простая проверка `typeof x`) заблокировано на уровне спецификации стандарта ECMAScript и вызывает аварийный останов программы.

### 3. Детальный пошаговый разбор выполнения шаблона 2
Разберем физику работы цикла `for (let i = 0; i < 3; i++)` на уровне движка V8:
1.  **Инициализация цикла:** Создается родительское лексическое окружение цикла, в котором объявляется переменная `i` со значением `0`.
2.  **Первая итерация (`i = 0`):**
    *   V8 создает новое независимое дочернее лексическое окружение для текущей итерации.
    *   Внутри него создается константная копия переменной `i` со значением `0`.
    *   Колбэк, переданный в `setTimeout`, регистрируется в фоновом потоке Web API. Его скрытое свойство &#91;&#91;Environment&#93;&#93; записывает ссылку на лексическое окружение *первой итерации*, фиксируя значение `0`.
3.  **Переход к следующей итерации (`i = 1`):**
    *   V8 вычисляет `i++`.
    *   Создается новое (второе) лексическое окружение для итерации со своим значением `i = 1`.
    *   Второй колбэк `setTimeout` записывает в свойство &#91;&#91;Environment&#93;&#93; ссылку на лексическое окружение *второй итерации*, фиксируя значение `1`.
4.  **Выполнение асинхронных задач:**
    Спустя 100 мс колбэки по очереди попадают в очередь макрозадач (Macrotask Queue) и отправляются в стек вызовов. Каждый колбэк при выполнении ищет переменную `i` в своем сохраненном лексическом окружении и выводит уникальные зафиксированные значения (`0`, `1`, `2`).

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Обращение к переменной `let`/`const` до объявления в замыканиях (скрытая TDZ)**
    *   *Проблема:* Разработчик вызывает функцию, которая считывает внешнюю переменную, до того как эта переменная была физически объявлена в коде. Происходит падение с ошибкой `ReferenceError: Cannot access '...' before initialization`.
    *   *Причина:* Хотя функция считывает переменную в момент выполнения, само лексическое окружение, в котором объявлена переменная, на момент вызова функции все еще находится в фазе TDZ.
    *   *Решение:* Перенесите вызовы любых функций, зависящих от внешних переменных `let` и `const`, строго ниже строк инициализации этих переменных.

```javascript
// ПЛОХО (Функция вызвана в TDZ переменной targetPayload)
try {
  executeLog(); // Вызов функции
  const targetPayload = "system_active"; // Объявление
  
  function executeLog() {
    console.log(targetPayload); // ReferenceError
  }
} catch (e) {
  console.error(e.message);
}

// ХОРОШО (Инициализация завершена до вызова функции)
const targetPayload = "system_active";
executeLog(); // Выведет "system_active"

function executeLog() {
  console.log(targetPayload);
}
```

*   **Ошибка 2: Мутация внутренних свойств объекта, объявленного через `const`**
    *   *Проблема:* Разработчик объявляет объект через `const` и считает его защищенным от изменений, однако другие модули беспрепятственно меняют его внутренние свойства, ломая логику иммутабельности данных.
    *   *Причина:* Ключевое слово `const` защищает от перезаписи исключительно саму переменную (ссылку на адрес в куче), находящуюся в стеке. Сам объект, хранящийся в куче (Heap), остается открытым для мутаций.
    *   *Решение:* Если объект должен быть неизменяемым, используйте метод `Object.freeze()` для неглубокого замораживания или создавайте новые иммутабельные копии через structuredClone / spread-оператор.

```javascript
// ПЛОХО (Объект мутирует вопреки const)
const targetConfig = { port: 8080 };
targetConfig.port = 3000; // Мутация разрешена, V8 не выдаст ошибку

// ХОРОШО (Жесткое замораживание структуры в памяти)
const secureConfig = Object.freeze({ port: 8080 });
try {
  secureConfig.port = 3000; // TypeError в строгом режиме
} catch (e) {
  console.warn("[ЗАЩИТА] Запись в замороженный объект заблокирована.");
}
```

*   **Ошибка 3: Случайная глобализация переменных из-за отсутствия строгого режима (Global Leak)**
    *   *Проблема:* Разработчик пропускает объявление переменной (не пишет `let` или `const`), в результате чего переменная становится свойством глобального объекта `window` / `globalThis`, вызывая утечки памяти и неконтролируемые конфликты в кодовой базе.
    *   *Причина:* Без строгого режима (`"use strict"`) неявное присвоение необъявленной переменной заставляет движок V8 динамически создать свойство в глобальном объекте верхнего уровня.
    *   *Решение:* Всегда пишите `"use strict";` на первой строчке JS-файла, либо используйте ES-модули (модульные скрипты выполняются в строгом режиме по умолчанию).

```javascript
// ПЛОХО (Утечка переменной во внешнюю среду без strict mode)
function setLegacyState() {
  activeSessionId = "session_token_123"; // Создает window.activeSessionId
}
setLegacyState();
console.log(window.activeSessionId); // "session_token_123"
```
