# Типы данных и приведение типов

## БЫСТРЫЙ СТАРТ

*   **Примитивы (Primitives)** — хранятся в стеке (Stack) как неизменяемые (immutable) значения. При копировании примитива всегда создается его независимый дубликат.
*   **Сложные типы (Objects)** — хранятся в куче (Heap), а переменная в стеке содержит лишь адрес ячейки (ссылку) в памяти. При копировании дублируется только ссылка, а сам объект остается в памяти в единственном экземпляре.
*   **8 типов данных** — `Number`, `BigInt`, `String`, `Boolean`, `null`, `undefined`, `Symbol` (примитивы) и `Object` (сложный тип).
*   **Строгое сравнение (`===`)** — проверяет равенство значений без приведения типов (type coercion). Всегда приоритетно к использованию.
*   **Нестрогое сравнение (`==`)** — пытается привести операнды к числам по внутренним алгоритмам спецификации ECMAScript, что часто порождает скрытые баги в логике.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Безопасное обнаружение и валидация NaN
*   **Назначение:** Обнаружение нечислового значения (`NaN`) после выполнения математических операций с динамическими внешними данными.

```javascript
// Имитируем получение невалидных данных от внешнего API
const rawApiResponse = "not_a_number_string";

// Математическая операция возвращает NaN (Not-a-Number)
const processedPrice = Number(rawApiResponse) * 1.2;

// ПЛОХО: processedPrice === NaN всегда вернет false, так как NaN не равен самому себе
// ХОРОШО: Использование строгого статического метода Number.isNaN
if (Number.isNaN(processedPrice)) {
  // Метод проверяет, что тип равен Number и само значение является NaN
  console.warn("[ПРЕДУПРЕЖДЕНИЕ] Цена не может быть рассчитана: получено NaN.");
}

// Альтернативный хак (защита для старых сред выполнения):
// Единственное значение в JS, которое не равно самому себе — это NaN
if (processedPrice !== processedPrice) {
  console.log("[ЗАЩИТА] Значение гарантированно является NaN.");
}
```

### Шаблон 2: Безопасная проверка типов и защита от аномалии null
*   **Назначение:** Определение того, является ли переменная реальным объектом (исключая массивы, функции и аномальное значение `null`).

```javascript
function processTargetPayload(payload) {
  // ПЛОХО: typeof null возвращает "object" из-за исторической ошибки в V8
  // ХОРОШО: Проверка на равенство null перед инспектированием typeof
  const isRealObject = payload !== null && typeof payload === "object" && !Array.isArray(payload);

  if (isRealObject) {
    // Внутри этого блока гарантированно находится чистый объект {}
    console.log(`[ОБРАБОТКА] Объект валиден. Ключи: ${Object.keys(payload)}`);
  } else {
    // payload является примитивом, null или массивом
    console.warn("[ОТКЛОНЕНО] Данные не являются объектом.");
  }
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Физическая аллокация памяти: Стек (Stack) против Кучи (Heap) в движке V8
Каждая переменная в JavaScript размещается в оперативной памяти компьютера под управлением движка V8. Память жестко разделена на два физических хранилища:

```text
  СТЕК (Stack) - Быстрый, фиксированный         КУЧА (Heap) - Медленная, динамическая
  ┌─────────────────────────────────────┐      ┌─────────────────────────────────────┐
  │ let baseTax = 20;                   │      │                                     │
  │ let name = "Aleksey";               │      │                                     │
  │ let userRef = [Адрес #0xff32] ──────┼─────►│ #0xff32: { name: "Ivan", age: 30 }  │
  └─────────────────────────────────────┘      └─────────────────────────────────────┘
```

1.  **Стек (Stack):**
    *   Быстрая, упорядоченная структура памяти с фиксированным размером ячеек.
    *   Здесь хранятся локальные переменные текущего кадра выполнения (Stack Frame) и примитивные значения.
    *   При копировании примитива (`let b = a`) значение просто дублируется в новый байт-код стека. Они полностью независимы.
2.  **Куча (Heap):**
    *   Большая, неструктурированная область памяти для динамической аллокации.
    *   Здесь хранятся все сложные объекты (`Object`, `Array`, `Function`). Размер объектов заранее не известен и может меняться.
    *   В стек записывается только **указатель** (адрес ячейки памяти в куче, например `#0xff32`). При копировании переменной объекта (`let objB = objA`) копируется лишь этот 64-битный адрес из стека. Обе переменные начинают указывать на один и тот же физический объект в куче.

> **Низкоуровневая деталь V8:** Строки (`String`) в JS концептуально ведут себя как примитивы (иммутабельны). Однако из-за оптимизаций V8 длинные строки физически хранятся в куче, чтобы не переполнять стек, а в стеке удерживается ссылка на них. Для разработчика этот процесс скрыт за абстракцией языка.

### 2. Спецификация неявного приведения типов (Type Coercion) и алгоритм Abstract Equality Comparison
Неявное приведение типов происходит под управлением внутренних утилит спецификации ECMAScript: `ToBoolean`, `ToNumber`, `ToString` и `ToPrimitive`.

Разберем классический пример аномального нестрогого сравнения `[] == ![]`:

```text
Шаг 1: Правая часть ![] приводится к логическому Boolean.
       Поскольку массивы [] являются объектами (а объекты всегда Truthy), то ![] -> !true -> false.
       Уравнение: [] == false

Шаг 2: По спецификации (Section 7.2.14), если один из операндов Boolean, он приводится к числу.
       false приводится к ToNumber(false) -> 0.
       Уравнение: [] == 0

Шаг 3: Сравнивается объект [] и число 0. Объект приводится к примитиву ToPrimitive([]).
       Вызывается [].toString(), что дает пустую строку "".
       Уравнение: "" == 0

Шаг 4: Сравнивается строка "" и число 0. Строка приводится к ToNumber("") -> 0.
       Уравнение: 0 == 0 ===> Итог: true
```

### 3. Детальный пошаговый разбор выполнения шаблонов
*   **В шаблоне 1:** Конструктор `Number(rawApiResponse)` преобразует нечисловую строку в `NaN`. В V8 значение `NaN` представлено специфическим битовым паттерном с плавающей точкой (IEEE 754), у которого все биты экспоненты установлены в 1. По спецификации, операция сравнения `NaN === NaN` аппаратно заблокирована процессором и возвращает `false`. Метод `Number.isNaN` проверяет внутренний тип переменной в куче перед чтением флага NaN, обеспечивая точечную валидацию.
*   **В шаблоне 2:** Проверка `payload !== null` отсекает аномалию, после чего `typeof payload === "object"` безопасно проверяет, является ли переменная сложной ссылочной структурой. Вызов `!Array.isArray(payload)` гарантирует, что массивы не будут классифицированы как простые объекты.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Попытка прямого сравнения с `NaN` через `===`**
    *   *Проблема:* Разработчик пытается проверить результат деления на ноль или некорректного парсинга через `if (value === NaN)`, но этот блок никогда не выполняется.
    *   *Причина:* Согласно стандарту IEEE 754, `NaN` не равен ни одному значению, включая самого себя.
    *   *Решение:* Используйте метод `Number.isNaN()` или проверку на неравенство самому себе `value !== value`.

```javascript
// ПЛОХО (Сравнение всегда вернет false)
const result = "text" * 2;
if (result === NaN) {
  console.log("Ошибка!"); // Код недостижим
}

// ХОРОШО (Использование безопасного статического метода)
if (Number.isNaN(result)) {
  console.log("Вычисление вернуло невалидное число NaN.");
}
```

*   **Ошибка 2: Пропуск проверки на `null` при инспектировании объектов**
    *   *Проблема:* Код падает с ошибкой `Cannot read properties of null` при попытке прочитать свойства переменной после проверки `if (typeof value === "object")`.
    *   *Причина:* Исторический баг JS: `typeof null` возвращает `"object"`. В ранних версиях V8 ссылки кодировались 32-битными словами. Младшие 3 бита использовались как маркер типа. Тег `000` обозначал объект. Поскольку `null` являлся нулевым указателем (все биты равны 0), его тег также считался `000`.
    *   *Решение:* Всегда явно проверяйте переменную на равенство `null` перед проверкой `typeof`.

```javascript
// ПЛОХО (Падение в рантайме, если payload пришел как null)
function render(payload) {
  if (typeof payload === "object") {
    console.log(payload.id); // TypeError: Cannot read properties of null
  }
}

// ХОРОШО (Полная защита от null-аномалии)
function renderSafe(payload) {
  if (payload !== null && typeof payload === "object") {
    console.log(payload.id);
  }
}
```

*   **Ошибка 3: Ложные срабатывания условных блоков при неявном приведении пустых коллекций**
    *   *Проблема:* Разработчик ожидает, что пустой массив `[]` приведется к `false` в условном блоке `if (array)`, аналогично пустой строке, но код внутри блока выполняется вопреки ожиданиям.
    *   *Причина:* Все объекты в JavaScript (включая пустые массивы `[]` и объекты `{}`) по спецификации приводятся к логическому `true` (они являются Truthy).
    *   *Решение:* Проверяйте физический размер коллекции явно: `if (array.length > 0)` или приводите к логическому типу через двойное отрицание `!!`.

```javascript
// ПЛОХО (Пустой массив оценивается как true)
const items = [];
if (items) {
  console.log("Элементы есть!"); // Выполнится, даже если массив пуст
}

// ХОРОШО (Явная проверка длины)
if (items.length > 0) {
  console.log("Массив не пуст.");
}
```
