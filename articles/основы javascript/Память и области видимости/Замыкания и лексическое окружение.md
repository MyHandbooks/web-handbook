# Замыкания и лексическое окружение

## БЫСТРЫЙ СТАРТ

*   **Замыкание (Closure)** — это способность функции запоминать свою внешнюю область видимости (переменные родительского контекста) и иметь к ним доступ даже тогда, когда она выполняется вне этой родительской области.
*   **Скрытое свойство [ [Environment] ]** — каждый объект функции в куче (Heap) содержит ссылку на то конкретное Лексическое окружение (Lexical Environment), в котором функция была создана.
*   **Лексическое окружение (LE)** — создается при каждом запуске функции или блока `{}`. Состоит из таблицы локальных переменных и указателя на внешнее LE.
*   **Сборка мусора** — родительское лексическое окружение не удаляется из памяти, пока жива ссылка на дочернюю функцию, удерживающую на него указатель через [ [Environment] ].

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Создание изолированного приватного состояния (Инкапсуляция)
*   **Назначение:** Реализация безопасного счетчика с сокрытием внутренних данных от прямого изменения из внешнего глобального контекста.

```javascript
function createSecureCounter() {
  // Переменная count скрыта от внешнего мира внутри лексического окружения createSecureCounter
  let count = 0; 
  
  // Возвращаем анонимную функцию, которая замыкается на локальную переменную count
  return function() {
    count++; // Функция имеет доступ к count через Outer Reference
    return count;
  };
}

// Создаем первый изолированный счетчик
const counterA = createSecureCounter(); 
console.log(counterA()); // Выведет: 1
console.log(counterA()); // Выведет: 2

// Создаем второй счетчик. Он получает свое собственное независимое лексическое окружение в памяти
const counterB = createSecureCounter();
console.log(counterB()); // Выведет: 1 (полностью независимый результат)
```

### Шаблон 2: Безопасный асинхронный цикл с использованием let
*   **Назначение:** Предотвращение ловушки общего состояния (Shared State) в циклах с асинхронными вызовами за счет создания независимых лексических окружений на каждой итерации.

```javascript
function runSecureIntervals() {
  // Использование let гарантирует создание нового лексического окружения для каждого шага
  for (let i = 0; i < 3; i++) {
    // Каждая анонимная функция таймаута замыкается на свое локальное i
    setTimeout(function() {
      // Каждый запуск выведет уникальное значение i, зафиксированное на момент итерации
      console.log(`[LET] Индекс: ${i}`); // Выведет последовательно: 0, 1, 2
    }, 100);
  }
}

runSecureIntervals();
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Архитектурный механизм: Скрытое системное свойство [ [Environment] ]
В JavaScript все функции являются замыканиями. Механизм их работы на уровне движка V8 основан на скрытом системном свойстве **[ [Environment] ]**, которое вшивается в объект функции при ее компиляции:

```text
  Фаза создания функции createSecureCounter() в глобальном контексте:
  ┌────────────────────────────────────────────────────────┐
  │ Глобальное Лексическое Окружение (Global LE)           │
  │ [ Environment Record: createSecureCounter, counterA ]  │
  └──────────────────────────┬─────────────────────────────┘
                             │
                             ▼ (Запись ссылки на Global LE в [ [Environment] ])
  ┌────────────────────────────────────────────────────────┐
  │ Объект функции в Куче (Heap)                           │
  │ - [ [Environment] ] ──► Ссылка на Global LE            │
  └────────────────────────────────────────────────────────┘
```

1.  **Создание функции:** Когда движок V8 парсит код и создает объект функции в памяти, он немедленно записывает в ее скрытое свойство **[ [Environment] ]** ссылку на текущее активное лексическое окружение.
2.  **Вызов функции:** При каждом вызове функции создается новое Лексическое окружение (Lexical Environment). Указатель на внешнее окружение (`Outer Reference`) этого нового LE автоматически заполняется ссылкой, сохраненной в свойстве **[ [Environment] ]** вызываемой функции.

### 2. Сборщик мусора (Garbage Collector) и удержание лексических окружений в куче
Обычно, когда функция завершает выполнение, ее кадр из Call Stack выталкивается, а связанное лексическое окружение удаляется сборщиком мусора по алгоритму **Mark-and-Sweep** (очистка недостижимых объектов).

Однако, если функция возвращает дочернюю функцию наружу (например, мы присвоили её в глобальную переменную `counterA`), лексическое окружение родителя **остается досягаемым** в графе ссылок:

```text
  Глобальная переменная counterA 
     │
     ▼ (ссылается на дочернюю функцию)
  [ Дочерняя функция в куче ] 
     │
     ▼ (удерживает ссылку через [ [Environment] ])
  [ Родительское Лексическое Окружение createSecureCounter() ]
     │
     ▼ (содержит переменную count)
  [ Значение count: 2 ]
```

Поскольку дочерняя функция жива и на нее есть ссылка в глобальном контексте, вся цепочка родительского лексического окружения остается защищенной от удаления сборщиком мусора.

### 3. Детальный пошаговый разбор выполнения шаблона 1
1.  **Запуск `createSecureCounter()`:** В стеке создается фрейм выполнения. В куче аллоцируется новое лексическое окружение родителя с переменной `count = 0`.
2.  **Создание дочерней функции:** Внутри родительского контекста создается объект анонимной функции. В его свойство **[ [Environment] ]** записывается ссылка на текущее лексическое окружение `createSecureCounter()`.
3.  **Возврат и присвоение:** Дочерняя функция возвращается наружу и записывается в `counterA`. Фрейм `createSecureCounter()` покидает Call Stack, но его лексическое окружение в куче выжить обязано, так как на него ссылается `counterA.[ [Environment] ]`.
4.  **Вызов `counterA()`:** Создается новое лексическое окружение для вызова. Его `Outer Reference` указывает на сохраненное родительское LE. Код выполняет `count++`. Движок идет по цепочке `Outer Reference`, находит переменную `count` в родительском окружении и инкрементирует ее.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Утечки памяти (Memory Leaks) из-за удержания тяжелых данных в замыканиях**
    *   *Проблема:* Память приложения постепенно заполняется, приводя к зависанию или аварийному закрытию вкладки (OOM - Out of Memory).
    *   *Причина:* Возвращаемая дочерняя функция замыкается на родительское лексическое окружение, в котором объявлены тяжелые массивы или ссылки на DOM-элементы, даже если сама дочерняя функция их непосредственно не использует. Вся область памяти родителя остается заблокированной в куче.
    *   *Решение:* Явно зануляйте (`null`) тяжелые переменные в конце родительской функции перед возвратом дочерней, либо выносите их за рамки замыкания.

```javascript
// ПЛОХО (Тяжелый массив остается жить в памяти вместе с функцией-кликом)
function setupInsecureHandler() {
  const heavyData = new Array(1000000).fill("data");
  return function() {
    console.log("Клик зафиксирован."); // heavyData не используется, но остается в памяти!
  };
}
const clickHandler = setupInsecureHandler();

// ХОРОШО (Освобождаем память перед возвратом замыкания)
function setupSecureHandler() {
  let heavyData = new Array(1000000).fill("data");
  const result = heavyData[0]; // Обрабатываем данные
  heavyData = null; // Освобождаем ссылку для сборщика мусора
  
  return function() {
    console.log(`Клик зафиксирован. Данные первого элемента: ${result}`);
  };
}
const secureClickHandler = setupSecureHandler();
```

*   **Ошибка 2: Проблема общего состояния (Shared State) при создании нескольких замыканий в рамках одного вызова**
    *   *Проблема:* Разработчик создает два метода для работы с объектом, но изменения в одном непредсказуемо затирают или ломают данные в другом.
    *   *Причина:* Все дочерние функции, созданные и возвращенные в рамках **одного и того же** вызова родительской функции, разделяют между собой **одно общее лексическое окружение**.
    *   *Решение:* Осознанно проектируйте архитектуру с учетом того, что функции делят контекст, либо изолируйте их создание в разных вызовах.

```javascript
// ПЛОХО (Оба метода делят один и тот же count в памяти)
function createSharedCounter() {
  let count = 0;
  return {
    increment: () => ++count,
    decrement: () => --count
  };
}
const counter = createSharedCounter();
console.log(counter.increment()); // 1
console.log(counter.decrement()); // 0 (изменили ту же переменную)
```

*   **Ошибка 3: Ловушка захвата переменной `var` в асинхронных колбэках циклов**
    *   *Проблема:* Асинхронные обработчики выводят только финальный индекс счетчика цикла, игнорируя промежуточные шаги.
    *   *Причина:* `var` игнорирует блоки `{}` и имеет функциональную область видимости. Переменная создается в единственном экземпляре, на который замыкаются все колбэки.
    *   *Решение:* Замените `var` на `let`, что заставит V8 генерировать отдельный кадр лексического окружения для каждой итерации.

```javascript
// ПЛОХО (Все колбэки замкнуты на одну переменную i, которая к моменту выполнения равна 3)
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100); // Выведет "3" три раза
}

// ХОРОШО (let изолирует каждую итерацию в памяти)
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100); // Выведет: 0, 1, 2
}
```
