# Анатомия Angular-компонента и шаблоны

## БЫСТРЫЙ СТАРТ

*   **Компонент** — фундаментальный кирпичик интерфейса в Angular, объединяющий класс на TypeScript (логика), HTML-разметку (шаблон представления) и CSS-стили (оформление).
*   **Декларативное связывание (Data Binding)** — механизм синхронизации данных между классом и шаблоном: интерполяция `{{}}`, привязка свойств `[]`, событий `()` и двусторонняя привязка `[()]`.
*   **Встроенный Control Flow** — современный компилируемый синтаксис управления структурой шаблона (`@if`, `@else`, `@for`, `@switch`), исключающий использование тяжелых структурных директив и не требующий импорта общих модулей.
*   **Используйте для:** построения инкапсулированных, переиспользуемых элементов UI со строго изолированной областью видимости стилей и логики.
*   **Не используйте для:** описания сквозных глобальных процессов (для этого предназначены синглтон-сервисы внедрения зависимостей).

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Современный компонент интерактивного списка на сигналах и Control Flow
*   **Назначение:** Описание структуры standalone-компонента, разделенного на три файла, демонстрирующего работу условного вывода, циклического рендеринга с обязательным уникальным ключом `track` и динамическое управление CSS-классами.

#### 1. Файл логики: `modern-list.ts`
```typescript
// Импортируем системные декораторы, типы и примитивы реактивности
import { Component, ChangeDetectionStrategy, signal } from '@angular/core';

// Описываем строгую сигнатуру элемента списка задач
export interface ListItem {
  id: number;
  name: string;
  isCompleted: boolean;
}

@Component({
  // Задаем уникальный тег-селектор компонента для вызова в родительских шаблонах
  selector: 'app-modern-list',
  // standalone: true опущен, так как начиная с Angular 19 это поведение по умолчанию
  // Связываем компонент с внешним файлом разметки
  templateUrl: './modern-list.html',
  // Связываем компонент с внешним файлом CSS-стилей
  styleUrl: './modern-list.css',
  // Использование стратегии OnPush гарантирует перерисовку только при изменении сигналов или Inputs
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class ModernList {
  // Реактивный сигнал для управления отображением лоадера загрузки
  readonly isLoading = signal<boolean>(false);

  // Реактивный сигнал-массив для хранения списка элементов
  readonly items = signal<ListItem[]>([
    { id: 101, name: 'Разработать архитектуру модулей', isCompleted: false },
    { id: 102, name: 'Настроить CI/CD пайплайны', isCompleted: true }
  ]);

  toggleLoader(): void {
    // Безопасно инвертируем булево значение реактивного сигнала через update()
    this.isLoading.update(status => !status);
  }

  toggleTaskStatus(id: number): void {
    // Иммутабельно обновляем поле isCompleted у выбранной задачи по её уникальному идентификатору
    this.items.update(list => 
      list.map(item => item.id === id ? { ...item, isCompleted: !item.isCompleted } : item)
    );
  }
}
```

#### 2. Файл разметки: `modern-list.html`
```html
<section class="list-wrapper">
  <header class="list-header">
    <!-- Привязка события клика (Event Binding) к методу изменения состояния -->
    <button class="action-btn" (click)="toggleLoader()">
      Переключить лоадер загрузки
    </button>
  </header>

  <!-- Современный условный рендеринг Angular (Control Flow @if) -->
  @if (isLoading()) {
    <div class="loader-box">
      <p>Идет загрузка данных из базы...</p>
    </div>
  } @else {
    <ul class="task-list">
      <!-- Циклический рендеринг (@for) со строго обязательным уникальным ключом отслеживания track -->
      @for (task of items(); track task.id; let isFirst = $first) {
        <!-- Динамическое связывание класса [class.highlighted] на основе булевой переменной context-переменной -->
        <!-- Динамическое связывание [class.completed] на основе реактивного поля объекта -->
        <li class="task-item" 
            [class.highlighted]="isFirst"
            [class.completed]="task.isCompleted">
          
          <span class="task-name">{{ task.name }}</span>
          
          <!-- Привязка события клика для инверсии статуса задачи -->
          <button class="status-btn" (click)="toggleTaskStatus(task.id)">
            {{ task.isCompleted ? 'Вернуть' : 'Выполнить' }}
          </button>
        </li>
      } @empty {
        <!-- Блок @empty рендерится автоматически, если массив сигналов items пуст -->
        <li class="empty-state">Список запланированных задач пуст.</li>
      }
    </ul>
  }
</section>
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Архитектурная декомпозиция и изоляция стилей компонента
При компиляции Angular-компонента рантайм-движок по умолчанию изолирует его CSS-стили от влияния глобальной верстки страницы. За это отвечает встроенный механизм инкапсуляции стилей.

```text
Эмуляция Shadow DOM (Поведение по умолчанию - Emulated):
  Входящий HTML: <li class="task-item">
  Скомпилированный HTML в браузере: <li class="task-item" _ngcontent-c42>
  
  Входящий CSS: .task-item { color: red; }
  Скомпилированный CSS в браузере: .task-item[_ngcontent-c42] { color: red; }
```

**Модели инкапсуляции стилей (`ViewEncapsulation`):**
1.  **`Emulated`** (по умолчанию): Angular парсит CSS-стили компонента на этапе сборки и добавляет к их селекторам уникальные сгенерированные атрибуты хоста (например, `_ngcontent-c42`). Соответствующие атрибуты дописываются ко всем HTML-элементам шаблона. Это позволяет эмулировать концепцию Shadow DOM, изолируя стили компонента без накладных расходов на создание реальных теневых корней.
2.  **`None`**: Инкапсуляция полностью отключена. Стили компонента компилируются в стандартный глобальный CSS-документ и могут неявно переопределить оформление элементов по всему приложению.
3.  **`ShadowDom`**: Angular использует нативное браузерное API `Shadow DOM` для полной изоляции. Под капотом создается реальный теневой корень (`#shadow-root`), внутри которого монтируются стили и шаблон. Внешние глобальные CSS-правила физически не могут проникнуть внутрь такого компонента.

---

### 2. Физика встроенного Control Flow в Angular 19+
Встроенный Control Flow (`@if`, `@for`, `@switch`) преобразуется компилятором Angular на этапе сборки в прямые, сверхоптимизированные системные инструкции создания, перемещения и удаления DOM-узлов.

*   В отличие от старого подхода с использованием директив (`*ngIf`, `*ngFor`), которые являлись обычными TypeScript-классами и требовали динамического инстанцирования тяжеловесных сущностей `ViewContainerRef` и `TemplateRef` в рантайме, новый синтаксис компилируется в плоскую структуру вызовов.
*   Отсутствуют накладные расходы на парсинг микросинтаксиса во время выполнения, а компилятор может проводить более строгую статическую проверку типов данных, используемых внутри условий шаблона.
*   Блок `@empty` внутри цикла `@for` интегрирован на уровне ядра компилятора, что исключает необходимость писать дополнительные дублирующие условные проверки длины массива.

### 3. Детальный пошаговый разбор выполнения шаблона 1
1.  **Инициализация**: Компонент `ModernList` монтируется. Реактивные сигналы `isLoading` и `items` инициализируются значениями по умолчанию.
2.  **Парсинг Control Flow**: Рантайм вычисляет условие `@if (isLoading())`. Так как значение сигнала равно `false`, блок загрузчика полностью игнорируется, а движок переходит к рендерингу ветки `@else`.
3.  **Генерация списка**: Запускается цикл `@for` для элементов из сигнала `items()`. Angular считывает первый объект `{ id: 101, name: '...' }`, сопоставляет его с ключом `track task.id` (записывая связь `101` с DOM-узлом в карту соответствий) и рендерит первый тег `<li>`. Наличие переменной `$first` активирует булев флаг `isFirst`, дописывая CSS-класс `highlighted`.
4.  **Изменение состояния**: Пользователь кликает по кнопке «Выполнить» у первой задачи. Запускается `toggleTaskStatus(101)`. Метод `update()` перезаписывает сигнал `items` иммутабельной копией массива, где у первой задачи статус меняется на `isCompleted: true`.
5.  **Точечное обновление (Change Detection)**: Благодаря OnPush-стратегии и реактивности сигналов Angular фиксирует изменение зависимости. Он не перерисовывает весь список заново. Движок обращается к карте ключей `track`, находит DOM-узел, связанный с ID `101`, и точечно дописывает к нему класс `completed` в DOM.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Полный перерендер списков из-за неверного использования `$index` в качестве ключа `track`**
    *   *Симптомы:* Просадка производительности (лагов) при добавлении или удалении элементов из больших списков, потеря локального состояния элементов в DOM (исчезает фокус ввода в инпутах, сбрасываются CSS-анимации).
    *   *Физика процесса:* Если в качестве ключа `track` указан системный индекс `$index` (или `track task` для неиммутабельных объектов), Angular при изменении порядка элементов или удалении одного узла посередине не сможет сопоставить старые DOM-узлы с новыми данными. Он решит, что изменились данные во всех позициях, уничтожит существующие DOM-элементы и отрендерит их заново.
    *   *Решение:* В качестве ключа `track` всегда указывайте уникальное неизменяемое поле бизнес-модели (например, системный `id`, `uuid` или уникальный хэш строки).

```html
<!-- ПЛОХО (Индекс $index приведет к полной перерисовке DOM-узлов при удалении задачи) -->
@for (task of items(); track $index) {
  <li class="task-item">{{ task.name }}</li>
}

<!-- ХОРОШО (Уникальный ID гарантирует точечное перемещение DOM-узлов без их пересоздания) -->
@for (task of items(); track task.id) {
  <li class="task-item">{{ task.name }}</li>
}
```

*   **Ошибка 2: Использование методов классов для вычислений интерполяции шаблона**
    *   *Симптомы:* Резкая просадка FPS, зависание страницы при движении мыши или скролле, перегрузка CPU.
    *   *Физика процесса:* Любая интерполяция вида `{{ getFormattedName(task) }}` вызывает метод класса. Так как Angular не может знать, изменился ли результат выполнения метода (метод может зависеть от внешних факторов), он вынужден принудительно перезапускать этот метод при *абсолютно каждом* проходе проверки изменений (Change Detection), превращая рендеринг в бесконечный цикл расчетов.
    *   *Решение:* Замените вызовы методов класса на чистые пайпы (Pipes), которые кэшируют результаты вычислений по ссылкам входных параметров, либо используйте реактивные сигналы `computed`.

```html
<!-- ПЛОХО (Метод calculateTax() будет запускаться десятки раз при каждом чихе в приложении) -->
<li>Налог: {{ calculateTax(task.price) }}</li>

<!-- ХОРОШО (Чистый пайп запустит расчет только при изменении числового значения price) -->
<li>Налог: {{ task.price | taxCalculator }}</li>
```

*   **Ошибка 3: Нарушение инкапсуляции стилей при попытке стилизовать спроецированный или дочерний контент**
    *   *Симптомы:* Написанные в CSS-файле компонента стили для дочерних элементов или элементов, приходящих через `<ng-content>`, игнорируются браузером.
    *   *Физика процесса:* Из-за режима инкапсуляции `ViewEncapsulation.Emulated` Angular дописывает уникальные атрибуты хоста только к элементам собственного шаблона. Дочерние компоненты или спроецированный контент получают свои собственные уникальные атрибуты хоста, из-за чего селекторы родителя до них не дотягиваются.
    *   *Решение:* Используйте специальный псевдокласс глубокого проникновения `::ng-deep` (в паре с `:host`, чтобы предотвратить утечку стилей в глобальную область) для точечной стилизации дочерних или спроецированных узлов.

```css
/* ПЛОХО (Стили проигнорируются, так как .child-element имеет другой атрибут хоста) */
.parent-box .child-element {
  background-color: red;
}

/* ХОРОШО (Компилятор Angular применит глубокое проникновение стилей строго внутрь хост-элемента) */
:host ::ng-deep .child-element {
  background-color: red; /* ✅ Стили успешно применятся к дочернему узлу */
}
```
