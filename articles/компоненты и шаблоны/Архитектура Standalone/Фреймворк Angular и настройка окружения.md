# Фреймворк Angular и настройка окружения

## БЫСТРЫЙ СТАРТ

*   **Angular** — это компонентно-ориентированная платформа и полнофункциональный веб-фреймворк от компании Google для проектирования, сборки и сопровождения масштабируемых одностраничных приложений (SPA).
*   **Окружение сборки** — базируется на среде выполнения Node.js и пакетном менеджере npm для управления транзитивными зависимостями, компиляции TypeScript, линтинга и бандлинга.
*   **Архитектура Standalone** — современный стандарт Angular (начиная с версии 14/15 и ставший дефолтным в версии 19+), полностью исключающий тяжелые промежуточные модули (`NgModule`) и делающий компоненты самодостаточными единицами декомпозиции.
*   **Используйте для:** проектирования отказоустойчивых enterprise-приложений со строгой структуризацией сетевого слоя, реактивного состояния, маршрутизации и безопасности.
*   **Не используйте для:** ультра-легковесных лендингов или статичных промо-страниц, где накладные расходы на инициализацию ядра фреймворка избыточны.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Точка входа и конфигурация инициализации Standalone-приложения
*   **Назначение:** Описание минимального набора конфигурационных файлов для сборки, инициализации и запуска современного standalone-приложения Angular 19+ с оптимизированной коалесценцией событий.

#### 1. Файл глобальной конфигурации: `app.config.ts`
```typescript
// Импортируем типы конфигурации приложения и системных оптимизаций
import { ApplicationConfig, provideZoneChangeDetection } from '@angular/core';

export const appConfig: ApplicationConfig = {
  providers: [
    // Настраиваем Zone.js для объединения частых микрозадач в один цикл проверки изменений.
    // Опция eventCoalescing снижает нагрузку на процессор при обработке потоков кликов/скролла.
    provideZoneChangeDetection({ eventCoalescing: true })
  ]
};
```

#### 2. Файл логики корневого компонента: `app.ts`
```typescript
// Импортируем декоратор Component и стратегию OnPush из системного ядра
import { Component, ChangeDetectionStrategy } from '@angular/core';

@Component({
  // Задаем корневой тег-селектор для монтирования в index.html
  selector: 'app-root',
  // standalone: true опущен, так как в Angular 19+ компоненты standalone по умолчанию
  // Указываем путь к внешнему HTML-файлу структуры представления
  templateUrl: './app.html',
  // Указываем путь к внешнему файлу стилей оформления
  styleUrl: './app.css',
  // OnPush защищает корневой элемент от избыточных глобальных проверок изменений
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class App {
  // Декларируем строго типизированное свойство названия приложения
  readonly title: string = 'Modern Enterprise Angular';
}
```

#### 3. Файл разметки корневого компонента: `app.html`
```html
<!-- Контейнер корневого макета страницы -->
<main class="app-container">
  <header class="app-header">
    <!-- Выводим реактивное значение свойства title через интерполяцию -->
    <h1 class="app-title">Добро пожаловать в {{ title }}</h1>
  </header>
  <article class="app-content">
    <p>Архитектура Standalone успешно настроена и готова к масштабированию.</p>
  </article>
</main>
```

#### 4. Файл стилей корневого компонента: `app.css`
```css
/* Базовый корневой контейнер макета */
.app-container {
  max-width: 1200px;
  margin: 0 auto;
  padding: 24px;

}

/* Оформление шапки приложения */

  border-bottom: 1px solid var(--border);

  margin-bottom: 24px;
}

/* Заголовок первого уровня */

/* Основной текстовый блок контента */

  color: var(--text-normal);
  line-height: 1.6;

```

#### 5. Файл инициализации (Bootstrap): `main.ts`
```typescript
// Импортируем браузерную функцию запуска приложения из системного ядра
import { bootstrapApplication } from '@angular/platform-browser';
// Импортируем корневой компонент без суффикса Component в имени класса
import { App } from './app';
// Импортируем объект глобальной конфигурации провайдеров
import { appConfig } from './app.config';

// Запускаем приложение в браузере, передавая корневой класс и настройки провайдеров
bootstrapApplication(App, appConfig)
  // Безопасно перехватываем и логируем возможные ошибки инициализации ядра
  .catch((err: unknown) => console.error('Ошибка инициализации Angular:', err));
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Архитектурная декомпозиция: Сдвиг к парадигме Standalone
Исторически в Angular фундаментальной единицей декомпозиции, группировки и компиляции кода являлся модуль (`NgModule`). Это вносило колоссальный объем избыточного шаблонного кода (boilerplate) и усложняло понимание зависимостей.

```text
NgModule-подход (Группировка через тяжелый модуль):
  [ AppModule ] ──► Декларирует Component A, Component B, Component C
                      Импортирует CommonModule, RouterModule
                      Сборщик вынужден включать весь модуль целиком.

Standalone-подход (Прямой граф импорта):
  [ Component A ] ──► Напрямую импортирует только [ Component B ] и [ Component C ]
                        Tree-Shaking сборщика легко вырезает неиспользуемый код.
```

Принципиальные отличия двух архитектурных подходов:

| Критерий | NgModule-архитектура | Standalone-архитектура |
| :--- | :--- | :--- |
| **Единица декомпозиции** | Модуль (класс с декоратором `@NgModule`) | Компонент (класс с декоратором `@Component`) |
| **Декларация зависимостей** | Описывается централизованно в модулях | Описывается непосредственно в самом компоненте через `imports` |
| **Сложность Tree-Shaking** | Затруднена из-за связанности элементов внутри модуля | Максимально упрощена благодаря прямой изоляции импортов |
| **Инициализация (Bootstrap)**| Через `platformBrowserDynamic().bootstrapModule()` | Через `bootstrapApplication(AppComponent, appConfig)` |

В современной standalone-архитектуре точка входа `src/main.ts` напрямую инициализирует корневой компонент приложения с помощью функции `bootstrapApplication`, передавая объект конфигурации `ApplicationConfig` (содержащий провайдеры для роутинга, HTTP-клиента, коалесценции событий и других глобальных систем).

### 2. Физика сборки и компиляции (AOT vs JIT)
Компилятор Angular преобразует декларативные HTML-шаблоны и декораторы классов в сверхоптимизированный исполняемый JavaScript-код. Существует две модели компиляции:

*   **JIT (Just-In-Time) компиляция**: Компиляция шаблонов происходит непосредственно в браузере клиента во время загрузки страницы. 
    *   *Проблема*: Браузер вынужден скачивать само ядро компилятора Angular (`@angular/compiler`), что значительно увеличивает итоговый размер бандла. Первичная отрисовка страницы (FCP) замедляется, так как устройство тратит процессорное время на генерацию кода в рантайме. Применяется преимущественно при локальной разработке для ускорения пересборки.
*   **AOT (Ahead-Of-Time) компиляция**: Перевод шаблонов в JS-код выполняется заранее на этапе сборки проекта (build time) силами Angular CLI и Node.js.
    *   *Преимущество*: В браузер доставляется чистый оптимизированный JS-код, не требующий наличия компилятора в бандле. Это повышает общую безопасность (шаблоны скомпилированы и защищены от динамических XSS-инъекций), минимизирует вес передаваемых файлов по сети и в разы ускоряет запуск приложения. AOT является обязательным и безальтернативным стандартом для всех production-сборок.

### 3. Детальный пошаговый разбор процесса инициализации (Bootstrapping)
1.  **Загрузка HTML-документа**: Браузер считывает файл `index.html` и натыкается на пустой селектор-тег `<app-root></app-root>`.
2.  **Загрузка бандлов**: Браузер последовательно скачивает и запускает скомпилированные JS-бандлы (включая файл `main.ts`).
3.  **Активация функции запуска**: Вызывается метод `bootstrapApplication(App, appConfig)`. Angular инициализирует глобальный DI-контейнер приложения на основе провайдеров из `appConfig`.
4.  **Анализ метаданных**: Считывается класс `App`. Компилятор Angular извлекает метаданные: находит селектор `app-root`, считывает скомпилированные шаблоны из `app.html` и стили из `app.css`.
5.  **Рендеринг и монтирование**: Angular инстанцирует корневой класс `App`, компилирует структуру его шаблона, выполняет первичный рендеринг данных и монтирует готовый DOM-узел прямо на место тега `<app-root></app-root>`. Приложение становится интерактивным.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Превышение бюджетов размеров файлов бандлов при сборке (Bundle Budgets Overflow)**
    *   *Симптомы:* Сбой сборки на CI/CD сервере с ошибкой `Error: budgets: Interior bundle size exceeded limit...`.
    *   *Физика процесса:* В файле конфигурации `angular.json` настроена секция `budgets`, которая жестко контролирует вес итоговых JS/CSS-файлов во избежание ухудшения UX пользователей из-за медленного скачивания. При случайном импорте тяжелых сторонних библиотек вес превышает установленный лимит, и CLI блокирует релиз.
    *   *Решение:* Проведите аудит зависимостей. Переведите тяжелые компоненты на ленивую загрузку (`loadComponent`), настройте Tree-Shaking, исключите дублирование импортов или скорректируйте лимиты бюджетов в `angular.json` в секции `budgets`, если рост размера обусловлен расширением бизнес-логики.

```json
// angular.json (Настройка лимитов бюджетов для контроля веса бандлов)
"budgets": [
  {
    "type": "initial",
    "maximumWarning": "500kb",
    "maximumError": "1mb" // ❌ Сборка упадет, если начальный бандл превысит 1МБ
  }
]
```

*   **Ошибка 2: Падение производительности из-за отключенной коалесценции событий Zone.js**
    *   *Симптомы:* Зависание интерфейса при частых минорных событиях (быстрый ввод в форму, скролл, mousemove), просадка FPS на мобильных устройствах.
    *   *Физика процесса:* По умолчанию Zone.js реагирует на абсолютно каждое асинхронное событие, запуская проверку изменений во всем дереве. Если пользователь быстро вводит текст, Angular будет перезапускать рендеринг на каждый символ, перегружая CPU.
    *   *Решение:* Явно передайте флаг `eventCoalescing: true` в метод `provideZoneChangeDetection` в файле `app.config.ts`. Это заставит Zone.js объединять микрозадачи, выполняемые в рамках одного тика, минимизируя число запусков Change Detection.

```typescript
// app.config.ts (Правильное включение коалесценции событий)
export const appConfig: ApplicationConfig = {
  providers: [
    provideZoneChangeDetection({ eventCoalescing: true }) // ✅ Объединяет события, оптимизируя производительность
  ]
};
```

*   **Ошибка 3: Различия в версиях npm на машинах разработчиков (Проблема рассинхронизации package-lock.json)**
    *   *Симптомы:* Приложение отлично запускается на локальной машине одного разработчика, но ломается при сборке на сервере или у другого участника команды.
    *   *Физика процесса:* Использование команды `npm install` вместо строгого `npm ci` на сборочных серверах позволяет менеджеру пакетов докачивать минорные обновления зависимостей согласно префиксам `^` или `~` в `package.json`, перезаписывая зафиксированные в `package-lock.json` версии и ломая обратную совместимость транзитивных зависимостей.
    *   *Решение:* Исключите использование `npm install` в скриптах деплоя и сборки на серверах. Всегда используйте команду `npm ci` (Clean Install), которая строго следует зафиксированным версиям из `package-lock.json`, полностью удаляя перед этим локальную папку `node_modules`.

```bash
# ПЛОХО (Может обновить минорные версии зависимостей на сервере в обход package-lock.json)
npm install

# ХОРОШО (Strict-сборка по слепку package-lock.json, гарантирующая идентичность бандлов)
npm ci
```
