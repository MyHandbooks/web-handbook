# Входные свойства на Сигналах (input)

## БЫСТРЫЙ СТАРТ

*   **Сигнальные инпуты (input)** — это современная реактивная альтернатива классическому декоратору `@Input()`, представленная в Angular 17.2+. Они представляют входящие свойства компонента в виде доступных только для чтения Сигналов (`InputSignal<T>`).
*   **Реактивный контракт:** Изменения входных данных больше не требуют императивного перехвата через `ngOnChanges` или сеттеры свойств. Сигнальные инпуты бесшовно связываются с декларативными вычислениями `computed` и побочными эффектами `effect`, автоматически пересчитывая граф зависимостей.
*   **Правила использования:**
    *   **Используйте:** Для всех входных свойств во всех новых Standalone-компонентах для достижения полной типобезопасности, упрощения логики и оптимизации бандла.
    *   **Не используйте:** Только в legacy-компонентах до проведения запланированной миграции на сигнальную архитектуру.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Базовые и обязательные сигнальные инпуты с декларативным вычислением
*   **Назначение:** Описание передачи обязательных и необязательных параметров дочернему компоненту с последующей мемоизацией производного состояния.

```typescript
import { Component, ChangeDetectionStrategy, input, computed } from '@angular/core';

@Component({
  selector: 'app-child-signal-input',
  standalone: true,
  imports: [],
  template: `
    <div class="card">
      <!-- Сигнальные инпуты в шаблоне считываются как обычные функции-сигналы -->
      <h3>Ресурс: {{ resourceName() }}</h3>
      <p>Идентификатор доступа: {{ accessCode() }}</p>
      <p>Форматированный заголовок: {{ uppercaseTitle() }}</p>
    </div>
  `,
  styles: [`
    .card { border: 1px solid var(--border); padding: 16px; border-radius: 8px; }
  `],
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class ChildSignalInputComponent {
  // 1. Необязательный инпут с дефолтным строковым значением. Автоматически выводится тип InputSignal<string>
  readonly resourceName = input<string>('Безымянный ресурс');

  // 2. Обязательный инпут без дефолтного значения. Если родитель его не передаст, возникнет ошибка сборки
  readonly accessCode = input.required<number>();

  // 3. Декларативный расчет производного значения. Автоматически перевычисляется при изменении любого из инпутов
  readonly uppercaseTitle = computed(() => {
    return `${this.resourceName().toUpperCase()} [КОД: ${this.accessCode()}]`;
  });
}
```

### Шаблон 2: Сигнальные инпуты с функциями трансформации данных (Transforms)
*   **Назначение:** Преобразование типов входящих значений «на лету» (например, приведение строковых атрибутов HTML к логическим флагам или массивам).

```typescript
import { Component, ChangeDetectionStrategy, input, booleanAttribute, numberAttribute } from '@angular/core';

// Кастомная чистая функция-трансформер: превращает строку через запятую в чистый массив строк
function splitTags(value: string | string[]): string[] {
  if (Array.isArray(value)) {
    return value;
  }
  return value ? value.split(',').map(tag => tag.trim()) : [];
}

@Component({
  selector: 'app-child-transformed-input',
  standalone: true,
  imports: [],
  template: `
    <div class="settings-panel">
      <!-- Чтение обработанных данных в шаблоне -->
      <p>Режим отладки: <strong>{{ isDebugActive() ? 'Включен' : 'Выключен' }}</strong></p>
      <p>Лимит соединений: {{ connectionLimit() }}</p>
      
      <div class="tags-container">
        @for (tag of tags(); track tag) {
          <span class="tag-badge">{{ tag }}</span>
        }
      </div>
    </div>
  `,
  styles: [`
    .settings-panel { padding: 15px; border-left: 4px solid var(--accent); }
    .tag-badge { background-color: var(--nav-active); padding: 2px 6px; border-radius: 4px; margin-right: 6px; font-size: 0.8rem; }
  `],
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class ChildTransformedInputComponent {
  // 1. Использование встроенной трансформации booleanAttribute.
  // Позволяет передавать атрибут просто флагом в HTML: <app-child-transformed-input isDebugActive />
  readonly isDebugActive = input(false, {
    transform: booleanAttribute
  });

  // 2. Использование встроенной трансформации numberAttribute.
  // Безопасно преобразует переданную строку "15" в число 15: <app-child-transformed-input connectionLimit="15" />
  readonly connectionLimit = input(5, {
    transform: numberAttribute
  });

  // 3. Кастомная трансформация. Первый generic-параметр - итоговый тип, второй - принимаемый тип
  readonly tags = input<string[], string | string[]>([], {
    transform: splitTags
  });
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Архитектурный недостаток старых декораторов `@Input()`
В классической кодовой базе Angular для отслеживания изменений входных данных приходилось реализовывать один из двух императивных подходов:
1.  **Сеттеры свойств (setters):** Написание приватного бэкинг-поля `_value` и перехват изменений в сеттере `@Input() set prop(val)`. Это приводило к раздуванию кода и усложняло отладку.
2.  **Хук жизненного цикла `ngOnChanges`:** Парсинг объекта `SimpleChanges`. Данный подход нарушал строгую типизацию, так как ключи изменений проверялись как строки (`changes['prop']`), и создавал проблемы со слиянием нескольких асинхронных потоков данных.

Сигнальные инпуты решают эти проблемы за счет перевода логики в декларативное русло. Свойство `input()` возвращает объект `InputSignal<T>`, который является полноценным реактивным узлом. Вместо императивного реагирования на изменения Angular выстраивает граф зависимостей. Если входное свойство обновляется, Angular точечно пересчитывает только те реактивные узлы (`computed`, `effect` или привязки в шаблоне), которые явно считывали этот сигнал.

### 2. Механизм трансформаций и интерфейс `InputSignalWithTransform`
HTML-атрибуты по своей природе всегда передаются как строки. Ранее, если дочернему компоненту требовался флаг активации, родительский шаблон выглядел громоздко:
`<app-child [isActive]="true"></app-child>`. Простая передача `<app-child isActive></app-child>` приводила к передаче пустой строки `""`, что ломало логику компонента.

Свойства трансформации (`transform`) позволяют исправить это на этапе компиляции. Внутри декоратора `input()` вы указываете функцию-трансформер. Angular типизирует такой инпут с использованием специального интерфейса `InputSignalWithTransform<ReadType, WriteType>`:
*   `ReadType` — тип данных, который получит дочерний компонент при чтении сигнала (например, `boolean`).
*   `WriteType` — тип данных, который разрешено передавать родителю в шаблоне (например, `boolean | string`).

Благодаря этому TypeScript полностью сохраняет строгий контроль типов как для родителя, так и для дочернего компонента.

### 3. Пошаговый разбор жизненного цикла и распространения изменений
При инициализации и работе сигнального инпута происходят следующие процессы:
1.  **Создание реактивного узла:** Во время конструирования класса Angular создает неизменяемый сигнальный узел во внутреннем графе Ivy.
2.  **Внедрение значения:** В фазе первичного рендеринга (до вызова хуков жизненного цикла `OnInit`) Angular считывает переданные родителем атрибуты, пропускает их через функции трансформаций и записывает в узел инпута.
3.  **Передача по графу:** Изменение значения инпута мгновенно переводит все зависимые `computed`-сигналы в статус `dirty` (требующие перерасчета).
4.  **Синхронное чтение в рендере:** При запуске проверки изменений (Change Detection) новые вычисленные значения считываются шаблоном за один проход, исключая повторные запуски рендеринга и ошибки `ExpressionChangedAfterItHasBeenCheckedError`.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Попытка прямой записи значения в `InputSignal`**
    *   *Симптомы:* Ошибка компиляции на этапе сборки: `Property 'set' does not exist on type 'InputSignal<T>'` или `Property 'update' does not exist...`.
    *   *Физика процесса:* Сигнальный инпут возвращает `InputSignal<T>`, который специально спроектирован как Read-Only (доступный только для чтения). Это гарантирует соблюдение архитектурного принципа однонаправленного потока данных (Unidirectional Data Flow): изменять состояние имеет право только тот компонент, который им владеет (родитель).
    *   *Решение:* Использовать новый реактивный узел `linkedSignal()` для создания локально изменяемой копии, которая синхронизируется с инпутом, но разрешает ручную перезапись в дочернем компоненте.

```typescript
import { Component, input, linkedSignal } from '@angular/core';

@Component({
  template: `
    <p>Текущее имя: {{ localUserName() }}</p>
    <button (click)="resetLocalName()">Сбросить локально</button>
  `
})
export class UserCardComponent {
  // Входной неизменяемый сигнал от родителя
  readonly externalUserName = input.required<string>();

  // ИСПРАВЛЕНИЕ: Создание локально изменяемой копии, связанной с инпутом.
  // При изменении externalUserName локальный сигнал автоматически сбросится к новому значению.
  readonly localUserName = linkedSignal(() => this.externalUserName());

  resetLocalName(): void {
    // В отличие от инпута, linkedSignal разрешает вызовы .set() и .update()
    this.localUserName.set('Анонимный гость');
  }
}
```

*   **Ошибка 2: Использование старого хука `ngOnChanges` для синхронизации локального состояния**
    *   *Симптомы:* Смешивание реактивного декларативного подхода и старого императивного жизненного цикла; раздувание кодовой базы; риск возникновения гонок данных.
    *   *Физика процесса:* Пытаясь отреагировать на изменение инпута, разработчик по привычке реализует интерфейс `OnChanges` и вручную перезаписывает локальные переменные, игнорируя граф реактивности.
    *   *Решение:* Заменить императивные перехватчики на декларативный вызов `computed()`.

```typescript
// ОШИБКА: Императивный перехват изменений через OnChanges
@Component({ ... })
export class BadChangesComponent implements OnChanges {
  readonly maxLimit = input<number>(100);
  formattedLimit = '';

  ngOnChanges(changes: SimpleChanges): void {
    if (changes['maxLimit']) {
      this.formattedLimit = `Лимит: ${this.maxLimit()} ед.`;
    }
  }
}

// ИСПРАВЛЕНИЕ: Полностью декларативное реактивное связывание без OnChanges
@Component({ ... })
export class GoodChangesComponent {
  readonly maxLimit = input<number>(100);

  // Значение всегда актуально, строго типизировано и обновляется автоматически
  readonly formattedLimit = computed(() => `Лимит: ${this.maxLimit()} ед.`);
}
```

*   **Ошибка 3: Попытка чтения необязательного сигнального инпута без обработки `undefined`**
    *   *Симптомы:* Ошибки во время работы приложения (runtime crash) типа `Cannot read properties of undefined` при вызове методов у объекта, полученного из инпута.
    *   *Физика процесса:* Если входное свойство объявлено как необязательное без указания дефолтного значения (`input<User>()`), TypeScript выведет его тип как `InputSignal<User | undefined>`. Попытка обратиться к свойствам напрямую без проверки приведет к падению приложения, если родитель ничего не передал.
    *   *Решение:* Использовать безопасный оператор навигации `?.` или указывать дефолтные пустые значения при объявлении сигнала.

```typescript
export interface UserPayload {
  readonly id: string;
  readonly role: string;
}

@Component({
  template: `
    <!-- ОШИБКА: Если пользователь не передан, произойдет падение рендеринга -->
    <p>Роль: {{ user().role }}</p>
    
    <!-- ИСПРАВЛЕНИЕ 1: Безопасное чтение nullable-сигнала -->
    <p>Роль: {{ user()?.role ?? 'Гость' }}</p>
  `
})
export class ProfileCardComponent {
  // Сигнал возвращает тип UserPayload | undefined
  readonly user = input<UserPayload>();
}
```
