# Взаимодействие компонентов в Angular

## БЫСТРЫЙ СТАРТ

*   **Взаимодействие компонентов** — это архитектурный механизм организации обмена данными и координации событий между различными узлами дерева разметки приложения.
*   **Принцип однонаправленного потока (Unidirectional Data Flow):** Современный стандарт Angular 19+ предписывает передавать данные строго сверху вниз от родителя к дочерним элементам через входные сигналы (`input()`), а события отправлять снизу вверх от потомков к родителю через легковесное Output API (`output()`).
*   **Изоляция состояния:** Дочерние компоненты должны быть пассивными и не иметь прямого доступа к изменению состояния родительского контекста. Любое изменение данных должно инициироваться родителем в ответ на событие, испущенное дочерним компонентом.
*   **Используйте для:** построения предсказуемых, легко тестируемых и слабосвязанных иерархий UI-элементов.
*   **Не используйте для:** сквозного обмена данными между далекими друг от друга или несвязанными ветками дерева компонентов. В этих сценариях передача данных через длинные цепочки промежуточных компонентов (Prop Drilling) является антипаттерном. Для этого применяйте общие сигнальные службы (Stores).

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Архитектурный каркас однонаправленного взаимодействия (Parent-Child)
*   **Назначение:** Шаблон демонстрирует чистую структуру связывания родительского компонента-контейнера и дочернего презентационного компонента, исключающую избыточное кодовое дублирование.

#### 1. Файл логики родительского компонента: `parent-container.ts`
```typescript
import { Component, ChangeDetectionStrategy, signal } from '@angular/core';
import { ChildPresenter } from './child-presenter'; // Импортируем дочерний класс напрямую

export interface ItemPayload {
  id: string;
  name: string;
}

@Component({
  selector: 'app-parent-container',
  // standalone: true опущен по умолчанию начиная с v19
  imports: [ChildPresenter], // Явный импорт дочернего компонента в локальный Scope
  templateUrl: './parent-container.html',
  styleUrl: './parent-container.css',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class ParentContainer { // Название класса соответствует стандартам без суффикса Component
  // Исходный реактивный источник правды для всей ветки компонентов
  public readonly activeItem = signal<ItemPayload>({
    id: 'usr_102',
    name: 'Базовая конфигурация'
  });

  public handleItemUpdate(updatedName: string): void {
    // Изменяем состояние строго на уровне родителя-владельца данных
    this.activeItem.update(current => ({
      ...current,
      name: updatedName
    }));
  }
}
```

#### 2. Файл разметки родительского компонента: `parent-container.html`
```html
<div class="parent-box">
  <h2>Родительский контейнер (Владелец состояния)</h2>

  <!-- 
    Передаем данные вниз через сигнальный вход [itemData] (Input).
    Слушаем события снизу через круглые скобки (nameChanged) (Output).
  -->
  <app-child-presenter 
    [itemData]="activeItem()" 
    (nameChanged)="handleItemUpdate($event)"
  />
</div>
```

#### 3. Файл стилей родительского компонента: `parent-container.css`
```css

  padding: 24px;
  background-color: var(--bg-secondary);
  border: 1px solid var(--border);
  border-radius: 12px;
}
```

#### 4. Файл логики дочернего компонента: `child-presenter.ts`
```typescript
import { Component, ChangeDetectionStrategy, input, output } from '@angular/core';
import { ItemPayload } from './parent-container';

@Component({
  selector: 'app-child-presenter',
  imports: [], // Массив пуст, так как дочерний компонент является чистым презентационным элементом
  templateUrl: './child-presenter.html',
  styleUrl: './child-presenter.css',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class ChildPresenter {
  // Принимаем входящее значение в виде доступного только для чтения сигнального инпута
  public readonly itemData = input.required<ItemPayload>();

  // Регистрируем выходной канал событий на базе легковесного Output API
  public readonly nameChanged = output<string>();

  public onActionTrigger(newValue: string): void {
    const trimmed = newValue.trim();
    if (!trimmed) return;

    // Эмитируем событие наверх, не пытаясь изменить значение itemData() локально
    this.nameChanged.emit(trimmed);
  }
}
```

#### 5. Файл разметки дочернего компонента: `child-presenter.html`
```html
<div class="presenter-card">
  <h4>Дочерний элемент (Презентационный)</h4>
  <p>Текущее имя ресурса: <b>{{ itemData().name }}</b></p>

  <div class="input-row">
    <input #newNameInput type="text" placeholder="Новое имя..." class="theme-input" />
    <button (click)="onActionTrigger(newNameInput.value); newNameInput.value = ''">
      Обновить имя
    </button>
  </div>
</div>
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Физика однонаправленного потока данных (Unidirectional Data Flow)
В основе архитектуры рендеринга Angular лежит принцип однонаправленного потока данных: **Data Down, Events Up (Данные вниз, События вверх)**.

```text
                  [ Родительский компонент ] 
                 (Владеет сигналом состояния)
                       │                ▲
  1. Передача значения │                │ 3. Перехват события
     через [input]     │                │    и обновление сигнала
                       ▼                │
                  [ Дочерний компонент ]
               (Эмитирует событие через output)
```

1.  **Движение вниз (Data Down):** Во время Change Detection компилятор Ivy считывает значения родительских сигналов и записывает их во входные сигнальные входы `input()` дочерних компонентов. Эти входы доступны потомкам только для чтения (`ReadOnly`), что исключает неконтролируемое изменение состояния.
2.  **Движение вверх (Events Up):** Если дочернему компоненту необходимо изменить состояние, он не делает этого сам. Он генерирует событие через свойство `output()`.
3.  **Синхронизация состояния:** Родительский компонент ловит это событие в своем шаблоне, вызывает обработчик, обновляет исходный сигнал состояния, запуская новый предсказуемый круг детекции изменений.

Такой подход гарантирует, что данные всегда движутся в одном направлении, исключая хаотичные побочные эффекты и делая структуру приложения прозрачной и простой для отладки.

### 2. Паттерны связи независимых компонентов (Службы-посредники)
Когда компоненты находятся в разных ветках дерева (например, корзина в шапке сайта и кнопка добавления в карточке товара на другом роуте), передача данных через родительские элементы становится невозможной или порождает антипаттерн **Prop Drilling** (прокидывание свойств сквозь десятки промежуточных компонентов-посредников).

В этих сценариях применяется паттерн **Службы-посредника (Service-based State Store)**:
*   Создается синглтон-сервис с областью видимости `providedIn: 'root'`.
*   Сервис содержит реактивное состояние на базе Сигналов или RxJS `BehaviorSubject`.
*   Оба компонента независимо внедряют этот сервис через `inject()` и работают с общим источником данных напрямую, минуя дерево DOM-узлов.

### 3. Детальный пошаговый разбор выполнения шаблона 1
Проследим шаги обновления имени в системе:

1.  **Ввод данных:** Пользователь вводит текст в инпут дочернего компонента и кликает на кнопку.
2.  **Срабатывание обработчика:** Запускается метод `onActionTrigger(newValue)`. Текст обрезается от пробелов.
3.  **Эмиссия события:** Вызывается `this.nameChanged.emit(trimmed)`. Легковесный объект событий `OutputRef` передает строковое значение наверх.
4.  **Перехват родителем:** В родительском шаблоне привязка `(nameChanged)="handleItemUpdate($event)"` улавливает событие. Переданная строка попадает в переменную `$event`.
5.  **Обновление сигнала-источника:** Запускается метод `handleItemUpdate()`. Сигнал `activeItem` обновляется иммутабельной копией объекта через метод `.update()`.
6.  **Точечный рендеринг (Change Detection):** Сигнал отправляет dirty-уведомление родительскому шаблону и сигнальному входу `itemData` дочернего компонента. Angular запускает проверку изменений, считывает новые значения и точечно перерисовывает текстовые ноды на экране.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Ошибка циклического импорта классов (Circular Dependency)**
    *   *Симптомы:* Сбой компиляции или рантайм-ошибка вида `Cannot access '...' before initialization` при загрузке компонентов.
    *   *Физика процесса:* Родительский компонент импортирует дочерний класс для регистрации в массиве `imports`. При этом дочерний компонент пытается импортировать родительский класс (например, для типизации входящего интерфейса `ItemPayload`). Создается циклическая зависимость модулей ES, которую компилятор не может разрешить.
    *   *Решение:* Выносите все общие интерфейсы, типы и контракты данных в отдельные, изолированные файлы типов (например, `user-types.ts` или `parent-container.interfaces.ts`), которые не импортируют сами компоненты.

*   **Ошибка 2: Мутация объектов по ссылке внутри входных свойств (Shared Mutability Leak)**
    *   *Симптомы:* Дочерний компонент изменяет свойство полученного объекта, состояние меняется на экране, но Angular не запускает проверку изменений, и другие компоненты видят рассогласованные данные.
    *   *Физика процесса:* Разработчик напрямую мутировал свойство полученного объекта: `this.itemData().name = 'new'`. Поскольку объект передается по ссылке, оригинальный объект в родителе изменился, но ссылка осталась прежней. Angular не зафиксировал смену ссылки и заблокировал Change Detection.
    *   *Решение:* Никогда не мутируйте свойства объектов внутри дочерних компонентов. Рассматривайте `input()` как строго иммутабельный источник данных и всегда транслируйте намерения об изменениях наверх через `output()`.

*   **Ошибка 3: Избыточное дублирование состояния в дочернем компоненте**
    *   *Симптомы:* Неконсистентность интерфейса: родитель обновил данные, но дочерний компонент продолжает отображать старую информацию.
    *   *Физика процесса:* Разработчик скопировал входящее значение во внутренний изменяемый сигнал при инициализации: `localValue = signal(this.itemData())` в надежде изменять его локально. При изменении родительского инпута локальный сигнал `localValue` не обновляется автоматически, так как связь разорвана на этапе инициализации.
    *   *Решение:* Если вам нужно вычислять локальное состояние на основе инпута, используйте `computed()` (если значение строго только для чтения) или `linkedSignal()` (если значение должно автоматически сбрасываться при смене инпута, но разрешает ручную перезапись).
