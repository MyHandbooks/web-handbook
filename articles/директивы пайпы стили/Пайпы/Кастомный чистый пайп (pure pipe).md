# Кастомный чистый пайп (pure pipe)

## БЫСТРЫЙ СТАРТ

*   **Чистый пайп (Pure Pipe)** — это встроенный механизм Angular для трансформации данных непосредственно в HTML-шаблоне. Он является «чистым» по умолчанию (`pure: true`), что означает строгое следование концепции чистых функций из функционального программирования.
*   **Кэширование вычислений:** Оптимизатор Angular вызывает метод `transform` чистого пайпа только тогда, когда изменяются входные аргументы. Если аргументы остаются прежними (проверка по ссылочной идентичности `===`), Angular мгновенно возвращает ранее вычисленный и закэшированный результат, не запуская код трансформации повторно.
*   **Используйте:** Для форматирования сырых данных в шаблоне (конвертация байт в мегабайты, форматирование валют, перевод единиц измерения, сложные математические или строковые манипуляции).
*   **Не используйте:** Для выполнения асинхронных HTTP-запросов, логирования или фильтрации массивов «на лету» по мутирующим свойствам объектов (это ломает концепцию чистоты вычислений и приводит к багам отрисовки).

### Шаблон 1: Высокопроизводительный конвертер размера файлов (BytesFormatter)
*   **Назначение:** Чистый пайп преобразует числовое значение размера файла в байтах в человекочитаемый формат (КБ, МБ, ГБ) с настраиваемой точностью округления.

#### 1. Файл логики пайпа: `bytes-formatter.ts`
```typescript
import { Pipe, PipeTransform } from '@angular/core';

@Pipe({
  name: 'appBytesFormatter', // Уникальное имя пайпа для использования в шаблоне
  pure: true // Явно декларируем пайп как чистый (значение по умолчанию)
})
export class BytesFormatter implements PipeTransform {
  // Метод transform принимает исходное число и необязательный параметр точности округления
  public transform(bytes: number, decimals = 2): string {
    // Если на входе невалидное число или ноль, возвращаем дефолтную строку
    if (bytes <= 0 || isNaN(bytes)) {
      return '0 Bytes';
    }

    const k = 1024;
    const dm = decimals < 0 ? 0 : decimals;
    const sizes = ['Bytes', 'KB', 'MB', 'GB', 'TB', 'PB'];

    // Вычисляем порядок величины
    const i = Math.floor(Math.log(bytes) / Math.log(k));

    // Возвращаем отформатированный результат
    return `${parseFloat((bytes / Math.pow(k, i)).toFixed(dm))} ${sizes[i]}`;
  }
}
```

#### 2. Файл логики демонстрационного компонента: `bytes-demo.ts`
```typescript
import { Component, ChangeDetectionStrategy, signal } from '@angular/core';
import { BytesFormatter } from './bytes-formatter';

@Component({
  selector: 'app-bytes-demo',
  imports: [BytesFormatter], // Импортируем кастомный пайп для работы в шаблоне
  templateUrl: './bytes-demo.html',
  styleUrl: './bytes-demo.css',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class BytesDemo {
  // Сигнал, хранящий размер файла в байтах (эмулируем размер 15.4 МБ)
  public readonly fileSizeBytes = signal<number>(16148070);
}
```

#### 3. Файл разметки демонстрационного компонента: `bytes-demo.html`
```html
<div class="demo-wrapper">
  <h3>Информация о файле</h3>
  <div class="info-card">
    <!-- Применяем чистый пайп. Значение пересчитается только при изменении fileSizeBytes -->
    <p>Размер (дефолтный округленный): <strong>{{ fileSizeBytes() | appBytesFormatter }}</strong></p>
    <p>Размер (точный до 4 знаков): <strong>{{ fileSizeBytes() | appBytesFormatter:4 }}</strong></p>
  </div>
</div>
```

### Шаблон 2: Калькулятор стоимости со сложными зависимостями (PriceDiscount)
*   **Назначение:** Чистый пайп вычисляет итоговую цену товара с учетом скидки и ставки налога. Демонстрирует работу чистого пайпа со сложными объектами конфигурации на входе.

#### 1. Файл логики пайпа: `price-discount.ts`
```typescript
import { Pipe, PipeTransform } from '@angular/core';

// Строгий интерфейс для конфигурации расчета
export interface DiscountOptions {
  discountPercent: number;
  taxPercent: number;
  currencySymbol: string;
}

@Pipe({
  name: 'appPriceDiscount',
  pure: true
})
export class PriceDiscount implements PipeTransform {
  // Метод принимает базовую цену и сложный конфигурационный объект
  public transform(basePrice: number, options: DiscountOptions): string {
    if (basePrice < 0 || isNaN(basePrice)) {
      return '—';
    }

    // Вычисляем цену со скидкой
    const priceWithDiscount = basePrice * (1 - options.discountPercent / 100);
    // Добавляем налог к полученной стоимости
    const finalPrice = priceWithDiscount * (1 + options.taxPercent / 100);

    // Возвращаем отформатированную строку
    return `${options.currencySymbol}${finalPrice.toFixed(2)}`;
  }
}
```

#### 2. Файл логики демонстрационного компонента: `price-demo.ts`
```typescript
import { Component, ChangeDetectionStrategy, signal } from '@angular/core';
import { PriceDiscount, DiscountOptions } from './price-discount';

@Component({
  selector: 'app-price-demo',
  imports: [PriceDiscount],
  templateUrl: './price-demo.html',
  styleUrl: './price-demo.css',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class PriceDemo {
  public readonly basePrice = signal<number>(1000);

  // Конфигурационный объект хранится в Сигнале
  public readonly billingOptions = signal<DiscountOptions>({
    discountPercent: 15,
    taxPercent: 20,
    currencySymbol: '€'
  });

  // Правильный метод обновления объекта конфигурации (через создание новой ссылки)
  public increaseDiscount(): void {
    this.billingOptions.update(current => ({
      ...current, // Копируем старые свойства
      discountPercent: current.discountPercent + 5 // Меняем скидку
    }));
  }
}
```

#### 3. Файл разметки демонстрационного компонента: `price-demo.html`
```html
<div class="demo-wrapper">
  <h3>Расчет финальной стоимости</h3>
  <div class="price-box">

    <p>Итого к оплате: <strong>{{ basePrice() | appPriceDiscount:billingOptions() }}</strong></p>
    <button (click)="increaseDiscount()">Увеличить скидку на 5%</button>
  </div>
</div>
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Физика мемоизации чистых пайпов в Angular
Чистый пайп — это один из ключевых инструментов оптимизации производительности рендеринга. 

Когда Angular компилирует HTML-шаблон, он превращает использование пайпа в системный вызов функции трансформации внутри фазы Change Detection. Однако, если пайп объявлен как `pure: true`, Angular оборачивает вызов метода `transform` защитным слоем мемоизации:

1.  **Сравнение аргументов:** При каждом цикле проверки изменений (Change Detection) Angular сравнивает текущие значения всех аргументов, переданных в пайп, с их предыдущими значениями.
2.  **Проверка ссылочной идентичности (Strict Equality):** Сравнение происходит строго по оператору тройного равенства `===`. 
3.  **Игнорирование вызова:** Если ни один из аргументов не изменился, Angular полностью пропускает выполнение тела метода `transform()`, мгновенно подставляя старое сохраненное значение из памяти.

Благодаря этому, даже если у вас на странице рендерятся сотни элементов в цикле `@for`, чистый пайп выполнит свои вычисления только один раз для каждого уникального набора данных, экономя такты процессора.

### 2. Разница между Pure и Impure пайпами
Вы можете отключить мемоизацию, указав в метаданных декоратора свойство `pure: false`. Это превратит пайп в «грязный» (Impure Pipe).

```typescript
// Декларация грязного пайпа
@Pipe({
  name: 'appImpureFormatter',
  pure: false // Пайп будет запускаться при абсолютно любой активности
})
```

*   **Чистый пайп (`pure: true`):** Запускается *только* тогда, когда меняется ссылка на входные данные. Смена внутренних свойств объекта или добавление элементов в массив без изменения ссылки не вызовет пересчет.
*   **Грязный пайп (`pure: false`):** Запускается при *каждом* цикле Change Detection приложения — при любом клике, движении мыши, срабатывании таймера или завершении HTTP-запроса в любой точке экрана. Если внутри грязного пайпа находятся тяжелые вычисления (например, фильтрация больших массивов), это гарантированно приведет к критическим просадкам FPS интерфейса.

### 3. Детальный пошаговый разбор фазы выполнения чистого пайпа
Проследим шаги работы пайпа `PriceDiscount` (Шаблон 2):

1.  **Первичный рендеринг:** Angular компилирует `<p>Итого к оплате: {{ basePrice() | appPriceDiscount:billingOptions() }}</p>`. Вызывается метод `transform(1000, { discountPercent: 15, ... })`. Результат `€1020.00` вычисляется и сохраняется в памяти инстанса представления.
2.  **Цикл проверки (Change Detection) без изменений:** Пользователь кликает в другую область экрана (не связанную с ценой). Запускается глобальный Change Detection. Angular проверяет пайп, видит, что `basePrice()` по-прежнему равен `1000`, а ссылка на объект `billingOptions()` не изменилась. Метод `transform` **не вызывается**. Результат берется из кэша.
3.  **Некорректное мутирование (ошибка разработчика):** Разработчик напрямую меняет свойство объекта: `options.discountPercent = 20`. Запускается Change Detection. Angular сравнивает ссылки. Ссылка на объект `options` осталась прежней (`options === options`). Метод `transform` **не вызывается**, на экране остается старая цена `€1020.00` (баг отображения).
4.  **Корректное иммутабельное изменение:** Разработчик обновляет сигнал через деструктуризацию: `this.billingOptions.set({ ...newOptions })`. Ссылка на объект изменилась. Angular видит несовпадение предыдущего и нового аргументов по `===`. Вызывается метод `transform`, вычисляется новая цена, обновляя UI.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Попытка фильтрации массивов через чистый пайп при мутации исходного массива**
    *   *Симптомы:* Пользователь добавляет элемент в список (например, через `array.push()`), но список на экране не обновляется.
    *   *Физика процесса:* Метод `push()` изменяет содержимое существующего массива, но не меняет ссылку на сам массив в памяти. Поскольку ссылка осталась прежней, чистый пайп считает, что данные не изменились, и возвращает старый закэшированный результат фильтрации.
    *   *Решение:* При работе с коллекциями внутри чистых пайпов всегда соблюдайте принцип иммутабельности — создавайте новую копию массива при любых изменениях.

```typescript
// ПЛОХО (Чистый пайп не зафиксирует изменения в шаблоне)
public addNewItem(newItem: string): void {
  this.itemsList().push(newItem);
}

// ХОРОШО (Новая ссылка на массив гарантирует вызов чистого пайпа)
public addNewItem(newItem: string): void {
  this.itemsList.update(current => [...current, newItem]);
}
```

*   **Ошибка 2: Тяжелые вычисления или запросы к API внутри метода transform**
    *   *Симптомы:* Зависание интерфейса, бесконечные сетевые запросы во вкладке Network браузера.
    *   *Физика процесса:* Разработчик пытается отправить HTTP-запрос прямо внутри пайпа (например, для получения перевода строки). Поскольку HTTP-запрос возвращает Observable, пайп вызывается многократно, порождая бесконечные каскады проверок изменений и запросов.
    *   *Решение:* Пайпы должны быть синхронными и детерминированными. Если вам необходимо получить данные из сети, делайте это внутри компонентов или сервисов через сигнальные ресурсы `Resource API` или RxJS-потоки, а пайпы используйте строго для форматирования уже полученных данных.

*   **Ошибка 3: Создание динамических объектов конфигурации прямо в разметке шаблона**
    *   *Симптомы:* Чистый пайп начинает работать как грязный — постоянно запускает вычисления при любых действиях на странице.
    *   *Физика процесса:* Разработчик передает объект конфигурации, создавая его прямо внутри HTML-шаблона:
        `{{ price | appPriceDiscount:{ discountPercent: 15 } }}`.
        При каждом запуске Change Detection шаблона Angular заново выполняет разметку и инициализирует новый физический объект `{ discountPercent: 15 }` в памяти. Ссылка на этот объект всегда отличается от предыдущей, что полностью ломает мемоизацию чистого пайпа.
    *   *Решение:* Всегда выносите объекты конфигурации в свойства класса компонента (или Сигналы) для сохранения стабильной ссылки между циклами рендеринга.
