# Организация SCSS-импортов (use, forward)

## БЫСТРЫЙ СТАРТ

*   **Директивы `@use` и `@forward`** — это современные инструменты модульной системы Sass (Dart Sass), полностью заменившие устаревшую и признанную небезопасной директиву `@import`.
*   **Директива `@use`** импортирует переменные, миксины и функции из внешнего файла в виде изолированного пространства имен (Namespace). По умолчанию имя пространства совпадает с именем файла (например, `@use 'variables'` дает доступ к `variables.$accent`). Это полностью исключает конфликты имен.
*   **Директива `@forward`** организует транзитную пересылку абстракций. Она позволяет собирать множество мелких SCSS-модулей в единый публичный интерфейс (входной файл `_index.scss`), не загружая сами стили в текущую область видимости.
*   **Используйте:** Для организации масштабируемой структуры стилей (дизайн-системы), где переменные, миксины, шрифты и адаптивные сетки импортируются в стили компонентов точечно и изолированно.
*   **Не используйте:** Устаревший `@import`. Он загрязняет глобальную область видимости, вызывает случайные конфликты имен и приводит к многократному дублированию скомпилированного CSS-кода при импорте одного и того же файла в разные компоненты.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Создание единой точки входа для дизайн-системы (abstracts/_index.scss)
*   **Назначение:** Модульная структура Sass объединяет файлы переменных и адаптивных миксинов в единый транзитный файл-индекс с помощью директивы `@forward`.

#### 1. Файл переменных темы: `src/styles/abstracts/_variables.scss`
```scss
// Объявляем переменные с флагом !default, чтобы их можно было переопределить извне
$theme-accent: #6366f1 !default;
$theme-border: #d0d7de !default;
$theme-bg-secondary: #f6f8fa !default;
$theme-font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif !default;
```

#### 2. Файл миксинов сетки и адаптивности: `src/styles/abstracts/_mixins.scss`
```scss
// Миксин для быстрого выравнивания элементов по центру через flexbox
@mixin flex-center {
  display: flex;
  align-items: center;
  justify-content: center;
}

// Миксин для создания медиа-запросов под разные экраны
@mixin respond-to($breakpoint) {
  @if $breakpoint == 'tablet' {
    @media (max-width: 768px) {
      @content; // Сюда подставится вложенный блок стилей
    }
  }
}
```

#### 3. Единый транзитный файл-индекс: `src/styles/abstracts/_index.scss`
```scss
/* 
  Директива @forward делает переменные и миксины доступными для импорта 
  через этот файл. Сам по себе этот файл ничего не компилирует в CSS.
*/
@forward 'variables';
@forward 'mixins';
```

### Шаблон 2: Использование абстракций в стилях компонента Angular (ThemePreview)
*   **Назначение:** Компонент Angular импортирует подготовленный слой абстракций через директиву `@use` и безопасно применяет переменные и миксины в своей изолированной верстке.

#### 1. Файл стилей компонента: `theme-preview.scss`
```scss
/*
  Импортируем наш единый индекс абстракций.
  Используем "as abstracts", чтобы переопределить стандартный неймспейс.
*/
@use '../../styles/abstracts' as abstracts;

.preview-card {
  font-family: abstracts.$theme-font-sans; // Обращаемся к переменной через пространство имен
  border: 1px solid abstracts.$theme-border;
  background-color: abstracts.$theme-bg-secondary;
  border-radius: 8px;
  padding: 24px;
  max-width: 400px;

  .btn-wrapper {
    @include abstracts.flex-center; // Встраиваем миксин выравнивания
    margin-top: 16px;
  }

  .action-btn {
    background-color: abstracts.$theme-accent;
    color: #ffffff;
    border: none;
    padding: 8px 16px;
    border-radius: 4px;
    cursor: pointer;
  }

  // Применяем адаптивный миксин для планшетов
  @include abstracts.respond-to('tablet') {
    max-width: 100%;
    padding: 16px;
  }
}
```

#### 2. Файл логики компонента: `theme-preview.ts`
```typescript
import { Component, ChangeDetectionStrategy } from '@angular/core';

@Component({
  selector: 'app-theme-preview',
  templateUrl: './theme-preview.html',
  styleUrl: './theme-preview.scss', // Указываем SCSS-файл в качестве источника стилей
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class ThemePreview { }
```

#### 3. Файл разметки компонента: `theme-preview.html`
```html
<div class="preview-card">
  <h4>Интеграция дизайн-системы</h4>
  <p>Стили этой карточки используют изолированные SCSS-переменные и миксины без риска глобальных конфликтов.</p>
  <div class="btn-wrapper">
    <button class="action-btn">Выполнить</button>
  </div>
</div>
```

### Шаблон 3: Динамическая конфигурация и переопределение переменных модуля (`@use ... with`)
*   **Назначение:** Шаблон демонстрирует настройку переменных абстрактного SCSS-модуля непосредственно в момент его импорта в конкретном файле.

#### 1. Файл стилей компонента с переопределением: `custom-preview.scss`
```scss
/* 
  Импортируем модуль с одновременным переопределением значений по умолчанию.
  Это возможно благодаря тому, что в исходном файле переменные были помечены флагом !default.
*/
@use '../../styles/abstracts' as custom with (
  $theme-accent: #f43f5e, // Меняем индиго на красный цвет для этой страницы
  $theme-bg-secondary: #fff1f2 // Меняем серый фон на светло-розовый
);

.custom-card {
  border: 1px solid custom.$theme-border;
  background-color: custom.$theme-bg-secondary; // Будет иметь светло-розовый цвет
  padding: 20px;
  border-radius: 6px;

  .custom-btn {
    background-color: custom.$theme-accent; // Кнопка станет красной
    color: white;
    border: none;
    padding: 6px 12px;
    border-radius: 4px;
    cursor: pointer;
  }
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Физика сборки и почему `@import` признан устаревшим (Deprecated)
В классической системе импорта Sass директива `@import` вела себя как императивное включение текста файла: она буквально копировала содержимое одного файла внутрь другого на этапе компиляции. Это приводило к трем архитектурным проблемам:

1.  **Дублирование скомпилированного CSS:**
    Если у вас есть файл `_base.scss` с общими стилями (например, стилями сброса `reset` или вспомогательными утилитами), и вы импортируете его через `@import` в 20 различных компонентов Angular, компилятор Sass сгенерирует дубликаты этих стилей 20 раз подряд. В итоге вес финального CSS-бандла приложения увеличится во много раз.
2.  **Загрязнение глобального пространства (Global Namespace):**
    Все импортированные переменные становились глобальными. Если в разных импортируемых файлах случайно объявлялись переменные с одинаковым названием (например, `$size: 10px` и `$size: 15px`), они молча перезаписывали друг друга, рождая непредсказуемые визуальные баги, которые было тяжело локализовать.
3.  **Непрозрачность источника:**
    Если в файле компонента использовался миксин `@include flex-center;`, компилятор не мог сразу определить, откуда он взялся. Приходилось анализировать всю цепочку вложенных `@import`, что замедляло скорость сборки проекта.

Директива `@use` решает эти проблемы: она компилирует импортируемый файл ровно **один раз** (сколько бы раз вы его ни вызывали), изолирует все сущности внутри пространства имен и делает структуру импортов явной и прозрачной для линтеров и компилятора.

### 2. Разница между `@use` и `@forward`
Хотя обе директивы управляют модулями, они имеют противоположное архитектурное назначение:

*   **Директива `@use` импортирует сущности для локального использования.**
    Она делает переменные и миксины доступными только внутри текущего файла. Она не позволяет другим файлам, которые импортируют текущий файл, увидеть эти зависимости.
*   **Директива `@forward` транслирует сущности наружу.**
    Она делает переменные и миксины доступными для последующего импорта другими файлами, но *не делает* их доступными внутри самого файла, где написана директива `@forward`. Это чистый транзитный мост для сборки общей дизайн-системы.

Благодаря комбинации этих директив вы можете создавать сложные библиотеки стилей, разбитые на десятки мелких файлов, предоставляя разработчикам единственную, чистую точку входа.

### 3. Детальный пошаговый разбор сборки модульных стилей Angular
Проследим этапы компиляции стилей компонента `ThemePreview`:

1.  **Обнаружение импорта:** Компилятор Sass видит строчку `@use '../../styles/abstracts' as abstracts`.
2.  **Поиск индекса:** Компилятор ищет файл `_index.scss` внутри папки `abstracts`.
3.  **Разрешение транзита:** Внутри `_index.scss` компилятор обрабатывает директивы `@forward 'variables'` и `@forward 'mixins'`. Он загружает переменные и миксины из соответствующих файлов, объединяя их в общий интерфейс модуля под именем `abstracts`.
4.  **Компиляция стилей:** В процессе генерации CSS-кода для компонента компилятор заменяет обращения `abstracts.$theme-accent` на реальное скомпилированное значение цвета `#6366f1`.
5.  **Применение инкапсуляции:** Полученный CSS-код передается в Angular, который навешивает на селекторы атрибуты эмуляции инкапсуляции (например, `_ngcontent-c12`).

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Попытка использования переменных форвардного модуля без явного импорта через `@use`**
    *   *Симптомы:* Ошибка сборки Sass: `Undefined variable` или `Undefined mixin` при попытке использовать абстракции внутри файла-индекса `_index.scss`.
    *   *Физика процесса:* Разработчик считает, что написание `@forward 'variables'` автоматически делает переменные доступными внутри самого файла `_index.scss`. Но директива `@forward` только транслирует сущности наружу, не импортируя их локально.
    *   *Решение:* Если вам нужно и использовать абстракции локально, и транслировать их дальше, используйте обе директивы одновременно.

```scss
// ПЛОХО (Вызовет ошибку компиляции в этом же файле)
@forward 'variables';
body {
  background-color: $theme-bg-secondary; 
}

// ХОРОШО (И локальный импорт, и трансляция наружу)
@use 'variables';
@forward 'variables';
body {
  background-color: variables.$theme-bg-secondary;
}
```

*   **Ошибка 2: Попытка изменения переменных, не помеченных флагом `!default`**
    *   *Симптомы:* Ошибка сборки Sass: `Cannot modify a read-only variable` или игнорирование переопределения переменных при использовании конструкции `@use ... with`.
    *   *Физика процесса:* Конструкция `@use ... with` пытается перезаписать значение переменной на этапе ее инициализации. Если в импортируемом файле переменная объявлена как `$theme-accent: #6366f1;` (без флага `!default`), она считается константой, защищенной от модификации.
    *   *Решение:* Всегда добавляйте флаг `!default` в конце объявления переменных вашей дизайн-системы, чтобы сделать их настраиваемыми.

*   **Ошибка 3: Нарушение структуры иерархии и дублирование глобальной верстки в компонентах Angular**
    *   *Симптомы:* Резкое увеличение размера CSS-файлов, дублирование глобальных классов сброса стилей (например, `.reset` или `.layout-grid`) внутри стилей изолированных компонентов Angular.
    *   *Физика процесса:* Разработчик помещает глобальную базовую верстку (например, селекторы `body`, `h1` или сброс стилей) внутрь модуля, импортируемого через `@use` в каждый компонент. Из-за этого при компиляции каждого компонента Angular заново генерирует и дублирует эти глобальные CSS-правила.
    *   *Решение:* Разделяйте абстракции (переменные, миксины, функции) и реальный генерируемый CSS-код. В файлы, импортируемые через `@use`, помещайте *только* сущности, не производящие физический CSS-вывод. Все глобальные стили (сбросы, шрифты) подключайте один раз в корневом файле `styles.css` или `styles.scss` вашего приложения.
