# Управление инкапсуляцией стилей (ViewEncapsulation)

## БЫСТРЫЙ СТАРТ

*   **Инкапсуляция стилей (ViewEncapsulation)** — это встроенная стратегия Angular, которая управляет тем, будут ли CSS-стили, объявленные в компоненте, изолированы внутри его шаблона, или они смогут "протекать" наружу и влиять на остальное приложение.
*   **Emulated (По умолчанию):** Angular эмулирует изоляцию, добавляя уникальные автогенерируемые атрибуты (например, `_ngcontent-c12`) ко всем элементам шаблона компонента и модифицируя CSS-селекторы. Стили не выходят за пределы компонента.
*   **None:** Инкапсуляция полностью отключена. CSS-стили компилируются в нативный тег `<style>` и добавляются в `<head>` документа, становясь глобальными. Они будут влиять на любые элементы во всем приложении.
*   **ShadowDom:** Angular использует нативный браузерный стандарт Shadow DOM. Компонент рендерится внутри изолированного `Shadow Root`, полностью закрывая стили от внешнего мира (и внешние глобальные стили также перестают влиять на разметку компонента, за исключением CSS-переменных и наследуемых свойств).
*   **Используйте:** `Emulated` для 95% бизнес-компонентов приложения. `None` для переопределения стилей сторонних библиотек (с обязательным использованием уникального родительского класса) или создания глобальных тем. `ShadowDom` для создания переиспользуемых микрофронтендов или Widget-компонентов, встраиваемых в другие платформы.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Стилизация дочерних компонентов и библиотек в режиме Emulated (NestedStyler)
*   **Назначение:** Компонент использует дефолтную эмулируемую инкапсуляцию, но точечно пробивает ее с помощью `:host ::ng-deep` для изменения стилей внутренней сторонней библиотеки, совмещая это с безопасными CSS Custom Properties.

#### 1. Файл логики компонента: `nested-styler.ts`
```typescript
import { Component, ChangeDetectionStrategy, ViewEncapsulation } from '@angular/core';

@Component({
  selector: 'app-nested-styler',
  templateUrl: './nested-styler.html',
  styleUrl: './nested-styler.css',
  // Указываем Emulated явно (хотя это значение по умолчанию)
  encapsulation: ViewEncapsulation.Emulated,
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class NestedStyler { }
```

#### 2. Файл разметки компонента: `nested-styler.html`
```html
<div class="styler-card">
  <h3>Настройка дочерних стилей</h3>
  
  <!-- Имитируем разметку сторонней библиотеки (например, ngx-datepicker) -->
  <div class="external-library-widget">
    <span class="widget-header">Календарь событий</span>
    <button class="widget-action-btn">Выбрать дату</button>
  </div>
</div>
```

#### 3. Файл стилей компонента: `nested-styler.css`
```css
/* Локальный стиль, изолированный внутри компонента */
.styler-card {
  padding: 20px;
  background-color: var(--bg-secondary);
  border: 1px solid var(--border);
  border-radius: 8px;
}

/* 
  Применяем ::ng-deep для стилизации дочерних/внешних элементов.
  ОБЯЗАТЕЛЬНО предваряем селектором :host, чтобы ограничить область 
  действия глубокого проникновения только текущим компонентом!
*/
:host ::ng-deep .external-library-widget {
  margin-top: 16px;
  padding: 12px;
  background-color: var(--bg-primary);
  border-radius: 6px;
}

/* Пробиваем стили дочерней кнопки */
:host ::ng-deep .external-library-widget .widget-action-btn {
  background-color: var(--accent);
  color: white;
  border: none;
  padding: 6px 12px;
  border-radius: 4px;
  cursor: pointer;
}
```

### Шаблон 2: Безопасное использование глобальных стилей (GlobalStyler)
*   **Назначение:** Компонент отключает инкапсуляцию стилей (`ViewEncapsulation.None`) для генерации динамической цветовой темы. Применяется строгая техника изоляции через уникальный CSS-класс во избежание загрязнения глобальной области видимости.

#### 1. Файл логики компонента: `global-styler.ts`
```typescript
import { Component, ChangeDetectionStrategy, ViewEncapsulation } from '@angular/core';

@Component({
  selector: 'app-global-styler',
  templateUrl: './global-styler.html',
  styleUrl: './global-styler.css',
  // Полностью отключаем инкапсуляцию стилей
  encapsulation: ViewEncapsulation.None,
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class GlobalStyler { }
```

#### 2. Файл разметки компонента: `global-styler.html`
```html
<!-- 
  Уникальный селектор-класс в корне разметки обязателен! 
  Он будет выступать в роли пространства имен (Namespace) в CSS.
-->
<div class="custom-neon-theme-scope">
  <div class="neon-panel">
    <h3>Экран с кастомной глобальной темой</h3>
    <p>Все стили этого компонента попадут в глобальный CSS-бандл приложения.</p>
    <button class="neon-btn">Подтвердить операцию</button>
  </div>
</div>
```

#### 3. Файл стилей компонента: `global-styler.css`
```css
/* 
  КАТЕГОРИЧЕСКИЙ ЗАПРЕТ: Писать селекторы без пространства имен в режиме None!
  Плохо: .neon-panel { ... } (может сломать карточки в других компонентах)
  
  ХОРОШО: Оборачиваем ВСЕ стили в уникальный селектор пространства имен.
*/
.custom-neon-theme-scope .neon-panel {
  padding: 24px;
  background-color: #0b0c10;
  border: 2px solid #1f2833;
  color: #c5a059;
  border-radius: 12px;
  box-shadow: 0 0 15px rgba(197, 160, 89, 0.2);
}

/* Стилизуем кнопку внутри пространства имен */
.custom-neon-theme-scope .neon-btn {
  background: transparent;
  border: 1px solid #c5a059;
  color: #c5a059;
  padding: 8px 16px;
  border-radius: 4px;
  cursor: pointer;
  transition: all 0.2s ease;
}

.custom-neon-theme-scope .neon-btn:hover {
  background-color: #c5a059;
  color: #0b0c10;
  box-shadow: 0 0 10px #c5a059;
}
```

### Шаблон 3: Полная изоляция стилей через нативный Shadow DOM (ShadowStyler)
*   **Назначение:** Компонент использует браузерную технологию Shadow DOM для полной физической изоляции разметки и стилей.

#### 1. Файл логики компонента: `shadow-styler.ts`
```typescript
import { Component, ChangeDetectionStrategy, ViewEncapsulation } from '@angular/core';

@Component({
  selector: 'app-shadow-styler',
  templateUrl: './shadow-styler.html',
  styleUrl: './shadow-styler.css',
  // Включаем нативную инкапсуляцию Shadow DOM
  encapsulation: ViewEncapsulation.ShadowDom,
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class ShadowStyler { }
```

#### 2. Файл разметки компонента: `shadow-styler.html`
```html
<div class="shadow-box">
  <h3>Полная изоляция (Shadow DOM)</h3>
  <p>Этот компонент находится внутри нативного Shadow Root.</p>
  <p>Внешние глобальные стили приложения (кроме CSS-переменных) не смогут повлиять на этот текст.</p>
</div>
```

#### 3. Файл стилей компонента: `shadow-styler.css`
```css
/* 
  В режиме Shadow DOM селектор :host ссылается напрямую на сам веб-компонент,
  выступающий родителем Shadow Root.
*/
:host {
  display: block;
  margin: 16px 0;
}

.shadow-box {
  padding: 16px;
  /* 
    Даже в Shadow DOM мы имеем беспрепятственный доступ к глобальным CSS-переменным,
    поскольку браузер наследует их свойства сквозь границы Shadow Root.
  */
  background-color: var(--bg-secondary);
  border: 1px solid var(--border);
  border-radius: 6px;
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как работает эмуляция инкапсуляции стилей на низком уровне
Режим `ViewEncapsulation.Emulated` — это интеллектуальная система парсинга шаблонов Angular. Поскольку нативная поддержка Shadow DOM долгое время отсутствовала в старых браузерах, Angular эмулирует её поведение:

1.  **Генерация хост-атрибутов:**
    При сборке Angular генерирует уникальный строковый маркер-идентификатор для каждого компонента (например, `_nghost-ng-c3971932145`). Этот маркер вешается в качестве атрибута на сам хост-элемент (тег-селектор компонента).
2.  **Генерация дочерних атрибутов:**
    Все нативные теги, находящиеся внутри HTML-шаблона этого компонента, получают дополнительный сгенерированный атрибут (например, `_ngcontent-ng-c3971932145`):
    ```html
    <app-nested-styler _nghost-ng-c3971932145>
      <div _ngcontent-ng-c3971932145 class="styler-card">...</div>
    </app-nested-styler>
    ```
3.  **Модификация CSS-селекторов:**
    Все селекторы из CSS-файла компонента автоматически переписываются компилятором Angular. Обычный класс `.styler-card` превращается в селектор по атрибуту:
    ```css
    .styler-card[_ngcontent-ng-c3971932145] { ... }
    ```
    Благодаря этому CSS-правило сработает исключительно на элементах этого конкретного компонента. Оно физически не сможет стилизовать похожий класс `.styler-card` в других частях страницы.

### 2. Спецификация ::ng-deep: почему она deprecated и какие есть альтернативы
Селектор `::ng-deep` отключает изоляцию стилей для всех дочерних элементов, идущих после него. 

*   **Почему `::ng-deep` помечен как Deprecated?**
    Потому что он нарушает стандарты W3C и спецификацию CSS. Это внутренний проприетарный механизм Angular, который заставляет компилятор стилей отбросить генерацию атрибутов вроде `[_ngcontent-...]` для последующей части селектора.
*   **Почему его до сих пор используют?**
    На данный момент в веб-стандартах отсутствует удобная нативная замена для проникновения стилей сквозь компоненты. Angular-команда заявляет, что `::ng-deep` будет полностью удален только тогда, когда в браузерах появится стабильная альтернатива.
*   **Архитектурная альтернатива (CSS Custom Properties):**
    Современный и безопасный подход стилизации сторонних виджетов — проектирование стилей на основе CSS-переменных. CSS-переменные наследуются сквозь любые границы (включая нативный Shadow DOM).

```css
/* Проектирование дочернего компонента с точками кастомизации */
.child-widget {
  background-color: var(--widget-bg-color, #ffffff);
  color: var(--widget-text-color, #333333);
}

/* Стилизация дочернего компонента из родителя без всяких ::ng-deep */
app-child-widget {
  --widget-bg-color: var(--bg-secondary);
  --widget-text-color: var(--accent);
}
```

### 3. Сравнение нативного Shadow DOM и Emulated
Режим `ShadowDom` кардинально отличается от `Emulated` на уровне рендеринга браузера:

1.  **Создание Shadow Root:** Browser API инициализирует настоящую изолированную капсулу внутри элемента (`#shadow-root`).
2.  **Полная изоляция:** Нативные стили, объявленные внутри этой капсулы, не выходят наружу. Внешний глобальный CSS-код (например, общие стили UI-библиотек) не проникает внутрь Shadow DOM. Это исключает случайный конфликт стилей при интеграции независимых виджетов на одной странице.
3.  **Специфика селекторов:** В режиме Shadow DOM вы не можете использовать `::ng-deep` (он просто проигнорируется браузером). Стилизация дочерних элементов возможна только через CSS-переменные или нативные селекторы вроде `part` (`::part()`).

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Загрязнение глобального CSS-окружения в режиме `ViewEncapsulation.None`**
    *   *Симптомы:* Стили одного компонента внезапно применились к кнопкам, спискам или карточкам во всем приложении, исказив верстку.
    *   *Физика процесса:* Разработчик установил `encapsulation: ViewEncapsulation.None`, чтобы переопределить стиль конкретной кнопки. При этом CSS-класс компонента компилируется в обычный глобальный CSS, заменяя дефолтное поведение всех одноименных тегов на странице.
    *   *Решение:* При выключении инкапсуляции всегда оборачивайте всю разметку шаблона в один корневой уникальный CSS-класс и пишите все правила внутри него (как показано в Шаблоне 2).

```typescript
// ПЛОХО (Повлияет на все h2 и .card во всем приложении)
@Component({
  encapsulation: ViewEncapsulation.None,
  styles: `h2 { color: red; } .card { border: none; }`
})

// ХОРОШО (Изолировано с помощью пространства имен)
@Component({
  encapsulation: ViewEncapsulation.None,
  styles: `.my-unique-page h2 { color: red; } .my-unique-page .card { border: none; }`
})
```

*   **Ошибка 2: Использование `::ng-deep` без селектора `:host`**
    *   *Симптомы:* Стилизация глубоких элементов дочерней библиотеки неожиданно применилась к другим страницам приложения, куда пользователь перешел позже.
    *   *Физика процесса:* Написание селектора `.my-class ::ng-deep .widget { ... }` заставляет компилятор стилей Angular убрать атрибуты изоляции для `.widget` глобально. В итоге создается глобальное CSS-правило.
    *   *Решение:* Всегда предваряйте `::ng-deep` псевдоклассом `:host`. Селектор `:host ::ng-deep .widget` компилируется в `[_nghost-...] .widget`, гарантируя, что влияние правила ограничится строго текущим компонентом и его дочерними элементами.

*   **Ошибка 3: Попытка стилизации спроецированного контента (`ng-content`) дефолтными селекторами**
    *   *Симптомы:* Родитель передает разметку внутрь дочернего компонента-контейнера через `<ng-content>`, но дочерний компонент не может применить к ней свои стили.
    *   *Физика процесса:* В режиме `Emulated` элементы, переданные в `<ng-content>`, физически принадлежат родителю. Они получают атрибуты изоляции родителя (например, `_ngcontent-c1`), в то время как дочерний компонент применяет стили по своим атрибутам `_ngcontent-c2`. Из-за несовпадения атрибутов стили не срабатывают.
    *   *Решение:* Для стилизации контента, проецируемого через `ng-content`, в CSS-файле дочернего компонента используйте специальный селектор `:host ::ng-deep` или нативный псевдокласс `::slotted()` в режиме Shadow DOM.
