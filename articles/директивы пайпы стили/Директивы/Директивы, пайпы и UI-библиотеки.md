# Директивы, пайпы и UI-библиотеки

## БЫСТРЫЙ СТАРТ

*   **Директивы и Пайпы** — это основные инструменты расширения шаблонов Angular. Директивы управляют логикой рендеринга и поведением элементов (атрибутные и структурные), а Пайпы декларативно форматируют значения непосредственно во время вывода на экран.
*   **Tree-Shaking и атомарный импорт (Angular 19+):** Тяжелые общие модули (такие как `CommonModule` или `ReactiveFormsModule`) считаются легаси-бойлерплейтом. Современный стандарт требует импортировать в массив `imports` компонента только те конкретные директивы и пайпы, которые реально используются в его HTML-шаблоне (например, `NgClass`, `DatePipe`, `DecimalPipe`).
*   **Используйте для:** создания переиспользуемых визуальных эффектов (тултипы, маски ввода), локализации форматов вывода и построения модульных UI-компонентов с предсказуемым весом бандла.
*   **Не используйте для:** сквозной бизнес-логики и тяжелых сетевых вызовов (для этих задач предназначены исключительно сервисы внедрения зависимостей).

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Атомарная интеграция директив и пайпов в Standalone-компонент
*   **Назначение:** Описание современной структуры компонента карточки мониторинга `DashboardStatsCard` с точечным импортом необходимых системных директив и пайпов, исключающим подключение тяжелого `CommonModule`.

#### 1. Файл логики: `dashboard-stats-card.ts`
```typescript
import { Component, ChangeDetectionStrategy, signal } from '@angular/core';
import { DatePipe, DecimalPipe, NgClass } from '@angular/common'; // Импортируем только конкретные директивы и пайпы для оптимизации бандла
import { HoverAccent } from './hover-accent'; // Импортируем нашу локальную кастомную директиву ховера

export interface MetricPayload {
  readonly value: number;
  readonly lastUpdated: Date;
  readonly isCritical: boolean;
}

@Component({
  selector: 'app-dashboard-stats-card',
  // standalone: true опущен по умолчанию в Angular 19+
  imports: [
    NgClass,       // Точечно импортируем директиву динамического изменения классов
    DatePipe,      // Точечно импортируем пайп форматирования дат
    DecimalPipe,   // Точечно импортируем пайп форматирования чисел
    HoverAccent    // Подключаем нашу кастомную директиву ховера
  ],
  templateUrl: './dashboard-stats-card.html',
  styleUrl: './dashboard-stats-card.css',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class DashboardStatsCard { // Имя класса очищено от суффикса Component
  // Сигнал, хранящий текущие показатели датчиков
  public readonly metrics = signal<MetricPayload>({
    value: 12450.852,
    lastUpdated: new Date(),
    isCritical: true
  });
}
```

#### 2. Файл разметки: `dashboard-stats-card.html`
```html
<!-- Применяем кастомную директиву ховера appHoverAccent напрямую в шаблоне -->
<div class="stats-card" appHoverAccent [hoverColor]="'var(--nav-active)'">
  <div class="card-header">
    <h4>Показания датчика ядра</h4>
    <!-- Используем нативный DatePipe для форматирования даты -->
    <small>Обновлено: {{ metrics().lastUpdated | date:'mediumTime' }}</small>
  </div>

  <!-- 
    Используем нативный NgClass для условной подсветки критического статуса.
    Используем DecimalPipe для форматирования дробной части числа (округление до 2 знаков).
  -->
  <div class="card-value" [ngClass]="{ 'critical-text': metrics().isCritical }">
    <span>{{ metrics().value | number:'1.2-2' }} МБ/с</span>
  </div>
</div>
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как Ivy Engine компилирует декларативные импорты в шаблонах
В классических версиях Angular (до Angular 14) компилятор не мог точечно оптимизировать использование директив и пайпов, так как они декларировались группами внутри тяжелых модулей `NgModule`. 

С переходом на Standalone-архитектуру и компилятор Ivy (`ngtsc`), процесс компиляции шаблона компонента кардинально изменился:
1.  **Создание локального контекста:** Когда вы перечисляете директивы и пайпы в массиве `imports` компонента `DashboardStatsCard`, компилятор строит изолированную карту соответствий (Scope) строго для шаблона этого компонента.
2.  **Генерация инструкций Ivy:** При трансляции HTML-файла в JavaScript-код компилятор преобразует использование тегов, привязок и пайпов в плоский набор быстрых системных функций рендеринга (так называемых *Ivy Instructions*):
    *   Привязка `[ngClass]` преобразуется во внутренний вызов `ɵɵclassMap()`.
    *   Использование пайпа `| number` преобразуется во внутреннюю инструкцию `ɵɵpipeBind1()`, которая ссылается на импортированный класс `DecimalPipe`.
3.  **Оптимизация Tree-Shaking:** Сборщики кода (Vite, Esbuild, Webpack) анализируют финальный JS-код компонента. Поскольку связи импорта стали прямыми (ES-импорты), неиспользуемые методы и классы из тяжелых пакетов (например, неиспользуемые пайпы из `@angular/common`) полностью вырезаются из итоговой сборки приложения.

### 2. Принцип мемоизации чистых пайпов против жизненного цикла директив
В основе реактивности шаблонов Angular лежит разделение обязанностей между директивами и пайпами:

*   **Директивы (Мутабельный жизненный цикл):** Директивы разрабатываются как активные участники жизненного цикла DOM. Они внедряют `ElementRef` и `Renderer2`, подписываются на события хост-элемента через `@HostListener` или `Renderer2.listen` и могут напрямую изменять структуру документа в рантайме. Их методы вызываются в рамках циклов Change Detection при проверке ветки дерева.
*   **Чистые пайпы (Pure Pipes — Мемоизация):** Пайпы со свойством `pure: true` (поведение по умолчанию) ведут себя как чистые функции математического анализа. Движок Ivy кэширует результат работы метода `transform()` пайпа. При проверке изменений Angular выполняет быстрое сравнение входных аргументов по ссылочной идентичности `===`. Если аргументы не изменились, метод `transform()` игнорируется вовсе, а на экран мгновенно выводится результат из кэша памяти, что экономит такты процессора при отрисовке сложных таблиц.

### 3. Детальный пошаговый разбор фазы рендеринга шаблона 1
Рассмотрим шаги Angular при отображении карточки `DashboardStatsCard`:

1.  **Парсинг и сопоставление:** Angular рендерит шаблон компонента. Находя в разметке атрибут `appHoverAccent`, движок сопоставляет его со скрытым селектором нашей директивы `HoverAccent` и создает ее экземпляр, привязывая к текущему DOM-узлу.
2.  **Инициализация пайпов:** Создаются экземпляры классов `DatePipe` и `DecimalPipe`.
3.  **Первый проход Change Detection:**
    *   Значение сигнала `metrics().lastUpdated` передается на вход `DatePipe`. Поскольку кэш пуст, запускается метод `transform()`, возвращая строку времени. Результат кэшируется.
    *   Значение сигнала `metrics().value` (12450.852) передается в `DecimalPipe` с параметром `'1.2-2'`. Вычисляется округленное значение `12 450.85`. Результат кэшируется.
4.  **Повторные проверки изменений (Change Detection):** Пользователь кликает в другой части экрана. Запускается проверка изменений. Движок сравнивает ссылки аргументов пайпов. Поскольку значение сигнала `metrics` не изменялось, вызовы методов `transform()` полностью блокируются, а данные выводятся из кэша.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Ошибка компиляции шаблона из-за дублирования импортов (Standalone Collision)**
    *   *Симптомы:* Критическая ошибка компиляции вида `NG8002: Can't bind to 'ngClass' since it isn't a known property of 'div'`.
    *   *Физика процесса:* Разработчик пытается применить `[ngClass]` в HTML-шаблоне standalone-компонента, но забыл указать класс `NgClass` в массиве `imports` декоратора `@Component`. Шаблон standalone-компонента полностью изолирован, и компилятор не имеет доступа к глобальным директивам по умолчанию.
    *   *Решение:* Явно импортируйте конкретный класс директивы в массив `imports` компонента, как показано в Шаблоне 1.

```typescript
// ПЛОХО (Компилятор выдаст ошибку, так как шаблон не знает про NgClass)
@Component({
  selector: 'app-bad-card',
  templateUrl: './bad-card.html'
})
export class BadCard {}

// ХОРОШО (Точечный импорт обеспечивает работоспособность и оптимизацию бандла)
import { NgClass } from '@angular/common';

@Component({
  selector: 'app-good-card',
  imports: [NgClass],
  templateUrl: './good-card.html'
})
export class GoodCard {}
```

*   **Ошибка 2: Коллизия CSS-селекторов кастомных директив со сторонними UI-библиотеками**
    *   *Симптомы:* Навешивание кастомной директивы неожиданно ломает стили или поведение компонентов из сторонних библиотек (например, Angular Material или PrimeNG).
    *   *Физика процесса:* Разработчик объявил директиву с общим селектором без префикса (например, `selector: '[selected]'`). Если подключенная сторонняя библиотека также использует атрибут `selected` для управления активными вкладками, Angular применит вашу директиву к элементам библиотеки, вызывая непредсказуемые побочные эффекты.
    *   *Решение:* Всегда добавляйте уникальный префикс вашего приложения ко всем селекторам кастомных директив (например, `selector: '[appHoverAccent]'`).

*   **Ошибка 3: Избыточный импорт `CommonModule` вместо атомарных классов**
    *   *Симптомы:* Раздувание размера бандла (Bundle Size inflation) за счет импорта неиспользуемых системных утилит.
    *   *Физика процесса:* Разработчик по привычке импортирует монолитный `CommonModule` в каждый Standalone-компонент ради использования одного лишь пайпа `| async` или директивы `[ngClass]`. `CommonModule` тянет за собой десятки других директив и пайпов, усложняя работу алгоритмов Tree-Shaking.
    *   *Решение:* Полностью откажитесь от импорта `CommonModule` в новых компонентах. Импортируйте строго атомарные классы (`NgClass`, `NgStyle`, `AsyncPipe`, `DatePipe` и т.д.) по мере необходимости.
