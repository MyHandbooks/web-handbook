# 2.1.2. Создание защитников типов (Type Guards)

## БЫСТРЫЙ СТАРТ

*   **Type Guards (Защитники типов)** — это кастомные функции-предикаты, которые возвращают логическое значение (`true`/`false`) и снабжены сигнатурой возвращаемого типа `parameter is TargetType`. Они сообщают компилятору TypeScript, что при успешном прохождении проверки тип переменной внутри блока `if` сужается до целевого.
*   **Безопасный мост между рантаймом и компиляцией:** В отличие от небезопасного принудительного приведения типов (`as TargetType`), защитники типов гарантируют, что логика проверки физически выполняется во время работы JavaScript-кода (в рантайме), а не просто декларируется для компилятора.
*   **Используйте их для:** валидации сложных динамических структур данных (вложенные ответы от серверов, конфигурации, сообщения из WebSockets), где встроенных операторов `typeof` или `instanceof` недостаточно.
*   **Не используйте их:** для слепого "заглушения" ошибок компилятора без глубокой рантайм-проверки каждого обязательного поля объекта. Ошибка в коде защитника приведет к ситуации, когда TypeScript будет считать структуру валидной, но в рантайме приложение упадет с ошибкой `TypeError`.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Базовый защитник типа для интерфейса (`parameter is Type`)
*   **Назначение:** Определение соответствия входящих динамических данных типа `unknown` структуре интерфейса.

```typescript
export interface TargetPayload {
  identifier: string;
  statusCode: number;
  isActive: boolean;
}

// Функция-защитник возвращает сигнатуру-предикат 'value is TargetPayload'
export function isTargetPayload(value: unknown): value is TargetPayload {
  // 1. Проверяем, что значение физически является непустым объектом
  if (typeof value !== "object" || value === null) {
    return false;
  }

  // 2. Для безопасного обращения к динамическим свойствам в рантайме кастим к Record
  const candidate = value as Record<string, unknown>;

  // 3. Выполняем строгую проверку типов для каждого обязательного поля интерфейса
  return (
    typeof candidate["identifier"] === "string" &&
    typeof candidate["statusCode"] === "number" &&
    typeof candidate["isActive"] === "boolean"
  );
}

// Пример практического использования в коде
export function processIncomingPayload(data: unknown): void {
  if (isTargetPayload(data)) {
    // Внутри этого блока TypeScript автоматически сужает data до типа TargetPayload
    console.log(`Данные валидны: ${data.identifier.toUpperCase()} (Код: ${data.statusCode})`);
  } else {
    console.error("Критический сбой: Полученные данные не соответствуют типу TargetPayload");
  }
}
```

### Шаблон 2: Проверка массива однородных объектов
*   **Назначение:** Валидация структуры массива, состоящего исключительно из объектов целевого типа.

```typescript
export interface ConfigOptions {
  activeUrl: string;
  retriesCount: number;
}

// Вспомогательный защитник для валидации одного объекта конфигурации
export function isConfigOptions(value: unknown): value is ConfigOptions {
  if (typeof value !== "object" || value === null) {
    return false;
  }
  const candidate = value as Record<string, unknown>;
  return (
    typeof candidate["activeUrl"] === "string" &&
    typeof candidate["retriesCount"] === "number"
  );
}

// Основной защитник для массива объектов конфигурации
export function isConfigOptionsArray(value: unknown): value is ConfigOptions[] {
  // 1. Проверяем в рантайме, что переданный аргумент действительно является массивом
  if (!Array.isArray(value)) {
    return false;
  }

  // 2. Проверяем, что каждый элемент массива удовлетворяет условиям защитника
  // Метод .every() гарантирует возврат true только если все элементы прошли валидацию
  return value.every((item: unknown) => isConfigOptions(item));
}
```

### Шаблон 3: Утверждающая функция (Assertion Guard / `asserts condition`)
*   **Назначение:** Прерывание выполнения программы и выброс исключения при несоответствии типов (подход fail-fast) вместо ветвления через `if/else`.

```typescript
export interface SessionContext {
  token: string;
  expiresAt: number;
}

// Используем утверждающую сигнатуру 'asserts value is SessionContext'
export function assertSessionContext(value: unknown): asserts value is SessionContext {
  // 1. Проверяем базовое соответствие типу object
  if (typeof value !== "object" || value === null) {
    throw new TypeError("Валидация контекста сессии провалена: Значение не является объектом");
  }

  const candidate = value as Record<string, unknown>;

  // 2. Проверяем типы полей и выбрасываем точечное исключение при любом несоответствии
  if (typeof candidate["token"] !== "string") {
    throw new TypeError("Валидация контекста сессии провалена: Поле 'token' должно быть строкой");
  }

  if (typeof candidate["expiresAt"] !== "number") {
    throw new TypeError("Валидация контекста сессии провалена: Поле 'expiresAt' должно быть числом");
  }

  // Если функция завершилась без исключений, TypeScript считает, что аргумент валиден
}

// Пример использования утверждающего защитника сессии
export function runAuthenticatedOperation(rawContext: unknown): void {
  // Вызов функции сужает тип rawContext до SessionContext в текущей области видимости
  assertSessionContext(rawContext);

  // Никаких дополнительных проверок if-else не требуется:
  // Переменная 'rawContext' теперь безопасно распознается компилятором как SessionContext
  console.log(`Сессия активна. Токен истекает в: ${rawContext.expiresAt}`);
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как TypeScript доверяет контрактам защитников на уровне компиляции
TypeScript — это инструмент статического анализа, типы которого полностью удаляются при транспиляции в JavaScript (Type Erasure). Конструкция `parameter is TargetType` является жестким соглашением между разработчиком и компилятором. Когда вы указываете такую сигнатуру, компилятор прекращает внутренний анализ логики функции и полностью полагается на возвращаемое ею булево значение.

Если вы напишете защитник типа `isTargetPayload` и внутри просто вернете `return true` без рантайм-проверок, компилятор без возражений сузит тип до `TargetPayload` во всех блоках, защищенных вызовом этой функции. Это перекладывает всю ответственность за фактическую безопасность типов в рантайме на качество реализации рантайм-проверок внутри тела защитника.

### 2. Сравнение классических Type Guards (`value is T`) и Assertion Guards
Выбор между ними зависит от архитектурной стратегии обработки некорректных данных:

*   **Классический Type Guard (`value is T`):** Предназначен для условного ветвления логики. Он возвращает логическое значение (`true`/`false`) и используется внутри управляющих конструкций `if`, `while` или тернарных операторов. Тип переменной сужается исключительно в пределах фигурных скобок `{}` соответствующей логической ветки.
*   **Assertion Guard (`asserts value is T`):** Предназначен для валидации жестких контрактов, нарушение которых делает дальнейшее выполнение текущей операции бессмысленным. Он ничего не возвращает (`void`), но выбрасывает рантайм-исключение при провале проверки. Главное преимущество: после вызова этой функции тип переменной сужается на **всю оставшуюся область видимости текущего блока**, избавляя код от глубокой вложенности `if-else`.

### 3. Детальный пошаговый разбор выполнения шаблона 3
Проследим выполнение функции `runAuthenticatedOperation(rawContext)`:
1.  **Вход в функцию:** На этапе инициализации переменная `rawContext` имеет тип `unknown`. Попытка прямого доступа к `rawContext.token` пресекается компилятором на этапе сборки.
2.  **Вызов ассерта:** Выполняется функция `assertSessionContext(rawContext)`.
3.  **Рантайм-проверки:**
    *   Сначала проверяется, что `rawContext` — это не `null` и имеет тип `"object"`. Если проверка не пройдена, генерируется исключение `TypeError`, и стек выполнения текущего потока прерывается.
    *   Переменная приводится к `Record<string, unknown>` для возможности динамического чтения по ключам без ошибок линтера.
    *   Проверяется тип поля `token`. При несовпадении выбрасывается точечное исключение.
    *   Проверяется тип поля `expiresAt`. При несовпадении выбрасывается точечное исключение.
4.  **Статический анализ после вызова:** Анализатор потока управления компилятора (Control Flow Analysis) видит, что функция `assertSessionContext` успешно завершилась и не выбросила ошибку. Поскольку сигнатура функции содержит `asserts value is SessionContext`, тип переменной `rawContext` в текущей области видимости переопределяется с `unknown` на `SessionContext`.
5.  **Выполнение операции:** Строка `console.log(rawContext.expiresAt)` успешно компилируется и выполняется в рантайме.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Ошибочное сужение типа при неполной валидации (Псевдо-защитники)**
    *   *Проблема:* Разработчик описывает защитник типа, но проверяет только часть обязательных свойств интерфейса. TypeScript верит сигнатуре и снимает ограничения, но в рантайме программа падает при обращении к непроверенным свойствам, которые оказались отсутствующими или неверного типа.
    *   *Решение:* Защитник должен строго и последовательно валидировать каждое обязательное свойство интерфейса.

```typescript
// ПЛОХО (Проверяется только одно свойство. Если statusCode будет undefined, программа упадет далее в рантайме)
export function isTargetPayloadUnsafe(value: unknown): value is TargetPayload {
  const candidate = value as Record<string, unknown>;
  return typeof candidate?.["identifier"] === "string"; // Поля statusCode и isActive проигнорированы
}

// ХОРОШО (Полное покрытие всей структуры интерфейса гарантирует рантайм-безопасность)
export function isTargetPayloadSafe(value: unknown): value is TargetPayload {
  if (typeof value !== "object" || value === null) return false;
  const candidate = value as Record<string, unknown>;
  return (
    typeof candidate["identifier"] === "string" &&
    typeof candidate["statusCode"] === "number" &&
    typeof candidate["isActive"] === "boolean"
  );
}
```

*   **Ошибка 2: Пропуск проверок на `null` и массивы**
    *   *Проблема:* Оператор `typeof` в JavaScript возвращает `"object"` для `null` и для массивов. Если защитник принимает `null` и сразу пытается прочесть свойство `candidate["identifier"]`, программа падает в рантайме с ошибкой `TypeError: Cannot read properties of null`.
    *   *Решение:* Первым делом в любом защитнике объекта должна стоять явная проверка на неравенство `null`. Если валидируется объект, а не массив, стоит также явно исключать массивы через `!Array.isArray(value)`.

*   **Ошибка 3: Ложные срабатывания при использовании оператора `in` без рантайм-проверки на тип `object`**
    *   *Проблема:* Разработчик пытается сузить тип через проверку `"propertyName" in value`, забывая, что на вход может прийти примитив (строка, число). Попытка выполнить оператор `in` на примитивном значении в JavaScript вызывает рантайм-ошибку `TypeError: Cannot use 'in' operator to search for...`.
    *   *Решение:* Используйте оператор `in` или прямое считывание ключей по индексу `candidate["propertyName"]` только после того, как в рантайме доказано, что проверяемое значение действительно является объектом и не равно `null`.
