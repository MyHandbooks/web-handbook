# 2.1.1. Безопасная работа с типом unknown

## БЫСТРЫЙ СТАРТ

*   **`unknown`** — это верхний тип (Top Type) в системе типов TypeScript. Он представляет любое значение, но в отличие от `any`, запрещает вызывать на себе методы, считывать свойства или передавать в другие функции без предварительного сужения типа.
*   **Безопасный аналог `any`:** `unknown` заставляет разработчика писать рантайм-проверки структуры данных, гарантируя, что программа не упадет с ошибкой во время выполнения.
*   **Используйте его для:** типизации внешних неконтролируемых данных (ответы от API, чтение файлов, парсинг JSON, пользовательский ввод).
*   **Не используйте:** приведение типов вида `value as TargetType` без предварительной физической проверки структуры объекта в рантайме — это маскирует логические ошибки и ломает типобезопасность.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Прием внешних данных через `unknown`
*   **Назначение:** Безопасный прием нетипизированного ответа от сервера с обязательной рантайм-проверкой перед использованием.

```typescript
export interface TargetPayload {
  identifier: string;
  statePayload: string;
}

export function processExternalData(rawResponse: unknown): void {
  // Напрямую считывать свойства из unknown запрещено компилятором:
  // console.log(rawResponse.identifier); // ! Ошибка компиляции TS

  // Физически проверяем, что данные являются объектом и содержат нужные ключи
  if (
    typeof rawResponse === "object" && 
    rawResponse !== null && 
    "identifier" in rawResponse && 
    "statePayload" in rawResponse
  ) {
    // TypeScript автоматически сужает тип rawResponse внутри блока if
    // Кастим свойства к типу string для безопасного вызова методов
    const id = String((rawResponse as any).identifier);
    const payload = String((rawResponse as any).statePayload);

    console.log(`Данные успешно валидированы. ID: ${id}, Полезная нагрузка: ${payload}`);
  } else {
    console.error("Критический сбой: Входящие данные не соответствуют типу TargetPayload");
  }
}
```

### Шаблон 2: Сужение типа для примитивов через `typeof`
*   **Назначение:** Определение и безопасная обработка примитивных типов данных (строка, число, булево значение), полученных из внешнего источника.

```typescript
export function formatValue(value: unknown): string {
  // Проверяем, является ли значение строкой в рантайме
  if (typeof value === "string") {
    // Внутри этого блока value имеет тип string. Методы строки доступны автодополнением
    return value.trim().toUpperCase(); 
  }

  // Проверяем, является ли значение числом
  if (typeof value === "number") {
    // Внутри этого блока value имеет тип number. Доступны математические операции
    return value.toFixed(2);
  }

  // Дефолтное поведение для всех остальных типов
  return "unsupported_format";
}
```

### Шаблон 3: Проверка принадлежности к классу через `instanceof`
*   **Назначение:** Определение типа сложного объекта на основе его прототипной цепочки (класса) во время выполнения программы.

```typescript
export class ConfigOptions {
  constructor(public activeUrl: string) {}
}

export class TemporaryResult {
  constructor(public records: string[]) {}
}

export function handleStateInstance(instance: unknown): void {
  // Проверяем, является ли объект экземпляром класса ConfigOptions
  if (instance instanceof ConfigOptions) {
    // TS сужает тип до ConfigOptions. Свойство activeUrl доступно безопасно
    console.log(`Конфигурация активна по адресу: ${instance.activeUrl}`);
    return;
  }

  // Проверяем принадлежность ко второму классу
  if (instance instanceof TemporaryResult) {
    // TS сужает тип до TemporaryResult. Доступен массив records
    console.log(`Записи успешно считаны. Количество: ${instance.records.length}`);
    return;
  }

  console.warn("Переданный объект не принадлежит ни к одному известному классу конфигурации.");
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как тип `unknown` устроен в системе типов TypeScript
В теории типов TypeScript `unknown` является **универсальным надмножеством** (Top Type) наряду с `any`. Это означает, что переменной типа `unknown` можно присвоить значение абсолютно любого типа (число, строку, объект, массив, функцию).

Однако между ними есть фундаментальное различие в правилах контроля типов:
*   Тип `any` отключает статический анализ. Вы можете читать свойства, вызывать методы и присваивать переменную `any` в переменные других строго заданных типов без явного преобразования.
*   Тип `unknown` заставляет соблюдать строгую безопасность. Вы не можете вызывать методы или читать свойства переменной `unknown`, пока компилятор не убедится в ее истинном типе посредством сужения. Также переменную типа `unknown` невозможно напрямую присвоить переменной любого другого типа (кроме самого `unknown` или `any`) без явного приведения типов или логических проверок.

### 2. Принцип безопасного сужения типов (Type Narrowing)
Сужение типов — это процесс, при котором статический компилятор TypeScript анализирует логическую цепочку выполнения (Control Flow Analysis) и временно переопределяет тип переменной на более узкий внутри конкретной ветки кода (например, внутри блоков `if`).

Движок TypeScript анализирует стандартные рантайм-операторы JavaScript:
*   `typeof value === "string"` — сужает тип до примитива.
*   `value instanceof ClassName` — сужает тип до конкретного класса-конструктора на основе прототипной цепочки.
*   `"propertyName" in object` — сужает тип до объекта, содержащего данное свойство.

Если рантайм-проверка успешно завершается, компилятор гарантирует, что внутри этой ветки обращение к свойствам безопасно, снимая ограничения `unknown`.

### 3. Детальный пошаговый разбор выполнения шаблона 3
1.  **Прием аргумента:** Функция `handleStateInstance(instance)` принимает объект. TypeScript помечает переменную `instance` типом `unknown`. Попытка прочитать `instance.activeUrl` заблокирована компилятором.
2.  **Запуск проверки `instanceof`:** Движок V8 в рантайме обращается к скрытому свойству `[[Prototype]]` объекта `instance` и сверяет его с прототипом класса `ConfigOptions`.
3.  **Логическое ветвление:**
    *   *Сценарий А (Совпадение найдено):* Рантайм возвращает `true`. Управление переходит внутрь блока `if`. Анализатор TypeScript видит успешный проход проверки и меняет тип `instance` с `unknown` на `ConfigOptions` в пределах этого блока скобок `{}`. Вызов `instance.activeUrl` проходит компиляцию.
    *   *Сценарий Б (Сбой проверки):* Рантайм возвращает `false`. Поток переходит ко второй проверке. Тип переменной `instance` вне первого блока остается `unknown`.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Попытка прямого чтения свойств из `unknown`**
    *   *Проблема:* Разработчик принимает ответ от API, типизирует его как `unknown` и пытается сразу использовать: `const key = response.id;`. Возникает ошибка компиляции: `TypeScript error: 'response' is of type 'unknown'.`.
    *   *Решение:* Опишите интерфейс ожидаемых данных и напишите функцию-валидатор (Type Guard), которая проверит наличие полей в рантайме.

*   **Ошибка 2: Небезопасное приведение типов (Type Assertion Bypass)**
    *   *Проблема:* Обход компилятора через принудительное приведение типа без физической проверки данных: `const data = rawData as TargetPayload;`. Код компилируется без ошибок, но если с сервера придет пустой объект или `null`, программа упадет в рантайме с ошибкой `TypeError`.
    *   *Решение:* Приведение типов через `as` сообщает компилятору: «Я верю, что здесь лежит этот тип». Используйте приведение типов только **после** того, как вы физически проверили структуру объекта с помощью операторов `typeof` или `in`.

```typescript
// ПЛОХО (Взлом компилятора. Если в rawData придет null, код упадет в рантайме)
export function bypassAssertionUnsafe(rawData: unknown): void {
  const payload = rawData as TargetPayload; // ! Обман компилятора
  console.log(payload.identifier.toLowerCase()); // ! TypeError: Свойство identifier undefined
}

// ХОРОШО (Приведение типов выполняется после рантайм-проверки структуры)
export function bypassAssertionSafe(rawData: unknown): void {
  if (typeof rawData === "object" && rawData !== null && "identifier" in rawData) {
    const payload = rawData as TargetPayload; // Безопасно, так как мы только что проверили наличие ключа
    console.log(payload.identifier.toLowerCase());
  }
}
```

*   **Ошибка 3: Попытка деструктурировать переменную типа `unknown`**
    *   *Проблема:* Написание конструкции вида `const { id } = rawResponse;` для переменной типа `unknown` вызовет ошибку компиляции.
    *   *Решение:* Выполняйте деструктуризацию только после сужения типа.

```typescript
// ПЛОХО (Деструктуризация unknown запрещена)
export function unpackUnsafe(data: unknown): void {
  // const { identifier } = data; // ! Ошибка компиляции TS
}
```
