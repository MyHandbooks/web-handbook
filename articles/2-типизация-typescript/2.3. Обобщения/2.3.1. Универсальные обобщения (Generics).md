# 2.3.1. Универсальные обобщения (Generics)

## БЫСТРЫЙ СТАРТ

*   **Обобщения (Generics)** — это абстрактные переменные для типов, которые позволяют создавать переиспользуемые классы, интерфейсы и функции, сохраняющие строгую типизацию данных при работе с самыми разными структурами.
*   **Сохранение сигнатур вместо стирания:** В отличие от типа `any`, который полностью отключает проверку типов, или `unknown`, требующего сужения, обобщения динамически "захватывают" тип переданного аргумента и переносят его на возвращаемое значение или внутренние структуры.
*   **Используйте их для:** создания универсальных сетевых оберток API, кэш-служб, базовых репозиториев данных, абстрактных таблиц, списков или чистых вспомогательных утилит трансформации данных.
*   **Не используйте их:** для избыточного усложнения простых функций. Если логика функции работает только с одним конкретным типом, введение дженериков снижает читаемость кода без получения практической выгоды.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Универсальный контейнер ответа API (Generic Response Wrapper)
*   **Назначение:** Единая типизация всех сетевых ответов от бэкенда с сохранением строгой структуры полезной нагрузки.

```typescript
// Обобщенный интерфейс принимает параметр T для описания структуры данных
export interface ResponseOutput<T> {
  success: boolean;
  data: T;
  error?: string;
  timestamp: number;
}

export interface UserAccount {
  uuid: string;
  email: string;
}

export interface ConfigOptions {
  activeUrl: string;
  retriesCount: number;
}

// Пример функции, обрабатывающей ответ сервера для конкретного типа данных
export function handleUserResponse(response: ResponseOutput<UserAccount>): void {
  if (response.success) {
    // TypeScript точно знает, что свойство data имеет тип UserAccount
    console.log(`Пользователь загружен: ${response.data.email}`);
  } else {
    console.error(`Ошибка запроса: ${response.error}`);
  }
}
```

### Шаблон 2: Обобщенная служба кэширования с ограничением (Constraint)
*   **Назначение:** Реализация переиспользуемого сервиса кэширования, который работает только с объектами, имеющими уникальный строковый идентификатор.

```typescript
// Интерфейс-контракт, требующий наличия ключевого свойства
export interface Identifiable {
  identifier: string;
}

// Параметр T обязан расширять Identifiable (наследование контракта)
export class GenericCacheService<T extends Identifiable> {
  // Словарь для хранения записей в памяти
  private storage: Record<string, T> = {};

  // Сохранение элемента
  public set(item: T): void {
    // Ограничение гарантирует, что у объекта T есть свойство identifier
    this.storage[item.identifier] = item;
  }

  // Получение элемента
  public get(key: string): T | undefined {
    return this.storage[key];
  }

  // Получение всех сохраненных идентификаторов
  public getKeys(): string[] {
    return Object.keys(this.storage);
  }
}
```

### Шаблон 3: Универсальная функция трансформации массивов
*   **Назначение:** Типизация вспомогательных хелперов, трансформирующих один массив данных в другой с полным отслеживанием изменения типов.

```typescript
// Функция принимает два параметра: T (исходный тип) и U (целевой тип)
export function transformPayloadArray<T, U>(
  items: T[], 
  transformer: (item: T) => U
): U[] {
  const result: U[] = [];
  
  for (const item of items) {
    // Вызов функции-трансформера возвращает строго тип U
    result.push(transformer(item));
  }
  
  return result;
}

// Пример использования:
const rawNumbers: number[] = [1, 2, 3];
// Передаем массив чисел, возвращаем массив строк. TS автоматически выводит типы T = number, U = string
const stringified = transformPayloadArray(rawNumbers, (num) => `ID_${num}`);
console.log(stringified); // Результат: ["ID_1", "ID_2", "ID_3"]
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Физика Generic-параметров в TypeScript на этапе статического анализа
Обобщения ведут себя как параметры или переменные, но оперируют не рантайм-значениями, а типами данных на этапе компиляции. 

Когда вы пишете `ResponseOutput<T>`, вы создаете шаблонный контракт. В момент объявления переменной вида `let response: ResponseOutput<UserAccount>` компилятор выполняет неявную подстановку: он заменяет все упоминания параметра `T` внутри интерфейса `ResponseOutput` на реальный тип `UserAccount`. 

В скомпилированном JavaScript-коде никаких дженериков не остается — они стираются без следа. Вся работа по проверке соответствия типов ложится строго на плечи статического анализатора TypeScript в процессе написания и сборки кода.

### 2. Ограничения обобщений (Generic Constraints) и значения по умолчанию
По умолчанию параметр обобщения `<T>` является абсолютно свободным — в него можно передать примитив, объект, массив или функцию. Но часто логика требует наличия определенных свойств. Для этого используются **ограничения (Constraints)** через ключевое слово `extends`:
```typescript
class Service<T extends BaseEntity> { ... }
```
Это выражение сообщает компилятору: «Принимаемый тип `T` может быть любым, но он обязан быть совместим со структурой `BaseEntity` (содержать как минимум те же поля с совместимыми типами)».

Также обобщениям можно задавать **значения по умолчанию** с помощью оператора `=`:
```typescript
interface RequestConfig<T = string> {
  payload: T;
}
```
Если при использовании интерфейса `RequestConfig` разработчик не укажет тип явно (`RequestConfig`), компилятор автоматически подставит `string` в качестве параметра `T`.

### 3. Детальный пошаговый разбор выполнения обобщенного сервиса кэширования
Разберем, как TypeScript анализирует работу класса `GenericCacheService<T extends Identifiable>` при инициализации:
1.  **Создание экземпляра класса:**
    ```typescript
    interface ProductRecord { identifier: string; price: number; }
    const productCache = new GenericCacheService<ProductRecord>();
    ```
2.  **Валидация ограничения `extends`:**
    Компилятор проверяет тип `ProductRecord`. Найдено свойство `identifier: string`, которое требуется интерфейсом `Identifiable`. Ограничение успешно пройдено.
3.  **Подстановка типов во внутренние методы:**
    *   Сигнатура метода `set(item: T)` для данного экземпляра трансформируется в `set(item: ProductRecord)`. Попытка передать туда объект без поля `price` вызовет ошибку компиляции.
    *   Сигнатура метода `get(key: string)` трансформируется в `get(key: string): ProductRecord | undefined`. TypeScript гарантирует, что возвращаемое значение будет строго типа `ProductRecord` или `undefined`.
4.  **Безопасное использование:**
    Разработчик получает полную автодополняемость свойств продукта при извлечении его из кэша.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Ошибка несовместимости при работе со свойствами внутри обобщенной функции без ограничений**
    *   *Проблема:* Разработчик пытается прочитать свойство `item.identifier` у переменной свободного обобщенного типа `T`. Компилятор выдает ошибку: `Property 'identifier' does not exist on type 'T'`.
    *   *Решение:* Зафиксируйте контракт для типа `T` с помощью конструкции `extends`. Компилятор должен быть уверен, что переданное значение гарантированно содержит запрашиваемое свойство.

```typescript
// ПЛОХО (Компилятор не знает, есть ли у типа T свойство identifier)
export function logIdUnsafe<T>(item: T): void {
  // console.log(item.identifier); // ! Ошибка компиляции TS
}

// ХОРОШО (Ограничение гарантирует наличие свойства)
export function logIdSafe<T extends Identifiable>(item: T): void {
  console.log(item.identifier); // Полностью безопасно
}
```

*   **Ошибка 2: Потеря безопасности типов при избыточном использовании `any` в качестве параметра дженерика**
    *   *Проблема:* Разработчик создает экземпляр обобщенного класса, передавая в него `any`: `const cache = new GenericCacheService<any>()`. Это отключает статическую валидацию. В кэш становится возможным записать некорректную структуру данных, что приведет к скрытым багам.
    *   *Решение:* Никогда не заменяйте параметры дженериков на `any`. Если точный тип данных на этапе инициализации неизвестен, используйте тип `unknown` в связке с кастомными защитниками типов (Type Guards) перед чтением свойств.

*   **Ошибка 3: Ошибка несоответствия типов при возврате дефолтных значений**
    *   *Проблема:* Попытка вернуть жестко заданное дефолтное значение из функции, которая должна возвращать динамический тип `T`.

```typescript
// ПЛОХО (Компилятор не может гарантировать, что дефолтный пустой объект совместим с типом T)
export function getOrCreateItemUnsafe<T extends Identifiable>(item?: T): T {
  if (item) return item;
  // return { identifier: "default" }; // ! Ошибка компиляции: Type '{ identifier: string; }' is not assignable to type 'T'.
  throw new Error("Не удалось создать элемент");
}

// ХОРОШО (Дефолтное значение передается снаружи в качестве аргумента того же типа T)
export function getOrCreateItemSafe<T extends Identifiable>(fallback: T, item?: T): T {
  return item ? item : fallback; // Типы гарантированно совпадают
}
```
