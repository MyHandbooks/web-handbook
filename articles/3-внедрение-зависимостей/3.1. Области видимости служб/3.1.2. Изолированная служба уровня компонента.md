# 3.1.2. Изолированная служба уровня компонента

## БЫСТРЫЙ СТАРТ

*   **Изолированная служба (Scoped/Component-scoped Service)** — это служба, область видимости и время жизни которой ограничены конкретным экземпляром компонента и его дочерним деревом элементов. Она регистрируется в массиве `providers` декоратора `@Component`.
*   **Изоляция экземпляров (Instance Isolation):** Если на одной странице одновременно отрендерить пять экземпляров одного и того же компонента, Angular создаст пять независимых копий этой службы. Они не будут влиять на состояние друг друга.
*   **Связанный жизненный цикл:** Экземпляр изолированной службы создается в момент инициализации компонента и автоматически уничтожается сборщиком мусора Angular вместе с разрушением этого компонента, вызывая метод `ngOnDestroy` для очистки ресурсов.
*   **Используйте её для:** совместного управления состоянием в сложных иерархических UI-блоках (например, многошаговые формы-визарды, интерактивные канбан-доски, кастомные табы), где дочерние компоненты должны обмениваться данными с родителем без засорения глобальной памяти.
*   **Не используйте её:** для передачи данных между независимыми экранами, кэширования ответов сервера или авторизации. Для этого существуют глобальные синглтоны.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Изолированная служба управления состоянием многошаговой формы
*   **Назначение:** Описание службы локального состояния формы, которая будет хранить промежуточные шаги и уничтожаться при закрытии визарда.

```typescript
import { Injectable, signal, computed, OnDestroy } from '@angular/core';

export interface WizardState {
  currentStep: number;
  userData: { email: string; fullName: string };
  paymentData: { cardNumber: string };
}

@Injectable() // Обратите внимание: свойство providedIn здесь НЕ указывается
export class ScopedFormService implements OnDestroy {
  // Локальный изменяемый сигнал состояния формы
  private readonly wizardState = signal<WizardState>({
    currentStep: 1,
    userData: { email: '', fullName: '' },
    paymentData: { cardNumber: '' }
  });

  // Экспортируем сигналы чтения для дочерних компонентов
  readonly step = computed(() => this.wizardState().currentStep);
  readonly userDetails = computed(() => this.wizardState().userData);

  public nextStep(): void {
    this.wizardState.update((state) => ({
      ...state,
      currentStep: state.currentStep + 1
    }));
  }

  public updateUserData(data: Partial<WizardState['userData']>): void {
    this.wizardState.update((state) => ({
      ...state,
      userData: { ...state.userData, ...data }
    }));
  }

  // Хук жизненного цикла выполнится автоматически при уничтожении родительского компонента
  public ngOnDestroy(): void {
    console.log('Изолированная служба ScopedFormService успешно уничтожена, память освобождена.');
  }
}
```

### Шаблон 2: Внедрение в родительский компонент-контейнер (Провайдер)
*   **Назначение:** Регистрация изолированной службы в родительском компоненте визарда для создания локального контекста.

```typescript
import { Component, inject } from '@angular/core';
import { ScopedFormService } from './scoped-form.service';
import { FormStepOneComponent } from './form-step-one.component';

@Component({
  selector: 'app-form-wizard',
  standalone: true,
  imports: [FormStepOneComponent],
  // Регистрируем службу на уровне Node Injector этого компонента.
  // Теперь этот компонент и ВСЕ его дочерние элементы получают доступ к ОДНОМУ изолированному экземпляру службы
  providers: [ScopedFormService],
  template: `
    <div class="wizard-container">
      <h2>Шаг формы: {{ formService.step() }}</h2>
      <app-form-step-one />
      <button (click)="formService.nextStep()">Далее</button>
    </div>
  `
})
export class FormWizardComponent {
  // Родительский компонент успешно внедряет локальный экземпляр службы
  protected readonly formService = inject(ScopedFormService);
}
```

### Шаблон 3: Совместное использование изолированной службы дочерним компонентом
*   **Назначение:** Доступ дочернего шага формы к состоянию, хранящемуся в родительском инжекторе, без дублирования провайдеров.

```typescript
import { Component, inject } from '@angular/core';
import { ScopedFormService } from './scoped-form.service';

@Component({
  selector: 'app-form-step-one',
  standalone: true,
  template: `
    <fieldset class="step-fields">
      <legend>Шаг 1: Личные данные</legend>
      <input 
        type="text" 
        placeholder="ФИО"
        [value]="formService.userDetails().fullName"
        (input)="onNameInput($event)"
      />
    </fieldset>
  `
})
export class FormStepOneComponent {
  // Дочерний компонент НЕ указывает ScopedFormService в массиве providers.
  // Благодаря этому функция inject поднимается по дереву инжекторов и находит экземпляр, созданный родителем
  protected readonly formService = inject(ScopedFormService);

  protected onNameInput(event: Event): void {
    const inputElement = event.target as HTMLInputElement;
    this.formService.updateUserData({ fullName: inputElement.value });
  }
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Физика иерархии инжекторов компонентов (Node Injector Hierarchy)
Каждый раз, когда Angular создает экземпляр компонента или директивы, он сопутствующе инициализирует так называемый **Node Injector (инжектор узла DOM)**. Из этих инжекторов выстраивается дерево, в точности повторяющее структуру DOM-дерева шаблона вашего приложения.

Когда в дочернем компоненте `FormStepOneComponent` происходит вызов `inject(ScopedFormService)`, Angular запускает алгоритм восходящего поиска зависимости:
1.  Сначала проверяется Node Injector самого компонента `FormStepOneComponent`. Там провайдер службы не объявлен.
2.  Поиск поднимается на уровень выше по DOM-дереву и обращается к Node Injector компонента `FormWizardComponent`.
3.  Angular находит объявление `ScopedFormService` в массиве `providers` родителя, извлекает созданный для этого родителя экземпляр службы и возвращает его дочернему компоненту.

Если бы мы отрендерили рядом второй независимый тег `<app-form-wizard />`, для него создалось бы отдельное DOM-поддерево со своим Node Injector, который сгенерировал бы совершенно новый, изолированный экземпляр `ScopedFormService`.

### 2. Управление жизненным циклом (Lifecycle Mapping) изолированного сервиса
Время жизни изолированной службы жестко синхронизировано с жизненным циклом элемента DOM, на котором она была объявлена. Когда Angular принимает решение удалить компонент-провайдер из DOM (например, сработал блок `@if` или произошла смена роута):
1.  Angular начинает рекурсивное уничтожение компонента и его дочерних узлов.
2.  Node Injector компонента `FormWizardComponent` помечается к уничтожению.
3.  Перед очисткой памяти инжектор проверяет все свои созданные сервисы. Если сервис реализует стандартный интерфейс `OnDestroy` или имеет метод `ngOnDestroy`, Angular принудительно вызывает этот метод.
4.  В методе `ngOnDestroy` служба может отписаться от внешних потоков, очистить локальные таймеры или обнулить ссылки.
5.  Экземпляр службы стирается из памяти вместе с инжектором. Это исключает утечки оперативной памяти, характерные для неконтролируемого накопления глобальных синглтонов.

### 3. Детальный пошаговый разбор совместного использования в иерархии "Родитель — Потомок"
1.  **Парсинг шаблона:** Angular рендерит `<app-form-wizard>`. Обнаружив в `providers` класс `ScopedFormService`, Node Injector родителя подготавливает пустой слот в реестре.
2.  **Инициализация родителя:** Компонент `FormWizardComponent` вызывает `inject(ScopedFormService)`. Инжектор создает экземпляр #1 службы и сохраняет его у себя.
3.  **Инициализация потомка:** Шаблон рендерит внутренний тег `<app-form-step-one>`.
4.  **Поиск зависимости:** `FormStepOneComponent` запрашивает ту же службу через `inject(ScopedFormService)`.
5.  **Разрешение связи:** Поиск поднимается к инжектору родителя. Инжектор родителя возвращает ссылку на уже созданный экземпляр #1. Родитель и потомок теперь работают с единым реактивным источником данных в рантайме.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Случайное переопределение (Shadowing) экземпляра службы**
    *   *Проблема:* Разработчик объявил службу в родительском компоненте, но по ошибке также добавил ее в массив `providers` дочернего компонента. Из-за этого дочерний компонент создает свой собственный независимый экземпляр #2. Синхронизация данных ломается: родитель не видит изменений, вводимых в дочерней форме.
    *   *Решение:* Удалите объявление службы из массива `providers` дочернего компонента. Дочерние элементы должны только потреблять службу (`inject`), но не объявлять ее заново.

```typescript
// ПЛОХО (Объявление службы в дочернем элементе изолирует его от родительского контекста)
@Component({
  selector: 'app-form-step-one',
  standalone: true,
  providers: [ScopedFormService], // ! Ошибка: Создает локальный дубликат, ломая связь с родителем
  template: `...`
})
export class FormStepOneComponent {}
```

*   **Ошибка 2: Утечка памяти из-за бесконечных подписок на глобальные RxJS-потоки**
    *   *Проблема:* Изолированная служба подписывается на события глобального синглтона (например, `Router.events` или `AuthService.user$`), но не выполняет отписку в методе `ngOnDestroy`. Из-за этого глобальный сервис продолжает удерживать ссылку на экземпляр уничтоженной службы в своей таблице подписчиков. Сборщик мусора (Garbage Collector) не может очистить эту службу, что приводит к утечке памяти.
    *   *Решение:* Всегда завершайте активные подписки при уничтожении службы. Используйте `DestroyRef` или ручную отписку в `ngOnDestroy`.

```typescript
import { Injectable, OnDestroy, inject } from '@angular/core';
import { Subscription } from 'rxjs';
import { GlobalEventService } from './global-event.service';

@Injectable()
export class ScopedFormService implements OnDestroy {
  private readonly globalEvents = inject(GlobalEventService);
  private readonly sub: Subscription;

  constructor() {
    this.sub = this.globalEvents.stream$.subscribe();
  }

  public ngOnDestroy(): void {
    // Гарантированно освобождаем ссылку в глобальном стриме
    this.sub.unsubscribe();
  }
}
```

*   **Ошибка 3: Попытка внедрить изолированный сервис вне иерархии его провайдера**
    *   *Проблема:* Разработчик пытается внедрить `ScopedFormService` в компонент, который находится на другом роуте или является соседним по дереву (sibling), а не дочерним. Angular выбрасывает ошибку `No provider for ScopedFormService found!`.
    *   *Решение:* Убедитесь, что запрашивающий компонент физически вложен в шаблон компонента-провайдера. Если вам требуется сделать внедрение безопасным (например, если служба опциональна), используйте модификатор разрешения `@Optional()` или modern `inject(ScopedFormService, { optional: true })`.

```typescript
import { Component, inject } from '@angular/core';
import { ScopedFormService } from './scoped-form.service';

@Component({
  selector: 'app-optional-widget',
  standalone: true,
  template: `...`
})
export class OptionalWidgetComponent {
  // Если виджет отрендерен вне визарда, ошибка не возникнет, а переменная примет значение null
  protected readonly formService = inject(ScopedFormService, { optional: true });
}
```
