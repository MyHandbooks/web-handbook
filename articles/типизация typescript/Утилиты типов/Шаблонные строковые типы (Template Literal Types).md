# Шаблонные строковые типы (Template Literal Types)

## БЫСТРЫЙ СТАРТ

*   **Шаблонные строковые типы** (стандарт TS 4.1+) конструируют новые типы данных на основе объединения и склеивания строковых литералов по синтаксису `` `${TypeA}_${TypeB}` ``.
*   **Автоматическая комбинаторика:** Если в качестве подстановочного параметра передается Union-тип, TypeScript автоматически вычисляет декартово произведение всех возможных комбинаций строк.
*   **Встроенные утилиты трансформации регистра:** TypeScript предоставляет встроенные системные типы для изменения регистра строк: `Uppercase<S>`, `Lowercase<S>`, `Capitalize<S>` и `Uncapitalize<S>`.
*   **Используйте их для:** жесткой типизации названий событий (например, префиксы `on` + действие), генерации ключей API, валидации строковых форматов (CSS-размерности, ISO-даты) или разбора параметров путей роутера.
*   **Не используйте их:** для произвольных строк, не имеющих четкой системной структуры (для этого достаточно использовать базовый тип `string`). Попытка перемножить огромные Union-типы (более 100 000 комбинаций) вызовет ошибку компиляции из-за чрезмерной нагрузки на парсер TS.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Строгий реестр обработчиков событий (on + Action)
*   **Назначение:** Автоматическая генерация и контроль названий методов-колбэков на основе списка допустимых действий пользователя в интерфейсе.

```typescript
export type UIAction = "click" | "hover" | "focus";

// Генерируем типы событий с использованием встроенной утилиты Capitalize.
// Результат будет: "onClick" | "onHover" | "onFocus"
export type UIEventHandlerName = `on${Capitalize<UIAction>}`;

// Описываем типизированную карту обработчиков
// Record обяжет разработчика объявить все три метода в объекте без пропусков
export const eventHandlers: Record<UIEventHandlerName, (event: Event) => void> = {
  onClick: (e) => console.log("Клик зафиксирован"),
  onHover: (e) => console.log("Наведение курсора"),
  onFocus: (e) => console.log("Поле в фокусе")
};
```

### Шаблон 2: Валидатор строковых размерностей CSS
*   **Назначение:** Ограничение строкового типа значений для стилей, требующее обязательного указания числового значения и валидной единицы измерения.

```typescript
export type CSSUnit = "px" | "em" | "rem" | "%";

// Описываем тип: строго числовая строка в начале, переходящая в валидную единицу измерения в конце
export type CSSDimensionValue = `${number}${CSSUnit}`;

export function setElementMargin(element: HTMLElement, margin: CSSDimensionValue): void {
  // Вызов метода с невалидной строкой типа "10pt" или "auto" вызовет ошибку компиляции TS
  element.style.margin = margin;
}
```

### Шаблон 3: Глубокий разбор параметров URL-пути (Парсер роутера)
*   **Назначение:** Автоматическое извлечение имен динамических параметров из строки роутинга (например, `"/user/:userId/post/:postId"`) для строгого контроля типов аргументов в коде.

```typescript
// Рекурсивный условный тип, который парсит строку слева направо.
// Он ищет подстроку, начинающуюся с ":" и заканчивающуюся до следующего "/" или конца строки.
export type ExtractRouteParams<Path extends string> =
  Path extends `${string}/:${infer Param}/${infer Rest}`
    ? Param | ExtractRouteParams<`/${Rest}`> // Если параметры идут дальше
    : Path extends `${string}/:${infer Param}`
    ? Param // Если параметр последний в пути
    : never;

// Пример практического использования в роутере:
type TargetRoute = "/user/:userId/post/:postId";

// TypeScript автоматически вычисляет Union-тип параметров: "userId" | "postId"
type RouteParams = ExtractRouteParams<TargetRoute>;

export class CustomAppRouter {
  // Наш метод принимает URL и типизированную карту параметров.
  // Разработчик не сможет передать неверное имя параметра в объект params
  public navigateTo(path: TargetRoute, params: Record<RouteParams, string>): void {
    let finalPath: string = path;
    
    Object.entries(params).forEach(([key, value]) => {
      finalPath = finalPath.replace(`:${key}`, value);
    });
    
    console.log(`Переход по пути: ${finalPath}`);
  }
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Комбинаторный взрыв и лимиты парсинга компилятора TypeScript
Когда вы подставляете несколько Union-типов в один шаблонный строковый тип, компилятор TypeScript производит операцию **декартова произведения** (перемножения) всех возможных вариантов строк:

```typescript
type Color = "red" | "blue";
type Intensity = "100" | "200" | "300";
type Variant = `${Color}-${Intensity}`; 
// Результат: "red-100" | "red-200" | "red-300" | "blue-100" | "blue-200" | "blue-300"
```

Этот механизм чрезвычайно полезен, но несет в себе опасность деградации производительности сборки проекта. С каждым новым операндом в шаблоне количество генерируемых вариантов возрастает по экспоненте. По этой причине в компилятор TypeScript встроено жесткое внутреннее ограничение: если результирующий тип превышает **100 000 комбинаций**, компилятор аварийно завершает работу с критической ошибкой, предотвращая бесконечное зависание процесса сборки.

### 2. Физика встроенных утилит изменения регистра
Системные типы `Uppercase`, `Lowercase`, `Capitalize` и `Uncapitalize` не описаны на чистом TypeScript. Вы не сможете найти их реализацию в файлах определений типов, так как они помечены как `intrinsic`.

Это означает, что обработка регистра строк выполняется **непосредственно внутри компилятора TypeScript на уровне C++ кода**. При анализе этих типов компилятор обращается к низкоуровневым C++ функциям форматирования строк юникода и возвращает уже готовые строковые литералы.

### 3. Разбор строк (String Parsing) через сопоставление шаблонов
С появлением шаблонных типов условные типы получили возможность парсить строки аналогично регулярным выражениям.

Когда вы пишете условную конструкцию:
```typescript
Path extends `${string}/:${infer Param}/${infer Rest}`
```
TypeScript сопоставляет переданную строку с шаблоном. Он разделяет строку на три части:
*   Свободный текст в начале (`string`).
*   Символ двоеточия `:` и захватываемая переменная `Param` (`infer Param`), идущая до первого разделителя `/`.
*   Оставшийся хвост строки `Rest` (`infer Rest`).

Если строка удовлетворяет этому шаблону, компилятор производит успешный вывод типов, позволяя строить рекурсивные парсеры любой сложности на этапе статического анализа.

### 4. Детальный пошаговый разбор выполнения шаблона 3
Проследим, как компилятор вычисляет тип `ExtractRouteParams<"/user/:userId/post/:postId">`:
1.  **Шаг 1:** Строка сопоставляется с шаблоном `` `${string}/:${infer Param}/${infer Rest}` ``.
    *   `string` соответствует `"/user"`.
    *   `Param` захватывает `"userId"`.
    *   `Rest` захватывает `"post/:postId"`.
    *   Условие истинно. Возвращается union `"userId" | ExtractRouteParams<"/post/:postId">`.
2.  **Шаг 2:** Запускается рекурсивное вычисление для `ExtractRouteParams<"/post/:postId">`.
3.  **Шаг 3:** Строка `"/post/:postId"` не соответствует первому шаблону, так как в ней нет второго символа `/` после двоеточия.
4.  **Шаг 4:** Происходит сопоставление со вторым шаблоном `` `${string}/:${infer Param}` ``.
    *   `string` соответствует `"/post"`.
    *   `Param` захватывает `"postId"`.
    *   Условие истинно. Возвращается тип `"postId"`.
5.  **Шаг 5 (Слияние результатов):** Рекурсия завершается. Компилятор склеивает полученные результаты в единый Union: `"userId" | "postId"`.

### 5. Типичные ошибки и их решение

*   **Ошибка 1: Комбинаторный взрыв при перемножении больших Union-типов (Expression produces a union type that is too complex)**
    *   *Проблема:* Сбой компиляции проекта при попытке объявить сложный тип.
    *   *Причина:* Вы попытались перемножить несколько больших списков (например, все коды валют на все коды стран на все типы операций). Количество комбинаций превысило допустимый лимит компилятора.
    *   *Решение:* Сокращайте размер исходных списков, разделяйте типы на независимые подгруппы или используйте базовый тип `string` для динамических полей.

*   **Ошибка 2: Потеря типизации при получении динамической строки из JS**
    *   *Проблема:* Функция ожидает тип `CSSDimensionValue` (например, `"10px"`), но вы считываете значение из атрибута элемента в JS и передаете его в функцию. TypeScript выдает ошибку, что тип `string` нельзя присвоить типу `CSSDimensionValue`.
    *   *Причина:* Динамические строки, считываемые во время работы программы (runtime), по умолчанию типизируются как общий тип `string`. Компилятор не может гарантировать, что в рантайме в переменной лежит именно `"px"` на конце.
    *   *Решение:* Используйте сужение типов через пользовательские защитники типов (Type Guards) с проверкой формата строки через регулярное выражение перед вызовом функции.

*   **Ошибка 3: Ошибка трансформирования ключей объектов без mapped-типов**
    *   *Проблема:* Разработчик пытается создать геттеры для полей объекта, но получает ошибку при попытке переопределить свойства.
    *   *Решение:* Преобразование ключей объекта требует совместного использования шаблонных строковых типов и сопоставленных типов (Mapped Types) с переопределением ключей через ключевое слово `as`.

```typescript
export interface User {
  id: string;
  age: number;
}

// ПЛОХО (Попытка применить шаблон напрямую к объекту не сработает)
// type UserGetters = `get${Capitalize<keyof User>}`; // Результат: "getId" | "getAge" (Но типы данных утеряны!)

// ХОРОШО (Использование Mapped Types с переопределением ключей)
export type UserGetters = {
  [K in keyof User as `get${Capitalize<K>}`]: () => User[K];
};
/* Результат вычисления:
  type UserGetters = {
    getId: () => string;
    getAge: () => number;
  }
*/
```
