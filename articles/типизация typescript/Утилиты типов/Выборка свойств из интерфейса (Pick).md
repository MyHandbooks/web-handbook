# Выборка свойств из интерфейса (Pick)

## БЫСТРЫЙ СТАРТ

*   **`Pick<T, K>`** — это встроенная утилита типов, которая конструирует новый тип, выбирая строго определенный набор свойств `K` (строковый литерал или Union строк) из исходного типа `T`.
*   **Принцип "Единого источника правды" (Single Source of Truth):** Вместо создания дублирующих интерфейсов вручную (например, отдельного интерфейса для карточки товара и отдельного для детальной страницы), вы объявляете одну большую доменную модель, а затем точечно "нарезаете" из нее легкие типы для UI-компонентов.
*   **Используйте его для:** конструирования усеченных типов данных, таких как превью-карточки в списках, навигационные крошки, усеченные профили пользователей или специфические тела событий.
*   **Не используйте его:** если вам нужно отбросить всего 1-2 свойства из огромного интерфейса. В таком случае гораздо эффективнее использовать утилиту `Omit<T, K>`, чтобы не перечислять десятки сохраняемых полей вручную.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Легковесный DTO для превью-компонента списков
*   **Назначение:** Создание компактного типа данных для рендеринга карточки товара в каталоге на основе полной схемы сущности.

```typescript
export interface ProductDetails {
  id: string;
  title: string;
  description: string;
  price: number;
  discountPercentage: number;
  rating: number;
  stock: number;
  brand: string;
  category: string;
  thumbnail: string;
  images: string[];
}

// Конструируем легкий тип для карточки каталога, забирая только 4 необходимых свойства
export type ProductPreviewDto = Pick<
  ProductDetails, 
  "id" | "title" | "price" | "thumbnail"
>;

// Пример использования в типизации компонента списка
export function renderProductCard(cardData: ProductPreviewDto): void {
  // Доступны только выбранные свойства. Попытка обратиться к cardData.images вызовет ошибку TS
  console.log(`Рендер карточки: ${cardData.title} за ${cardData.price}$`);
  console.log(`Превью изображение: ${cardData.thumbnail}`);
}
```

### Шаблон 2: Строгая типизация полезной нагрузки событий (Event Payload)
*   **Назначение:** Формирование типа для аргументов событий изменений, гарантирующее, что событие переносит только те поля, которые действительно изменились в рамках конкретного действия.

```typescript
export interface UserAccount {
  uuid: string;
  email: string;
  username: string;
  role: "admin" | "user" | "guest";
  lastLoginIp: string;
  failedAttempts: number;
}

// Создаем тип события обновления базовой информации профиля (пользователь может менять только email и username)
export type ProfileUpdatedEvent = Pick<UserAccount, "email" | "username">;

export function emitProfileUpdate(event: ProfileUpdatedEvent): void {
  // Вызов гарантирует, что системные поля типа role или uuid не будут случайно переданы в событие
  const payload: ProfileUpdatedEvent = {
    email: event.email.trim(),
    username: event.username
  };
  
  console.log("Генерация события обновления профиля:", payload);
}
```

### Шаблон 3: Выборка вложенных типов через цепочку Pick и Indexed Access
*   **Назначение:** Точечное извлечение сложного вложенного типа данных из большой схемы для последующего переиспользования в дочерних сервисах.

```typescript
export interface AppConfig {
  environment: "production" | "development" | "test";
  database: {
    host: string;
    port: number;
    ssl: boolean;
    credentialsToken: string;
  };
  features: {
    enableSso: boolean;
    enableWebSockets: boolean;
  };
}

// Нам нужен тип настроек подключения к БД. Выбираем свойство database и получаем его тип через Indexed Access
export type DatabaseSettings = AppConfig["database"];

// Если нам нужен только усеченный тип настроек базы данных (без токена доступа для публичных хелперов)
export type PublicDatabaseConfig = Pick<DatabaseSettings, "host" | "port" | "ssl">;

export function checkDbConnection(config: PublicDatabaseConfig): void {
  console.log(`Проверка связи по адресу: ${config.host}:${config.port} (SSL: ${config.ssl})`);
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Внутренний механизм Mapped Types под капотом `Pick<T, K>`
Утилита `Pick` является одной из фундаментальных утилит стандартной библиотеки TypeScript и описывается следующим образом:
```typescript
type Pick<T, K extends keyof T> = {
    [P in K]: T[P];
};
```
*   `K extends keyof T` — это ключевое ограничение обобщения (Generic Constraint). Оно требует, чтобы передаваемый тип `K` строго являлся подмножеством ключей типа `T`. Вы не можете передать туда произвольную строку; компилятор проверит, действительно ли свойство с таким именем объявлено в оригинальном интерфейсе.
*   `[P in K]` — итератор сопоставления типов, который проходит строго по списку ключей, переданных в `K`.
*   `T[P]` — тип оригинального свойства по ключу `P`.

В отличие от `Partial<T>`, `Pick` не модифицирует свойства (не добавляет знак `?` и не изменяет модификатор `readonly`), а переносит их в новый тип в неизменном виде.

### 2. Архитектурное преимущество "подтягивания" типов
Использование `Pick` гарантирует автоматическую синхронизацию типов во всей кодовой базе:
*   Если завтра тип поля `price` в интерфейсе `ProductDetails` изменится с `number` на `string` (например, для поддержки форматирования валют с сервера), тип этого свойства в `ProductPreviewDto` обновится автоматически.
*   Это полностью устраняет баги, связанные с тем, что разработчик обновил тип в API-модели, но забыл обновить его в локальном интерфейсе карточки товара в UI-слое.

### 3. Детальный пошаговый разбор конструирования типа карточки каталога
Разберем, как компилятор вычисляет выражение `Pick<ProductDetails, "id" | "title" | "price" | "thumbnail">`:
1.  **Проверка контракта `extends keyof T`:**
    Компилятор проверяет, входят ли строки `"id"`, `"title"`, `"price"`, `"thumbnail"` в состав множества `keyof ProductDetails`. Все строки найдены, ограничение соблюдено.
2.  **Итерация сопоставления:**
    Итератор `P` последовательно проходит по четырем строковым литералам:
    *   `P = "id"`: Тип свойства `ProductDetails["id"]` равен `string`. Записывается `id: string;`.
    *   `P = "title"`: Тип `ProductDetails["title"]` равен `string`. Записывается `title: string;`.
    *   `P = "price"`: Тип `ProductDetails["price"]` равен `number`. Записывается `price: number;`.
    *   `P = "thumbnail"`: Тип `ProductDetails["thumbnail"]` равен `string`. Записывается `thumbnail: string;`.
3.  **Формирование финального типа:**
    TypeScript создает новый анонимный тип с четырьмя строго типизированными свойствами.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Опечатки при рефакторинге родительского интерфейса**
    *   *Проблема:* Разработчик переименовал поле `thumbnail` в `imageUrl` внутри интерфейса `ProductDetails`. Компиляция немедленно прерывается с ошибкой во всех местах, где используется `Pick<ProductDetails, ... "thumbnail">`, сообщая, что такое свойство больше не существует.
    *   *Решение:* Это нормальное поведение компилятора, предотвращающее появление багов. Но чтобы упростить рефакторинг в IDE (например, в VS Code), всегда используйте встроенные инструменты автоматического переименования (клавиша `F2`), которые умеют находить и автоматически обновлять строковые литералы внутри `Pick` по всей кодовой базе.

*   **Ошибка 2: Ложная иллюзия фильтрации объекта в рантайме**
    *   *Проблема:* Разработчик считает, что типизация `const preview: ProductPreviewDto = originalProduct` автоматически очищает JS-объект в оперативной памяти от "лишних" свойств перед отправкой. Это опасное заблуждение. TypeScript работает только на этапе компиляции. В скомпилированном JS-коде объект сохранит абсолютно все исходные свойства (включая тяжелый массив `images`), что может привести к избыточному потреблению трафика при передаче объекта далее.
    *   *Решение:* `Pick` — это исключительно инструмент статического анализа. Чтобы физически очистить объект в рантайме, необходимо выполнить явное преобразование данных:

```typescript
// ПЛОХО (Объект в памяти сохраняет массив images, хотя тип это скрывает)
export function sendCardUnsafe(originalProduct: ProductDetails): void {
  const preview: ProductPreviewDto = originalProduct; // Лишние данные не удалены в рантайме!
  console.log(preview); // Выведет объект со всеми вложенными картинками
}

// ХОРОШО (Физическое удаление лишних свойств через явный маппинг в рантайме)
export function sendCardSafe(originalProduct: ProductDetails): ProductPreviewDto {
  return {
    id: originalProduct.id,
    title: originalProduct.title,
    price: originalProduct.price,
    thumbnail: originalProduct.thumbnail
  }; // Теперь в памяти только нужные свойства
}
```

*   **Ошибка 3: Попытка передать динамическую переменную вместо строкового литерала**
    *   *Проблема:* Попытка написать конструкцию вида `type DynamicPick = Pick<ProductDetails, myVariable>` вызовет ошибку компиляции. Вторым аргументом `Pick` принимает только типы (в данном случае строковые литералы-типы), а не рантайм-переменные JavaScript.
    *   *Решение:* Если список полей определяется динамически в рантайме, используйте ручную фильтрацию объектов и тип `Record<string, unknown>` для промежуточного хранения данных.
