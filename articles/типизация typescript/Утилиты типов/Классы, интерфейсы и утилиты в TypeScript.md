# Классы, интерфейсы и утилиты в TypeScript

## БЫСТРЫЙ СТАРТ

*   **Модификаторы доступа (`public`, `private`, `protected`)** — регулируют видимость свойств и методов класса на этапе компиляции. Модификатор `readonly` запрещает перезапись значения поля после его первичной инициализации в конструкторе.
*   **Интерфейс (`interface`)** — описывает виртуальную структуру (контракт) объекта. Интерфейсы полностью стираются компилятором при трансляции в JS и не генерируют дополнительного кода во время выполнения.
*   **Абстрактный класс (`abstract class`)** — задает структуру и контракт для наследников, но, в отличие от интерфейса, может содержать физическую реализацию методов. Напрямую создать экземпляр абстрактного класса через `new` нельзя.
*   **Утилиты типов (`Partial`, `Omit`, `Pick`, `Record`)** — встроенные generic-типы для декларативного преобразования исходных интерфейсов без ручного дублирования полей.
*   **Когда использовать:** Для проектирования масштабируемой архитектуры по принципам SOLID и гибкого сужения контрактов данных при передаче по сети (DTO).
*   **Когда НЕ использовать:** Избегайте использования compile-time модификаторов TypeScript (`private`) для защиты конфиденциальных данных во время выполнения (для этого используйте нативные приватные поля `#`).

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Абстрактный репозиторий с инкапсулированными членами
*   **Назначение:** Описание базового класса для работы с базами данных, скрывающего детали подключения от внешнего кода с помощью модификаторов доступа.

```typescript
export interface BaseEntity {
  id: string;
  createdAt: Date;
}

// Абстрактный класс фиксирует контракт, но хранит общую логику конструктора
export abstract class BaseRepository<T extends BaseEntity> {
  // Доступ к свойству открыт только для этого класса и классов-наследников
  protected readonly connectionString: string;

  constructor(connection: string) {
    this.connectionString = connection;
  }

  // Абстрактный метод без реализации, обязательный для переопределения в наследниках
  public abstract save(entity: T): void;
}

export interface UserAccount extends BaseEntity {
  username: string;
  emailAddress: string;
}

export class UserAccountRepository extends BaseRepository<UserAccount> {
  // Приватное свойство доступно только внутри этого класса во время компиляции
  private readonly inMemoryStorage: Record<string, UserAccount> = {};

  constructor(connection: string) {
    // Обязательный вызов конструктора родителя
    super(connection);
  }

  // Реализация абстрактного метода родительского класса
  public save(entity: UserAccount): void {
    this.inMemoryStorage[entity.id] = entity;
    console.log(`[DB SUCCESS] Запись сохранена в базу: ${this.connectionString}`);
  }
}
```

### Шаблон 2: Конструирование DTO с помощью утилит `Omit` и `Partial`
*   **Назначение:** Создание производных типов данных на основе базового интерфейса для безопасной отправки изменений на сервер.

```typescript
export interface TaskDetails {
  id: string;
  title: string;
  description: string;
  isCompleted: boolean;
  createdAt: Date;
}

// 1. Исключаем системные поля id и createdAt при создании новой задачи
// Создается тип: { title: string; description: string; isCompleted: boolean; }
export type CreateTaskDto = Omit<TaskDetails, "id" | "createdAt">;

// 2. Делаем все поля необязательными для выполнения частичного обновления (PATCH)
// Создается тип: { title?: string; description?: string; isCompleted?: boolean; }
export type UpdateTaskDto = Partial<CreateTaskDto>;

export class TaskService {
  private readonly tasks: TaskDetails[] = [];

  public create(dto: CreateTaskDto): TaskDetails {
    const newTask: TaskDetails = {
      ...dto,
      id: Math.random().toString(36).substring(2, 9),
      createdAt: new Date()
    };
    this.tasks.push(newTask);
    return newTask;
  }
}
```

### Шаблон 3: Строго типизированный словарь конфигураций через `Record`
*   **Назначение:** Описание ассоциативной карты, где ключами могут быть только значения из строго определенного перечисления, а значениями — заданный тип.

```typescript
export type EnvironmentScope = "development" | "staging" | "production";

export interface NetworkConfig {
  apiUrl: string;
  enableDebugLogs: boolean;
}

// Утилита Record гарантирует, что в объекте будут описаны все три среды из EnvironmentScope
export const applicationSettings: Record<EnvironmentScope, NetworkConfig> = {
  development: {
    apiUrl: "http://localhost:3000/api",
    enableDebugLogs: true
  },
  staging: {
    apiUrl: "https://staging-api.eltex.co",
    enableDebugLogs: true
  },
  production: {
    apiUrl: "https://api.eltex.co",
    enableDebugLogs: false
  }
};
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Модификаторы доступа в TS против нативной приватности ES (`#`)
TypeScript-модификаторы `private` и `protected` проверяются исключительно на этапе статического анализа. После компиляции все эти ключевые слова удаляются, а свойства в JavaScript-коде становятся обычными публичными полями объекта.
*   **Проблема:** Если скомпилированная JS-библиотека используется в среде без TypeScript, сторонний разработчик сможет беспрепятственно прочитать и переписать приватные свойства вашего класса.
*   **Решение:** Нативные приватные свойства с префиксом `#` (например, `#storage`) обеспечивают абсолютную изоляцию на уровне спецификации самого JavaScript во время выполнения. Попытка обратиться к `object.#storage` извне вызовет критическую синтаксическую ошибку в рантайме браузера.

### 2. Сравнение интерфейса и абстрактного класса в памяти
При компиляции интерфейсы и абстрактные классы ведут себя по-разному с точки зрения потребления ресурсов:
*   **Интерфейсы (`interface`)** — это чисто виртуальные контракты. Они полностью стираются и не создают накладных расходов на генерацию JS-кода.
*   **Абстрактные классы (`abstract class`)** — компилируются в стандартные JavaScript-классы (или функции-конструкторы) и остаются жить в прототипной цепочке объектов. Они занимают реальное место на диске в итоговом бандле и потребляют память в куче.

### 3. Схема иерархии и наследования

```text
┌───────────────────────────────────────┐
│              ИНТЕРФЕЙС                │ ◄─── Только сигнатура (без кода)
│  - save(entity: T): void              │      [ Стирается при компиляции ]
└──────────────────┬────────────────────┘
                   ▲ (implements)
                   │
┌──────────────────┴────────────────────┐
│          АБСТРАКТНЫЙ КЛАСС            │ ◄─── Общий контракт + физический код
│  - abstract save(entity: T): void     │      [ Сохраняется в JS-прототипе ]
│  - getDbUri(): string { ... }         │
└──────────────────┬────────────────────┘
                   ▲ (extends)
                   │
┌──────────────────┴────────────────────┐
│           КОНКРЕТНЫЙ КЛАСС            │ ◄─── Итоговая полная реализация
│  - save(entity: T): void { ... }      │      [ Доступен для создания через new ]
└───────────────────────────────────────┘
```

### 4. Детальный пошаговый разбор выполнения шаблона 1
1.  **Компиляция контракта:** Компилятор видит класс `UserAccountRepository extends BaseRepository<UserAccount>`. Он проверяет, что дочерний класс переопределил абстрактный метод `save`. Если метод не объявлен, сборка завершится с ошибкой.
2.  **Вызов конструктора:** При выполнении `new UserAccountRepository("postgres://...")` сначала отрабатывает вызов `super(connection)`. Движок обращается к прототипу родителя и записывает свойство `connectionString` на создаваемый объект.
3.  **Инициализация хранилища:** Создается приватное вложенное свойство `inMemoryStorage`. На этапе компиляции к нему нельзя обратиться снаружи, однако после трансляции оно становится обычным свойством объекта JS.

### 5. Типичные ошибки и их решение

*   **Ошибка 1: Взлом compile-time приватности в рантайме JavaScript**
    *   *Симптомы:* Метод, помеченный как `private`, успешно вызывается и изменяет состояние класса при интеграции с ванильными JavaScript-модулями, ломая инкапсуляцию.
    *   *Причина:* Модификатор `private` стирается при компиляции и не защищает свойства в среде выполнения.
    *   *Решение:* Если класс будет поставляться в виде скомпилированной JS-библиотеки, используйте нативную ECMAScript-приватность через префикс `#` для гарантированной защиты.

```typescript
// ПЛОХО (private сотрется при сборке, свойство key можно прочитать извне в JS)
export class Cipher {
  private key = "secret-key";
}

// ХОРОШО (абсолютная изоляция данных на уровне спецификации JavaScript)
export class SecureCipher {
  #key = "secret-key";
}
```

*   **Ошибка 2: Ручное дублирование типов для DTO-сущностей**
    *   *Симптомы:* При добавлении нового поля в базу данных приходится вручную дописывать его в десятки связанных интерфейсов создания, обновления и отображения. Код раздувается.
    *   *Причина:* Отсутствие использования встроенных утилит типов и нарушение принципа DRY.
    *   *Решение:* Опишите один базовый интерфейс сущности, а DTO-типы генерируйте автоматически с помощью `Omit`, `Pick` и `Partial`.

```typescript
interface User { id: string; name: string; age: number; }

// ПЛОХО (ручное дублирование полей)
interface CreateUserRequest { name: string; age: number; }

// ХОРОШО (автоматическое вычисление типа без дублирования кода)
type CreateUserDto = Omit<User, "id">;
```

*   **Ошибка 3: Попытка объявить непубличные (`private`/`protected`) члены в интерфейсе**
    *   *Симптомы:* Ошибка компиляции: `TypeScript error: 'private' modifier cannot appear on a member in an interface.`.
    *   *Причина:* Интерфейс по определению описывает исключительно публичный контракт взаимодействия с объектом. Внутренние детали реализации и защищенные методы не могут быть частью интерфейса.
    *   *Решение:* Если вам нужно зафиксировать приватную структуру или общие свойства для цепочки классов, используйте абстрактный класс вместо интерфейса.

```typescript
// ПЛОХО (интерфейс не может содержать модификаторы доступа)
interface BadInterface {
  // private log(msg: string): void; // ! Ошибка компиляции
}

// ХОРОШО (абстрактный класс позволяет фиксировать внутреннюю структуру)
abstract class GoodAbstractClass {
  protected abstract log(msg: string): void;
}
```
