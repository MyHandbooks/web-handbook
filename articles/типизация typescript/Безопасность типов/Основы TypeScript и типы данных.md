# Основы TypeScript и типы данных

## БЫСТРЫЙ СТАРТ

*   **TypeScript** — это строго типизированное компилируемое надмножество (superset) JavaScript, предоставляющее статический анализ типов для выявления багов на этапе разработки.
*   **Вывод типов (Type Inference):** Компилятор автоматически выводит базовые типы при объявлении и инициализации переменных, избавляя от необходимости писать лишние аннотации.
*   **Базовые примитивы:** Включают `string`, `number`, `boolean`, `symbol`, а также служебные типы `null`, `undefined` (обозначающие отсутствие данных) и `void` (обозначающий отсутствие возвращаемого значения у функций).
*   **Тип `any`:** Отключает любые статические проверки компилятора, возвращая код к небезопасному JavaScript. Стандартами надежной разработки использование `any` запрещено.
*   **Когда использовать:** Для описания контрактов данных, структур, аргументов функций и API во всех веб-приложениях.
*   **Когда НЕ использовать:** Не дублируйте типы вручную в простых присвоениях, где компилятор может вывести их самостоятельно без потери безопасности.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Строгая типизация функций с Union-типами и опциональностью
*   **Назначение:** Описание контракта функции со строгим указанием типов входящих параметров, возвращаемого значения, объединений (`Union`) и опциональных полей (`?`).

```typescript
export interface ContactPayload {
  emailAddress: string;
  phoneNumber?: string; // Опциональный параметр (может быть string или undefined)
}

export function formatContactDetails(
  userId: string | number, // Входящий параметр может быть либо строкой, либо числом
  card: ContactPayload
): string { // Явно указываем строгий возвращаемый тип функции
  // Выполняем сужение типа для userId перед форматированием
  const formattedId = typeof userId === "number" ? `ID-${userId}` : userId.trim();

  // Безопасно обрабатываем опциональный параметр с помощью оператора ??
  const contactPhone = card.phoneNumber ?? "Телефон не указан";

  return `[Пользователь ${formattedId}]: Почта: ${card.emailAddress}, Связь: ${contactPhone}`;
}
```

### Шаблон 2: Строгое описание сложных структур через интерфейсы
*   **Назначение:** Описание комплексных объектов, защита отдельных полей от перезаписи (`readonly`) и описание вложенных сущностей.

```typescript
export interface ComponentDimensions {
  readonly widthPixels: number; // Свойство доступно только для чтения
  readonly heightPixels: number;
}

export interface RenderConfigOptions {
  identifier: string;
  dimensions: ComponentDimensions; // Вложенный интерфейс
  paddingOffsets?: number[]; // Опциональный массив чисел
}

export function createRenderConfig(id: string, width: number, height: number): RenderConfigOptions {
  return {
    identifier: id,
    dimensions: {
      widthPixels: width,
      heightPixels: height
    }
    // Свойство paddingOffsets не передано, так как оно помечено как опциональное
  };
}
```

### Шаблон 3: Ограничение значений через литеральные объединения (Literal Unions)
*   **Назначение:** Создание жестко заданного набора допустимых текстовых значений взамен числовых `enum` для снижения веса бандла и повышения безопасности.

```typescript
// Декларативно объявляем набор строковых литералов
export type OperationState = "idle" | "processing" | "success" | "failed";

export interface TransactionReport {
  transactionId: string;
  state: OperationState;
}

export function updateTransactionState(
  report: TransactionReport,
  nextState: OperationState // Компилятор заблокирует передачу любых сторонних строк
): TransactionReport {
  return {
    ...report,
    state: nextState
  };
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как TypeScript выводит типы (Type Inference) и компилируется в JavaScript
TypeScript существует исключительно на этапе разработки и сборки проекта. Процесс компиляции состоит из двух независимых фаз:
1.  **Статический анализ (Type Checking):** Анализатор компилятора строит граф типов и сверяет соответствие всех контрактов. При обнаружении ошибок выводится предупреждение, но компиляция все равно может быть завершена.
2.  **Стирание типов (Type Erasure):** Все интерфейсы, типы (`type`), дженерики и аннотации полностью удаляются. На выходе получается стандартный JavaScript-код (ES5/ES6+).

*Вывод типов (Inference):* Компилятор автоматически выводит тип переменной по значению литерала справа. Например, при написании `let count = 10` переменная автоматически получит тип `number`. Дублировать аннотацию `let count: number = 10` избыточно — это засоряет код.

### 2. Семантика специальных типов: `void`, `null`, `undefined` в строгом режиме
В системе типов TypeScript данные типы выполняют важные служебные роли:
*   **`undefined`** — означает, что переменная была объявлена, но значение ей еще не присвоено (дефолтное состояние памяти).
*   **`null`** — намеренное указание на отсутствие значения. При включенном строгом флаге компиляции `--strictNullChecks` типы `null` и `undefined` изолируются. Их нельзя неявно присвоить переменной типа `string` или `number` (для этого нужно использовать объединение `string | null`).
*   **`void`** — указывает на то, что функция не возвращает никакого полезного значения. В рантайме JavaScript такая функция вернет `undefined`, однако в TypeScript типы `void` и `undefined` различаются: тип `void` сообщает компилятору, что возвращаемое значение функции должно быть полностью проигнорировано вызывающей стороной.

### 3. Иерархия типов (Top & Bottom Types)
Система типов TypeScript представляет собой иерархическое дерево:

```text
                    [ any ]        [ unknown ] (Верхние типы / Top Types)
                       │                │
                       ▼                ▼
                    (Любые типы данных в системе)
                       │
                       ▼
                    [ never ]                  (Нижний тип / Bottom Type)
```

*   **Top Types (any / unknown):** Могут принимать абсолютно любые значения. Разница заключается в безопасности: `any` полностью отключает статический анализ для переменной, а `unknown` требует предварительного сужения типа перед работой с ним (детали использования `unknown` разобраны в отдельной статье: [[Безопасная работа с типом unknown]]).
*   **Bottom Type (never):** Представляет собой пустое множество типов. Переменной типа `never` невозможно присвоить ни одно значение (даже `any`). Тип `never` возвращают функции, которые гарантированно никогда не завершают свое выполнение (выбрасывают бесконечный цикл или критическое исключение `throw`).

### 4. Детальный пошаговый разбор выполнения шаблона 1
Разберем компиляцию вызова `formatContactDetails(102, { emailAddress: "info@domain.co" })`:
1.  **Проверка первого параметра:** Компилятор видит, что передан аргумент `102` (тип `number`). Метод принимает `string | number`. Типы совместимы.
2.  **Проверка второго параметра:** Передан объект `{ emailAddress: "info@domain.co" }`. Компилятор сверяет структуру с интерфейсом `ContactPayload`. Обязательное поле `emailAddress` присутствует и является строкой. Опциональное поле `phoneNumber` отсутствует, что разрешено правилами.
3.  **Внутреннее сужение:** На первой строчке функции выполняется условие `typeof userId === "number"`. Компилятор понимает, что внутри блока `if` переменная `userId` имеет тип `number`, поэтому вызов метода `userId.trim()` был бы заблокирован. В ветке `else` тип сужается до `string`.
4.  **Генерация кода:** При компиляции интерфейсы удаляются, а сам код превращается в стандартную функцию JavaScript.

### 5. Типичные ошибки и их решение

*   **Ошибка 1: Ошибки обращения к nullable-значениям под флагом `--strictNullChecks`**
    *   *Симптомы:* Сбой компиляции с сообщением: `Object is possibly 'null' or 'undefined'`.
    *   *Причина:* Попытка напрямую прочитать свойство у переменной, тип которой допускает отсутствие значения (например, `string | undefined`).
    *   *Решение:* Используйте оператор опционального зацепления `?.` (optional chaining) или выставляйте дефолтные значения через оператор нулевого слияния `??`.

```typescript
// ПЛОХО (компилятор выдаст ошибку, так как значение может быть undefined)
export function logPhoneUnsafe(card: ContactPayload) {
  console.log(card.phoneNumber.toUpperCase()); 
}

// ХОРОШО (безопасное чтение или установка дефолтного значения)
export function logPhoneSafe(card: ContactPayload) {
  console.log(card.phoneNumber?.toUpperCase()); // Опциональный вызов
  const phone = card.phoneNumber ?? "НЕТ ТЕЛЕФОНА"; // Дефолтное значение
}
```

*   **Ошибка 2: Ошибка неявного типа any (`Parameter implicitly has an 'any' type`)**
    *   *Симптомы:* Компилятор ругается на аргументы функций, у которых не указан тип: `Parameter 'userId' implicitly has an 'any' type`.
    *   *Причина:* При включенном строгом флаге компиляции `--noImplicitAny` TypeScript запрещает опускать типы аргументов, если он не может вывести их автоматически.
    *   *Решение:* Всегда явно аннотируйте типы входящих параметров функций.

```typescript
// ПЛОХО (неявный any заблокирован правилами компилятора)
// export function processUser(id) { ... } 

// ХОРОШО (явное указание контракта)
export function processUser(id: string): void {}
```

*   **Ошибка 3: Ложная типобезопасность числовых перечислений `enum`**
    *   *Симптомы:* Функция, принимающая числовой `enum`, без ошибок компиляции принимает абсолютно любое случайное число (например, `999`), ломая логику во время работы.
    *   *Причина:* Числовые перечисления в TypeScript компилируются в двунаправленные JavaScript-объекты и совместимы с базовым типом `number`. Любое число считается валидным аргументом для `enum`.
    *   *Решение:* Заменяйте числовые перечисления на строгие литеральные объединения (Literal Unions), которые жестко контролируются компилятором.

```typescript
// ПЛОХО (ошибки компиляции не будет, хотя состояние 500 некорректно)
enum State { Active, Inactive }
function update(s: State) {}
update(500); 

// ХОРОШО (любые сторонние строки будут жестко заблокированы компилятором)
type StateType = "active" | "inactive";
function updateSafe(s: StateType) {}
// updateSafe("deleted"); // ! Ошибка компиляции TS
```
