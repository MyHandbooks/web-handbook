# Условные типы и динамический вывод (Conditional Types, infer)

## БЫСТРЫЙ СТАРТ

*   **Условные типы (`Conditional Types`)** — это механизм статического анализа в TypeScript, описываемый синтаксисом `T extends U ? X : Y`. Он позволяет вычислять типы динамически на основе логических условий на этапе компиляции.
*   **Ключевое слово `infer`** — позволяет объявить временную переменную внутри условия `extends` для автоматического извлечения (захвата) скрытых типов из сложных структур (например, возвращаемого значения функции или типа элементов массива).
*   **Дистрибутивность (Distributivity):** По умолчанию, если условному типу передается Union-тип (объединение), TypeScript автоматически распределяет условие по каждому элементу этого объединения.
*   **Используйте для:** создания гибких, самовычисляемых архитектурных хелперов, типизации универсальных обработчиков событий, автоматического извлечения типов из API-моделей или сторонних библиотек.
*   **Не используйте для:** простых типов. Чрезмерное усложнение статических контрактов условными типами снижает читаемость кода и сильно замедляет работу компилятора TypeScript в крупных проектах.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Автоматическое извлечение типа значения из Promise (`infer`)
*   **Назначение:** Написание универсальной утилиты типа для распаковки асинхронных ответов (извлечение чистого типа данных из обертки `Promise<T>`).

```typescript
// Описываем условный тип UnwrapPromise.
// Если тип T расширяет Promise, мы захватываем его внутренний тип в переменную R и возвращаем её.
// В противном случае возвращаем сам тип T без изменений.
export type UnwrapPromise<T> = T extends Promise<infer R> ? R : T;

// Пример использования:
export interface UserProfile {
  id: string;
  email: string;
}

// Имитируем асинхронную функцию API
type ApiCallResult = Promise<UserProfile>;

// Автоматически извлекаем чистый тип UserProfile на этапе компиляции
type ResolvedData = UnwrapPromise<ApiCallResult>; // Тип ResolvedData строго равен UserProfile
```

### Шаблон 2: Извлечение типов аргументов и возвращаемого значения функции
*   **Назначение:** Автоматический перенос типов сторонней недокументированной функции в локальные структуры (эквивалент системных `ReturnType` и `Parameters`).

```typescript
// Извлекаем тип возвращаемого значения функции
export type GetReturnType<T> = T extends (...args: any[]) => infer R ? R : never;

// Извлекаем тип первого аргумента функции
export type GetFirstArgument<T> = T extends (first: infer A, ...args: any[]) => any ? A : never;

// Пример практического использования:
const saveConfiguration = (config: { url: string; retries: number }): boolean => {
  console.log("Конфигурация сохранена:", config);
  return true;
};

// Извлекаем тип аргумента config для типизации локальной формы
export type SavedConfigType = GetFirstArgument<typeof saveConfiguration>; 
// SavedConfigType равен { url: string; retries: number }

// Извлекаем тип возвращаемого значения
export type SaveResultType = GetReturnType<typeof saveConfiguration>; 
// SaveResultType равен boolean
```

### Шаблон 3: Отключение дистрибутивности условных типов (Non-Distributive)
*   **Назначение:** Проверка Union-типа целиком без его автоматического разделения на отдельные элементы (например, точная проверка на тип `any` или `never`).

```typescript
// Дистрибутивный условный тип (по умолчанию)
// При передаче "A | B" он проверит "A" отдельно и "B" отдельно, вернув "X[] | Y[]"
type DistributiveArray<T> = T extends any ? T[] : never;

// Недистрибутивный условный тип.
// Обертывание параметров в квадратные скобки [T] и [any] отключает автоматическое распределение Union-типов.
// Это заставляет компилятор проверять весь Union-тип как единую монолитную структуру.
type NonDistributiveArray<T> = [T] extends [any] ? T[] : never;

// Сравнение результатов:
type TestUnion = string | number;

type ResultDist = DistributiveArray<TestUnion>;    // Результат: string[] | number[]
type ResultNonDist = NonDistributiveArray<TestUnion>; // Результат: (string | number)[]
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как условные типы устроены на уровне компилятора TypeScript
Условные типы переносят логику классического тернарного оператора в плоскость статического анализа. Компилятор вычисляет их лениво:

```
                  [ Проверить: T совместим с U ? ]
                             /         \
                         ( Да )       ( Нет )
                           /             \
                   [ Вернуть тип X ]   [ Вернуть тип Y ]
```

Если на момент парсинга тип `T` еще не определен (например, это свободный параметр generic-функции), компилятор не вычисляет условие сразу. Он оставляет его в состоянии отложенного вычисления (*deferred conditional type*) и разрешает тип только тогда, когда функция будет фактически вызвана с конкретными аргументами в коде.

### 2. Физика ключевого слова `infer` и ленивый захват контекста
Инструкция `infer` — это механизм декларативного вывода типов внутри условного контекста. 
*   Вы не можете использовать `infer` вне блока условия `extends`.
*   Записывая `infer R`, вы сообщаете компилятору: «Я не знаю заранее, какой тип будет находиться в этой позиции. Создай под него временную переменную `R`, и если условие `extends` выполнится успешно, запиши туда фактически обнаруженный тип».

Компилятор анализирует структуру и сопоставляет шаблоны. Например, при проверке `Promise<string> extends Promise<infer R>` компилятор сопоставляет шаблон `Promise<...>` с фактически переданным типом, вырезает из него внутренний параметр `string` и записывает его в созданную переменную `R`.

### 3. Механика дистрибутивности (Naked Type Parameters)
Дистрибутивность — это важнейшая системная особенность условных типов, которая срабатывает только тогда, когда проверяемый параметр `T` является "голым" (*naked type parameter*) — то есть не обернут во внешние структуры (массивы, кортежи, промисы).

Если мы передаем Union-тип `string | number` в голый условный тип `T extends any ? T[] : never`, компилятор распределяет выполнение условия по каждому элементу объединения:
1.  Вычисляет `string extends any ? string[] : never` $\rightarrow$ получает `string[]`.
2.  Вычисляет `number extends any ? number[] : never` $\rightarrow$ получает `number[]`.
3.  Объединяет результаты через оператор ИЛИ $\rightarrow$ возвращает `string[] | number[]`.

Если обернуть параметр в кортеж `[T] extends [any]`, параметр перестает быть "голым". Дистрибутивность отключается, и компилятор проверяет весь Union целиком, возвращая `(string | number)[]`.

### 4. Детальный пошаговый разбор выполнения шаблона 1
Разберем, как компилятор вычисляет тип `UnwrapPromise<Promise<UserProfile>>`:
1.  **Парсинг:** Компилятор видит вызов условного типа, где параметр `T` равен `Promise<UserProfile>`.
2.  **Сопоставление шаблона:** Вычисляется условие `Promise<UserProfile> extends Promise<infer R>`.
3.  **Захват типа:** Шаблоны совместимы. Компилятор извлекает тип `UserProfile` из обобщенной структуры `Promise` и записывает его в переменную `R`.
4.  **Ветвление:** Так как условие истинно, компилятор переходит по левой ветке (после знака `?`) и возвращает тип, хранящийся в переменной `R` (то есть `UserProfile`).

### 5. Типичные ошибки и их решение

*   **Ошибка 1: Ошибка циклического вывода при неверном указании ограничений `infer`**
    *   *Проблема:* Компилятор выдает ошибку `Type instantiation is excessively deep and possibly infinite` или уходит в бесконечный цикл анализа при попытке рекурсивного разбора типов.
    *   *Причина:* Слишком глубокая или некорректная рекурсия в условных типах без базового условия выхода.
    *   *Решение:* Всегда предусматривайте базовое условие выхода из рекурсии (например, возвращая тип `never` или исходный тип `T`, когда разбирать структуру больше невозможно).

*   **Ошибка 2: Ложное срабатывание дистрибутивности на типе `never`**
    *   *Проблема:* Передача типа `never` в дистрибутивный условный тип неожиданно возвращает сам `never` вместо ожидаемой ветки тернарного оператора.
    *   *Причина:* `never` — это пустое объединение в TypeScript. При передаче пустого объединения в дистрибутивный условный тип компилятору нечего распределять, поэтому цикл итераций по Union не запускается вовсе, и утилита мгновенно возвращает `never`.
    *   *Решение:* Для точной проверки типа на соответствие `never` всегда принудительно отключайте дистрибутивность с помощью квадратных скобок `[T]`.

```typescript
// ПЛОХО (Дистрибутивный тип вернет never вместо "YES")
type IsNeverUnsafe<T> = T extends never ? "YES" : "NO";
type Result1 = IsNeverUnsafe<never>; // Результат: never! (Ложное срабатывание)

// ХОРОШО (Отключение дистрибутивности гарантирует правильную проверку)
type IsNeverSafe<T> = [T] extends [never] ? "YES" : "NO";
type Result2 = IsNeverSafe<never>; // Результат: "YES" (Успешно)
```

*   **Ошибка 3: Попытка использовать `infer` вне условного блока**
    *   *Проблема:* Ошибка компиляции `infer declarations are only permitted in the extends clause of a conditional type` при попытке объявить тип.
    *   *Решение:* Захват типов через `infer` разрешен спецификацией языка исключительно внутри условной конструкции после ключевого слова `extends`. Для всех остальных случаев используйте явные обобщения (Generics).
