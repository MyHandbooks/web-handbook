# Функциональный перехватчик запросов (Auth Interceptor)

## БЫСТРЫЙ СТАРТ

*   **Функциональный перехватчик (`HttpInterceptorFn`)** — современный, легковесный и древотрясаемый (tree-shakable) тип данных в Angular, представляющий собой чистую функцию-посредник. Он перехватывает все исходящие HTTP-запросы и входящие HTTP-ответы приложения.
*   **Паттерн «Цепочка обязанностей» (Chain of Responsibility):** Перехватчик принимает объект запроса `HttpRequest` и функцию перехода `HttpHandlerFn`. Он может клонировать запрос, модифицировать его заголовки, выполнить побочные действия и обязан передать управление следующему звену цепи через `next(clonedRequest)`.
*   **Правила использования:**
    *   **Используйте:** Для глобальной и автоматической подстановки токенов авторизации (JWT / Bearer) во все исходящие запросы, добавления системных заголовков локализации, сквозного логирования или централизованного управления заголовками безопасности.
    *   **Не используйте:** Для изменения специфичной логики единичных запросов. Если модификация заголовка нужна только одному компоненту в исключительном сценарии, настраивайте заголовки локально в параметрах вызова `http.get/post`.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Функциональный перехватчик авторизации с фильтрацией эндпоинтов и контекстом обхода
*   **Назначение:** Описание современной функции перехвата, которая безопасно извлекает токен из сигнального хранилища, проверяет базовый URL-адрес и поддерживает явное отключение авторизации для публичных запросов через контекст.

```typescript
import { HttpInterceptorFn, HttpContextToken } from '@angular/common/http';
import { inject } from '@angular/core';
import { AuthStore } from './auth.store'; // Наше реактивное сигнальное хранилище сессии

// Создаем токен контекста для явной пометки публичных запросов
// Это позволит точечно отключать авторизацию на уровне отдельных вызовов HttpClient
export const BYPASS_AUTH = new HttpContextToken<boolean>(() => false);

export const authInterceptor: HttpInterceptorFn = (req, next) => {
  // 1. Проверяем, содержит ли текущий запрос флаг обхода авторизации
  if (req.context.get(BYPASS_AUTH)) {
    // Без изменений передаем управление следующему перехватчику в цепи
    return next(req);
  }

  // 2. С помощью функционального inject() извлекаем глобальный сервис сессии.
  // Это работает, так как Angular запускает перехватчики в активном Injection Context.
  const authStore = inject(AuthStore);
  const jwtToken = authStore.authToken(); // Извлекаем строковое значение реактивного сигнала

  // Определяем базовый URL-адрес нашего бэкенда (избегаем утечки токенов на сторонние API)
  const baseApiUrl = 'https://api.enterprise-service.com/v1';

  // 3. Безопасно сопоставляем: если токен существует и запрос направлен именно на наш бэкенд
  if (jwtToken && req.url.startsWith(baseApiUrl)) {
    // Создаем клон оригинального запроса. Изменять исходный req напрямую запрещено спецификацией.
    const authorizedRequest = req.clone({
      setHeaders: {
        // Добавляем стандартный заголовок авторизации Bearer
        Authorization: `Bearer ${jwtToken}`,
        // Попутно добавляем заголовок локализации для бэкенда
        'Accept-Language': 'ru'
      }
    });

    // Передаем клонированный авторизованный запрос дальше по цепочке
    return next(authorizedRequest);
  }

  // Если условий для добавления токена нет, отправляем исходный запрос дальше
  return next(req);
};
```

### Шаблон 2: Регистрация функциональных перехватчиков в app.config.ts
*   **Назначение:** Конфигурация DI-контейнера приложения для активации сетевого клиента с перечислением цепочки перехватчиков в строгом порядке выполнения.

```typescript
import { ApplicationConfig, provideZoneChangeDetection } from '@angular/core';
import { provideRouter } from '@angular/router';
import { provideHttpClient, withInterceptors } from '@angular/common/http';
import { routes } from './app.routes';
import { authInterceptor } from './auth.interceptor';

export const appConfig: ApplicationConfig = {
  providers: [
    provideZoneChangeDetection({ eventCoalescing: true }),
    provideRouter(routes),
    
    // Инициализируем сетевой слой приложения
    provideHttpClient(
      // Подключаем функциональные перехватчики. 
      // Важно: перехватчики выполняются строго в том порядке, в котором они перечислены в массиве!
      withInterceptors([
        authInterceptor
      ])
    )
  ]
};
```

### Шаблон 3: Пример использования контекста BYPASS_AUTH при локальном запросе
*   **Назначение:** Вызов метода `HttpClient`, который явно отключает добавление JWT-токена (например, при загрузке публичного файла конфигурации).

```typescript
import { Injectable, inject } from '@angular/core';
import { HttpClient, HttpContext } from '@angular/common/http';
import { Observable } from 'rxjs';
import { BYPASS_AUTH } from './auth.interceptor';

@Injectable({
  providedIn: 'root'
})
export class PublicAssetService {
  private readonly http = inject(HttpClient);

  public loadPublicConfig(): Observable<unknown> {
    const publicUrl = 'https://api.enterprise-service.com/v1/public-settings.json';

    return this.http.get<unknown>(publicUrl, {
      // Передаем созданный контекст с флагом обхода авторизации
      context: new HttpContext().set(BYPASS_AUTH, true)
    });
  }
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Физика неизменяемости (Immutability) HTTP-запросов
В Angular объекты `HttpRequest` спроектированы как строго неизменяемые (Immutable). Свойства, такие как `headers`, `body`, `url`, закрыты для прямой записи.

Почему это важно?
Сетевой запрос в современном асинхронном приложении может подвергаться повторной отправке (вспоминаем оператор `retry`), кэшированию, параллельному логированию или ветвлению. Если бы один из перехватчиков мутировал исходный объект `req` напрямую, последующие попытки повторной отправки или параллельные обработчики получили бы искаженную структуру данных (например, повторно примененный или испорченный токен). 

По этой причине единственный способ изменить параметры запроса — использовать метод `req.clone()`. Он создает поверхностную копию объекта запроса, переопределяя только те свойства, которые вы явно передали в объекте конфигурации.

### 2. Магия DI во встроенных функциях HttpInterceptorFn
В классических версиях Angular (до версии 15) для использования внедрения зависимостей в перехватчиках приходилось объявлять полноценный класс, декорированный `@Injectable()`. 

Современные функциональные перехватчики `HttpInterceptorFn` объявляются как простые JavaScript-функции. Тем не менее, внутри них можно беспрепятственно вызывать `inject()`. Это возможно благодаря тому, что Angular запускает цепочку перехватчиков внутри специального **активного контекста внедрения (Injection Context)**, создаваемого корневым инжектором среды (Environment Injector). 

Данное архитектурное решение позволило полностью отказаться от бойлерплейта классов, сделав код перехватчиков чистым, компактным и дружелюбным для сборщиков (бандлеров), так как неиспользуемые функции гораздо легче подвергаются tree-shaking.

### 3. Пошаговый разбор выполнения перехвата запроса
Рассмотрим движение сетевого запроса к эндпоинту `https://api.enterprise-service.com/v1/profile` через наш `authInterceptor`:

1.  **Создание запроса:** Компонент вызывает `http.get('/profile')`.
2.  **Запуск перехватчика:** Angular перенаправляет запрос в первую зарегистрированную функцию `authInterceptor(req, next)`.
3.  **Анализ контекста:** Проверяется `req.context.get(BYPASS_AUTH)`. Значение по умолчанию равно `false`. Двигаемся дальше.
4.  **Разрешение зависимости:** Вызывается `inject(AuthStore)`. DI-контейнер Angular находит синглтон-стор авторизации и считывает реактивный сигнал `authToken()`. Предположим, токен равен `"jwt_abc_123"`.
5.  **Проверка домена:** Перехватчик проверяет, начинается ли `req.url` с префикса `https://api.enterprise-service.com/v1`. Условие истинно.
6.  **Клонирование:** Создается глубокий клон запроса:
    ```typescript
    const authorizedRequest = req.clone({ ... });
    ```
    Внутренняя карта заголовков клона дополняется полем `Authorization: Bearer jwt_abc_123`.
7.  **Передача контроля:** Вызывается `next(authorizedRequest)`. Модифицированный запрос передается следующему интерцептору или, если цепочка завершена, в сетевой бэкэнд `HttpXhrBackend` для отправки в сеть.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Бесконечный цикл рекурсии при инжекции сервисов (Circular Dependency Nightmare)**
    *   *Симптомы:* При попытке инициализировать приложение вкладка браузера зависает или падает с критической ошибкой `Maximum call stack size exceeded` в консоли.
    *   *Физика процесса:* Вы инжектируете службу `AuthService` в интерцептор: `const auth = inject(AuthService)`. При этом сам класс `AuthService` в своем конструкторе или методах инжектирует `HttpClient` для выполнения запросов обновления токена (`/auth/refresh`). Сетевой клиент `HttpClient` при создании требует загрузки всех интерцепторов $\rightarrow$ интерцептор требует `AuthService` $\rightarrow$ `AuthService` требует `HttpClient`. Круг замыкается, вызывая переполнение стека вызовов DI.
    *   *Решение:* Перенесите хранение токена в легковесный реактивный `AuthStore` или `TokenStorageService`, который вообще не использует `HttpClient` внутри себя (работает напрямую со свойствами в памяти или `localStorage`), либо извлекайте зависимости лениво через `Injector` непосредственно в момент обработки запроса, а не при инициализации.

```typescript
// ОШИБКА: AuthService тянет за собой HttpClient, вызывая циклическую зависимость при сборке DI
// const authService = inject(AuthService); 

// ИСПРАВЛЕНИЕ: Токены хранятся в изолированном TokenStorage, у которого нет HttpClient в зависимостях
const tokenStorage = inject(TokenStorageService);
```

*   **Ошибка 2: Утечка авторизационных JWT-токенов на сторонние сервера (Security Breach)**
    *   *Симптомы:* Сторонние сервисы (например, S3-хранилища, внешние виджеты карт или CDN) начинают возвращать ошибки `400/401` на запросы ассетов, либо в логах сторонних серверов обнаруживаются ваши внутренние корпоративные токены доступа.
    *   *Физика процесса:* Разработчик написал перехватчик, который без разбора подставляет заголовок `Authorization` ко всем исходящим запросам: `req.clone({ setHeaders: { Authorization: token } })`. Когда приложение запрашивает картинку из публичного S3-бакета или обращается к внешнему API карт Google, секретный токен уходит во внешнюю сеть.
    *   *Решение:* Всегда проверяйте адрес назначения перед клонированием запроса с помощью метода `.startsWith()` или регулярного выражения.

```typescript
// ОШИБКА: Токен уходит на любые адреса в интернете, включая сторонние CDN
// const cloned = req.clone({ setHeaders: { Authorization: `Bearer ${token}` } });

// ИСПРАВЛЕНИЕ: Проверка принадлежности URL нашему доверенному домену API
if (token && req.url.startsWith('https://api.my-enterprise.com')) {
  const cloned = req.clone({ setHeaders: { Authorization: `Bearer ${token}` } });
  return next(cloned);
}
```

*   **Ошибка 3: Попытка прямой мутации заголовков (Direct Mutation Fail)**
    *   *Симптомы:* Ошибка компиляции или рантайм-сбой при выполнении HTTP-запроса.
    *   *Физика процесса:* Разработчик пытается добавить заголовок напрямую: `req.headers.set('Authorization', token)`. Так как `req.headers` является иммутабельным экземпляром класса `HttpHeaders`, этот вызов либо выбрасывает ошибку, либо не вносит изменений в реальный запрос, отправляемый в сеть.
    *   *Решение:* Изменяйте заголовки строго через вызов метода `clone()`.

```typescript
// ОШИБКА: Прямое изменение свойств иммутабельного объекта не сработает
// req.headers.set('Authorization', token);

// ИСПРАВЛЕНИЕ: Клонирование с передачей новых заголовков
const cloned = req.clone({
  setHeaders: {
    Authorization: token
  }
});
```
