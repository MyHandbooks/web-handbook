# Реактивный WebSocket-клиент (WebSocketSubject)

## БЫСТРЫЙ СТАРТ

*   **Класс `WebSocketSubject`** — специализированный подтип `Subject` в библиотеке RxJS, который оборачивает нативный браузерный WebSocket API. Он представляет собой полноценный реактивный мост для двустороннего полнодуплексного (Full-Duplex) обмена сообщениями в режиме реального времени.
*   **Специфика дуализма:** Будучи наследником `Subject`, он одновременно выступает в двух ролях:
    *   **Observable (Приемник):** Вы можете подписаться на него через `.subscribe()`, чтобы реактивно реагировать на каждое входящее текстовое или бинарное сообщение от сервера.
    *   **Observer (Передатчик):** Вы можете вызывать у него метод `.next(payload)`, чтобы беспрепятственно отправлять данные на сервер.
*   **Правила использования:**
    *   **Используйте:** Для разработки интерактивных чатов, систем уведомлений (push notifications), графиков котировок акций, дашбордов реального времени и совместного редактирования документов.
    *   **Не используйте:** Для простых разовых GET-запросов (используйте стандартный `HttpClient`), ленивой загрузки файлов или при отсутствии жестких требований к низкой задержке (low latency) передачи данных.

### Шаблон 1: Корпоративный устойчивый сервис WebSocket с авто-реконнектом
*   **Назначение:** Реализация надежного синглтон-сервиса, который автоматически восстанавливает соединение при обрывах сети с задержкой, поддерживает логирование жизненного цикла и предоставляет единый интерфейс передачи сообщений.

```typescript
import { Injectable } from '@angular/core';
import { webSocket, WebSocketSubject } from 'rxjs/webSocket';
import { Observable, EMPTY, Subject, timer } from 'rxjs';
import { retry, catchError } from 'rxjs/operators';

// Описываем стандартную структуру сообщений обмена
export interface SocketMessagePayload {
  event: string;      // Имя события (например, 'SUBSCRIBE', 'TICKER_UPDATE')
  data: unknown;      // Полезная нагрузка сообщения произвольной формы
}

@Injectable({
  providedIn: 'root'
})
export class RealtimeSocketService {
  // Нативный объект WebSocketSubject от RxJS
  private socket$: WebSocketSubject<SocketMessagePayload> | null = null;
  
  // Внутренний горячий поток-шина для безопасной раздачи сообщений всем подписчикам
  private readonly messages$ = new Subject<SocketMessagePayload>();

  // Базовый адрес WebSocket эндпоинта
  private readonly socketUrl = 'wss://api.enterprise-service.com/ws';

  /**
   * Инициализирует соединение (если не создано) и возвращает безопасный поток сообщений
   */
  public connect(): Observable<SocketMessagePayload> {
    if (!this.socket$ || this.socket$.closed) {
      this.socket$ = this.createWebSocketConnection();
    }
    return this.messages$.asObservable();
  }

  /**
   * Безопасно отправляет событие на сервер
   * @param event Название события
   * @param data Полезная нагрузка
   */
  public sendMessage(event: string, data: unknown): void {
    if (this.socket$ && !this.socket$.closed) {
      // Отправляем данные на сервер. 
      // Под капотом WebSocketSubject автоматически вызовет JSON.stringify()
      this.socket$.next({ event, data });
    } else {
      console.error('[Socket] Невозможно отправить сообщение: сокет неактивен.');
    }
  }

  /**
   * Принудительно и корректно закрывает соединение со стороны клиента
   */
  public disconnect(): void {
    if (this.socket$) {
      // Вызываем complete(), чтобы закрыть сокет по протоколу и завершить все подписки
      this.socket$.complete();
      this.socket$ = null;
    }
  }

  /**
   * Внутренний метод сборки сетевого сокета с хуками жизненного цикла
   */
  private createWebSocketConnection(): WebSocketSubject<SocketMessagePayload> {
    const connection = webSocket<SocketMessagePayload>({
      url: this.socketUrl,
      // Хук: вызывается в момент успешного хэндшейка TCP/WS
      openObserver: {
        next: () => console.log('[Socket] Соединение с сервером успешно открыто.')
      },
      // Хук: вызывается при нормальном или аварийном закрытии сокета браузером
      closeObserver: {
        next: (closeEvent) => {
          console.warn(`[Socket] Сокет закрыт. Код: ${closeEvent.code}. Причина: ${closeEvent.reason || 'Нет данных'}`);
        }
      }
    });

    // Запускаем внутреннюю реактивную подписку для поддержания соединения активным
    connection.pipe(
      // Реализуем авто-подключение при сбоях сети (используем современную сигнатуру retry)
      retry({
        delay: (error) => {
          console.error('[Socket] Сетевой сбой. Попытка восстановить подключение через 5 секунд...', error);
          // Возвращаем таймер задержки. По истечении 5 сек произойдет повторная подписка
          return timer(5000); 
        }
      }),
      // Локально перехватываем критические невосстановимые ошибки
      catchError((error) => {
        console.error('[Socket] Критическая ошибка потока:', error);
        return EMPTY; // Возвращаем пустой поток для предотвращения падения приложения
      })
    ).subscribe({
      // Транслируем каждое входящее сообщение в нашу общую шину messages$
      next: (message) => this.messages$.next(message),
      error: (err) => console.error('[Socket] Ошибка конвейера подписки:', err),
      complete: () => console.log('[Socket] Поток сокета полностью завершен.')
    });

    return connection;
  }
}
```

### Шаблон 2: Компонент отображения живых котировок с автоматической отпиской
*   **Назначение:** Реализация UI-компонента, который при инициализации подписывается на WebSocket-сервис, выводит динамическую цену котировок на Сигналах и шлет управляющие сокет-команды на сервер.

```typescript
import { Component, inject, signal, OnInit, DestroyRef } from '@angular/core';
import { takeUntilDestroyed } from '@angular/core/rxjs-interop';
import { RealtimeSocketService, SocketMessagePayload } from './realtime-socket.service';

@Component({
  selector: 'app-ticker-dashboard',
  standalone: true,
  template: `
    <div class="ticker-card">
      <h3>Монитор котировок BTC</h3>
      
      @if (bitcoinPrice(); as price) {
        <p class="price-text">BTC/USD: <b>{{ price }} $</b></p>
      } @else {
        <p class="status-loading">Ожидание подключения к потоку реального времени...</p>
      }

      <div class="btn-group">
        <button class="action-btn" (click)="subscribeToLiveTicker()">Запустить поток</button>
        <button class="action-btn" (click)="unsubscribeFromLiveTicker()">Остановить поток</button>
      </div>
    </div>
  `,
  styles: [`
    .ticker-card { padding: 24px; border: 1px solid var(--border); border-radius: 12px; background-color: var(--bg-secondary); max-width: 380px; }
    .price-text { font-size: 1.5rem; color: var(--success-text); margin: 16px 0; font-weight: 700; }
    .btn-group { display: flex; gap: 10px; margin-top: 15px; }
  `]
})
export class TickerDashboardComponent implements OnInit {
  private readonly socketService = inject(RealtimeSocketService);
  private readonly destroyRef = inject(DestroyRef);

  // Локальный сигнал для живого отображения цены в шаблоне
  public readonly bitcoinPrice = signal<number | null>(null);

  public ngOnInit(): void {
    // Подключаемся к нашей общей шине сокет-сервиса
    this.socketService.connect()
      .pipe(
        // Обязательно отписываемся от сокета при уничтожении экрана
        takeUntilDestroyed(this.destroyRef)
      )
      .subscribe({
        next: (message: SocketMessagePayload) => {
          // Реагируем на конкретное системное событие от сервера
          if (message.event === 'TICKER_UPDATE') {
            this.bitcoinPrice.set(Number(message.data));
          }
        },
        error: (err: Error) => console.error('[UI Component] Сбой чтения сокета:', err)
      });
  }

  /**
   * Отправляет на сервер команду подписки на котировки
   */
  public subscribeToLiveTicker(): void {
    this.socketService.sendMessage('SUBSCRIBE', { symbol: 'BTCUSD' });
  }

  /**
   * Отправляет на сервер команду отмены подписки
   */
  public unsubscribeFromLiveTicker(): void {
    this.socketService.sendMessage('UNSUBSCRIBE', { symbol: 'BTCUSD' });
  }
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Архитектурная физика жизненного цикла WebSocketSubject
Понимание внутренней физики `WebSocketSubject` убережет вас от избыточного расхода ресурсов сервера. 

В отличие от нативного JavaScript-объекта `new WebSocket(url)`, который открывает сетевое соединение мгновенно в момент инициализации класса, `WebSocketSubject` ленив по своей природе:
1.  **Ленивое открытие (Lazy Opening):** Создание экземпляра через фабричную функцию `webSocket()` не инициирует отправку сетевых пакетов. Физическое TCP-соединение и хэндшейк происходят **только тогда, когда на сокет подписывается первый клиент** (вызывается метод `.subscribe()`).
2.  **Мультивещание (Multicasting):** Если у вас уже есть открытое активное соединение, и на этот же экземпляр `WebSocketSubject` подписывается второй, третий и последующие клиенты, новые сетевые сокеты в браузере не открываются. RxJS мультивещает (дублирует) приходящие сообщения от единого открытого физического канала связи всем активным подписчикам.
3.  **Автоматическое закрытие (Auto-Teardown):** Когда количество активных подписчиков падает с 1 до 0 (то есть абсолютно все клиенты вызвали метод `.unsubscribe()`), `WebSocketSubject` автоматически отправляет на сервер системный фрейм закрытия соединения и полностью закрывает физический сокет для экономии ресурсов операционной системы.

В Шаблоне 1 мы намеренно подписались на сокет внутри синглтон-сервиса `RealtimeSocketService` на все время жизни приложения. Это гарантирует, что соединение держится постоянно открытым, а компоненты лениво подписываются и отписываются от нашей внутренней шины-посредника `messages$`, не заставляя браузер закрывать и открывать физические порты при каждом переходе по страницам.

### 2. Специфика сериализации данных по умолчанию
Из коробки `WebSocketSubject` берет на себя рутину по парсингу данных. 
*   Каждое входящее текстовое сообщение, приходящее из сети от сервера, неявно прогоняется через встроенный десериализатор `JSON.parse()`. Если сервер пришлет невалидный JSON (например, простую строку `Ping`), поток мгновенно упадет по ошибке парсинга.
*   Каждое отправляемое вами сообщение через метод `.next(payload)` автоматически конвертируется в строку через `JSON.stringify()`.

Если ваш бэкенд использует другие протоколы сериализации (например, бинарный формат Protocol Buffers, MessagePack или передает сырой неструктурированный текст), вы должны переопределить стандартный сериализатор в конфигурационном объекте:
```typescript
const customSocket = webSocket<string>({
  url: 'wss://api.enterprise.com',
  // Отключаем JSON.parse, возвращаем сырой текст в поток
  deserializer: (msgEvent: MessageEvent<string>) => msgEvent.data,
  // Отключаем JSON.stringify, отправляем сырую строку на сервер
  serializer: (value: string) => value
});
```

### 3. Пошаговый разбор логики авто-реконнекта при разрыве связи
Разберем алгоритм работы устойчивого сокета из Шаблона 1 при переключении пользователя с мобильного интернета на домашнюю сеть Wi-Fi:

1.  **Обрыв линка:** Операционная система закрывает TCP-соединение. Браузер генерирует событие закрытия сокета.
2.  **Срабатывание хука:** Выполняется коллбэк `closeObserver.next`. В консоли выводится предупреждение о разрыве соединения.
3.  **Событие ошибки:** Так как сокет закрылся аварийно, `WebSocketSubject` генерирует терминальный сигнал `error` в конвейер RxJS.
4.  **Реакция `retry`:**
    *   Оператор `retry` ловит сетевой сбой.
    *   Срабатывает функция `delay()`. Нам передается объект ошибки и срабатывает `timer(5000)`.
    *   Поток засыпает на 5 секунд, предотвращая создание DDOS-нагрузки на ваш сервер при его плановой перезагрузке.
5.  **Re-subscribe:** По истечении 5 секунд `retry` делает повторную подписку на `webSocket`.
6.  **Новый коннект:** Ленивый `WebSocketSubject` отправляет пакеты на сервер, устанавливает новое соединение, и поток возобновляет трансляцию данных в компонент.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Попытка отправки сообщений до фактического открытия сокета (Buffer Overflow)**
    *   *Симптомы:* Сообщения, отправленные при старте приложения через метод `.next()`, бесследно теряются и не доходят до бэкенда, либо сокет падает по ошибке.
    *   *Физика процесса:* Установление WebSocket соединения занимает время (от 100мс до нескольких секунд на медленном интернете). Если вы вызываете `.next()` сразу после создания сокета, физический сокет находится в состоянии `CONNECTING`. Попытка записать данные в неактивное соединение завершается их потерей.
    *   *Решение:* `WebSocketSubject` имеет встроенный буфер для неотправленных сообщений, но надежнее всего производить инициализирующие отправки (например, подписку на каналы) строго после того, как сокет подтвердит состояние готовности, либо использовать встроенные события `openObserver`.

```typescript
// ХОРОШО: Отправляем подписку строго в момент генерации события openObserver на сервере
const connection = webSocket({
  url: 'wss://api.my-domain.com',
  openObserver: {
    next: () => {
      // Сокет гарантированно открыт и готов к приему данных
      this.sendMessage('SUBSCRIBE', { channel: 'orders' });
    }
  }
});
```

*   **Ошибка 2: «Призрачные» соединения при отсутствии пинг-понг пинга (Ghost Connection Leaks)**
    *   *Симптомы:* Мобильные клиенты периодически перестают получать обновления из сокета, хотя код ошибок не генерирует и статус сокета в браузере значится как активный.
    *   *Физика процесса:* При переходе мобильного устройства между сотовыми вышками сетевой шлюз оператора связи может молча уничтожить TCP-сессию. Браузер при этом не получает физического пакета `FIN` от сервера и считает, что сокет по-прежнему открыт. Соединение переходит в состояние «призрака» — данные не могут дойти ни в одну из сторон.
    *   *Решение:* Реализуйте механизм Heartbeat (Ping-Pong). Каждые 30 секунд шлите с клиента легкое текстовое сообщение `Ping`. Если сервер в течение 5 секунд не вернул ответный фрейм `Pong`, принудительно закрывайте сокет со стороны клиента через `.error()` — это заставит оператор `retry` перезапустить чистое соединение.

*   **Ошибка 3: Утечка соединений при некорректном ручном закрытии (Socket Leak)**
    *   *Симптомы:* Администратор сервера бэкенда жалуется на колоссальное количество висящих «мертвых» WebSocket-соединений от одного и того же клиента.
    *   *Физика процесса:* При уходе пользователя со страницы разработчик просто отписывается от потока входящих сообщений, но сам объект `WebSocketSubject` не закрывается, так как на него была оформлена постоянная подписка внутри синглтон-сервиса, или в коде была допущена ошибка удержания ссылок.
    *   *Решение:* Принудительно завершайте жизненный цикл сокета с помощью вызова `.complete()` на экземпляре `WebSocketSubject` (как показано в методе `disconnect` Шаблона 1) при выходе пользователя из системы или закрытии приложения.
