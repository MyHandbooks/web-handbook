# 1.5.2. Фильтрация списка по критериям (filter)

## БЫСТРЫЙ СТАРТ

*   **`Array.prototype.filter(callback)`** — встроенный метод массивов, который обходит каждый элемент исходного списка, применяет к нему проверочную функцию-коллбэк и возвращает **новый массив**, состоящий исключительно из элементов, прошедших эту проверку (коллбэк вернул истинное значение).
*   **Иммутабельность:** Метод не изменяет исходный массив. Если ни один элемент не прошел проверку, метод возвращает пустой массив `[]`, а не `null` или `undefined`.
*   **Используйте его для:** отсеивания невалидных или пустых значений, удаления элементов по идентификатору или сложной выборки объектов на основе вложенных условий.
*   **Не используйте его:** когда вам нужно найти ровно **один** уникальный элемент. Для поиска единичного значения по условию используйте метод `.find()`, так как `.filter()` всегда обходит массив до самого конца, снижая производительность.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Очистка списка от пустых и ложных (falsy) значений
*   **Назначение:** Быстрое удаление пустых строк, `null`, `undefined` и других невалидных значений из одномерного массива.

```typescript
export function cleanPrimitiveArray(rawList: (string | null | undefined)[]): string[] {
  // Передача Boolean в качестве коллбэка автоматически отсеивает все falsy-значения
  // Использование синтаксиса "is string" гарантирует правильное сужение типа в TypeScript
  return rawList.filter((item): item is string => Boolean(item));
}
```

---

### Шаблон 2: Фильтрация объектов по точному совпадению свойства
*   **Назначение:** Выборка подмножества объектов из общего массива по конкретному признаку (например, фильтрация активных сессий или ролей).

```typescript
export interface DataState {
  id: string;
  status: "active" | "inactive" | "suspended";
}

export function filterActiveStates(items: DataState[]): DataState[] {
  // Возвращает новый массив, содержащий только активные элементы
  return items.filter((item): boolean => {
    // Строгое сравнение гарантирует точную фильтрацию
    return item.status === "active"; 
  });
}
```

---

### Шаблон 3: Сложная многокритериальная фильтрация объектов
*   **Назначение:** Выборка данных на основе диапазона числовых значений, текстового поиска по подстроке и логических условий одновременно.

```typescript
export interface ConfigOptions {
  identifier: string;
  thresholdLimit: number;
  isSystemRequired: boolean;
}

export function filterConfigOptions(
  configs: ConfigOptions[], 
  searchQuery: string, 
  minThreshold: number
): ConfigOptions[] {
  const normalizedQuery = searchQuery.toLowerCase().trim();

  return configs.filter((config): boolean => {
    // 1. Проверяем вхождение поискового запроса без учета регистра
    const matchesQuery = config.identifier.toLowerCase().includes(normalizedQuery);
    
    // 2. Проверяем попадание числового значения в заданный диапазон
    const matchesLimit = config.thresholdLimit >= minThreshold;
    
    // 3. Проверяем флаг обязательности системы
    const isRequired = config.isSystemRequired;

    // Объект попадает в финальный массив только при соблюдении всех трех условий
    return matchesQuery && matchesLimit && isRequired;
  });
}
```

---

### Шаблон 4: Иммутабельное удаление элемента по идентификатору
*   **Назначение:** Безопасное удаление элемента из стейта приложения по его ID без изменения оригинального массива в памяти.

```typescript
export interface TemporaryResult {
  uid: string;
  payloadData: string;
}

export function removeResultById(results: TemporaryResult[], targetUid: string): TemporaryResult[] {
  // Возвращает новый массив без элемента, у которого совпал идентификатор
  return results.filter(result => result.uid !== targetUid);
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как метод `Array.prototype.filter()` устроен под капотом движка V8
На уровне спецификации ECMAScript метод `.filter()` работает по принципу условного накопления данных:

1.  **Динамическое выделение памяти:** В отличие от `.map()`, движок V8 не может заранее знать точный размер результирующего массива на этапе инициализации метода. Результирующий массив создается пустым, и память под него выделяется динамически по мере нахождения подходящих элементов.
2.  **Поверхностное копирование ссылок (Shallow Copy):** Если исходный массив содержит сложные объекты, в результирующий массив копируются **только адреса ссылок на эти объекты в куче (heap)**, а не сами объекты. Это означает, что отфильтрованный массив и исходный массив продолжают делить одни и те же объекты в памяти.
3.  **Обработка дыр (Sparse Arrays):** По аналогии с другими методами итерации, `.filter()` полностью игнорирует отсутствующие (неинициализированные) индексы в разреженных массивах. Коллбэк для пустых ячеек не вызывается, а в результирующем массиве эти пропуски не сохраняются (длина сокращается строго до количества успешно отфильтрованных элементов).

### 2. Оптимизация процесса поиска в V8 и иммутабельность
Поскольку `.filter()` возвращает новую физическую ссылку на массив в оперативной памяти, он идеально подходит для разработки реактивных интерфейсов. При изменении фильтрации (например, при вводе в поисковую строку) Angular считывает новую ссылку на отфильтрованный массив и точечно обновляет только измененные DOM-узлы.

**Оптимизация V8:**
Для ускорения динамической аллокации памяти внутри цикла `.filter()`, движок V8 использует оптимизацию **Pre-allocation**. Сначала движок выделяет небольшой буфер в памяти (обычно на 4 или 8 элементов). Если лимит превышается, буфер динамически расширяется по экспоненциальному закону. JIT-компилятор оптимизирует этот процесс, избавляя код от постоянных тяжелых перевыделений памяти при небольших размерах массивов.

### 3. Детальный пошаговый разбор выполнения шаблона 3
1.  **Нормализация параметров:** Вычисляется `normalizedQuery` (приведение к нижнему регистру и обрезка пробелов).
2.  **Инициация массива:** Движок V8 создает новый пустой массив в куче для результатов фильтрации.
3.  **Итерация 1:** Движок считывает первый объект `configs[0]`. Запускается функция-коллбэк. Вычисляются булевы флаги: `matchesQuery = true`, `matchesLimit = false`, `isRequired = true`. Коллбэк возвращает `false`. Объект отбрасывается.
4.  **Итерация 2:** Считывается объект `configs[1]`. Все три условия вычисляются как `true`. Коллбэк возвращает `true`. Движок копирует ссылку на объект `configs[1]` в результирующий массив.
5.  **Завершение работы:** Цикл обходит весь массив `configs` до конца. Результирующий массив с успешно прошедшими проверку элементами возвращается из функции.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Мутация объектов внутри проверочного коллбэка `.filter()`**
    *   *Проблема:* Попытка изменить свойства обрабатываемого объекта прямо внутри проверочного условия (например, `if (item.status === 'suspended') { item.archived = true; return false; }`). Это грубейшее нарушение функциональной парадигмы, приводящее к неконтролируемому искажению данных в оригинальном массиве.
    *   *Причина:* Объект передается в колбэк по ссылке. Любое изменение свойства мутирует оригинал в куче.
    *   *Решение:* Если данные нужно изменить, делайте это на отдельном шаге через метод `.map()`, либо возвращайте иммутабельную копию объекта.

```typescript
// ПЛОХО (Прямое изменение свойства ломает оригинальный массив)
export function filterAndMutateUnsafe(items: DataState[]): DataState[] {
  return items.filter(item => {
    if (item.status === "inactive") {
      // item.status = "suspended"; // ! Мутирует оригинальный объект в куче!
      return false;
    }
    return true;
  });
}
```

*   **Ошибка 2: Использование `.filter()` вместо `.find()` для поиска одного элемента**
    *   *Проблема:* Поиск уникального элемента по ID через `.filter()` (например, `arr.filter(x => x.id === targetId)[0]`). Код работает крайне неэффективно на больших массивах.
    *   *Причина:* Метод `.filter()` обязан проитерировать массив до самого конца (даже если целевой элемент находился на первой позиции). Метод `.find()` останавливает итерации мгновенно, как только условие выполнилось.
    *   *Решение:* Всегда используйте `.find()` для поиска единичных уникальных записей.

```typescript
// ПЛОХО (V8 просканирует весь миллион элементов, даже если нужный был первым)
export function findRecordUnsafe(items: DataState[], targetId: string): DataState | undefined {
  return items.filter(item => item.id === targetId)[0]; 
}

// ХОРОШО (V8 остановит цикл мгновенно при первом совпадении)
export function findRecordSafe(items: DataState[], targetId: string): DataState | undefined {
  return items.find(item => item.id === targetId); 
}
```

*   **Ошибка 3: Ложные срабатывания фильтрации из-за неявного приведения типов**
    *   *Проблема:* Разработчик пишет нестрогую проверку равенства (например, `config.rating == searchQuery`) или забывает обработать возможность получения пустой строки в качестве критерия. Из-за этого отфильтровываются валидные числовые нули или пустые массивы.
    *   *Решение:* Всегда используйте строгое сравнение `===` и явно валидируйте входящие параметры поиска перед запуском фильтрации.
