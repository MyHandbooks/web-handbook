# 1.5.1. Преобразование структуры списка (map)

## БЫСТРЫЙ СТАРТ

*   **`Array.prototype.map(callback)`** — это встроенный метод массивов, который «пробегается» по каждому элементу исходного списка, применяет к нему функцию-колбэк и возвращает **новый массив строго той же длины**, состоящий из результатов работы этой функции.
*   **Иммутабельность:** Метод спроектирован в рамках концепции функционального программирования — он **не изменяет (не мутирует) исходный массив**.
*   **Используйте его для:** трансформации структур данных (например, приведение объектов от формата бэкенда к формату интерфейса), извлечения массивов отдельных полей или иммутабельного точечного изменения элемента по его идентификатору.
*   **Не используйте его:** для выполнения побочных эффектов (Side Effects), таких как запись в базу, отправка сетевых запросов или изменение внешних переменных. Для простых циклов без возврата новых данных используйте метод `.forEach()`.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Преобразование примитивов в массив объектов
*   **Назначение:** Быстрая генерация типизированного списка объектов из плоского массива простых строк или чисел (удобно для создания элементов меню или справочников).

```typescript
export interface DataState {
  id: string;
  label: string;
}

export function transformPrimitivesToObjects(rawList: string[]): DataState[] {
  // map возвращает новый массив объектов типа DataState
  return rawList.map((item, index): DataState => {
    // Для каждого элемента формируем уникальный объект
    return {
      id: `state_id_${index}`, // генерируем строковый идентификатор
      label: item.toUpperCase() // форматируем текст в верхний регистр
    };
  });
}
```

### Шаблон 2: Конвертация модели бэкенда в модель отображения (DTO-Mapping)
*   **Назначение:** Трансформация структуры данных, пришедших от внешнего API, под требования интерфейса (вырезание лишних полей, переименование ключей, форматирование дат).

```typescript
// Описание структуры ответа сервера
export interface SourceModel {
  uid_value: string;
  raw_content_payload: string;
  created_at_time: string;
  is_deleted: boolean;
}

// Описание целевой структуры для UI компонентов
export interface ViewModel {
  id: string;
  text: string;
  displayDate: string;
}

export function mapSourceToViewModel(serverItems: SourceModel[]): ViewModel[] {
  // Трансформируем исходный массив в массив чистого представления
  return serverItems.map((item): ViewModel => {
    return {
      id: item.uid_value, // переименовываем ключ идентификатора
      text: item.raw_content_payload, // сопоставляем контентное свойство
      displayDate: new Date(item.created_at_time).toLocaleDateString("ru-RU") // форматируем системную дату в читаемый вид
    };
  });
}
```

### Шаблон 3: Экстракция массива значений конкретного свойства
*   **Назначение:** Быстрый сбор значений одного ключа (например, всех ID или названий) из сложного массива объектов.

```typescript
export interface TargetPayload {
  uniqueKey: string;
  stateValue: string;
}

export function extractIdentifiers(payloads: TargetPayload[]): string[] {
  // На каждой итерации возвращаем только значение свойства uniqueKey
  return payloads.map(payload => payload.uniqueKey);
}
```

### Шаблон 4: Иммутабельное обновление одного элемента по ID
*   **Назначение:** Точечное изменение данных конкретного объекта внутри массива по его идентификатору без мутации оригинального массива в памяти (классический паттерн для Redux/Signals).

```typescript
export interface ExecutionState {
  id: string;
  status: "pending" | "completed";
}

export function updateStateById(states: ExecutionState[], targetId: string): ExecutionState[] {
  // Возвращаем новый массив, заменяя только целевой объект
  return states.map((state): ExecutionState => {
    if (state.id !== targetId) {
      // Если ID не совпадает, возвращаем элемент как есть (сохраняем ссылку в памяти)
      return state; 
    }
    // Если ID совпал, возвращаем новую иммутабельную копию объекта с измененным статусом
    return {
      ...state,
      status: "completed"
    };
  });
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как метод `Array.prototype.map()` устроен на уровне спецификации ECMAScript
Метод `.map()` — это строгий абстрактный цикл, поведение которого зафиксировано в системной спецификации.

Ключевые технические особенности работы метода под капотом движка:
1.  **Фиксированная длина:** Движок V8 перед началом итераций считывает длину исходного массива (`length`) и выделяет в памяти непрерывный блок под новый массив **точно такого же размера**. Длина результирующего массива никогда не может измениться в процессе работы `.map()`.
2.  **Поведение на пустых элементах (Sparse Arrays):** Если исходный массив имеет пропуски (дыры, незаполненные индексы, например, созданные через `new Array(5)`), метод `.map()` пропустит эти индексы. Колбэк-функция для них вызвана не будет, но в результирующем массиве на этих местах останутся точно такие же пустые дыры (`holes`), сохраняя длину структуры.
3.  **Параметры колбэка:** На каждой итерации движок V8 передает в функцию обратного вызова три аргумента:
    *   `value` — текущий обрабатываемый элемент.
    *   `index` — числовой индекс текущего элемента.
    *   `array` — прямая ссылка на исходный итерируемый массив (позволяет считывать общую структуру данных без сохранения ее в промежуточные внешние переменные).

### 2. Иммутабельность в куче и оптимизация JIT-компилятора V8
Концепция иммутабельности гарантирует, что исходный массив на диске/в памяти остается нетронутым. Это критично для реактивных систем (таких как Angular Signals), которые сравнивают старые и новые состояния по физической ссылке в памяти (Shallow Comparison). Если ссылка не изменилась, Change Detection считает данные неизменными, предотвращая лишние перерисовки интерфейса.

**Оптимизация V8:**
Исторически ручные циклы `for` работали быстрее встроенных методов массивов. Однако современные JIT-компиляторы V8 выполняют глубокую оптимизацию (Inlining) для методов `.map()`, `.filter()` и `.reduce()`. Если массив является "плотным" (не содержит дыр) и имеет однородный скрытый класс объектов (Shape), компилятор преобразует цикл `.map()` в оптимизированные векторные машинные инструкции процессора, скорость выполнения которых сопоставима с нативными C++ циклами.

### 3. Детальный пошаговый разбор выполнения шаблона 2
1.  **Определение длины:** Вызывается функция `mapSourceToViewModel(serverItems)`. Движок V8 считывает `serverItems.length` (например, 100), выделяет память под новый массив `ViewModel[]` размером ровно 100 ячеек.
2.  **Инициация итераций:** Запускается внутренний цикл. Индекс `i` равен `0`.
3.  **Чтение и запуск:** Движок считывает `serverItems[0]`, передает этот объект аргументом в колбэк.
4.  **Сборка нового объекта:** Колбэк выполняется. Создается абсолютно новый объект в куче с ключами `id`, `text`, `displayDate`. 
5.  **Запись по индексу:** Ссылка на созданный объект записывается в ячейку `0` нового массива.
6.  **Завершение работы:** Процесс повторяется до `i === 99`. Итоговый массив возвращается из функции. Исходный массив `serverItems` и все его объекты в куче остались нетронутыми.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Случайная мутация объектов внутри `.map()` (Потеря иммутабельности)**
    *   *Проблема:* Разработчик пытается обновить свойство объекта внутри массива через `.map()`, но изменяет это свойство напрямую (например, `item.isActive = true`). Это приводит к тому, что оригинальный массив и его объекты мутируют в памяти, ломая предсказуемость состояния.
    *   *Причина:* Объекты в JavaScript передаются по ссылке. Переменная `item` внутри колбэка — это не копия, а прямая ссылка на объект в куче.
    *   *Решение:* При изменении свойств объектов всегда возвращайте новый объект, скопированный через spread-оператор `{ ...item }`.

```typescript
// ПЛОХО (Прямая мутация объекта ломает оригинальные данные)
export function markActiveUnsafe(items: ViewModel[]): ViewModel[] {
  return items.map(item => {
    // item.text = "modified"; // ! Мутирует оригинальный объект в куче по ссылке!
    return item;
  });
}

// ХОРОШО (Использование spread-копирования гарантирует иммутабельность)
export function markActiveSafe(items: ViewModel[]): ViewModel[] {
  return items.map(item => {
    return {
      ...item, // Копируем все свойства в новый объект
      text: "modified" // Безопасно переопределяем нужное свойство
    };
  });
}
```

*   **Ошибка 2: Отсутствие оператора `return` внутри колбэка**
    *   *Проблема:* Разработчик пишет тело функции-колбэка внутри скобок `{}`, но забывает написать ключевое слово `return`. В результате метод `.map()` возвращает массив, полностью состоящий из значений `undefined`.
    *   *Решение:* Если вы используете фигурные скобки `{}` в стрелочной функции, вы обязаны явно написать `return`. Если скобок нет, возврат значения происходит неявно (Implicit Return).

```typescript
// ПЛОХО (Забытый return вернет [undefined, undefined, ...])
export function getIdsUnsafe(items: ViewModel[]): string[] {
  // return items.map(item => { item.id; }); // ! На выходе массив undefined
  return [];
}

// ХОРОШО (Явный возврат или неявный стрелочный возврат)
export function getIdsSafe(items: ViewModel[]): string[] {
  return items.map(item => item.id); // Неявный возврат значения
}
```

*   **Ошибка 3: Использование `.map()` вместо `.forEach()` для побочных эффектов**
    *   *Проблема:* Использование `.map()` для запуска циклов, которые просто изменяют внешние переменные или вызывают функции, не возвращая новых данных. Это создает в памяти лишний, ненужный массив-пустышку, который нагружает Garbage Collector.
    *   *Решение:* Если вам не нужен результирующий трансформированный массив той же длины, всегда используйте метод `.forEach()` или классический цикл `for...of`.
