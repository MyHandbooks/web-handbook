# 1.3.1. Создание объектов через Object.create

## БЫСТРЫЙ СТАРТ

*   **`Object.create(proto, [propertiesObject])`** — статический метод, который создает новый пустой объект и явно связывает его с переданным объектом-прототипом через скрытую системную ссылку `[[Prototype]]`.
*   **Конструкторы не нужны:** Метод позволяет реализовать классическое прототипное наследование напрямую между объектами без использования функций-конструкторов или классов.
*   **Используйте `Object.create(null)` для:** создания абсолютно чистых словарей-карт (хранилищ данных), у которых нет прототипа. Они защищены от атак типа Prototype Pollution и случайных совпадений ключей с системными методами (например, `toString`).
*   **Не используйте:** для динамического изменения прототипов уже созданных объектов (через метод `Object.setPrototypeOf`), так как это ломает оптимизации компилятора V8 и сильно замедляет доступ к свойствам объекта.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Базовое прототипное наследование
*   **Назначение:** Наследование общих методов и свойств родительского объекта-чертежа без создания классов и накладных расходов.

```typescript
// Описание интерфейса родительского прототипа
export interface BasePrototype {
  activePrefix: string;
  generateLabel: (value: string) => string;
}

// Родительский объект, выступающий в роли прототипа-чертежа
export const parentTemplate: BasePrototype = {
  activePrefix: "BASE_TEMPLATE",
  generateLabel(value: string): string {
    // Метод использует контекст this, который сошлется на объект-потомок при вызове
    return `[${this.activePrefix}] Измененный: ${value}`;
  }
};

export function executePrototypeInheritance(): void {
  // Создаем дочерний объект, прототипом которого станет parentTemplate
  const childInstance = Object.create(parentTemplate);

  // Переопределяем (перекрываем) свойство родителя на уровне потомка (Property Shadowing)
  childInstance.activePrefix = "CHILD_INSTANCE";

  // Метод вызывается из родительского прототипа, но видит переопределенный activePrefix потомка
  const label = childInstance.generateLabel("payload_data");
  
  console.log(label); // Вывод: "[CHILD_INSTANCE] Измененный: payload_data"
}
```

### Шаблон 2: Создание объекта с тонкой настройкой дескрипторов
*   **Назначение:** Одновременное создание объекта, связывание его с прототипом и объявление защищенных, доступных только для чтения свойств.

```typescript
export interface TargetPayload {
  identifier: string;
  statePayload: string;
}

export function createProtectedObject(proto: object, uid: string, initialData: string): TargetPayload {
  // Создаем новый объект с прототипом proto и дескрипторами новых свойств
  return Object.create(proto, {
    identifier: {
      value: uid,
      writable: false,      // Свойство защищено от перезаписи
      enumerable: true,     // Свойство отображается в циклах и при сериализации в JSON
      configurable: false   // Запрещено удалять свойство или менять его дескрипторы
    },
    statePayload: {
      value: initialData,
      writable: true,       // Свойство разрешено перезаписывать
      enumerable: true,
      configurable: true
    }
  });
}
```

### Шаблон 3: Абсолютно чистый объект-словарь (кэш без прототипа)
*   **Назначение:** Создание безопасного хранилища данных, у которого полностью отсутствуют системные методы и свойства прототипа `Object.prototype`.

```typescript
export function createAbsoluteDictionary<T>(): Record<string, T> {
  // Передаем null в качестве прототипа. У объекта не будет свойства __proto__
  const cleanMap = Object.create(null);

  // Теперь объект защищен от атак Prototype Pollution. 
  // Ключи типа "toString" или "__proto__" будут трактоваться как обычные строки-данные, 
  // не ломая встроенные методы объекта.
  return cleanMap;
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как устроен скрытый системный слот `[[Prototype]]` в V8
В оперативной памяти каждый объект в JavaScript имеет скрытое системное свойство — **`[[Prototype]]`**. Метод `Object.create(proto)` записывает переданную ссылку на объект `proto` непосредственно в этот скрытый слот нового объекта.

Алгоритм поиска свойств при чтении (Property Lookup):
1.  Движок пытается найти свойство среди собственных ключей самого объекта (в локальной памяти).
2.  Если свойство отсутствует, движок обращается к системному слоту `[[Prototype]]` и переходит к объекту-прототипу.
3.  Поиск продолжается рекурсивно вверх по цепочке прототипов (`Prototype Chain`) до тех пор, пока не встретит `Object.prototype`, а затем `null`. Если свойство так и не найдено, возвращается `undefined`.

Алгоритм записи свойств (Property Shadowing):
*   Если мы записываем свойство (например, `child.activePrefix = "new"`), движок **никогда не изменяет родительский прототип**.
*   Вместо этого он создает новое собственное свойство с именем `activePrefix` прямо на объекте `child`. При последующем чтении это локальное свойство перекроет (затенит) одноименное свойство родителя. Это защищает общие чертежи-прототипы от случайных мутаций со стороны отдельных потомков.

### 2. Почему `Object.create(null)` производительнее и безопаснее обычного `{}` для кэшей
Когда вы объявляете обычный объект через литерал `const map = {}`, он неявно наследует свойства класса `Object.prototype` (такие как `toString`, `hasOwnProperty`, `constructor`).

Это несет в себе две критические проблемы:
1.  **Уязвимость Prototype Pollution:** Если внешние невалидированные данные содержат ключ `__proto__`, злоумышленник может перезаписать методы прототипа базового класса, изменив поведение всей программы.
2.  **Конфликт ключей:** Если в ваш кэш придут данные от пользователя с ключом `"toString"`, вызов `map["toString"]` вернет системную функцию, а не ваши данные.

Объект, созданный через `Object.create(null)`, полностью лишен прототипа. Он не имеет методов, не наследует ничего и является абсолютно пустым контейнером в оперативной памяти. Для V8 такой объект является идеальным плоским словарем, доступ к ключам которого оптимизирован на уровне хэш-таблиц процессора без накладных расходов на обход цепочки прототипов.

### 3. Детальный пошаговый разбор выполнения шаблона 2
1.  **Вызов метода:** Вызывается функция `createProtectedObject(parentTemplate, "u_99", "start")`.
2.  **Выделение памяти:** Метод `Object.create` выделяет память под новый пустой объект в куче.
3.  **Связывание прототипа:** Ссылка на `parentTemplate` записывается в скрытый слот `[[Prototype]]` нового объекта.
4.  **Применение дескрипторов:** Движок V8 берет объект свойств. Он создает на новом объекте ключ `identifier` и жестко блокирует для него флаг `writable: false`. Затем создает ключ `statePayload` с флагом `writable: true`.
5.  **Возврат результата:** Полностью сконфигурированный объект возвращается наружу.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Попытка использовать методы `Object.prototype` на чистых словарях `Object.create(null)`**
    *   *Проблема:* Разработчик создает чистый словарь и пытается проверить наличие ключа через `map.hasOwnProperty("key")`. Программа падает с ошибкой `TypeError`.
    *   *Причина:* У чистого объекта нет прототипа, а значит, у него отсутствует и метод `hasOwnProperty`.
    *   *Решение:* Вызывайте оригинальный метод из прототипа базового класса в контексте вашего чистого объекта.

```typescript
// ПЛОХО (Вызов метода вызовет падение)
const badMap = Object.create(null);
badMap.data = "payload";
// badMap.hasOwnProperty("data"); // ! TypeError: badMap.hasOwnProperty is not a function

// ХОРОШО (Безопасный вызов метода из базового прототипа через call)
const goodMap = Object.create(null);
goodMap.data = "payload";
const hasKey = Object.prototype.hasOwnProperty.call(goodMap, "data"); // Вернет true
console.log(hasKey);
```

*   **Ошибка 2: Мутация объектов внутри прототипа**
    *   *Проблема:* Родительский прототип содержит свойство, являющееся сложным объектом или массивом (например, `items: []`). Потомок пытается добавить элемент в этот массив (`child.items.push(x)`). Из-за этого массив изменяется **у всех потомков сразу**.
    *   *Причина:* Метод `.push()` не перезаписывает саму ссылку на массив, а мутирует структуру в куче. Поскольку ссылка на массив общая для прототипа и потомков, происходит непреднамеренное изменение родительского состояния.
    *   *Решение:* Избегайте хранения изменяемых сложных объектов внутри прототипов. Если это необходимо, перезаписывайте ссылку на массив целиком на уровне потомка.

```typescript
// ПЛОХО (Мутация общего массива в прототипе ломает состояние всех потомков)
const protoWithList = { items: [] as string[] };
const childA = Object.create(protoWithList);
const childB = Object.create(protoWithList);

childA.items.push("data_A"); // Мутирует массив в куче по общей ссылке
console.log(childB.items); // Вывод: ["data_A"] (Данные утекли ко второму потомку!)

// ХОРОШО (Иммутабельное переопределение ссылки на уровне потомка)
const protoFixed = { items: [] as string[] };
const childC = Object.create(protoFixed);
const childD = Object.create(protoFixed);

childC.items = [...childC.items, "data_C"]; // Создаем новый массив на уровне childC
console.log(childD.items); // Вывод: [] (Прототип чист, данные в безопасности)
```

*   **Ошибка 3: Динамическое изменение прототипа через `__proto__`**
    *   *Проблема:* Изменение прототипа уже существующего объекта во время выполнения программы через `obj.__proto__ = newProto`. Код работает крайне медленно.
    *   *Причина:* Современные JIT-компиляторы V8 создают скрытые оптимизированные классы (Shapes/Hidden Classes) для объектов на основе их прототипной структуры. Динамическая смена прототипа полностью ломает эти скрытые классы, переводя доступ к свойствам объекта в медленный режим словаря.
    *   *Решение:* Всегда задавайте прототип объекта один раз в момент его создания через `Object.create()`.
