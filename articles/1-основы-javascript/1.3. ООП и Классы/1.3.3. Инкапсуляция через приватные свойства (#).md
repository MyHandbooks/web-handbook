# 1.3.3. Инкапсуляция через приватные свойства (#)

## БЫСТРЫЙ СТАРТ

*   **Приватные свойства (`#`)** — это нативный механизм сокрытия данных внутри классов JavaScript (ES2020), префикс которых начинается строго с символа решетки `#`.
*   **Истинная изоляция (Runtime Enforced):** Доступ к приватным свойствам жестко заблокирован на уровне движка браузера. Их невозможно прочитать, изменить, удалить или получить через цикл перебора свойств извне класса.
*   **TypeScript `private` против `#`:** TypeScript-модификатор `private` стирается после компиляции в чистый JavaScript, делая свойство публичным в рантайме. Приватность через `#` полностью сохраняется после сборки и компиляции.
*   **Используйте приватные свойства для:** защиты конфиденциальных внутренних данных (ключей, хэшей, состояний) и инкапсуляции служебных вспомогательных методов класса.
*   **Не используйте:** динамический синтаксис (вроде `this['#property']`) — попытка динамического обращения к приватным полям через квадратные скобки всегда вызовет синтаксическую ошибку на этапе компиляции.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Базовое сокрытие данных и методов через `#`
*   **Назначение:** Ограничение доступа к внутреннему состоянию и служебным методам класса от неконтролируемого изменения извне.

```typescript
export interface TargetPayload {
  identifier: string;
  statePayload: string;
}

export class TaskRunner {
  // 1. Декларируем приватное свойство на уровне класса
  #activeToken: string;

  constructor(token: string) {
    // Инициализируем приватное поле внутри конструктора
    this.#activeToken = token; 
  }

  // 2. Объявляем приватный служебный метод
  #validateToken(): boolean {
    // Внутренний метод имеет полный доступ к приватным свойствам класса
    return this.#activeToken.startsWith("SECURE_");
  }

  public runTask(payload: TargetPayload): void {
    // Публичный метод безопасно вызывает приватную логику проверки
    if (this.#validateToken()) {
      console.log(`[УСПЕХ] Выполнение задачи: ${payload.identifier}`);
    } else {
      console.error("[ОТКАЗ] Невалидный авторизационный токен.");
    }
  }
}
```

### Шаблон 2: Инкапсуляция с использованием геттеров и сеттеров (get & set)
*   **Назначение:** Контроль записи и форматирования данных при чтении приватного свойства с помощью встроенных рантайм-валидаций.

```typescript
export class DataStateController {
  // Локальный приватный буфер данных
  #bufferSize: number = 0;

  // Геттер для безопасного чтения значения извне
  public get bufferSize(): number {
    return this.#bufferSize;
  }

  // Сеттер с жесткой валидацией входящих данных перед записью
  public set bufferSize(value: number) {
    if (value < 0) {
      console.error("Критическая ошибка: Размер буфера не может быть меньше 0.");
      return;
    }
    // Запись разрешена только после успешного прохождения бизнес-правил
    this.#bufferSize = value; 
  }
}
```

### Шаблон 3: Совместное использование TS-модификатора `private` и нативного `#`
*   **Назначение:** Понимание разницы между архитектурной защитой TypeScript и физической защитой рантайма JavaScript при создании классов.

```typescript
export class ConfigurationSecureManager {
  // TypeScript private: Защищает от случайных вызовов другими разработчиками на этапе написания кода.
  // После компиляции в JS превратится в обычное публичное свойство.
  private tsProtectedSecret: string = "ts_only_lock";

  // Нативное приватное свойство #: Физически защищено движком браузера во время выполнения.
  #jsRuntimeSecret: string = "js_runtime_lock";

  public exportSecrets(): void {
    // Внутри класса оба свойства доступны для чтения
    console.log(this.tsProtectedSecret, this.#jsRuntimeSecret);
  }
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Как приватные свойства с решеткой (`#`) устроены в движке V8
Наличие приватных полей полностью меняет привычную модель объектов JavaScript, где свойства хранятся в виде динамических хэш-таблиц. 

Когда движок V8 компилирует класс с приватным полем `#activeToken`, он не добавляет этот ключ в стандартную цепочку дескрипторов свойств объекта. Вместо этого V8 реализует одну из двух стратегий под капом:

1.  **WeakMap-модель (Слабые ассоциативные карты):**
    Для каждого приватного поля движок создает невидимую изолированную коллекцию `WeakMap` внутри замыкания класса. Ключом в этой карте выступает ссылка на сам экземпляр класса `this`, а значением — значение приватного свойства.
    При выполнении `this.#activeToken` движок тайно выполняет операцию `activeTokenWeakMap.get(this)`. Поскольку `WeakMap` скрыта от внешнего контекста выполнения, прочитать данные из нее снаружи физически невозможно.
2.  **Brand-Checking (Проверка метки бренда):**
    При доступе к `#activeToken` движок проверяет, помечен ли текущий объект-экземпляр специальной скрытой системной меткой-брендом этого класса. Если метка отсутствует (например, если мы пытаемся одолжить метод через `call` для обычного объекта), V8 немедленно выбрасывает `TypeError`.

Благодаря этому синтаксический анализатор V8 может оптимизировать доступ к приватным полям на уровне машинных кодов, зная, что структура этих свойств никогда не изменится динамически из внешнего кода.

### 2. Сравнение TypeScript `private` и нативного `#`
*   **Модификатор `private` в TS:** Это концепция уровня компилятора (Design-Time). Он нужен для статического анализатора кода, чтобы подсветить ошибку в IDE, если вы пытаетесь прочитать свойство извне. Но после компиляции в JS (файлы `.js`) модификатор стирается. Свойство становится обычным полем, доступным через `obj.tsProtectedSecret` или при переборе через `for...in`.
*   **Синтаксис `#`:** Это концепция уровня спецификации ECMAScript (Runtime). Физическая защита выполняется движком JavaScript во время работы приложения. Свойство невозможно обнаружить через методы `Object.keys()`, `Object.getOwnPropertyNames()` или проксировать без специальных ухищрений.

### 3. Детальный пошаговый разбор выполнения шаблона 2
1.  **Инстанцирование:** Создается объект `const controller = new DataStateController()`. Движок V8 выделяет память под экземпляр класса и тайно вешает на него бренд-метку класса `DataStateController`.
2.  **Запись через сеттер:** Выполняется `controller.bufferSize = 256`. Программа натыкается на вызов публичного сеттера `set bufferSize(value)`.
3.  **Валидация:** Поток выполнения переходит в тело сеттера. Происходит валидация `value < 0` (проверка успешна).
4.  **Скрытая запись:** Выполняется `this.#bufferSize = value`. Движок V8 проверяет бренд-метку объекта `this`. Проверка успешна. Движок записывает значение `256` в скрытый системный слот объекта, связанный с `#bufferSize`.
5.  **Попытка взлома:** Попытка выполнить `controller.#bufferSize = -100` из внешнего скрипта приводит к тому, что парсер браузера выдает `SyntaxError` еще на этапе разбора файла — приложение даже не запустится.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Попытка динамического доступа к приватным полям через квадратные скобки**
    *   *Проблема:* Разработчик пытается прочитать приватное свойство динамически, используя строковый ключ в квадратных скобках (например, `this['#activeToken']`). Код возвращает `undefined` или падает.
    *   *Причина:* Динамический доступ к приватным свойствам запрещен спецификацией языка. Приватные поля не добавляются в стандартный хэш-словарь свойств объекта. Ссылки на них разрешены только статически через явный синтаксис `this.#fieldName`.
    *   *Решение:* Если вам нужен динамический доступ по строковым ключам, используйте обычные публичные или защищенные свойства со знаком подчеркивания `_`.

```typescript
// ПЛОХО (Динамический доступ вернет undefined)
export class DynamicSecureUnsafe {
  #secret = "private_data";
  public readSecretDynamically(key: string): any {
    // return this[key]; // ! TypeScript подсветит ошибку, JS вернет undefined
  }
}
```

*   **Ошибка 2: Проблема одалживания методов класса с приватными полями (Brand Check Failure)**
    *   *Проблема:* Разработчик одалживает публичный метод класса через `.call()` для обычного литерального объекта (например, `processor.runTask.call({ db: 'mock' })`). Метод падает с критической ошибкой `TypeError`.
    *   *Причина:* Внутри публичного метода происходит обращение к приватному полю `#activeToken`. Движок V8 проверяет бренд-метку на переданном объекте-контексте, не находит её и немедленно блокирует выполнение.
    *   *Решение:* Не используйте Method Borrowing (одалживание методов) для классов, содержащих приватные поля, либо проверяйте соответствие объекта классу через оператор `instanceof` или оператор `in` (например, `#activeToken in targetObject`).

```typescript
// ПЛОХО (Brand Check падает при попытке подменить контекст на невалидный объект)
export class Processor {
  #secret = "secured";
  public log() { console.log(this.#secret); }
}
const proc = new Processor();
// proc.log.call({ value: "fake" }); // ! TypeError: Cannot read private member #secret from an object whose class did not declare it
```

*   **Ошибка 3: Потеря приватности при деструктуризации полей**
    *   *Проблема:* Попытка выполнить деструктуризацию приватного поля класса напрямую из внешнего кода. Это вызовет ошибку на этапе синтаксического разбора.
    *   *Решение:* Извлекайте приватные данные только через вызовы публичных методов или геттеров класса.

```typescript
// ПЛОХО (Деструктуризация приватных полей запрещена синтаксисом)
export class SafeStore {
  #token = "api_key";
}
const store = new SafeStore();
// const { #token } = store; // ! SyntaxError: Private fields can't be destructured
```
