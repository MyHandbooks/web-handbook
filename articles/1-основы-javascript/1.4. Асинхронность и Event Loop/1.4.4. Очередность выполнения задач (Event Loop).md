# 1.4.4. Очередность выполнения задач (Event Loop)

## БЫСТРЫЙ СТАРТ

*   **Событийный цикл (Event Loop)** — это встроенный механизм браузера, который координирует работу однопоточного JavaScript, распределяя выполнение синхронного кода, микрозадач, макрозадач и отрисовку интерфейса.
*   **Синхронный код** — выполняется в первую очередь в Стек вызовов (Call Stack) до полного его опустошения.
*   **Микрозадачи (`Promise`, `queueMicrotask`)** — имеют наивысший приоритет среди асинхронных тасок. Очередь микрозадач должна быть **вычищена абсолютно полностью** перед тем, как браузер перейдет к рендерингу или следующей макрозадаче.
*   **Макрозадачи (`setTimeout`, `setInterval`, события DOM)** — выполняются по принципу «одна задача за один цикл». После выполнения одной макрозадачи событийный цикл прерывается для очистки вновь скопившихся микрозадач и рендеринга.
*   **requestAnimationFrame (rAF)** — специальная очередь для выполнения кода, связанного со стилями и анимациями, запускаемая строго перед фазой отрисовки экрана (Repaint).

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Чанкование (разделение) тяжелых синхронных вычислений
*   **Назначение:** Разделение длительного синхронного процесса на мелкие части (чанки) с планированием их через макрозадачи (`setTimeout`), чтобы дать браузеру возможность плавно перерисовывать экран в паузах.

```typescript
export interface ExecutionState {
  currentIteration: number;
  totalLimit: number;
  chunkSize: number;
}

export function executeHeavyProcessAsync(state: ExecutionState, onProgress: (percent: number) => void): void {
  const endLimit = Math.min(state.currentIteration + state.chunkSize, state.totalLimit);

  // Выполняем небольшую часть работы (чанк) синхронно в Call Stack
  for (; state.currentIteration < endLimit; state.currentIteration++) {
    const temporaryResult = Math.sqrt(state.currentIteration) * Math.sin(state.currentIteration);
    // Симулируем легкую фиксацию результата вычислений
    if (temporaryResult < -100) console.log("Критическое смещение");
  }

  // Вычисляем и отдаем процент прогресса
  const progressPercent = Math.round((state.currentIteration / state.totalLimit) * 100);
  onProgress(progressPercent);

  if (state.currentIteration < state.totalLimit) {
    // Регистрируем следующую итерацию (чанк) как МАКРОЗАДАЧУ с нулевой задержкой
    // В паузах между макрозадачами браузер успеет выполнить рендеринг прогресс-бара
    setTimeout(() => executeHeavyProcessAsync(state, onProgress), 0);
  } else {
    console.log("Тяжелые вычисления успешно завершены без зависания интерфейса.");
  }
}
```

### Шаблон 2: Принудительное планирование микрозадачи через `queueMicrotask()`
*   **Назначение:** Планирование легковесной асинхронной задачи, которая должна гарантированно выполниться сразу после текущего синхронного кода, но строго до перерисовки экрана и макрозадач.

```typescript
export interface DataPayload {
  identifier: string;
  statePayload: string;
}

export function processImmediateBatch(payload: DataPayload): void {
  console.log("1. Начало синхронного процесса инициализации...");

  // Планируем микрозадачу вручную в обход конструктора Promise
  queueMicrotask(() => {
    // Выполнится во вторую очередь, сразу после очистки Call Stack
    console.log(`3. [МИКРОЗАДАЧА] Быстрая обработка пакета: ${payload.identifier}`);
  });

  // Планируем макрозадачу для сравнения
  setTimeout(() => {
    // Выполнится в последнюю очередь, после микрозадач и шага отрисовки экрана
    console.log("4. [МАКРОЗАДАЧА] Фоновый таймер сработал.");
  }, 0);

  console.log("2. Завершение синхронного процесса инициализации.");
}
```

### Шаблон 3: Оптимизация анимации через `requestAnimationFrame`
*   **Назначение:** Декларативное управление стилями или позиционированием элементов синхронно с частотой обновления экрана монитора (обычно 60Гц/120Гц).

```typescript
export interface AnimationState {
  startPosition: number;
  currentPosition: number;
  targetPosition: number;
}

export function animateElementShift(element: HTMLElement, state: AnimationState): void {
  // Вычисляем шаг смещения
  state.currentPosition += (state.targetPosition - state.currentPosition) * 0.1;

  // Изменяем стили элемента безопасно для рендеринга
  element.style.transform = `translateX(${state.currentPosition}px)`;

  // Проверяем, достигнута ли цель анимации с погрешностью
  if (Math.abs(state.targetPosition - state.currentPosition) > 0.5) {
    // Планируем следующий кадр анимации строго в очередь рендеринга браузера
    requestAnimationFrame(() => animateElementShift(element, state));
  } else {
    console.log("Анимация успешно завершена.");
  }
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Архитектура событийного цикла (Event Loop) в браузере
Браузерная среда выполнения — это многопоточная система, но сам движок JavaScript работает только в одном, главном потоке. 

Event Loop координирует взаимодействие следующих системных компонентов:
1.  **Call Stack (Стек вызовов):** Структура данных LIFO (Last In, First Out). Сюда попадают все синхронно выполняемые функции. Пока Стек вызовов не пуст, событийный цикл полностью заблокирован и ожидает.
2.  **Web APIs:** Фоновые потоки браузера, предоставляемые хост-средой. Они выполняют отсчет таймеров (`setTimeout`), слушают сетевые сокеты или события мыши параллельно с основным потоком.
3.  **Очередь микрозадач (Microtask Queue):** Очередь с наивысшим приоритетом. Сюда попадают колбэки промисов (`.then`, `.catch`), вызовы `queueMicrotask` и MutationObserver.
4.  **Очередь макрозадач (Macrotask Queue):** Очередь событий ввода-вывода, таймеров и сообщений.
5.  **Render Queue (Очередь отрисовки):** Очередь задач по пересчету стилей (Recalculate Style), компоновке макета (Layout) и физической отрисовке пикселей на экране (Paint). Запускается браузером периодически (обычно каждые 16.6 мс для экранов 60 Гц).

### 2. Приоритеты выполнения: Микрозадачи против Макрозадач
Событийный цикл работает по строгому бесконечному циклу. Шаги выполнения одного прохода (Tick):

*   **Шаг 1: Макрозадача.** Из очереди макрозадач извлекается и выполняется **ровно одна** старейшая макрозадача. На старте страницы этой задачей является сам файл скрипта (main script).
*   **Шаг 2: Полная очистка микрозадач.** Движок переходит к очереди микрозадач. Он выполняет их одну за другой до тех пор, пока очередь не станет **абсолютно пустой**. 
    *   *Критическая деталь:* Если в процессе выполнения микрозадачи планируется новая микрозадача, она добавляется в конец этой же очереди и выполняется в рамках этого же текущего цикла (шага).
*   **Шаг 3: Отрисовка (Render).** Браузер проверяет, нужно ли обновить кадр на экране. Если да, выполняются задачи из `requestAnimationFrame`, затем пересчитываются геометрические размеры элементов (Layout) и происходит физическая перерисовка пикселей (Paint).
*   **Шаг 4: Ожидание.** Событийный цикл переходит в начало и ожидает появления новых задач.

### 3. Детальный пошаговый разбор выполнения шаблона 2
1.  **Синхронный старт:** Вызывается функция `processImmediateBatch`. В Call Stack попадает строка `console.log("1...")` и немедленно выводится на экран.
2.  **Планирование микрозадачи:** Инструкция `queueMicrotask` отправляет переданный колбэк в `Microtask Queue`. Физического выполнения не происходит.
3.  **Регистрация макрозадачи:** Инструкция `setTimeout` регистрирует таймер в Web APIs. Браузер сразу же перемещает колбэк таймера в конец `Macrotask Queue`.
4.  **Синхронный финиш:** Выполняется строка `console.log("2...")` и выводится на экран. Call Stack пуст.
5.  **Очистка микрозадач:** Event Loop видит пустой Call Stack и сразу переходит к `Microtask Queue`. Извлекается микрозадача и выводит `"3. [МИКРОЗАДАЧА]..."`. Очередь микрозадач пуста.
6.  **Выполнение макрозадачи:** Event Loop переходит к очереди макрозадач, извлекает колбэк таймера и запускает его. Выводится строка `"4. [МАКРОЗАДАЧА]..."`. Цикл завершен.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Бесконечный цикл рекурсивных микрозадач (Зависание страницы)**
    *   *Проблема:* Разработчик запускает рекурсивный вызов функции через `queueMicrotask` или бесконечный цикл промисов. Вкладка браузера мгновенно замерзает, не реагируя на клики, скролл и движения мыши.
    *   *Причина:* Очередь микрозадач обязана быть вычищена полностью. Поскольку рекурсивные микрозадачи бесконечно добавляют новые элементы в текущую очередь, событийный цикл застревает на шаге 2 и физически не может перейти к шагу рендеринга экрана (Render Queue) и обработки событий ввода-вывода (макрозадач).
    *   *Решение:* Для периодических тяжелых фоновых задач всегда используйте планирование через макрозадачи (`setTimeout` или `requestIdleCallback`).

```typescript
// ПЛОХО (Намертво повесит вкладку браузера)
export function runInfiniteMicrotaskLoop(): void {
  queueMicrotask(() => {
    runInfiniteMicrotaskLoop(); // Рекурсия микрозадач заблокирует Render
  });
}

// ХОРОШО (Использование макрозадачи дает браузеру делать рендеринг между итерациями)
export function runSafeLoop(): void {
  setTimeout(() => {
    runSafeLoop(); // Браузер успеет перерисовать экран перед следующим вызовом
  }, 0);
}
```

*   **Ошибка 2: Layout Thrashing (Вынужденный синхронный макет) внутри requestAnimationFrame**
    *   *Проблема:* Разработчик пытается читать геометрические размеры элементов (`element.offsetHeight`) сразу после их изменения внутри анимационного кадра. Анимация начинает дергаться и тормозить.
    *   *Причина:* Когда вы меняете стиль, браузер помечает разметку грязной. Если на следующей строчке вы пытаетесь прочитать размер, браузер вынужден экстренно остановить выполнение JS, выполнить тяжелый пересчет геометрии макета (Layout) прямо сейчас во время работы скрипта, а не на фазе Render.
    *   *Решение:* Разделяйте фазы чтения и записи стилей. Сначала считывайте все нужные размеры у всех элементов разом, и только затем изменяйте стили.

```typescript
// ПЛОХО (Вынуждает браузер делать Layout на каждой итерации цикла)
export function mutateDOMUnsafe(elements: HTMLElement[]): void {
  elements.forEach(el => {
    const width = el.offsetWidth; // Чтение
    el.style.width = `${width + 10}px`; // Запись (Ломает макет)
  });
}

// ХОРОШО (Сначала читаем все размеры, затем изменяем стили)
export function mutateDOMSafe(elements: HTMLElement[]): void {
  // Сначала считываем все геометрические размеры без изменений DOM
  const widths = elements.map(el => el.offsetWidth);
  // Затем применяем изменения за один проход рендеринга
  elements.forEach((el, index) => {
    el.style.width = `${widths[index] + 10}px`;
  });
}
```

*   **Ошибка 3: Блокировка главного потока тяжелыми синхронными циклами**
    *   *Проблема:* Выполнение сложного математического расчета в один проход (более 100-200 мс). Пользователь видит "фриз" интерфейса, кнопки не нажимаются.
    *   *Решение:* Разбивайте вычисления на мелкие части (чанки) с планированием их через `setTimeout(f, 0)` (как показано в Шаблоне 1) или выносите весь расчет во вспомогательный фоновый поток Web Worker.
