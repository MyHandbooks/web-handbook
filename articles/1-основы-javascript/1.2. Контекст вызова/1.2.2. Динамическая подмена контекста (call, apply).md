# 1.2.2. Динамическая подмена контекста (call, apply)

## БЫСТРЫЙ СТАРТ

*   **Динамическая подмена контекста** — это механизм принудительного запуска функции в контексте определенного объекта. В отличие от метода `.bind()`, методы `.call()` и `.apply()` не создают копию функции, а **вызывают её немедленно**.
*   **Метод `.call()`** — передает аргументы в вызываемую функцию **по отдельности, через запятую** (списком).
*   **Метод `.apply()`** — передает аргументы в вызываемую функцию **в виде единого массива**.
*   **Используйте их для:** одалживания методов у других объектов (Method Borrowing) или выполнения обобщенных служебных функций над нетипизированными структурами данных.
*   **Не используйте их:** на стрелочных функциях (они полностью игнорируют подмену контекста) и в высоконагруженных циклах, где производительность критически важна (вызов через `.call`/`.apply` медленнее обычного вызова метода).

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Явный вызов со списком аргументов через `.call()`
*   **Назначение:** Немедленное выполнение внешней обобщенной утилитарной функции в контексте конкретного изолированного объекта.

```typescript
// Описание структуры целевого контекста
export interface TargetPayload {
  identifier: string;
  statePayload: string;
}

// Обобщенная функция, ожидающая контекст типа TargetPayload
// Использование this в параметрах TypeScript гарантирует строгую проверку типов на этапе компиляции
export function formatDataState(this: TargetPayload, prefix: string, suffix: string): string {
  // Читаем свойства из динамического контекста this
  return `${prefix}_${this.identifier}_${this.statePayload}_${suffix}`;
}

export function executeCallExample(): void {
  const activeRecord: TargetPayload = {
    identifier: "record_404",
    statePayload: "connection_error"
  };

  // Вызываем функцию formatDataState немедленно
  // Первым параметром передаем объект контекста, далее — аргументы функции через запятую
  const resultString = formatDataState.call(activeRecord, "SYS", "WARN");
  
  console.log(resultString); // Вывод: "SYS_record_404_connection_error_WARN"
}
```

### Шаблон 2: Вызов с передачей массива аргументов через `.apply()`
*   **Назначение:** Выполнение функции в контексте объекта, когда аргументы для нее вычисляются динамически и хранятся в виде массива.

```typescript
export interface DataState {
  multiplier: number;
}

export function calculateAggregatedValue(this: DataState, baseOffset: number, correctionFactor: number): number {
  // Вычисляем значение, используя контекст и аргументы
  return (baseOffset + correctionFactor) * this.multiplier;
}

export function executeApplyExample(): void {
  const currentMetric: DataState = {
    multiplier: 1.5
  };

  // Аргументы подготовлены динамически в виде массива
  const calculatedArgs: [number, number] = [100, 10];

  // Вызываем функцию с передачей контекста и массива аргументов
  // V8 автоматически распакует массив и передаст элементы как отдельные параметры
  const totalScore = calculateAggregatedValue.apply(currentMetric, calculatedArgs);

  console.log(totalScore); // Вывод: 165
}
```

### Шаблон 3: Одалживание методов (Method Borrowing)
*   **Назначение:** Использование готового сложного метода одного класса для обработки данных другого объекта, не связанного с ним узами наследования.

```typescript
export interface TemporaryResult {
  records: string[];
}

export class DataLogger {
  constructor(private prefix: string) {}

  public printList(this: { prefix: string }, data: string[]): void {
    data.forEach(item => {
      console.log(`[${this.prefix}] Запись: ${item}`);
    });
  }
}

export function executeBorrowingExample(): void {
  // Объект не является экземпляром класса DataLogger, но имеет схожую структуру контекста
  const adHocLogger = { prefix: "TEMP_AD_HOC" };
  const logsToPrint = ["session_start", "handshake_ok"];

  const baseLogger = new DataLogger("SYSTEM");

  // Одалживаем метод printList у экземпляра baseLogger
  // Запускаем его в контексте легковесного объекта adHocLogger
  baseLogger.printList.call(adHocLogger, logsToPrint);
  // Вывод в консоль:
  // "[TEMP_AD_HOC] Запись: session_start"
  // "[TEMP_AD_HOC] Запись: handshake_ok"
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Низкоуровневая разница между call, apply и bind в V8
На уровне системного рантайма и спецификации ECMAScript все функции в JavaScript являются объектами, унаследованными от системного класса `Function.prototype`. Методы `.call()`, `.apply()` и `.bind()` физически объявлены внутри этого прототипа.

Главная разница между ними заключается в логике выполнения:
*   **`bind()` (Ленивое связывание):** Создает и возвращает новый экзотический объект функции (Bound Function Exotic Object). Внутренние слоты этого объекта хранят ссылки на исходную функцию и жестко привязанный контекст. Физического вызова не происходит до тех пор, пока созданная функция не будет запущена в коде.
*   **`call()` и `apply()` (Немедленное выполнение):** Эти методы инициируют немедленный запуск функции. Они временно подменяют контекст выполнения в текущем кадре стека вызовов (`Execution Context Stack`) на переданный объект и передают управление интерпретатору. После завершения работы функции исходный контекст кадра стека восстанавливается.

### 2. Спецификация передачи аргументов и оптимизация V8
*   **Метод `.call()`** работает быстрее в старых версиях JS-движков, так как его аргументы сопоставляются со стеком вызовов напрямую один к одному на этапе разбора AST.
*   **Метод `.apply()`** требует от движка выполнения дополнительной работы. Перед тем как запустить функцию, движок V8 обязан проитерироваться по переданному массиву аргументов, выделить память в стеке под каждый элемент и скопировать туда значения. 
*   **Современный синтаксис Spread (`...`):** В современном JavaScript вызов `func.call(context, ...args)` практически полностью заменяет `.apply()`. Современные JIT-компиляторы оптимизируют spread-оператор на лету, превращая его в эффективный низкоуровневый массив инструкций процессора. По производительности этот подход равен или превосходит `.apply()`, являясь при этом более читаемым и типобезопасным.

### 3. Детальный пошаговый разбор выполнения шаблона 3
1.  **Создание контекстов:** Создаются два объекта: экземпляр класса `baseLogger` с внутренним свойством `prefix: "SYSTEM"` и литеральный объект `adHocLogger` со свойством `prefix: "TEMP_AD_HOC"`.
2.  **Запрос метода:** Программа обращается к свойству `baseLogger.printList`. Движок V8 находит функцию `printList` в прототипе класса `DataLogger`.
3.  **Вызов `.call()`:** Выполняется вызов `.call(adHocLogger, logsToPrint)`. Движок V8 приостанавливает выполнение текущего кадра, создает новый Execution Context для функции `printList`.
4.  **Подмена `this`:** Движок V8 записывает ссылку на объект `adHocLogger` во внутренний регистр `this` нового кадра выполнения, полностью игнорируя тот факт, что метод принадлежит объекту `baseLogger`.
5.  **Выполнение:** Функция `printList` считывает свойство `this.prefix`. Поскольку в `this` записан `adHocLogger`, на экран выводится значение `"TEMP_AD_HOC"`. После завершения работы функции кадр ее стека уничтожается, освобождая ресурсы.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Подмена контекста на стрелочных функциях**
    *   *Проблема:* Разработчик пытается динамически изменить контекст выполнения стрелочной функции через `.call()` или `.apply()`. Вызов отрабатывает без ошибок, но контекст игнорируется, и функция продолжает считывать данные из внешнего лексического окружения, где была создана.
    *   *Причина:* По спецификации у стрелочных функций нет своего `this`, их контекст лексический и жестко зафиксирован в момент объявления.
    *   *Решение:* Перепишите функцию как обычную (regular function), если предполагается динамическая подмена контекста.

```typescript
// ПЛОХО (Вызов через .call никак не повлияет на стрелочную функцию)
const badContext = { value: "isolated" };
const badArrow = () => console.log(this.value); // Считывает глобальный window.value
badArrow.call(badContext); // Выведет: undefined (или глобальное значение)

// ХОРОШО (Обычная функция успешно принимает новый контекст)
const goodContext = { value: "isolated" };
const goodFunc = function(this: typeof goodContext) { console.log(this.value); };
goodFunc.call(goodContext); // Успешно выведет: "isolated"
```

*   **Ошибка 2: Одалживание методов без учета внутренней структуры зависимостей**
    *   *Проблема:* Разработчик одалживает метод у класса `ClassA` для объекта `ObjectB`, но забывает, что этот метод обращается к другим методам или свойствам `ClassA` (например, `this.helperMethod()`), которых нет на объекте `ObjectB`. Это приводит к падению программы с ошибкой `TypeError`.
    *   *Решение:* Проверяйте, что целевой объект-контекст полностью реализует все интерфейсы, свойства и методы, к которым обращается одалживаемая функция.

```typescript
// ПЛОХО (Одалживание метода ломает программу, так как helper() отсутствует)
export class Processor {
  public helper() { return 10; }
  public compute(this: Processor, x: number) { return x + this.helper(); }
}
const badObject = { value: 5 };
// const res = Processor.prototype.compute.call(badObject, 2); // ! TypeError: this.helper is not a function
```

*   **Ошибка 3: Передача `null` или `undefined` в качестве контекста в нестрогом режиме**
    *   *Проблема:* Если в `.call()` или `.apply()` передать `null` или `undefined` в качестве первого аргумента (например, когда контекст не важен), в обычном нестрогом режиме (sloppy mode) V8 автоматически заменит его на глобальный объект `window`. Это приводит к случайному изменению глобальных переменных.
    *   *Решение:* Всегда пишите код в строгом режиме `"use strict"` (в TypeScript он включен по умолчанию). В строгом режиме передача `null`/`undefined` запишет в `this` именно `null`/`undefined`, защищая глобальную память.

```typescript
// ПЛОХО (В нестрогом режиме перезапишет window.dataState)
function modifyGlobal(this: any, val: string) {
  this.dataState = val; // В sloppy mode создаст глобальную переменную window.dataState!
}
// modifyGlobal.call(null, "broken"); 
```
