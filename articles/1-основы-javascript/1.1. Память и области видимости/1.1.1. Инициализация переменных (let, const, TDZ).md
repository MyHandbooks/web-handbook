# 1.1.1. Инициализация переменных (let, const, TDZ)

## БЫСТРЫЙ СТАРТ

*   **`const`** — Объявляет константу (ссылку на область памяти). Саму переменную перезаписать нельзя, но свойства объекта внутри нее изменять можно. **Используйте по умолчанию**.
*   **`let`** — Объявляет переменную, значение которой будет перезаписываться в процессе работы (счетчики, флаги).
*   **TDZ (Временная мертвая зона)** — Период от начала области видимости до строки объявления переменной `let`/`const`. Обращение к переменной в этой зоне вызовет ошибку `ReferenceError`.
*   **`var`** — Игнорирует блочную область видимости `{}` и автоматически инициализируется как `undefined` при поднятии. **Никогда не используйте**.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Изоляция переменных в блоке
*   **Назначение:** Ограничение видимости переменных рамками фигурных скобок `{}` (условия, циклы, функции) для предотвращения утечки данных во внешний код.

```typescript
export function executeBlockScope(): void {
  // Внешняя переменная доступна для чтения внутри блоков {}
  const outerPayload: string = "outer_data";

  if (outerPayload) {
    // let используется, так как значение localCounter будет перезаписываться
    let localCounter = 0;
    localCounter += 1;

    // Константа isolatedState существует ТОЛЬКО внутри этого блока if {}
    const isolatedState = `step_${localCounter}`;
    
    // Успешное чтение внешней и локальных переменных
    console.log(outerPayload, isolatedState); 
  }

  // Попытка обратиться к локальным переменным вне блока {} вызовет ошибку:
  // console.log(localCounter); // ! ReferenceError: localCounter is not defined
  // console.log(isolatedState); // ! ReferenceError: isolatedState is not defined
}
```

### Шаблон 2: Контроль мутабельности ссылок (const & freeze)
*   **Назначение:** Блокировка переопределения самой переменной (`const`), а также предотвращение нежелательной мутации свойств объектов с помощью рантайм-заморозки.

```typescript
export interface ConfigOptions {
  uid: string;
  statePayload: string;
}

export function handleConstMutability(): void {
  const targetConfig: ConfigOptions = {
    uid: "id_01",
    statePayload: "initial_payload"
  };

  // 1. Изменение свойств объекта (РАЗРЕШЕНО для const)
  targetConfig.statePayload = "updated_payload_value";

  // 2. Перезапись самой константы (ЗАПРЕЩЕНО)
  // targetConfig = { uid: "02", statePayload: "err" }; // ! TypeError: Assignment to constant variable

  // 3. Полная блокировка изменений свойств объекта в рантайме (Иммутабельность)
  const frozenConfig: Readonly<ConfigOptions> = Object.freeze({
    uid: "id_02",
    statePayload: "frozen_payload"
  });

  // Попытка изменить свойство замороженного объекта вызовет ошибку (в строгом режиме):
  // frozenConfig.statePayload = "new"; // ! TypeError: Cannot assign to read only property
}
```

### Шаблон 3: Безопасный обход Временной мертвой зоны (TDZ)
*   **Назначение:** Организация правильной последовательности объявления и вызова переменных для предотвращения критических падений приложения при инициализации.

```typescript
export function handleTemporalDeadZone(): void {
  // === НАЧАЛО ТДЗ ДЛЯ ПЕРЕМЕННОЙ dataPayload ===
  // Любое обращение к dataPayload на этих строках приведет к падению приложения:
  // console.log(dataPayload); // ! ReferenceError: Cannot access 'dataPayload' before initialization

  // Инициализация (Выход из ТДЗ)
  const dataPayload: string = "processed_api_data";
  // === КОНЕЦ ТДЗ ===

  // Теперь переменная безопасна для чтения и передачи в функции
  console.log(dataPayload); 
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Архитектура Лексического окружения (Lexical Environment) под капотом V8
Движок V8 (и любой другой современный движок JavaScript) управляет областями видимости с помощью концепции **Лексического окружения (Lexical Environment)**. Лексическое окружение — это внутренний системный объект, который создается каждый раз, когда поток выполнения заходит в блок кода `{}` (функцию, цикл или условие).

Этот объект состоит из двух ключевых компонентов:
1.  **Запись окружения (Environment Record):** Фактическая локальная таблица «ключ-значение», где хранятся имена всех переменных, констант и функций, объявленных в текущем блоке, а также значения параметров функций.
2.  **Ссылка на внешнее окружение (Outer Lexical Environment Reference):** Прямой физический указатель на родительское лексическое окружение (тот код, который находится снаружи текущего блока).

Когда программа пытается прочитать переменную, движок сначала ищет ее в локальной таблице `Environment Record` текущего блока. Если переменная там отсутствует, движок использует ссылку `Outer Reference` и переходит к родительскому лексическому окружению. Этот процесс продолжается рекурсивно вверх по всей цепочке областей видимости (Scope Chain) до тех пор, пока не достигнет Глобального окружения (`Global Scope`). Если переменной нет и там, движок выбрасывает ошибку `ReferenceError`.

### 2. Механика Temporal Dead Zone (TDZ) на этапах компиляции и выполнения
Временная мертвая зона (TDZ) — это не просто синтаксическое ограничение, а фундаментальный механизм безопасности, жестко контролируемый движком V8. Выполнение вашего кода делится на две фазы:

#### А. Фаза компиляции (Парсинга)
Перед запуском кода парсер движка компилирует исходный текст в Абстрактное синтаксическое дерево (AST) и регистрирует все объявления переменных в текущем `Environment Record`:
*   Если натыкается на `var x`, движок выделяет память, создает ключ `x` и **сразу присваивает ему значение `undefined`**. Она готова к работе.
*   Если натыкается на `let y` или `const z`, движок также выделяет ячейки памяти и создает ключи в таблице, но помечает их системным статусом **"неинициализировано"**. С этого момента для этих переменных официально начинается период TDZ.

#### Б. Фаза выполнения (JIT-компиляция и рантайм)
Движок начинает выполнять код строка за строкой. Если на этой фазе рантайм встречает обращение к переменной, которая в `Environment Record` все еще имеет флаг "неинициализировано" (например, чтение, запись или вызов `typeof`), выполнение программы немедленно прерывается системным исключением `ReferenceError`.

Выход из TDZ происходит строго тогда, когда поток выполнения физически наступает на строчку, где объявлена переменная `let/const`. Движок V8 вычисляет значение справа от знака равенства, записывает его в ячейку памяти и снимает с переменной статус "неинициализировано". Теперь переменная полностью доступна для программы.

### 3. Различия между let, const и var (Детальный анализ)
Главная проблема `var` заключается в ее непредсказуемости. Она полностью игнорирует блочную область видимости `{}`. Если объявить `var` внутри условия `if` или цикла `for`, переменная "утечет" во внешнюю функцию или глобальную область видимости, засоряя память и перезаписывая одноименные переменные.

Кроме того, `var` допускает повторное объявление в рамках одной области видимости (например, `var x = 1; var x = 2;`). Движок просто молча перезапишет данные, не выдав никаких предупреждений. Использование `let` или `const` защищает от подобных ошибок на этапе парсинга: попытка повторно объявить их в одном блоке вызовет критическую синтаксическую ошибку `SyntaxError` еще до того, как код начнет выполняться.

### 4. Контроль мутабельности ссылок (Стек против Кучи)
Понимание работы `const` требует четкого разграничения двух типов памяти в JS: **Стека (Stack)** и **Кучи (Heap)**.

*   **Стек (Stack):** Быстрая память фиксированного размера, где хранятся примитивные значения и адреса ссылок на сложные объекты.
*   **Куча (Heap):** Динамическая память произвольного размера, где физически хранятся структуры сложных объектов и массивов.

Ключевое слово `const` блокирует изменение значения **строго в Стек-памяти**. 
*   Если через `const` объявлен примитив (число, строка), его значение хранится прямо в стеке. Изменить его нельзя.
*   Если через `const` объявлен объект, в стеке хранится лишь **адрес ссылки** (указатель), ведущий на ячейку в куче. `const` гарантирует, что эта ссылка в стеке никогда не изменится. Вы не сможете привязать к этой переменной другой объект. Однако внутренняя структура самого объекта в куче (добавление, изменение или удаление свойств) никак не контролируется стеком, поэтому свойства объекта изменять разрешено.

Для реализации полной рантайм-неизменяемости объектов используется метод `Object.freeze()`. Он делает объект иммутабельным на уровне кучи. Но у `Object.freeze()` есть ограничение: он выполняет поверхностную «заморозку» (shallow freeze). Если внутри замороженного объекта есть вложенные объекты, их свойства все еще можно изменять. Для полной блокировки требуется рекурсивный обход объекта с вызовом `Object.freeze()` для каждого вложенного уровня.

## 5. Критические ошибки и подводные камни

### Ошибка 1: TDZ при передаче параметров по умолчанию
*   *Проблема:* Разработчик пытается использовать переменную в качестве дефолтного значения параметра функции до того, как она была объявлена в теле функции.
*   *Причина:* Локальные параметры функции имеют свою собственную область видимости, которая вычисляется слева направо. Если попытаться сослаться на параметр, который находится правее (или на локальную переменную из тела функции), возникнет TDZ-ошибка.

```typescript
// ПЛОХО (Ошибка TDZ при вызове функции)
export function calculateVolume(height = width, width: number): number {
  return height * width; // ! ReferenceError: Cannot access 'width' before initialization
}

// ХОРОШО (Параметры считываются по порядку их объявления)
export function calculateVolumeFixed(width: number, height = width): number {
  return height * width;
}
```

### Ошибка 2: Случайная мутация объектов-констант
*   *Проблема:* Передача объекта, объявленного через `const`, во внешние чистые функции, которые изменяют его свойства «на месте» (in-place), приводя к непредсказуемому изменению глобального состояния.
*   *Решение:* Использование TypeScript-модификатора `readonly` на уровне типов, который запрещает компиляцию кода при попытке мутации полей, и создание иммутабельных копий через spread-оператор.

```typescript
// ПЛОХО (Свойство объекта изменяется напрямую, ломая иммутабельность)
export function updateStateUnsafe(options: ConfigOptions): void {
  options.statePayload = "new_value"; 
}

// ХОРОШО (TypeScript запрещает мутацию на этапе компиляции, функция возвращает новый объект)
export function updateStateSafe(options: Readonly<ConfigOptions>): ConfigOptions {
  // options.statePayload = "new"; // ! Ошибка компиляции TS
  return {
    ...options,
    statePayload: "new_value" // Возвращаем абсолютно новую копию объекта
  };
}
```

### Ошибка 3: Замыкание неинициализированной переменной в отложенных функциях
*   *Проблема:* Стрелочная функция или обработчик события замыкается на переменную, которая на момент создания функции находится в TDZ, и пытается выполниться раньше, чем переменная инициализируется в основном коде.

```typescript
// ПЛОХО (Функция-обработчик вызывается до инициализации)
export function setupDeferredCall(): void {
  const triggerCall = () => console.log(cachedPayload); // Функция замкнулась на cachedPayload
  
  triggerCall(); // ! ReferenceError: Cannot access 'cachedPayload' before initialization

  const cachedPayload = "api_cache_data";
}

// ХОРОШО (Вызовы перенесены строго ниже строки выхода из TDZ)
export function setupDeferredCallFixed(): void {
  const triggerCall = () => console.log(cachedPayload);
  
  const cachedPayload = "api_cache_data";
  
  triggerCall(); // Успешно выведет данные, так как cachedPayload уже инициализирован
}
```
