# 1.1.3. Предотвращение утечек памяти в JS

## БЫСТРЫЙ СТАРТ

*   **Утечка памяти (Memory Leak)** — это ситуация, при которой программа резервирует область в оперативной памяти для временных данных, но не освобождает её после того, как эти данные перестали быть нужными.
*   **Используйте ручную очистку для:** запущенных интервалов (`setInterval`), подписок на глобальные события (`window.addEventListener`), неиспользуемых ссылок в кэше и ссылок на удаленные из DOM-дерева элементы.
*   **Используйте WeakMap и WeakSet для:** создания кэшей или ассоциации метаданных с объектами. Ссылки в этих коллекциях являются слабыми и не мешают сборщику мусора удалять объекты.
*   **Не оставляйте:** активные таймеры или глобальные обработчики событий при уничтожении компонентов или переходе между страницами — это главная причина прогрессирующего замедления интерфейса.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Корректное уничтожение таймеров (Tear-down Timer)
*   **Назначение:** Гарантированное удаление запущенного интервала и очистка ссылки на его идентификатор при выходе из контекста выполнения.

```typescript
export interface ExecutionController {
  terminate: () => void; // Метод принудительной остановки и очистки памяти
}

export function initializeTaskScheduler(delayTime: number): ExecutionController {
  // Локальный идентификатор таймера
  let schedulerId: any | null = null;

  // Имитируем запуск циклической задачи
  schedulerId = setInterval(() => {
    console.log("Выполнение запланированной фоновой задачи...");
  }, delayTime);

  // Возвращаем метод очистки для вызова при уничтожении контекста
  return {
    terminate: (): void => {
      if (schedulerId) {
        // Физически останавливаем интервал в Web APIs браузера
        clearInterval(schedulerId); 
        
        // Обнуляем ссылку, чтобы Garbage Collector очистил замыкание
        schedulerId = null; 
        console.log("Таймер успешно остановлен, ресурсы освобождены.");
      }
    }
  };
}
```

### Шаблон 2: Безопасное управление глобальными слушателями событий
*   **Назначение:** Добавление обработчика на глобальный объект (`window` / `document`) с обязательной регистрацией функции удаления во избежание бесконечного удержания памяти.

```typescript
export interface EventListenerController {
  unregister: () => void; // Метод для удаления глобального слушателя
}

export function registerGlobalResizeHandler(callback: (width: number) => void): EventListenerController {
  // Декларируем изолированную функцию-обработчик
  const resizeHandler = (): void => {
    callback(window.innerWidth);
  };

  // Регистрируем слушатель в браузере
  window.addEventListener("resize", resizeHandler);

  return {
    unregister: (): void => {
      // Обязательно передаем ту же самую ссылку на функцию resizeHandler
      window.removeEventListener("resize", resizeHandler); 
      console.log("Глобальный слушатель resize успешно удален.");
    }
  };
}
```

### Шаблон 3: Очистка временного кэша объектов через `WeakMap`
*   **Назначение:** Создание кэша метаданных, который автоматически очищается сборщиком мусора, как только исходные объекты удаляются из основной программы.

```typescript
export interface CachePayload {
  lastUpdated: number;
  metadata: string;
}

export function createWeakCache<T extends object>() {
  // Используем WeakMap, ключами в котором могут быть только объекты
  const privateCache = new WeakMap<T, CachePayload>();

  return {
    setRecord: (keyObject: T, payload: CachePayload): void => {
      // Записываем данные в кэш. Ключ-объект удерживается по слабой ссылке
      privateCache.set(keyObject, payload);
    },
    getRecord: (keyObject: T): CachePayload | undefined => {
      // Считываем данные из кэша
      return privateCache.get(keyObject);
    }
    // Метод удаления всех записей не нужен: как только keyObject удалят из программы,
    // запись в WeakMap сотрется из памяти автоматически в следующем цикле GC
  };
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Алгоритмы сборки мусора (Garbage Collection) в V8 под капотом
Сборщик мусора в движке V8 работает по основному алгоритму **Mark-and-Sweep (Пометь и Смети)**, который базируется на концепции **досягаемости (Reachability)** объектов. 

Процесс сборки мусора делится на три основные фазы:
1.  **Поиск корней (Roots):** Движок определяет базовый набор "досягаемых" объектов, которые гарантированно не могут быть удалены (глобальные переменные `window`, стек вызовов текущих функций и их локальные переменные).
2.  **Маркировка (Marking):** Сборщик рекурсивно обходит все ссылки от корней к дочерним объектам. Каждый объект, до которого удалось дотянуться по цепочке ссылок, помечается флагом «досягаем».
3.  **Очистка (Sweeping):** Сборщик сканирует всю кучу (heap). Все объекты, которые не получили флаг досягаемости на предыдущем шаге, физически удаляются из памяти, а занимаемое ими пространство освобождается для будущих аллокаций.

В V8 куча дополнительно разделена на два поколения: **Молодое (Young Generation)** для короткоживущих объектов и **Старое (Old Generation)** для долгоживущих. Объекты, пережившие несколько циклов очистки в молодом поколении, перемещаются в старое. Очистка старого поколения (Major GC) — тяжелая операция, блокирующая основной поток выполнения, поэтому частые утечки памяти приводят к заметным задержкам интерфейса (Lag/Jank).

### 2. Физика возникновения утечек памяти
Утечка памяти в JavaScript возникает тогда, когда в программе непреднамеренно сохраняется логическая связь (цепочка ссылок) от глобального корня (`window` или активного стека выполнения) к объекту, который больше не нужен для работы. 

Основные физические причины:
*   **Забытые таймеры (`setInterval` / `setTimeout`):** Если внутри колбэка `setInterval` используется внешняя переменная, функция замыкается на нее. До тех пор, пока интервал не остановлен через `clearInterval()`, Web APIs браузера удерживают ссылку на колбэк, а колбэк удерживает ссылки на все лексическое окружение в куче, блокируя очистку памяти.
*   **Глобальные слушатели событий:** Если компонент вешает обработчик на `window` или `document` и уничтожается, браузер продолжает хранить ссылку на этот обработчик. Функция-обработчик не может быть удалена, удерживая в памяти весь контекст компонента.
*   **Отсоединенные DOM-узлы (Detached DOM nodes):** Возникают, когда элемент удаляется со страницы через `element.remove()`, но ссылка на него продолжает храниться в каком-либо JavaScript-массиве или объекте. Объект `HTMLDivElement` физически отсутствует на экране, но не может быть удален из оперативной памяти, так как на него ведет ссылка из JS.

### 3. Детальный пошаговый разбор выполнения шаблона 3
1.  **Инициализация WeakMap:** Создается кэш `createWeakCache()`. В куче резервируется структура `WeakMap`. Она не имеет ссылок на свои ключи, а лишь ассоциирует их значения в памяти.
2.  **Запись данных:** Вызывается `setRecord(userObj, data)`. В `WeakMap` записывается слабая связь. Объект `userObj` выступает в качестве ключа.
3.  **Использование в программе:** Пока `userObj` используется в кодовой базе (например, выведен в список), он досягаем от глобального корня. Данные в кэше доступны по вызову `.getRecord(userObj)`.
4.  **Уничтожение объекта:** Программа удаляет `userObj` (например, очищается переменная: `userObj = null`). 
5.  **Автоматическая очистка:** Во время следующей сборки мусора V8 видит, что на исходный объект `userObj` больше нет сильных ссылок. Слабая ссылка из `WeakMap` игнорируется сборщиком. Объект удаляется из кучи, а связанная с ним запись `CachePayload` стирается из `WeakMap` автоматически без вызова деструкторов.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Хранение ссылок на удаленные DOM-элементы**
    *   *Проблема:* Разработчик кэширует ссылки на DOM-узлы в массиве для быстрой анимации, затем удаляет элементы со страницы, но забывает очистить массив. Память утекает.
    *   *Решение:* Очищайте ссылки в массивах или используйте `WeakMap`/`WeakSet` для ассоциации данных с DOM-элементами.

```typescript
// ПЛОХО (Удаленный div навсегда зависает в памяти из-за ссылки в массиве)
export class DOMHolderUnsafe {
  private cache: HTMLElement[] = [];

  public registerElement(el: HTMLElement): void {
    this.cache.push(el);
  }

  public clearDOM(el: HTMLElement): void {
    el.remove(); // Элемент удален из DOM-дерева, но остался в массиве cache
  }
}

// ХОРОШО (Очистка ссылок в JS-структурах при удалении из DOM)
export class DOMHolderSafe {
  private cache = new WeakSet<HTMLElement>();

  public registerElement(el: HTMLElement): void {
    this.cache.add(el); // WeakSet не мешает удалению элемента сборщиком мусора
  }

  public clearDOM(el: HTMLElement): void {
    el.remove(); // Как только ссылки на el исчезнут из программы, он полностью удалится из памяти
  }
}
```

*   **Ошибка 2: Прогрессирующие утечки из-за неснятых подписок resize/scroll**
    *   *Проблема:* Компонент подписывается на событие `scroll` окна браузера. При частом переключении страниц создаются десятки новых обработчиков, нагружающих процессор и забивающих память.
    *   *Решение:* Всегда сохраняйте ссылки на колбэки и вызывайте `removeEventListener` в деструкторах или хуках жизненного цикла (`ngOnDestroy` / `DestroyRef` в Angular).

```typescript
// ПЛОХО (Слушатель накапливается при каждом вызове инициализации)
export function initWindowSpyUnsafe(callback: () => void): void {
  window.addEventListener("scroll", () => {
    callback(); // Анонимный колбэк невозможно удалить,removeEventListener не сработает
  });
}
```

*   **Ошибка 3: Накопление тяжелых объектов в глобальных коллекциях (Кэш-синглтонах)**
    *   *Проблема:* Разработчик создает синглтон-сервис для кэширования ответов сервера через обычный `Map`. Со временем кэш разрастается до сотен мегабайт, приводя к зависанию вкладки.
    *   *Решение:* Реализуйте алгоритм вытеснения кэша (например, LRU - Least Recently Used) или ограничивайте максимальный размер коллекции, удаляя старые записи при добавлении новых.

```typescript
// ПЛОХО (Кэш разрастается бесконечно)
export class InfiniteCache {
  private storage = new Map<string, any>();
  public set(key: string, data: any) { this.storage.set(key, data); }
}

// ХОРОШО (Кэш с ограничением размера)
export class LimitedCache<T> {
  private storage = new Map<string, T>();
  private readonly maxLimit = 100;

  public set(key: string, data: T): void {
    if (this.storage.size >= this.maxLimit) {
      // Находим самый старый ключ и удаляем его из памяти
      const oldestKey = this.storage.keys().next().value;
      if (oldestKey) this.storage.delete(oldestKey);
    }
    this.storage.set(key, data);
  }
}
```
