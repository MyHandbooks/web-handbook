# 1.1.2. Наследственность и замыкания

## БЫСТРЫЙ СТАРТ

*   **Замыкание (Closure)** — это способность функции запоминать свою внешнюю область видимости (лексическое окружение) и иметь к ней доступ даже тогда, когда функция выполняется вне этой родительской области.
*   **Наследование областей видимости** — механизм, при котором вложенные функции неявно получают доступ ко всем переменным внешних родительских функций.
*   **Используйте замыкания для:** создания приватных переменных (инкапсуляции данных), каррирования (частичного применения аргументов) и сохранения контекста в асинхронных колбэках.
*   **Не используйте замыкания:** для хранения тяжелых неактивных данных в памяти без их своевременной очистки, так как это блокирует работу сборщика мусора.

## ПРАКТИЧЕСКИЕ ШАБЛОНЫ ДЛЯ КОПИРОВАНИЯ

### Шаблон 1: Инкапсуляция состояния (Приватное хранилище)
*   **Назначение:** Создание изолированного контейнера данных, состояние которого невозможно прочитать или перезаписать напрямую из внешнего кода.

```typescript
// Описание интерфейса возвращаемого метода управления
export interface StateController<T> {
  getState: () => T;                   // Метод чтения текущего состояния
  updateState: (payload: T) => void;   // Метод безопасной перезаписи состояния
}

export function createStateContainer<T>(initialValue: T): StateController<T> {
  // Локальное приватное свойство, недоступное извне
  let internalState: T = initialValue;

  // Возвращаем объект методов, замыкающихся на переменную internalState
  return {
    getState: (): T => {
      // Метод удерживает доступ к internalState своего родительского окружения
      return internalState; 
    },
    updateState: (payload: T): void => {
      // Безопасное обновление инкапсулированных данных
      internalState = payload; 
    }
  };
}
```

### Шаблон 2: Каррирование и частично примененные функции
*   **Назначение:** Создание переиспользуемых конфигурационных шаблонов функций за счет фиксации первых аргументов в замыкании.

```typescript
// Описание типов параметров
export type OperationCallback<T> = (value: T) => T;
export type ConfigurationFactory<T> = (config: T) => OperationCallback<T>;

export function createConfigurator<T>(modifier: (base: T, option: T) => T): ConfigurationFactory<T> {
  // Первая функция фиксирует общую логику модификации и возвращает фабрику конфигураций
  return (configOption: T): OperationCallback<T> => {
    // Вторая функция фиксирует конкретную настройку configOption в замыкании
    return (baseValue: T): T => {
      // Выполняем вычисление, используя переданную базу и сохраненную конфигурацию
      return modifier(baseValue, configOption); 
    };
  };
}
```

### Шаблон 3: Сохранение контекста итерации в асинхронном цикле
*   **Назначение:** Гарантированное изолирование значения переменной на каждой итерации асинхронного цикла для предотвращения побочных эффектов.

```typescript
export function executeAsyncSequence(payloadList: string[]): void {
  // Использование блочного let гарантирует создание нового окружения на каждой итерации
  for (let iterationIndex = 0; iterationIndex < payloadList.length; iterationIndex++) {
    
    // Каждая итерация создает свою константу, которая фиксируется в колбэке таймера
    const currentPayload = payloadList[iterationIndex];

    setTimeout(() => {
      // Функция замыкается на свою уникальную копию переменной currentPayload в куче
      console.log(`Индекс: ${iterationIndex}, Данные: ${currentPayload}`);
    }, iterationIndex * 100); // Динамическая задержка
  }
}
```

## ГЛУБОКОЕ ПОГРУЖЕНИЕ

### 1. Физика замыкания и скрытое свойство `[[Environment]]`
Каждая функция в JavaScript при создании получает от движка V8 скрытое системное свойство **`[[Environment]]`**. В это свойство записывается прямая ссылка на то конкретное **Лексическое окружение (Lexical Environment)**, в котором эта функция была физически объявлена в коде. 

Когда функция запускается, для ее выполнения создается новое локальное лексическое окружение. По спецификации ECMAScript, указатель на внешнее родительское окружение (`Outer Lexical Environment Reference`) для этого нового запуска берется напрямую из скрытого свойства `[[Environment]]` вызываемой функции.

Если родительская функция завершает работу и возвращает из себя дочернюю функцию, лексическое окружение родителя **не может быть удалено из оперативной памяти**. Сборщик мусора (Garbage Collector) работает по принципу досягаемости (Reachability). Поскольку возвращенная дочерняя функция сохраняет ссылку на родительское окружение через свое свойство `[[Environment]]`, все переменные родителя в куче (heap) остаются досягаемыми и продолжают жить в памяти.

### 2. Наследование областей видимости (Scope Chain) и поиск переменных
Наследование областей видимости — это древовидная структура лексических окружений. Поиск переменных выполняется строго снизу вверх по цепочке областей видимости:

1.  **Локальная запись:** Движок ищет имя переменной в `Environment Record` текущего лексического окружения выполняемой функции.
2.  **Поиск по внешней ссылке:** Если имя не найдено, движок обращается к свойству `Outer Reference` и переходит к родительскому лексическому окружению.
3.  **Глобальная область:** Этот процесс повторяется вплоть до Глобального лексического окружения (`Global Scope`). Если переменная не найдена и в глобальной области, в строгом режиме рантайм выбросит `ReferenceError`.

Дочерние лексические окружения имеют полный доступ к чтению и перезаписи переменных родительских окружений, но родительские окружения физически не могут заглянуть во внутренние области видимости своих потомков.

### 3. Детальный пошаговый разбор выполнения шаблона 1
1.  **Создание контейнера:** Вызывается функция `createStateContainer("initial")`. Создается лексическое окружение `createStateContainer_Env`. В его `Environment Record` записывается переменная `internalState` со значением `"initial"`.
2.  **Объявление методов:** Внутри функции создается объект с методами `getState` и `updateState`. Обе эти дочерние функции получают ссылку на окружение `createStateContainer_Env` в свои скрытые свойства `[[Environment]]`.
3.  **Возврат и сохранение:** Объект методов возвращается наружу и записывается в переменную `const controller = createStateContainer("initial")`. Стек вызовов функции очищается, но окружение `createStateContainer_Env` остается в куче, так как объект `controller` держит ссылки на методы, которые ссылаются на это окружение.
4.  **Чтение состояния:** Вызывается метод `controller.getState()`. Создается новое локальное лексическое окружение вызова. Поиск переменной `internalState` в нем завершается неудачей. Движок обращается по ссылке во внешнее окружение `createStateContainer_Env`, находит там переменную `internalState` и возвращает её актуальное значение.

### 4. Типичные ошибки и их решение

*   **Ошибка 1: Утечка памяти из-за неиспользуемых замкнутых переменных**
    *   *Проблема:* Родительская функция содержит тяжелый объект, который не используется дочерней функцией. Тем не менее, дочерняя функция удерживает ссылку на все родительское лексическое окружение целиком, блокируя очистку тяжелого объекта сборщиком мусора.
    *   *Решение:* Явно зануляйте ссылки на тяжелые неиспользуемые переменные в конце родительской функции или выносите их за пределы области видимости замыкания.

```typescript
// ПЛОХО (Тяжелый массив остается висеть в памяти из-за замыкания)
export function leakMemory(): () => string {
  const heavyPayload = new Array(1000000).fill("data");
  return () => {
    return "active_data"; // heavyPayload не используется, но заблокирован в памяти
  };
}

// ХОРОШО (Высвобождение неиспользуемой памяти)
export function clearMemorySafe(): () => string {
  let heavyPayload: string[] | null = new Array(1000000).fill("data");
  const processedData = "active_data";
  
  // Выполняем все необходимые операции
  console.log(heavyPayload.length);
  
  // Явно зануляем ссылку перед возвратом замыкания
  heavyPayload = null; 
  return () => {
    return processedData;
  };
}
```

*   **Ошибка 2: Устаревшие замыкания (Stale Closures) в асинхронных колбэках**
    *   *Проблема:* Функция обратного вызова ссылается на переменную, которая успела обновиться во внешнем коде, из-за чего колбэк считывает неактуальные (устаревшие) данные.
    *   *Решение:* Передавайте актуальное состояние в колбэк в качестве аргумента или используйте Сигналы (`computed`) для декларативной синхронизации значений.

```typescript
// ПЛОХО (Колбэк считывает устаревшее значение)
export function setupStaleCallback(): void {
  let dynamicState = "state_1";
  
  // Функция замыкается на динамическую переменную
  const logState = () => console.log(dynamicState);
  
  setTimeout(logState, 100); // Ожидаем вывод актуального состояния
  
  dynamicState = "state_2"; // Значение обновилось до срабатывания таймера
}
```

*   **Ошибка 3: Создание функций в теле цикла `var`**
    *   *Проблема:* Использование `var` для счетчика цикла приводит к тому, что все асинхронные замыкания ссылаются на одну и ту же переменную в памяти, которая к моменту запуска колбэков уже равна максимальному значению.
    *   *Решение:* Всегда объявляйте счетчики циклов с помощью ключевого слова `let`. Это заставляет движок создавать новое независимое лексическое окружение для каждой итерации.

```typescript
// ПЛОХО (Все вызовы выведут индекс 3)
export function runBadLoop(): void {
  for (var index = 0; index < 3; index++) {
    setTimeout(() => console.log(index), 100); 
  }
}

// ХОРОШО (Каждый вызов выведет свой уникальный индекс: 0, 1, 2)
export function runGoodLoop(): void {
  for (let index = 0; index < 3; index++) {
    setTimeout(() => console.log(index), 100); 
  }
}
```
